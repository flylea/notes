# 前端路由 vs 后端路由：同一个模式，不同的终点

## 路由的本质

无论前端还是后端，路由的核心都是：**URL Pattern → Handler**

```
前端：/users/:id → render UserDetail component
后端：/users/:id → execute UserController.findOne()
```

## 前端路由（Vue Router）

```typescript
const routes = [
  {
    path: '/users',
    component: () => import('@/views/UserList.vue'),
    meta: { requiresAuth: true },  // 需要登录
    children: [
      {
        path: ':id',                // /users/123
        component: () => import('@/views/UserDetail.vue'),
        props: route => ({ id: Number(route.params.id) }),
      },
    ],
  },
];
```

## 后端路由（Nest Controller）

```typescript
@Controller('users')
export class UserController {
  @Get()                            // /users
  @UseGuards(AuthGuard)             // 需要登录
  findAll() {}

  @Get(':id')                       // /users/123
  findOne(@Param('id', ParseIntPipe) id: number) {}
}
```

## 概念对照表

| 前端路由 | 后端路由 | 说明 |
|---------|---------|------|
| `path: '/users'` | `@Controller('users')` | 定义路由前缀 |
| `path: ':id'` | `@Get(':id')` | 动态路径参数 |
| `props: route => ({ id })` | `@Param('id') id: string` | 提取参数 |
| `meta: { requiresAuth }` | `@UseGuards(AuthGuard)` | 访问控制 |
| `component: UserDetail` | Controller 方法 + Service | 处理逻辑 |
| `router.beforeEach()` 守卫 | Guard / Middleware | 全局拦截 |

## 后端路由的不同关注点

| 关注点 | 前端路由 | 后端路由 |
|--------|---------|---------|
| 输出 | 渲染 UI（DOM/HTML） | 返回数据（JSON） |
| 状态 | 浏览器地址栏 + History API | 无状态（每个请求独立） |
| 嵌套 | 组件嵌套（children） | 通常不嵌套 |
| 参数 | `route.params.id`（浏览器端） | `@Param('id')`（服务端） |
| 守卫 | `beforeEach` 导航守卫 | Guard + Middleware |
| 404 | `path: '*', component: NotFound` | `NotFoundException` / ExceptionFilter |
| 中间件 | 导航守卫是中间件的一种 | Middleware 链（洋葱模型） |

> **核心差异**：前端路由是"客户端状态管理"（哪个 URL 显示哪个 UI），后端路由是"服务端请求分发"（哪个 URL 执行哪个逻辑）。形式上相似，本质不同。
