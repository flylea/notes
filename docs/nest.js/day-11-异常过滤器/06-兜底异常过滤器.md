# 兜底异常过滤器

## 为什么要兜底？

不是所有异常都是你主动抛的：

```typescript
// 可能的未知异常来源：
// 1. 第三方库内部抛的 Error（如 Prisma 的 PrismaClientKnownRequestError）
// 2. 运行时语法错误（TypeError: Cannot read properties of undefined）
// 3. 数据库连接失败
// 4. 内存溢出
```

如果只处理 `HttpException`，这些未知异常会变成 Nest 默认的 500 响应：

```json
{
  "statusCode": 500,
  "message": "Internal Server Error"
}
```

这不符合统一响应格式。

## 完整的兜底过滤器

```typescript
import {
  ExceptionFilter,
  Catch,
  ArgumentsHost,
  HttpException,
  HttpStatus,
  Logger,
} from '@nestjs/common';
import { Request, Response } from 'express';

@Catch()  // 不传参数 = 捕获所有异常
export class AllExceptionsFilter implements ExceptionFilter {
  private readonly logger = new Logger('AllExceptionsFilter');

  catch(exception: unknown, host: ArgumentsHost) {
    const ctx = host.switchToHttp();
    const response = ctx.getResponse<Response>();
    const request = ctx.getRequest<Request>();

    // 确定状态码
    let status: HttpStatus;
    let message: string;
    let code: number;

    if (exception instanceof HttpException) {
      status = exception.getStatus();
      const exceptionResponse = exception.getResponse();

      // 如果是已经包装好的业务异常（有 code 字段），直接透传
      if (typeof exceptionResponse === 'object' && (exceptionResponse as any).code) {
        const resp = exceptionResponse as any;
        return response.status(status).json({
          code: resp.code,
          data: resp.data ?? null,
          message: resp.message,
          errors: resp.errors,
          path: request.url,
          timestamp: new Date().toISOString(),
        });
      }

      // 处理 ValidationPipe 的数组消息
      const msg = (exceptionResponse as any).message || exception.message;
      message = Array.isArray(msg) ? msg.join('; ') : msg;
      code = status;
    } else {
      // === 未知异常 ===
      status = HttpStatus.INTERNAL_SERVER_ERROR;
      const err = exception as Error;

      // 记录完整错误栈（包括从未见过的异常）
      this.logger.error(
        `[Unhandled Error] ${request.method} ${request.url}`,
        err.stack || err.message,
      );

      // 生产/开发环境区分
      const isProduction = process.env.NODE_ENV === 'production';
      message = isProduction ? '服务器内部错误，请稍后重试' : err.message;
      code = 500;
    }

    response.status(status).json({
      code,
      data: null,
      message,
      path: request.url,
      timestamp: new Date().toISOString(),
    });
  }
}
```

## Prisma 异常的特殊处理

Prisma 抛的是 Prisma 自己的异常类（不是 HttpException），需要在兜底过滤器中特殊识别：

```typescript
import { Prisma } from '@prisma/client';

catch(exception: unknown, host: ArgumentsHost) {

  // Prisma 已知错误 → 转为更友好的消息
  if (exception instanceof Prisma.PrismaClientKnownRequestError) {
    switch (exception.code) {
      case 'P2002':
        status = HttpStatus.CONFLICT;
        message = `字段 "${(exception.meta?.target as string[])?.[0]}" 已存在`;
        code = 10002;
        break;
      case 'P2025':
        status = HttpStatus.NOT_FOUND;
        message = '记录不存在';
        code = 10001;
        break;
      case 'P2003':
        status = HttpStatus.BAD_REQUEST;
        message = '外键约束失败，关联数据不存在';
        code = 20003;
        break;
      default:
        status = HttpStatus.INTERNAL_SERVER_ERROR;
        message = '数据库操作失败';
        code = 500;
    }
  }

  // Prisma 连接错误
  if (exception instanceof Prisma.PrismaClientInitializationError) {
    status = HttpStatus.SERVICE_UNAVAILABLE;
    message = '数据库连接失败';
    code = 503;
  }

  // ... 后续常规处理
}
```

## 与 Sentry / 日志系统集成

```typescript
@Catch()
export class AllExceptionsFilter implements ExceptionFilter {
  constructor(
    // 注入自定义 Logger（Day 23 详讲）
    private readonly logger: AppLogger,
  ) {}

  catch(exception: unknown, host: ArgumentsHost) {
    // ...

    if (!(exception instanceof HttpException)) {
      // 1. 记录到日志文件
      this.logger.error({
        message: 'Unhandled exception',
        error: exception,
        url: request.url,
        user: request.user,
      });

      // 2. 上报到 Sentry（可选）
      // Sentry.captureException(exception);
    }
  }
}
```

## 注册顺序：HttpExceptionFilter 在前，AllExceptionsFilter 在后

```typescript
// main.ts — 正确的顺序
app.useGlobalFilters(
  new AllExceptionsFilter(),  // 兜底的放最前面（外层）→ 先注册，后执行
);

// 或者：
{
  provide: APP_FILTER,
  useClass: HttpExceptionFilter,  // 精确匹配的先执行
},
{
  provide: APP_FILTER,
  useClass: AllExceptionsFilter,  // 兜底的后执行
},
```

Nest 的多个 Filter 从右到左执行（洋葱模型）。`AllExceptionsFilter` 放在 `useGlobalFilters` 参数列表的第一位（最外层的洋葱皮），意味着：
1. `HttpExceptionFilter` 先尝试捕获 → 匹配则处理
2. 不匹配 → `AllExceptionsFilter` 兜底捕获

> 兜底过滤器是你"最后一道防线"。永远记得打印完整错误栈——一个未被识别的异常可能是生产环境最隐蔽的 bug。
