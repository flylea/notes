# 交互式事务详解

## 什么是交互式事务

交互式事务允许你在一个事务回调中**按顺序执行多个 Prisma 操作**，并且可以根据中间查询结果**动态决定下一步做什么**。

```typescript
// 语法
await prisma.$transaction(async (tx) => {
  // tx 是一个独立的 PrismaClient 实例
  // 所有操作在同一个事务中执行
});
```

## 前端类比

```
Vue 的 asyncData / React 的 useEffect：
  - 你可以在里面 await 多个请求
  - 可以根据第一个请求的结果决定第二个请求发不发

Nest 的交互式事务：
  - 你可以在里面 await 多个数据库操作
  - 可以根据第一个查询的结果决定是否执行后续操作
```

## 完整的借书事务

```typescript
import { Injectable, BadRequestException } from '@nestjs/common';
import { PrismaService } from '../prisma/prisma.service';

@Injectable()
export class BorrowService {
  constructor(private prisma: PrismaService) {}

  async borrowBook(userId: number, bookId: number) {
    return this.prisma.$transaction(async (tx) => {
      // 步骤 1：检查图书状态
      const book = await tx.book.findUnique({
        where: { id: bookId },
      });

      if (!book) {
        throw new BadRequestException('图书不存在');
      }
      if (book.status === 'BORROWED') {
        throw new BadRequestException('该书已被借出');
      }

      // 步骤 2：检查用户借阅数量上限
      const borrowCount = await tx.borrowRecord.count({
        where: {
          userId,
          returnedAt: null, // 未归还的
        },
      });

      if (borrowCount >= 3) {
        throw new BadRequestException('每人最多同时借阅 3 本书');
      }

      // 步骤 3：创建借阅记录
      const record = await tx.borrowRecord.create({
        data: {
          userId,
          bookId,
          borrowedAt: new Date(),
        },
      });

      // 步骤 4：更新图书状态
      await tx.book.update({
        where: { id: bookId },
        data: { status: 'BORROWED' },
      });

      // 步骤 5：更新用户借阅计数
      await tx.user.update({
        where: { id: userId },
        data: { borrowCount: { increment: 1 } },
      });

      return record;
    });
  }
}
```

## 核心机制

```
$transaction(async (tx) => {
  // tx 与外部 prisma 的区别：
  // ┌─────────────────┬──────────────────┬──────────────────┐
  // │      特性        │   prisma（外部）   │   tx（事务内）     │
  // ├─────────────────┼──────────────────┼──────────────────┤
  // │ 自动提交         │ ✅ 每条独立提交    │ ❌ 回调结束时统一提交 │
  // │ 异常时回滚       │ ❌ 已提交的无法撤销 │ ✅ 全部回滚        │
  // │ 隔离性           │ 取决于数据库配置    │ 数据库事务隔离级别   │
  // │ API 完全一致     │ ✅               │ ✅               │
  // └─────────────────┴──────────────────┴──────────────────┘
```

## 事务超时

```typescript
await this.prisma.$transaction(
  async (tx) => {
    // 耗时操作...
  },
  {
    maxWait: 5000,    // 等待获取锁的最长时间（ms）
    timeout: 10000,   // 事务最长执行时间（ms）
  },
);
```

> ⚠️ `timeout` 是 Prisma 4+ 才支持的参数。超时后会抛出 `PrismaClientKnownRequestError`，错误码 `P2028`。

## 事务中的异常处理

```typescript
async borrowBook(userId: number, bookId: number) {
  try {
    return await this.prisma.$transaction(async (tx) => {
      // ... 事务逻辑
    });
  } catch (error) {
    // 事务中的任何异常都会导致回滚
    if (error instanceof Prisma.PrismaClientKnownRequestError) {
      if (error.code === 'P2028') {
        throw new BadRequestException('操作超时，请重试');
      }
      if (error.code === 'P2034') {
        throw new BadRequestException('事务冲突，请重试');
      }
    }
    throw error;
  }
}
```

## 事务隔离级别控制

```typescript
// Prisma 4.2+ 支持设置隔离级别
await this.prisma.$transaction(
  async (tx) => {
    // ...
  },
  {
    isolationLevel: Prisma.TransactionIsolationLevel.Serializable,
  },
);
```

| 隔离级别 | MySQL | PostgreSQL | 防脏读 | 防不可重复读 | 防幻读 |
|---------|-------|-----------|--------|------------|--------|
| `ReadUncommitted` | ✅ | ✅ | ❌ | ❌ | ❌ |
| `ReadCommitted` | ✅ | ✅ | ✅ | ❌ | ❌ |
| `RepeatableRead` | ✅(默认) | ✅ | ✅ | ✅ | ❌ |
| `Serializable` | ✅ | ✅(默认) | ✅ | ✅ | ✅ |

## 实战：还书事务

```typescript
async returnBook(userId: number, bookId: number) {
  return this.prisma.$transaction(async (tx) => {
    // 查找未归还的借阅记录
    const record = await tx.borrowRecord.findFirst({
      where: {
        userId,
        bookId,
        returnedAt: null,
      },
    });

    if (!record) {
      throw new BadRequestException('未找到该借阅记录');
    }

    // 更新借阅记录
    await tx.borrowRecord.update({
      where: { id: record.id },
      data: { returnedAt: new Date() },
    });

    // 恢复图书状态
    await tx.book.update({
      where: { id: bookId },
      data: { status: 'AVAILABLE' },
    });

    // 减少用户借阅计数
    await tx.user.update({
      where: { id: userId },
      data: { borrowCount: { decrement: 1 } },
    });

    return { success: true };
  });
}
```

## 交互式事务 vs 手动事务管理

```typescript
// ❌ 手动管理——容易出错
async borrowBookBad(userId: number, bookId: number) {
  await this.prisma.$queryRaw`START TRANSACTION`;
  try {
    await this.prisma.borrowRecord.create(...);
    await this.prisma.book.update(...);
    await this.prisma.$queryRaw`COMMIT`;
  } catch (error) {
    await this.prisma.$queryRaw`ROLLBACK`;
    throw error;
  }
}

// ✅ Prisma 交互式事务——自动管理
async borrowBookGood(userId: number, bookId: number) {
  return this.prisma.$transaction(async (tx) => {
    await tx.borrowRecord.create(...);
    await tx.book.update(...);
  });
}
```

## 注意事项

1. **不要在事务内使用外部 `prisma` 实例**：事务内的操作必须使用 `tx`，否则不在同一事务中
2. **事务不宜过长**：持有数据库锁的时间越长，并发性能越差
3. **不要从事务中执行发邮件等外部 IO**：邮件发送成功但事务回滚，数据就不一致了
4. **异步操作要 await**：忘记 await 意味着操作在事务外执行

```typescript
// ❌ 常见错误：忘记 await
await this.prisma.$transaction(async (tx) => {
  tx.book.update({ ... });  // 忘了 await——在事务外执行！
  await tx.borrowRecord.create({ ... });
});

// ❌ 常见错误：事务内用外部 prisma
await this.prisma.$transaction(async (tx) => {
  await this.prisma.book.update({ ... });  // 应该用 tx！
});
```
