# 5 大 Node.js 后端框架深度对比

## 为什么会有这么多框架？

一个常见的误解是"框架越多说明生态越乱"。实际上，框架的涌现是生态成熟的标志——不同业务场景需要不同的抽象层级。

比如 Vue 生态中有 Nuxt（服务端渲染）、VitePress（文档站）、Quasar（跨平台 App），它们没有互相"取代"，而是在不同场景下解决了不同问题。

Node.js 后端框架也一样。按出现时间排序：

## Express（2009）— 百废待兴时代的先驱

```
Star: 66k+ | 周下载: 30M+ | 作者: TJ Holowaychuk
```

Express 定义了 Node.js Web 开发的范式：**中间件 + 路由**。它极度简约、极低心智负担，但也极"任性"——Controller 放哪？Service 怎么写？项目怎么分层？全凭你和团队的约定。

**Express 的问题不是"功能少"，而是"没有约束"**。当你从 1 个人写到 5 个人再写到 20 个人时，每个人的写法都不一样，代码腐化速度远超预期。

```javascript
// Express 项目中你能看到这几种写法全混在一起：
// 写法 A：逻辑全写路由里
app.get('/users', async (req, res) => {
  const users = await db.query('SELECT * FROM users');
  res.json(users);
});

// 写法 B：抽了一个 controller 文件但随便放
app.get('/users', userController.getAll);

// 写法 C：有人用了 Service 层，有人没用
// 写法 D：有人用的 callback，有人用的 async/await
```

**选 Express 的理由**：极简项目、原型验证、Serverless 函数（单个文件）

## Koa（2013）— Express 原班人马的反思之作

```
Star: 35k+ | 周下载: 2M+ | 作者: Express 原班团队
```

Koa 的核心改进只有一个但非常关键：**用 async/await 替代回调**。这让中间件的洋葱模型前所未有的清晰：

```javascript
// Koa 洋葱模型
app.use(async (ctx, next) => {
  console.log('1. 请求进来');
  await next();
  console.log('4. 响应出去');  // 等所有下游中间件执行完再执行
});

app.use(async (ctx, next) => {
  console.log('2. 第二个中间件');
  await next();
  console.log('3. 第三个中间件完成');
});
// 输出：1 → 2 → 3 → 4
```

但 Koa 在架构约束上比 Express 更"放任"——连 Router 都是外部中间件（`koa-router`）。它更像是一个精良的工具箱，而不是一套完整的建筑蓝图。

**选 Koa 的理由**：需要 async/await 优雅异步控制、追求极简内核

## Egg（2016）— 阿里的"约定大于配置"实践

```
Star: 19k+ | 周下载: 80k+ | 维护: 阿里 Node.js 团队
```

Egg 的定位非常精准：**给 Express/Koa 加上架构约束**。

```javascript
// Egg 的目录约定——不按这个放就跑不起来
app/
├── controller/    // 必须放这
│   └── user.js
├── service/       // 必须放这
│   └── user.js
├── middleware/    // 必须放这
├── router.js      // 必须叫这个
config/
├── config.default.js
├── config.prod.js
```

Egg 引入的关键概念：
- **约定大于配置**：目录结构、文件命名、加载顺序全部约定好
- **多进程管理**：内置 cluster 模式，自动利用多核 CPU
- **插件体系**：标准化的插件加载和扩展机制
- **框架之上有框架**：阿里内部的 Chair、Midway 都是在 Egg 之上再封装

**Egg 的困境**：成也"约定"，败也"约定"。2016 年的约定在今天看有些过时了——比如它对 TypeScript 的支持是后期补丁式的，不像 Nest 从设计之初就是 TypeScript-first。

**选 Egg 的理由**：阿里系项目（内部生态）、已有大量 Egg 项目的团队

## Midway（2019）— Egg 的 TypeScript 进化版

```
Star: 7k+ | 周下载: 30k+ | 维护: 阿里 Node.js 团队
```

Midway 可以看作"Egg + TypeScript + IoC"：

```typescript
// Midway 的核心改进：装饰器 + 依赖注入
@Provide()           // 相当于 @Injectable()
@Controller('/api/user')
export class UserController {
  @Inject()
  userService: UserService;  // 自动注入

  @Get('/')
  async getUser() {
    return this.userService.getUsers();
  }
}
```

Midway 在阿里内部大量使用，和 Egg 生态打通。如果你在阿里工作或使用阿里云服务（如函数计算 FC），Midway 是第一选择。

**Midway vs Nest 的关键区别**：
- Midway 深度绑定 Egg 生态和阿里云，Nest 是平台无关的
- Midway 社区主要在国内，Nest 是全球社区（GitHub 47k+ Stars, Discord 30k+ 成员）
- Nest 的设计更接近 Spring（Java），Midway 更接近 Egg 的进化

**选 Midway 的理由**：阿里系团队、国内社区支持、和阿里云深度集成

## NestJS（2017）— 真正的 Node.js 版 Spring

```
Star: 69k+ | 周下载: 4.5M+ | 维护: NestJS 公司 + 社区
```

Nest 的野心最大：**做 Node.js 生态的 Spring**。它的设计灵感直接来自 Angular（前端）和 Spring（后端）：

- Angular 给了它 Module/Decorator/DI 的语法
- Spring 给了它 AOP/IoC/分层架构的思想
- Express/Fastify 是它的底层 HTTP 引擎

```typescript
@Module({
  imports: [UserModule, BookModule],
  controllers: [AppController],
  providers: [AppService],
})
export class AppModule {}
```

**为什么 Nest 在 2026 年已经是事实上的首选？**

1. **TypeScript-first**：从第一天起就用 TS 设计，类型安全是骨架不是外皮
2. **架构完整**：不需要额外拼凑——认证、校验、日志、文档、队列、微服务全有官方方案
3. **全球社区**：47k+ GitHub Stars、丰富的 npm 生态、活跃的 Discord
4. **后端思想现代化**：IoC、AOP、装饰器——这些 Java/C# 后端验证了 20 年的最佳实践
5. **招聘溢价**：国内外 NestJS 岗位持续增长，薪资高于 Express 开发者 30-50%

## 五框架决策矩阵

| 维度 | Express | Koa | Egg | Midway | NestJS |
|------|---------|-----|-----|--------|--------|
| TypeScript 支持 | 手动 | 手动 | 补丁式 | 原生 | **一等公民** |
| 依赖注入 | 无 | 无 | 无 | 有 | **完整 IoC** |
| 架构约束 | 无 | 无 | 约定式 | 装饰器式 | **装饰器+Module** |
| 中间件生态 | 巨大 | 适配 Express | Egg 插件 | Egg 插件 | 兼容 Express |
| 官方模块 | 无 | 无 | 少 | 中等 | **全（认证/文档/队列/微服务）** |
| 微服务支持 | 手动 | 手动 | 手动 | 部分 | **内置多传输层** |
| GitHub Star | 66k | 35k | 19k | 7k | **69k** |
| 周下载量 | 30M | 2M | 80k | 30k | **4.5M** |
| 适合项目 | 原型/小项目 | 极简定制 | 阿里内部 | 阿里+TS | **所有规模** |
| 学习曲线 | 极低 | 低 | 中 | 中高 | 中高 |

## 结论：为什么这个教程选 Nest

不是因为 Nest "最新最火"，而是因为：

1. 学 Nest 学到的**不仅是框架**，还有 IoC/DI/AOP 这些跨越语言的后端设计思想。你今天会写 Nest，明天学 Spring Boot 难度减半
2. Nest 的架构约束让你的代码在 3 个月后还能看懂——这对学习者和团队都至关重要
3. Express 的手动挡经验有价值，但 Nest 的自动挡让你把注意力放在业务上，而不是拼凑中间件
4. 如果你只会 Express，跳槽时你的对手是 10 年 Express 经验的 Node 开发者；如果你掌握 Nest，你的对手范围缩小 90%
