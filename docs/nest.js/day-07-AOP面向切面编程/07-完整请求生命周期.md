# 完整请求生命周期图解

## 一张终极流程图

```
客户端发起 HTTP 请求
  │
  │  GET /book/list?keyword=Nest&page=1
  │
  ▼
═══════════════════════════════════════════════════════════════════
                           Middleware
═══════════════════════════════════════════════════════════════════
  │  1. 全局 Middleware （cors、helmet、session）
  │  2. Module 级 Middleware
  │  3. 路由级 Middleware
  │
  │  产出：修改过的 req/res 对象（如 req.session、req.userId）
  │
  ▼
═══════════════════════════════════════════════════════════════════
                            Guard
═══════════════════════════════════════════════════════════════════
  │  1. 全局 Guard
  │  2. Controller 级 Guard  (@UseGuards)
  │  3. Handler 级 Guard   (@UseGuards)
  │
  │  ┌─ canActivate() === false → 403 Forbidden
  │  ├─ 抛出异常 → 跳转到 ExceptionFilter ────────────┐
  │  └─ canActivate() === true → 继续 ↓                │
  │                                                      │
  ▼                                                      │
══════════════════════════════════════════════════════════ │ ═════
                     Interceptor (前)                     │
══════════════════════════════════════════════════════════ │ ═════
  │  1. 全局 Interceptor          │                      │
  │  2. Controller 级 Interceptor  │                      │
  │  3. Handler 级 Interceptor     │                      │
  │                                │                      │
  │  Before 逻辑：                │                      │
  │  ─ 记录请求开始时间            │                      │
  │  ─ 缓存命中 → 直接返回（跳过 Controller）            │
  │  ─ 限流检查                   │                      │
  │                                │                      │
  ▼                                │                      │
════════════════════════════════════ │ ─────────────────────│──
                            Pipe     │                      │
════════════════════════════════════ │ ─────────────────────│──
  │  1. 全局 Pipe （ValidationPipe）│                      │
  │  2. Handler 参数级 Pipe         │                      │
  │                                │                      │
  │  ┌─ 校验通过 → 转换后的值 → Controller                │
  │  └─ 校验失败 → throw → 跳转到 ExceptionFilter ──────┘
  │
  ▼
═══════════════════════════════════════════════════════════════════
                       Controller
═══════════════════════════════════════════════════════════════════
  │
  │  BookController.list(@Query() query: ListBookDto) {
  │    return this.bookService.findAll(query);
  │                                                  }
  │
  │  ┌─ 正常返回 data ─────────────────────────┐
  │  └─ 抛出异常 → 跳转到 ExceptionFilter ──────│────┐

  ▼                                              │    │
══════════════════════════════════════════════════ │ ───│──────
                     Interceptor (后)              │    │
══════════════════════════════════════════════════ │ ───│──────
  │  嵌套解包（洋葱模型，从内到外）：               │    │
  │  3. Handler 级 Interceptor (后)               │    │
  │  2. Controller 级 Interceptor (后)            │    │
  │  1. 全局 Interceptor (后)                     │    │
  │                                               │    │
  │  After 逻辑：                                 │    │
  │  ─ map(data) → 包装响应格式                   │    │
  │  ─ tap() → 记录请求耗时                       │    │
  │  ─ catchError() → 异常转换                    │    │
  │                                               │    │
  ▼                                               │    │
═════════════════════════════════════════════════  │    │
               ExceptionFilter                     │    │
═════════════════════════════════════════════════  │    │
  │  ← ← ← ← ← ← ← ← ← ← ← ← ← ← ← ← ← ← ← ← ← ┘    │
  │  ← ← ← ← ← ← ← ← ← ← ← ← ← ← ← ← ← ← ← ← ← ← ← ┘
  │

  │  @Catch()                → 兜底处理未知异常（500）
  │
  │  统一响应格式：
  │  {
  │    statusCode: 400,
  │    message: '该用户已注册',
```

## 请求流转完整示例

以 `POST /user/register` 为例，追踪一次完整的请求：

```
客户端提交：
{
  "username": "john",
  "password": "123456",
  "isAdmin": true          // ← 多余字段
}

1. Middleware 层
   ─ RequestLogMiddleware：记录请求开始时间和 url
   ─ 没有修改请求

2. Guard 层
   ─ AuthGuard：/user/register 有 @IsPublic()，跳过鉴权
   ─ 放行

3. Interceptor (前)
   ─ 记录 now = Date.now()
   ─ 放行

4. Pipe 层
   ─ ValidationPipe：
     ├── transform: true → 将 Body 转为 RegisterUserDto 实例
     ├── whitelist: true → 剔除 isAdmin（它不在 DTO 中）
     └── 校验：
         ├── @IsNotEmpty() username → 'john' ✓
         └── @MinLength(6) password → '123456' ✓
   ─ 校验通过，dto = RegisterUserDto { username: 'john', password: '123456' }
   ─ 传给 Controller

5. Controller 层
   ─ UserController.register(dto)
     └── UserService.register(dto)
         ├── users.find() → 用户名不重复 ✓
         ├── users.push({ username: 'john', password: '123456' })
         ├── dbService.write(users)
         └── return { username: 'john' }

6. Interceptor (后)
   ─ map(data) → { code: 0, data: { username: 'john' }, message: 'ok' }
   ─ tap() → console.log(`POST /user/register 200 45ms`)

7. ExceptionFilter
   ─ Controller 没有抛异常，不进入

8. HTTP 响应
   ─ 200 OK
   ─ { code: 0, data: { username: 'john' }, message: 'ok' }
```

## 各切面的注册方式和级别对照表

| 切面 | 全局注册 | Module 级 | Controller 级 | Handler 级 |
|------|---------|----------|--------------|-----------|
| Middleware | ❌ (需在 Module.configure 中) | ✅ `consumer.apply().forRoutes()` | ❌ | ❌ (只有路径匹配) |
| Guard | ✅ `useGlobalGuards()` 或 `APP_GUARD` | ✅ `APP_GUARD` token | ✅ `@UseGuards()` | ✅ `@UseGuards()` |
| Interceptor | ✅ `useGlobalInterceptors()` 或 `APP_INTERCEPTOR` | ✅ `APP_INTERCEPTOR` token | ✅ `@UseInterceptors()` | ✅ `@UseInterceptors()` |
| Pipe | ✅ `useGlobalPipes()` 或 `APP_PIPE` | ✅ `APP_PIPE` token | ❌ | ✅ `@UsePipes()` 或参数级 |
| ExceptionFilter | ✅ `useGlobalFilters()` 或 `APP_FILTER` | ✅ `APP_FILTER` token | ✅ `@UseFilters()` | ✅ `@UseFilters()` |

## 切面选择决策树

遇到一个需求时，按这张决策树选择正确的切面：

```
需要对所有请求做统一处理吗？
├── 是
│   ├── 需要修改 req/res 对象本身？ → Middleware
│   │   （比如：解析 cookie、设置 CORS、添加 security headers）
│   │
│   ├── 需要根据"调的是哪个接口"做不同处理吗？
│   │   ├── 是 → Guard 或 Interceptor
│   │   │   ├── 处理结果是"放行或拦截"？ → Guard
│   │   │   └── 处理结果是"修改返回值"？ → Interceptor
│   │   │
│   │   └── 否 → Middleware 或全局 Interceptor
│   │
│   ├── 需要校验参数吗？ → Pipe
│   └── 需要处理异常吗？ → ExceptionFilter
│
└── 否 → 在 Controller/Service 中直接处理
```

## 5 个高频踩坑点

### 1. 全局 Guard 用 `useGlobalGuards()` 无法注入依赖

```typescript
// ❌ 错误：这样注册的 Guard 无法注入 Reflector
app.useGlobalGuards(new AuthGuard());

// ✅ 正确：用 APP_GUARD token，可通过 DI 实例化
// 在 AppModule 的 providers 中：
{ provide: APP_GUARD, useClass: AuthGuard }
```

### 2. Guard 中返回 false 和抛出异常的区别

```typescript
// 返回 false → Nest 自动返回 403，错误信息固定
canActivate() { return false; }

// 抛出异常 → 可自定义错误信息
canActivate() { throw new UnauthorizedException('Token 已过期'); }
```

### 3. Interceptor 的 `next.handle()` 只能调用一次

```typescript
// ❌ 错误：多次调用
intercept(ctx, next) {
  const stream = next.handle();  // 正确
  next.handle();                 // 错误！重复调用会触发两次 Controller
}

// ✅ 正确：缓存返回值
intercept(ctx, next) {
  const stream$ = next.handle();
  return stream$.pipe(map(data => ...));
}
```

### 4. Pipe 中抛异常不会进入 Interceptor 后置逻辑

```typescript
// Pipe 抛出 BadRequestException
// → 直接跳到 ExceptionFilter
// → interceptor 的 tap() 不会执行（因为 stream 上没有数据流过）
```

### 5. Controller + Interceptor(后) 的执行顺序

```typescript
// Controller 中 return { username: 'john' }
// → Nest 先序列化 JSON
// → 然后 Interceptor(后) 的 map() 才执行
// 所以 map 收到的 data 是序列化后的对象，不是原始的 Service 返回值
```

## 前端类比总结

| Nest 概念 | Vue 类比 | React 类比 |
|-----------|---------|-----------|
| Middleware | app.config.globalProperties 全局混入 | React Portal / Context Provider |
| Guard | Router beforeEach 守卫 | Protected Route 组件包裹 |
| Interceptor | Axios interceptors | Custom Hook 包装 |
| Pipe | VeeValidate / Zod 校验 | React Hook Form validate |
| ExceptionFilter | app.config.errorHandler | Error Boundary |
| 请求生命周期 | Vue 组件生命周期 | React 组件生命周期 |
