# 自定义存储引擎

## 为什么要自定义？

`diskStorage` 虽然简单，但有些场景需要更精细的控制：

1. **自动创建目录**：`destination` 不会自动创建不存在的目录
2. **文件名策略**：需要统一的前缀（如按日期分类）
3. **与业务逻辑集成**：上传同时记录到数据库

## 自定义 diskStorage — 自动创建目录 + 按日期分组

```typescript
// src/common/storage/book-cover.storage.ts
import { diskStorage } from 'multer';
import { extname, join } from 'path';
import { mkdirSync, existsSync } from 'fs';
import { randomUUID } from 'crypto';

const UPLOAD_ROOT = './uploads';

export const bookCoverStorage = diskStorage({
  destination: (req, file, cb) => {
    // 按日期分文件夹：uploads/2026-05-10/
    const today = new Date().toISOString().split('T')[0];
    const dir = join(UPLOAD_ROOT, 'covers', today);

    // 确保目录存在（递归创建）
    if (!existsSync(dir)) {
      mkdirSync(dir, { recursive: true });
    }

    cb(null, dir);
  },

  filename: (req, file, cb) => {
    // 文件名：时间戳_UUID.扩展名
    const uniqueName = `${Date.now()}_${randomUUID()}${extname(file.originalname)}`;
    cb(null, uniqueName);
  },
});
```

### 使用

```typescript
@Post('upload-cover')
@UseInterceptors(
  FileInterceptor('file', {
    storage: bookCoverStorage,  // ← 使用自定义 storage
    limits: { fileSize: 5 * 1024 * 1024 },
  }),
)
uploadCover(@UploadedFile() file: Express.Multer.File) {}
```

## 自定义 storage 引擎（完全控制）

如果需要将文件保存到OSS/MinIO而不是磁盘（Day 25 详讲）：

```typescript
import { StorageEngine } from 'multer';
import { Request } from 'express';

// 自定义 StorageEngine 的骨架
class CustomStorageEngine implements StorageEngine {
  _handleFile(
    req: Request,
    file: Express.Multer.File,
    callback: (error?: any, info?: Partial<Express.Multer.File>) => void,
  ): void {
    // 处理文件存储
    // 1. 从 file.stream 读取数据
    // 2. 保存到目标位置（OSS / MinIO / 数据库）
    // 3. 调用 callback 返回保存结果
  }

  _removeFile(
    req: Request,
    file: Express.Multer.File,
    callback: (error: Error | null) => void,
  ): void {
    // 删除文件
    callback(null);
  }
}
```

> 自定义 Storage Engine 是高级用法——大多数情况下 `diskStorage` 配合自动创建目录的包装就够了。Day 25 学 MinIO/RustFS 时，我们会实现直传 OSS 的 Storage Engine。

## 文件名的安全处理

用户上传的文件名可能包含中文、空格、特殊字符。需要做安全处理：

```typescript
function sanitizeFilename(originalName: string): string {
  const ext = extname(originalName);

  // 方案 1：完全随机文件名（最安全）
  return `${Date.now()}-${randomUUID()}${ext}`;

  // 方案 2：保留原文件名但清理特殊字符
  const basename = originalName
    .replace(ext, '')           // 去掉扩展名
    .replace(/[^a-zA-Z0-9一-龥]/g, '_')  // 只保留字母数字中文
    .slice(0, 50);              // 截断过长的文件名
  return `${basename}_${Date.now()}${ext}`;
}
```

## 文件大小限制的友好提示

```typescript
// 拦截 multer 的大小超限错误，给出中文提示
import { MulterError } from 'multer';

@Catch(MulterError)
export class MulterExceptionFilter implements ExceptionFilter {
  catch(exception: MulterError, host: ArgumentsHost) {
    const ctx = host.switchToHttp();
    const response = ctx.getResponse<Response>();

    let message = '文件上传失败';

    switch (exception.code) {
      case 'LIMIT_FILE_SIZE':
        message = '文件大小超过限制（最大 5MB）';
        break;
      case 'LIMIT_FILE_COUNT':
        message = '文件数量超过限制';
        break;
      case 'LIMIT_UNEXPECTED_FILE':
        message = '文件字段名不正确';
        break;
    }

    response.status(400).json({
      code: 400,
      data: null,
      message,
    });
  }
}
```

> 自定义 Storage 的核心价值在于：将文件命名规则、目录结构、安全策略集中管理，而不是散落在每个 Controller 的 `FileInterceptor` 配置中。
