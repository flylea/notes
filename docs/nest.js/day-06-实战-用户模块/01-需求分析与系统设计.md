# 需求分析与系统设计

## 图书管理系统功能全景

完整系统分为三个阶段实现：

**V1（本周）— JSON 文件存储**：
- 用户注册（输入用户名+密码）
- 用户登录（验证用户名+密码）
- 数据存储：JSON 文件

**V2（Day 12）— 图书管理**：
- 图书列表/详情
- 新增/修改/删除图书
- 封面图片上传
- 数据存储：仍用 JSON 文件

**V3（Day 19）— 数据库升级**：
- 全部数据迁移到 Prisma + MySQL
- 模糊搜索 + 分页
- 借阅/归还功能

## 今日范围：用户模块

### 接口设计

| 接口 | 方法 | 路径 | 说明 |
|------|------|------|------|
| 用户注册 | POST | `/user/register` | 输入用户名+密码 |
| 用户登录 | POST | `/user/login` | 验证用户名+密码 |

### 数据流

```
注册流程：
客户端 POST { username, password }
  → ValidationPipe 校验 DTO
  → Controller.register(dto)
  → Service.register(dto)
    → DbService.read()（从 users.json 读取）
    → 查重（检查 username 是否已存在）
    → 已存在 → throw BadRequestException
    → 不存在 → 创建用户对象 → DbService.write()（写入 users.json）
  → 返回用户信息（不含密码）

登录流程：
客户端 POST { username, password }
  → ValidationPipe 校验 DTO
  → Controller.login(dto)
  → Service.login(dto)
    → DbService.read()（从 users.json 读取）
    → 查找用户（匹配 username）
    → 不存在 → throw BadRequestException
    → 密码不匹配 → throw BadRequestException
    → 匹配 → 返回用户信息
```

### 技术选型

| 层 | 选择 | 原因 |
|----|------|------|
| 数据校验 | class-validator + ValidationPipe | Nest 生态标配 |
| 数据存储 | JSON 文件（DbModule） | 先不引入数据库，专注 Nest 本身 |
| 密码存储 | 明文（现阶段） | Day 20 引入 hash |
| 接口风格 | GET/POST | 务实规范 |
