# 各切面的注册级别对比

## 四级注册体系

Nest 的每个切面都可以在 4 个级别注册（部分切面在某些级别不可用）：

```
全局 (Global)           → 所有 Module、所有 Controller、所有 Handler
Module (模块级)          → 当前 Module 内的所有 Controller
Controller (控制器级)     → 当前 Controller 下的所有 Handler
Handler (处理器级)        → 仅当前 Handler
```

## Middleware 的注册级别

| 级别 | 注册方式 | 说明 |
|------|---------|------|
| 全局 | `app.use()` 在 main.ts 中 | 对**所有**请求生效 |
| Module | `consumer.apply().forRoutes()` | 对匹配的路由生效 |
| Controller | `consumer.apply().forRoutes(BookController)` | 对指定 Controller 生效 |
| Handler | `consumer.apply().forRoutes({ path: 'book', method: RequestMethod.GET })` | 对特定路径+方法生效 |

Middleware **不支持 `@UseMiddleware()`** 装饰器级别的注解注册（这是 Nest 的设计选择——Middleware 属于底层，不适合装饰器语义）。

## Guard 的注册级别

| 级别 | 注册方式 | 示例 |
|------|---------|------|
| 全局 | `app.useGlobalGuards()` 或 `APP_GUARD` token | `app.useGlobalGuards(new AuthGuard())` |
| Module | `APP_GUARD` token 在 Module 的 providers 中 | ❌ 不推荐（Guard 依赖具体路由的元数据，全局不够） |
| Controller | `@UseGuards(AuthGuard)` | `@Controller('book')` → `@UseGuards(AuthGuard)` |
| Handler | `@UseGuards(RolesGuard)` | `@Post('create')` → `@UseGuards(RolesGuard)` |

```typescript
// 混合使用
@Controller('book')
@UseGuards(AuthGuard)      // 整个模块需要登录
export class BookController {
  @Get('list')
  list() {}  // 只需要登录

  @Post('create')
  @UseGuards(RolesGuard)   // 除了登录，还需要特定角色
  create() {}

  @Post('delete')
  @UseGuards(RolesGuard, PermissionGuard)  // 多个 Guard 组合
  delete() {}
}
```

## Interceptor 的注册级别

| 级别 | 注册方式 |
|------|---------|
| 全局 | `app.useGlobalInterceptors()` 或 `APP_INTERCEPTOR` token |
| Controller | `@UseInterceptors(TransformInterceptor)` |
| Handler | `@UseInterceptors(CacheInterceptor)` |

## Pipe 的注册级别

| 级别 | 注册方式 |
|------|---------|
| 全局 | `app.useGlobalPipes()` 或 `APP_PIPE` token（推荐用于 ValidationPipe） |
| Handler（参数级） | `@Body(ValidationPipe)` / `@Param('id', ParseIntPipe)` |

## ExceptionFilter 的注册级别

| 级别 | 注册方式 |
|------|---------|
| 全局 | `app.useGlobalFilters()` 或 `APP_FILTER` token |
| Controller | `@UseFilters(HttpExceptionFilter)` |
| Handler | `@UseFilters(HttpExceptionFilter)` |

## APP_* Token 注册 vs useGlobal*() 对比

```typescript
// 方式 1: useGlobalGuards()
app.useGlobalGuards(new AuthGuard());
// ✅ 简单直接
// ❌ 无法注入依赖（AuthGuard 的生命周期不属于 Nest DI 容器）

// 方式 2: APP_GUARD token
@Module({
  providers: [
    {
      provide: APP_GUARD,
      useClass: AuthGuard,
    },
  ],
})
// ✅ 可以注入依赖
// ❌ 代码分散
```

> ⚠️ 全局注册的 Guard/Interceptor/Pipe/Filter 如果**不需要注入依赖**，用 `useGlobalXxx()` 即可。如果需要注入 `Reflector`、`PrismaService` 等，必须用 `APP_*` token。

## 执行优先级规则

1. **同一切面**：Handler 级 > Controller 级 > Module 级 > 全局级
2. **不同切面**：按固定顺序（Middleware → Guard → Interceptor(前) → Pipe → Controller → Interceptor(后) → ExceptionFilter），不受注册级别影响
3. **多个同一切面同级别**：从左到右执行

## 注册方式的完整对照表

| 切面 | 支持全局 | 支持 Module | 支持 Controller | 支持 Handler | 装饰器注册 | APP_* Token |
|------|:---:|:---:|:---:|:---:|:---:|:---:|
| Middleware | ✅ | ✅ | ⚠️ Controller 匹配 | ⚠️ 路径匹配 | ❌ 无 | ❌ 无 |
| Guard | ✅ | ⚠️ 不推荐 | ✅ | ✅ | `@UseGuards` | `APP_GUARD` |
| Interceptor | ✅ | ⚠️ 不推荐 | ✅ | ✅ | `@UseInterceptors` | `APP_INTERCEPTOR` |
| Pipe | ✅ | ❌ | ❌ | ✅ 参数级 | `@UsePipes` | `APP_PIPE` |
| ExceptionFilter | ✅ | ❌ | ✅ | ✅ | `@UseFilters` | `APP_FILTER` |

## 图书管理系统推荐配置

```typescript
// main.ts — 全局配置
async function bootstrap() {
  const app = await NestFactory.create(AppModule);

  // ===== Middleware =====
  app.use(cors({ origin: true, credentials: true }));
  app.use(helmet());
  app.use(compression());
  app.use(cookieParser());

  // ===== Pipe =====
  app.useGlobalPipes(new ValidationPipe({
    whitelist: true,
    transform: true,
  }));

  // ===== Interceptor =====
  app.useGlobalInterceptors(new TransformInterceptor());

  // ===== ExceptionFilter =====
  app.useGlobalFilters(new AllExceptionsFilter());

  await app.listen(3000);
}

// AppModule — 需要 DI 的全局注册
@Module({
  providers: [
    { provide: APP_GUARD, useClass: AuthGuard },       // 需要注入 Reflector
  ],
})
export class AppModule {}
```

> 需要 DI（Reflector/PrismaService）的用 `APP_*` token，不需要 DI 的用 `app.useGlobal*()`。这是 Nest 架构设计中的"灵活之处"也是"学习曲线陡峭之处"。
