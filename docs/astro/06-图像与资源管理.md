# 第 6 章 图像与资源管理

## 6.1 图片放哪里

`src/` 和 `public/` 的区别不在目录名字，在构建时的处理路径：

| 位置 | 构建行为 | 用途 |
|---|---|---|
| `src/assets/` | 经过打包，可压缩、转格式、生成多尺寸 | 页面里展示的图片 |
| `public/` | 原样复制到产物根目录 | favicon、robots.txt、下载文件、需要固定 URL 的图 |

判断方法很简单：**需要按尺寸或格式优化的图放 `src/`，需要固定路径的放 `public/`**。

`public/` 里的图引用时用根路径，构建后 URL 不变：

```astro
<img src="/images/team.jpg" alt="团队合影" />
```

`src/` 里的图必须先 `import`，得到一个带元数据的对象，再交给 `<Image />`：

```astro
---
import { Image } from 'astro:assets';
import team from '../assets/team.jpg';
---

<Image src={team} alt="团队合影" width={800} height={400} />
```

从 `public/` 拿不到宽高，浏览器要等图片下载完才知道尺寸，期间不占位，页面会跳一下（CLS）。`import` 进来的图在构建期就知道尺寸，`<Image />` 会把 `width`、`height` 写进标签，占位是确定的。这是把图片从 `public/` 迁到 `src/` 最直接的收益。

代价是 `src/` 里的图片名会变成带哈希的路径，不能分享固定 URL，也不能被外站引用。需要被别处引用的图（Open Graph 图、邮件里的图、SVG logo 直链）放 `public/`。

## 6.2 用 `<Image />` 渲染图片

`<Image />` 从 `astro:assets` 导入，产出标准 `<img>`：

```astro
---
import { Image } from 'astro:assets';
import photo from '../assets/photo.jpg';
---

<Image src={photo} alt="照片描述" />

<Image src={photo} alt="照片" width={600} />

<Image
  src={photo}
  alt="优化的照片"
  width={800}
  height={600}
  format="avif"
  quality={85}
  loading="lazy"
  decoding="async"
/>
```

常用属性：

| 属性 | 说明 |
|---|---|
| `src` | 导入的图片对象，或允许的远程 URL |
| `alt` | 必填，缺失直接报错 |
| `width` / `height` | 输出尺寸，只给一个时按原比例算另一个 |
| `format` | `webp`、`avif`、`png`、`jpeg`、`svg` |
| `quality` | 1–100，JPEG、WebP、AVIF 有效，PNG 无效 |
| `loading` / `decoding` | 原样透传给 `<img>` |
| `layout` | 响应式布局，见 6.3 |

`alt` 必填是刻意的。纯装饰图要显式写 `alt=""`，空字符串表示"读屏软件跳过"，不写则构建失败。

`format` 的选择取决于浏览器支持。AVIF 体积最小，2024 年之后的浏览器都支持；老环境多时用 WebP 更稳。`<Image />` 只会输出你指定的一种格式，需要多格式兼容就用 `<Picture />`。

## 6.3 响应式图片

固定宽度在大屏上会浪费带宽，在小屏上会溢出。`layout` 属性让 Astro 自动生成 `srcset` 和 `sizes`：

```astro
---
import { Image } from 'astro:assets';
import hero from '../assets/hero.jpg';
---

<Image src={hero} alt="首屏图" layout="full-width" />
```

四个取值：

- `constrained`：不超过指定宽高，容器更窄时等比缩小。适合正文插图、卡片图。不确定选什么就选它。
- `full-width`：撑满容器宽度。适合首屏大图和横幅。
- `fixed`：尺寸固定，只按屏幕像素密度给 `srcset`（1x、2x）。适合图标、logo。
- `none`：不生成 `srcset`，行为与旧版一致。

生成的 HTML 大致是：

```html
<img
  src="/_astro/hero.hash.webp"
  srcset="/_astro/hero.hash1.webp 640w,
          /_astro/hero.hash2.webp 750w,
          /_astro/hero.hash3.webp 1200w"
  sizes="(max-width: 1200px) 100vw, 1200px"
  width="1200"
  height="800"
  alt="首屏图"
/>
```

注意 `sizes` 的默认值是"视口窄于图片宽度时占满屏宽"。图放在两栏布局里时这个假设不成立，要自己覆盖：

```astro
<Image
  src={hero}
  alt="首屏图"
  layout="constrained"
  widths={[400, 800, 1200]}
  sizes="(max-width: 800px) 100vw, 50vw"
/>
```

想要所有图片默认响应式，在配置里设一次：

```js
// astro.config.mjs
export default defineConfig({
  image: {
    layout: 'constrained',
    responsiveStyles: true,
  },
});
```

`responsiveStyles: true` 会注入几条全局样式，让图按布局规则缩放。不开的话 `constrained` 和 `full-width` 只有 `srcset`，图不会真的随容器缩。

三个代价要考虑：

- **构建时间**。一张图生成 3 个尺寸就是 3 次转换，图片多的站点构建时间线性上涨。只给首屏和有价值的图开多尺寸。
- **磁盘产物**。同一张图的多份转换结果都进 `dist/`，几十张图可能多出几百 MB。
- **DOM 复杂度**。`srcset` 很长，调试时不好读，浏览器选哪张只能在开发者工具的网络面板看。

`densities` 和 `layout` 互斥。设了 `layout` 之后 `densities` 被忽略，不要同时写。

## 6.4 用 `<Picture />` 提供多格式

`<Picture />` 输出 `<picture>`，同一场景下同时给 AVIF、WebP 和回退格式：

```astro
---
import { Picture } from 'astro:assets';
import hero from '../assets/hero.jpg';
---

<Picture
  src={hero}
  formats={['avif', 'webp']}
  widths={[400, 800, 1200]}
  sizes="(max-width: 800px) 100vw, 50vw"
  alt="响应式主图"
/>
```

产出：

```html
<picture>
  <source srcset="hero-400.avif 400w, hero-800.avif 800w, hero-1200.avif 1200w"
          sizes="(max-width: 800px) 100vw, 50vw" type="image/avif" />
  <source srcset="hero-400.webp 400w, hero-800.webp 800w, hero-1200.webp 1200w"
          sizes="(max-width: 800px) 100vw, 50vw" type="image/webp" />
  <img src="hero.jpg" alt="响应式主图" width="1200" height="800" loading="lazy" decoding="async" />
</picture>
```

`formats` 里按优先级从新到旧排，浏览器取第一个支持的。最后一个 `<img>` 是回退，格式取 `fallbackFormat`（默认由源图决定）或用 `src` 的原始格式。

`<Picture />` 的转换次数是 `formats.length × widths.length`。3 种格式 4 个宽度就是 12 次转换，构建慢一倍以上。只有首屏图和落地页主图值得这么做，正文插图用单一 WebP 就够。

## 6.5 远程图片

远程图片默认被禁止优化，防止站点被当成图片代理。要优化必须在配置里声明允许的来源：

```js
// astro.config.mjs
export default defineConfig({
  image: {
    domains: ['images.example.com', 'cdn.myapp.com'],
    remotePatterns: [{ protocol: 'https', hostname: '**.example.com' }],
  },
});
```

`domains` 精确匹配主机名，`remotePatterns` 支持通配符。两个都配时任一命中即可。

声明之后才能给 `<Image />` 传 URL：

```astro
<Image
  src="https://images.example.com/photo.jpg"
  alt="远程图片"
  width={800}
  height={600}
/>
```

远程图必须显式给尺寸，因为构建期不会去下载它探测大小。确实需要探测时用 `inferRemoteSize()`：

```astro
---
import { inferRemoteSize } from 'astro:assets';

const { width, height } = await inferRemoteSize('https://images.example.com/photo.jpg');
---
```

这一步会发一次 HEAD 或 GET 请求拿尺寸，构建时间变长，网络抖动会导致构建失败。能用固定尺寸就用固定尺寸。

远程图的优化发生在构建期（静态页）或请求期（按需渲染页）。请求期每次访问都可能触发转换，图片服务按次计费的话成本要算进去。

## 6.6 用 getImage() 生成图片

需要拿到优化后图片的 URL 而不想渲染 `<img>` 时，用 `getImage()`：

```astro
---
import { getImage } from 'astro:assets';
import bg from '../assets/background.jpg';
import cover from '../assets/cover.jpg';

const optimizedBg = await getImage({ src: bg, width: 1200, format: 'avif' });
const ogImage = await getImage({ src: cover, width: 1200, height: 630, format: 'jpeg' });
---

<div style={`background-image: url(${optimizedBg.src})`}>
  内容区域
</div>

<meta property="og:image" content={new URL(ogImage.src, Astro.site)} />
```

`getImage()` 返回 `{ src, srcSet, attributes }`。用 `src` 拼内联样式，用 `attributes.width/height` 给 `<img>` 手工加尺寸。

Open Graph 图必须是绝对 URL 且能被外部访问，所以用 `new URL(ogImage.src, Astro.site)` 拼上域名。`Astro.site` 没在配置里设置时这里是 `undefined`，`new URL` 会抛 `TypeError: Invalid URL`。

`getImage()` 是异步的，每次调用都是一次转换任务。在列表里循环调用会让构建时间迅速失控。

## 6.7 图像服务

默认服务是 Sharp，本地处理，无需配置：

```js
// astro.config.mjs
export default defineConfig({
  image: {
    service: { entrypoint: 'astro/assets/services/sharp' },
  },
});
```

部署到不支持 Sharp 的运行时（Cloudflare Workers 没有原生二进制），换成空实现：

```js
// astro.config.mjs
import { defineConfig } from 'astro/config';
import { passthroughImageService } from 'astro/config';

export default defineConfig({
  image: {
    service: passthroughImageService(),
  },
});
```

空实现不做任何转换，`<Image />` 只负责写 `width`、`height`、`alt` 和基础属性，图片原样输出。好处是布局不跳、API 不变，坏处是没有压缩和格式转换，图片体积回到原样。

也有第三方服务（ImageKit、Cloudinary 之类）通过集成接管，转换发生在 CDN 上，源站不耗 CPU，但要按流量付费。

## 6.8 public/ 里的静态资源

`public/` 的文件原样复制到产物根目录，路径不变：

```
public/
├── favicon.svg
├── robots.txt
├── og-default.png
├── fonts/
│   └── inter-var.woff2
└── downloads/
    └── resume.pdf
```

```astro
<link rel="icon" type="image/svg+xml" href="/favicon.svg" />
<a href="/downloads/resume.pdf">下载简历</a>
```

几个容易踩的点：

- `public/favicon.svg` 的路径是 `/favicon.svg`，不是 `/public/favicon.svg`。
- `public/` 里同名文件会覆盖构建产物。根目录已有 `404.html`，`public/404.html` 会让路由生成的 404 页面失效。
- `public/` 里的文件不带哈希，浏览器缓存可能拿到旧版本。改完要改文件名或加查询参数。
- 需要 `Content-Type` 正确的文件（`.woff2`、`.webmanifest`）放在 `public/` 时，托管平台的默认 MIME 可能不对，要在部署配置里补。

## 6.9 资源导入

`src/` 里的非图片资源也可以直接导入，行为由后缀决定：

```astro
---
import hero from '../assets/hero.jpg';         // 图片对象，可直接给 <Image />
import logoRaw from '../assets/logo.svg?raw';  // SVG 源码字符串
import docUrl from '../assets/manual.pdf?url'; // 构建后的 URL 字符串
import products from '../data/products.json';  // 解析后的对象
import config from '../data/config.yaml';      // YAML 解析后的对象
import '../styles/global.css';                 // 注入 CSS
---

<div set:html={logoRaw} />
<a href={docUrl}>下载手册</a>
<p>共 {products.length} 个产品</p>
```

`?raw` 和 `?url` 是 Vite 的约定，不是 Astro 独有。不给后缀时，`.svg` 默认被当作组件（见 6.10），`.json`、`.yaml` 默认解析成对象。

导入的 JSON 会被打包进 JS，适合几百 KB 以内的数据。更大的数据集放 `public/` 用 `fetch` 取，或者上内容集合。

### 6.9.1 按变量导入图片

图片路径来自 frontmatter 时不能写 `import()` 拼字符串，Vite 需要在构建时静态分析所有可能路径：

```ts
// 错的：构建时无法解析
const img = await import(`../assets/${post.data.cover}`);

// 对的：先声明所有候选，再按 key 取
const images = import.meta.glob<{ default: ImageMetadata }>('../assets/*.{jpg,png,webp}', {
  eager: true,
});
const img = images[`../assets/${post.data.cover}`];
if (!img) throw new Error(`找不到图片 ${post.data.cover}`);
```

`import.meta.glob` 的路径参数必须是字面量，返回一个 key 为相对路径的对象。`eager: true` 表示构建时全部加载，图片少时没问题；几百张图时把 `eager` 去掉，改成异步函数取。

更省事的做法是在第 5 章的 schema 里用 `image()`，让集合直接返回可用的图片对象，模板里不用查表。

## 6.10 SVG 当作组件

`src/` 里的 `.svg` 默认导入为 Astro 组件，可以直接传属性：

```astro
---
import Logo from '../assets/logo.svg';
---

<Logo class="logo" width={120} height={40} />

<Logo fill="currentColor" aria-label="公司 logo" />
```

传入的属性会覆盖 SVG 文件里的同名属性，所以 `fill="currentColor"` 能让图标跟随文字颜色。

注意事项：

- 组件名必须大写开头，`<logo />` 会被当成 HTML 标签。
- 导入的 SVG 内联进 HTML，多了会增加页面体积，同一个图标在列表里循环 100 次就是 100 份内联。这种情况改用 `<img src={logo}>`，或者用 CSS mask。
- 内联 SVG 里的 `<style>` 和 `id` 会进入全局作用域，两个 SVG 用同一个 `id` 会冲突，`<defs>` 里的渐变、滤镜会互相覆盖。
- `.svg` 当图片优化（`<Image src={logo} />`）会走光栅化，SVG 本身不需要这个处理，一般是误用。

## 6.11 字体

Astro 6 起内置 Fonts API，字体配置进 `astro.config.mjs`，由框架负责下载、托管和生成 `@font-face`：

```js
// astro.config.mjs
import { defineConfig, fontProviders } from 'astro/config';

export default defineConfig({
  fonts: [
    {
      provider: fontProviders.google(),
      name: 'Roboto',
      cssVariable: '--font-roboto',
      weights: [400, 500, 700],
      styles: ['normal'],
      subsets: ['latin'],
    },
  ],
});
```

在页面 `<head>` 里用 `<Font />` 输出样式标签：

```astro
---
// src/components/Head.astro
import { Font } from 'astro:assets';
---

<Font cssVariable="--font-roboto" preload />
```

CSS 里通过变量引用：

```css
body {
  font-family: var(--font-roboto), system-ui, sans-serif;
}
```

`provider` 目前有 `fontProviders.google()`、`fontProviders.fontsource()` 和 `fontProviders.local()`。本地字体用 `local()` 指向 `src/` 里的文件，适用于买了授权、不能走公共 CDN 的字体。

不用内置 API 的老办法是装 Fontsource 包并导入 CSS：

```bash
npm install @fontsource/inter
```

```css
@import '@fontsource/inter/400.css';
@import '@fontsource/inter/600.css';
```

代价是每个字重一个文件，中文字体动辄几 MB。中文站点更常见的做法是子集化，或者直接用系统字体栈，先不引 Web 字体。

字体是首屏渲染的阻塞资源。`preload` 只对首屏用到的字重开，全部 preload 等于把带宽全花在字体上。

## 6.12 完整示例：文章页的图片处理

```astro
---
// src/pages/blog/[id].astro
import { Image, getImage } from 'astro:assets';
import BaseLayout from '../../layouts/BaseLayout.astro';
import { getCollection, render } from 'astro:content';
import fallbackCover from '../../assets/cover-default.jpg';

export async function getStaticPaths() {
  const posts = await getCollection('blog', ({ data }) => !data.draft);
  return posts.map((post) => ({ params: { id: post.id }, props: { post } }));
}

const { post } = Astro.props;
const { Content } = await render(post);

// schema 里用 image() 时，cover 已经是可用的图片对象
const cover = post.data.cover ?? fallbackCover;

const ogImage = await getImage({
  src: cover,
  width: 1200,
  height: 630,
  format: 'jpeg',
  quality: 80,
});
---

<BaseLayout
  title={post.data.title}
  description={post.data.description}
  image={new URL(ogImage.src, Astro.site).toString()}
>
  <article class="post">
    <header>
      <h1>{post.data.title}</h1>
      <time datetime={post.data.publishDate.toISOString()}>
        {post.data.publishDate.toLocaleDateString('zh-CN')}
      </time>
    </header>

    <Image
      src={cover}
      alt={post.data.coverAlt ?? post.data.title}
      layout="constrained"
      width={800}
      height={400}
      format="webp"
      loading="eager"
    />

    <div class="prose">
      <Content />
    </div>
  </article>
</BaseLayout>
```

封面图用 `loading="eager"`，因为它在首屏；正文里的图保持默认的 `lazy`。OG 图固定 1200×630，这是各家社交平台通用的比例。

## 6.13 本章小结

- 要优化的图放 `src/` 并 `import`，要固定 URL 的放 `public/`。
- `<Image />` 负责单张图；`layout` 让它在不同屏宽下换尺寸，代价是构建时间和磁盘。
- `<Picture />` 提供多格式回退，转换次数是格式数乘尺寸数。
- 远程图要先在 `image.domains` 或 `image.remotePatterns` 里放行，且必须给尺寸。
- `getImage()` 用于背景图、OG 图这类只要 URL 的场景。
- 变量路径的图片用 `import.meta.glob`，不要用字符串拼 `import()`。
- 字体从 Astro 6 起有原生 Fonts API，`<Font />` 输出样式并可选 preload。
