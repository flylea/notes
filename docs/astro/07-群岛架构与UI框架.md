# 第 7 章 群岛架构、UI 框架与页面过渡

## 7.1 群岛架构解决什么

默认情况下 `.astro` 组件在服务端执行完就变成静态 HTML，浏览器收到的是纯 HTML 加零 JavaScript。群岛架构要解决的是"页面大部分静态、少部分需要交互"的场景：把交互部分单独标记成岛，只给岛下发 JavaScript。

一个商品详情页可以这样拆：

- 标题、描述、参数表：静态 HTML，不下发 JS。
- 加购物车按钮：岛，需要 JS。
- 颜色选择器：岛。
- 评论列表：静态渲染 + 一个"加载更多"按钮作为岛。

关键在设计阶段做判断，而不是渲染阶段。**每个需要交互的区域就是一个岛，岛与岛之间默认不共享状态**。这个约束带来性能收益，也带来架构成本：跨岛状态要显式设计（见 7.6），不能靠父组件 prop 传递。

## 7.2 客户端指令

给框架组件加 `client:*` 指令，它才会在浏览器里水合。不加指令的框架组件只在服务端渲染一次，交互完全失效，而且不报错，这是最容易困惑的地方。

| 指令 | 何时水合 | 适用 |
|---|---|---|
| `client:load` | 页面加载后立即 | 首屏必须可交互的部分 |
| `client:idle` | 浏览器空闲时 | 次要交互，不急着用 |
| `client:visible` | 进入视口时 | 首屏以下的组件 |
| `client:media={query}` | 媒体查询匹配时 | 只在移动端出现的菜单 |
| `client:only="react"` | 跳过服务端渲染，只在客户端 | 依赖 `window` 的组件 |

```astro
---
import MobileMenu from '../components/MobileMenu.jsx';
import Newsletter from '../components/Newsletter.vue';
import Analytics from '../components/Analytics.svelte';
import Chart from '../components/Chart.jsx';
---

<MobileMenu client:media="(max-width: 768px)" />
<Newsletter client:visible />
<Analytics client:idle />
<Chart client:load />
```

`client:idle` 和 `client:visible` 都可以带选项，控制触发时机和占位内容：

```astro
<Newsletter client:visible={{ rootMargin: '200px' }} />
<Analytics client:idle={{ timeout: 3000 }} />
```

`client:only` 必须写框架名：

```astro
<Clock client:only="react" />
```

漏了框架名会报错，因为 `client:only` 跳过了服务端渲染，Astro 需要知道用哪个运行时的渲染函数：

```
NoClientOnlyHint: Unable to render `Clock`. When using the `client:only` hydration strategy, Astro needs a hint to use the correct renderer.
```

`client:only` 的代价是这块内容不在 HTML 里，首屏白一块，SEO 也拿不到内容，只在组件真的依赖 `window`、`localStorage` 时用。

指令加错的两种典型症状：

- 忘了加指令：按钮点了没反应，页面源码里没有水合脚本。
- 给 `<script>` 加了 `client:*`：`client:*` 只对框架组件生效，`.astro` 组件加了无效。

## 7.3 接 React

```bash
npx astro add react
```

命令装 `@astrojs/react`、`react`、`react-dom`，并在配置里注册集成。

```tsx
// src/components/Counter.tsx
import { useState } from 'react';

export default function Counter({ initial = 0 }: { initial?: number }) {
  const [count, setCount] = useState(initial);
  return (
    <div>
      <button onClick={() => setCount((c) => c - 1)}>-</button>
      <span>{count}</span>
      <button onClick={() => setCount((c) => c + 1)}>+</button>
    </div>
  );
}
```

```astro
---
import Counter from '../components/Counter';
---

<Counter initial={5} client:load />
```

`initial={5}` 这样的静态值可以直接传。函数、类实例、`Date` 之外的复杂对象不能传到客户端组件里，序列化会丢，或者直接报错：

```
Unable to serialize props to the client
```

需要把逻辑写在客户端组件内部，或者通过 API 拿数据。

## 7.4 接 Vue、Svelte、Solid

Vue：

```bash
npx astro add vue
```

```vue
<!-- src/components/TodoList.vue -->
<script setup>
import { ref } from 'vue';

const items = ref([]);
const draft = ref('');

function add() {
  if (!draft.value.trim()) return;
  items.value.push({ text: draft.value.trim(), done: false });
  draft.value = '';
}
</script>

<template>
  <form @submit.prevent="add">
    <input v-model="draft" placeholder="新任务" />
  </form>
  <ul>
    <li v-for="(item, i) in items" :key="i">{{ item.text }}</li>
  </ul>
</template>
```

Svelte（`npx astro add svelte` 装的是 Svelte 5，用 runes 语法）：

```svelte
<!-- src/components/Counter.svelte -->
<script>
  let count = $state(0);
  let doubled = $derived(count * 2);
</script>

<button onclick={() => count++}>
  点击 {count} 次（双倍：{doubled}）
</button>
```

Solid：

```tsx
// src/components/Clock.tsx
import { createSignal, onCleanup } from 'solid-js';

export default function Clock() {
  const [time, setTime] = createSignal(new Date());
  const timer = setInterval(() => setTime(new Date()), 1000);
  onCleanup(() => clearInterval(timer));
  return <div>{time().toLocaleTimeString('zh-CN')}</div>;
}
```

老教程里的 Svelte 4 写法 `on:click` 和 `$:` 在 Svelte 5 里还能跑，但会有警告，新项目直接用 `onclick` 和 `$state`、`$derived`。

## 7.5 水合成本

每接一个框架，页面就会加载这个框架的运行时。React 和 ReactDOM 压缩后约 45 KB，Vue 约 35 KB，Svelte 约 5 KB。同一个页面混用三种框架，用户就要下载三份运行时。

判断要不要接框架：

- 只有一个下拉菜单、一个折叠面板，用原生 `<details>` 或者一小段内联脚本，不引框架。
- 交互集中在少数几处，Svelte 或 Solid 体积最小。
- 团队已有 React 组件库、需要复用，接 React，别为了体积重写。
- 需要图表、富文本编辑器这类重型组件，框架体积相比组件本身可以忽略。

`client:load` 的岛越多，首屏 JS 越大。首页只放必须交互的岛，其余用 `client:visible` 或 `client:idle`，让首屏先出内容。

## 7.6 岛之间共享状态

岛是独立水合的，父组件的 React context 传不到另一个岛。跨岛状态用 Nano Stores，框架无关，每个框架有对应的绑定包：

```bash
npm install nanostores @nanostores/react
```

```ts
// src/stores/cart.ts
import { atom, computed } from 'nanostores';

export const cartItems = atom<{ id: string; price: number }[]>([]);
export const cartCount = computed(cartItems, (items) => items.length);

export function addToCart(item: { id: string; price: number }) {
  cartItems.set([...cartItems.get(), item]);
}
```

```tsx
// src/components/CartButton.tsx
import { useStore } from '@nanostores/react';
import { cartCount, addToCart } from '../stores/cart';

export default function CartButton({ id, price }: { id: string; price: number }) {
  const count = useStore(cartCount);
  return (
    <button onClick={() => addToCart({ id, price })}>
      加入购物车（{count}）
    </button>
  );
}
```

state 存在客户端内存里，刷新页面就丢。需要持久化时用 `persistentAtom` 存 `localStorage`，或者让服务端成为唯一数据源，客户端只读缓存。

代价是又多了一个依赖和一层间接。只有真的需要跨岛通信时才引入，单个岛内部的状态管理用框架自带的就够了。

## 7.7 视图过渡

页面之间切换默认是整页刷新，白屏一闪。视图过渡让新旧页面的对应元素做动画。开关是布局里加一个组件：

```astro
---
// src/layouts/BaseLayout.astro
import { ClientRouter } from 'astro:transitions';
---

<html lang="zh-CN">
  <head>
    <meta charset="utf-8" />
    <ClientRouter />
  </head>
  <body>
    <slot />
  </body>
</html>
```

`<ClientRouter />` 必须放在 `<head>` 里。它接管站内链接的点击：拦截导航、`fetch` 新页面、替换 `<body>`、执行动画，浏览器地址栏正常变化。

代价要说清楚：

- 变成了客户端路由。所有依赖"页面加载"的脚本只执行一次，第二页开始不再执行，事件监听会失效（见 7.8）。
- 首屏之外多加载一个约 4 KB 的路由脚本。
- 没有 JavaScript 或浏览器不支持时退化整页跳转，功能不受影响，只是没动画。

### 7.7.1 命名过渡元素

默认按元素在页面中的结构匹配，列表页和详情页结构不同就匹配不上。用 `transition:name` 手工配对：

```astro
<!-- 列表页 -->
<a href={`/blog/${post.id}`}>
  <img src={post.data.cover} transition:name={`cover-${post.id}`} alt="" />
  <h2 transition:name={`title-${post.id}`}>{post.data.title}</h2>
</a>
```

```astro
<!-- 详情页 -->
<img src={post.data.cover} transition:name={`cover-${post.id}`} alt="" />
<h1 transition:name={`title-${post.id}`}>{post.data.title}</h1>
```

同一个 `transition:name` 在一个页面里只能用一次。两张图同名，过渡会乱跳。

### 7.7.2 动画类型

`transition:animate` 接受内置动画或自定义对象：

```astro
<main transition:animate="slide">
  <slot />
</main>
```

内置值：

- `fade`：默认，交叉淡入淡出。
- `slide`：旧页左出、新页右入，返回时方向相反。
- `none`：关闭动画，也关掉浏览器的默认过渡。
- `initial`：不用 Astro 的动画，退回浏览器原生行为。

调整内置动画的参数，从 `astro:transitions` 导入对应函数：

```astro
---
import { fade, slide } from 'astro:transitions';
---

<header transition:animate={fade({ duration: '0.4s' })}>
<main transition:animate={slide({ duration: '0.3s' })}>
```

要完全自定义，需同时给前进和后退两个方向，每个方向再分新旧两个动画：

```astro
---
// src/layouts/BaseLayout.astro
import { ClientRouter } from 'astro:transitions';
---

<html lang="zh-CN">
  <head>
    <ClientRouter />
    <style is:global>
      @keyframes bump-in {
        from { transform: scale(0.98); opacity: 0; }
      }
      @keyframes bump-out {
        to { transform: scale(1.02); opacity: 0; }
      }
      ::view-transition-old(bump) {
        animation: 0.2s ease-out both bump-out;
      }
      ::view-transition-new(bump) {
        animation: 0.2s ease-in both bump-in;
      }
    </style>
  </head>
  <body>
    <slot />
  </body>
</html>
```

```astro
<article transition:animate="bump">...</article>
```

自定义动画的 keyframes 要写在全局样式里，`::view-transition-*` 伪元素不受组件作用域约束。

### 7.7.3 保留元素

导航时某些元素不该重建：播放中的视频、正在输入的搜索框、需要保持状态的计数器。加 `transition:persist`：

```astro
<video controls transition:persist src="/intro.mp4"></video>
<Counter client:load transition:persist initialCount={5} />
```

`transition:persist` 保留了 DOM 和组件状态，但 CSS 动画会重播、iframe 会重载，这两样省不掉。

## 7.8 客户端路由下的脚本

`<script>` 在整页导航时执行一次。用了 `<ClientRouter />` 之后第二次导航不重新执行，所有初始化逻辑都失效。标准做法是监听 `astro:page-load`：

```astro
---
// src/components/Carousel.astro
---

<div class="carousel">...</div>

<script>
  function initCarousel() {
    document.querySelectorAll('.carousel').forEach((el) => {
      // 初始化轮播
    });
  }

  initCarousel();
  document.addEventListener('astro:page-load', initCarousel);
</script>
```

Astro 的事件：

- `astro:page-load`：首屏和新页面导航完成后都触发。
- `astro:before-swap`：新旧 DOM 替换之前触发，用来清理定时器、解绑监听。
- `astro:after-swap`：替换之后、`astro:page-load` 之前触发。

利用 `astro:before-swap` 做清理，避免定时器和全局监听越积越多：

```astro
<script>
  let timer;

  function start() {
    timer = setInterval(() => {
      // 轮询
    }, 5000);
  }

  start();
  document.addEventListener('astro:page-load', start);
  document.addEventListener('astro:before-swap', () => clearInterval(timer));
</script>
```

用 `is:inline` 的脚本行为一样：内联脚本在替换 `<body>` 时会重新执行，但绑定在 `window` 和 `document` 上的监听仍然需要手动清理，否则同一次会话里越绑越多。

## 7.9 完整示例：商品详情页

```astro
---
// src/pages/products/[id].astro
import BaseLayout from '../../layouts/BaseLayout.astro';
import { Image } from 'astro:assets';
import { getEntry, render } from 'astro:content';
import cover from '../../assets/product.jpg';
import AddToCart from '../../components/AddToCart.jsx';
import ColorPicker from '../../components/ColorPicker.vue';
import Reviews from '../../components/Reviews.svelte';

export async function getStaticPaths() {
  return [{ params: { id: 'shirt-001' } }];
}

const product = {
  id: 'shirt-001',
  name: 'Astro 主题 T 恤',
  price: 299,
};
---

<BaseLayout title={product.name}>
  <!-- 静态部分：不进 JS -->
  <Image src={cover} alt={product.name} width={600} height={600} layout="constrained" />
  <h1>{product.name}</h1>
  <p>¥{product.price}</p>

  <!-- 岛：需要立即交互 -->
  <AddToCart productId={product.id} price={product.price} client:load />

  <!-- 岛：首屏以下，滚到才加载 -->
  <ColorPicker colors={['白', '黑', '灰', '蓝']} client:visible />

  <!-- 岛：不着急 -->
  <Reviews productId={product.id} client:idle />
</BaseLayout>
```

判断标准：这个区域用户第一眼会不会点。会，`client:load`；在首屏之外，`client:visible`；只是锦上添花，`client:idle`。

## 7.10 本章小结

- 群岛只给需要交互的区域下发 JS，没加 `client:*` 的框架组件不会水合。
- 五个指令：`load`、`idle`、`visible`、`media`、`only`，`client:only` 必须写框架名。
- 每个框架有自己的运行时，混用越多首屏 JS 越大。
- 跨岛状态用 Nano Stores，不要指望父组件传参。
- 视图过渡由 `<ClientRouter />` 开启，代价是变成客户端路由。
- 客户端路由下脚本只跑一次，初始化逻辑要挂到 `astro:page-load`。
