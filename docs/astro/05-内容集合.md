# 第 5 章 内容集合

## 5.1 什么时候需要内容集合

内容集合用来管理一批结构相同的 Markdown、JSON 或远程数据：博客文章、文档页面、产品列表、团队成员。它解决的问题只有两个：**这批数据长什么样由代码定义**，以及**查询这批数据时有类型**。

下面几种情况适合用：

- 内容以 Markdown 或 MDX 为主，数量在几十到几千篇。
- frontmatter 的字段需要校验，缺字段要让构建失败，而不是渲染出空标题。
- 页面模板需要按条件筛选、排序、聚合条目。
- 内容来源会变（本地文件、CMS、数据库），但模板不想跟着改。

不适合的情况也说清楚：

- 只有一两个页面，直接写 `.astro` 更快。为 3 个页面配一套集合是额外负担。
- 数据每次请求都要变化（库存、评论），构建时集合不合适，看 5.12 的实时集合。
- 数据本身没有统一结构，比如一堆异构的 JSON，用 `z.any()` 兜住等于没校验，不如不建集合。

## 5.2 配置文件与目录

配置文件放在 `src/content.config.ts`，注意是 `content.config.ts`，不在 `content/` 目录里：

```
src/
├── content.config.ts       配置文件和 schema
├── content/
│   ├── blog/               集合 blog 的 Markdown 文件
│   │   ├── first-post.md
│   │   └── second-post.md
│   └── authors/            集合 authors 的 YAML 文件
│       └── alice.yaml
└── pages/
    └── blog/
        └── [id].astro
```

`content/` 目录本身不要求文件名和集合名一致，是 loader 的 `base` 决定的，但按集合名分文件夹最省事。

v4 的写法是把配置放在 `src/content/config.ts`。这个位置在 v6 已被移除，放错会直接报错，构建起不来：

```
Found legacy content config file in "src/content/config.ts". Please move this file to "src/content.config.ts" and ensure each collection has a loader defined.
```

看到这句话就说明文件放错了层级，往上挪一层即可。

## 5.3 定义集合

一个集合由两件事描述：loader 说明数据从哪来，schema 说明数据长什么样。

```ts
// src/content.config.ts
import { defineCollection, reference } from 'astro:content';
import { glob, file } from 'astro/loaders';
import { z } from 'astro/zod';

const blog = defineCollection({
  loader: glob({ pattern: '**/*.{md,mdx}', base: './src/content/blog' }),
  schema: z.object({
    title: z.string(),
    description: z.string(),
    publishDate: z.coerce.date(),
    updatedDate: z.coerce.date().optional(),
    tags: z.array(z.string()).default([]),
    draft: z.boolean().default(false),
    author: reference('authors'),
  }),
});

const authors = defineCollection({
  loader: glob({ pattern: '**/*.{yaml,yml,json}', base: './src/content/authors' }),
  schema: z.object({
    name: z.string(),
    email: z.string().email(),
    avatar: z.string().url(),
    bio: z.string().optional(),
  }),
});

export const collections = { blog, authors };
```

三点与网上老教程的差异：

- `z` 从 `astro/zod` 导入，不是 `astro:content`。
- 没有 `type: 'content'` 或 `type: 'data'` 字段，用什么数据全靠 loader。写了 `type` 会报 `ContentCollectionInvalidType`。
- 文件名是 `content.config.ts`，不是 `content/config.ts`。

`defineCollection` 少了 `loader` 会报：

```
Collections must have a `loader` defined. Check your collection definitions in your content config file.
```

### 5.3.1 glob 加载器

从目录里按模式匹配文件，最常用：

```ts
const blog = defineCollection({
  loader: glob({
    base: './src/content/blog',
    pattern: '**/*.md',
    generateId: ({ entry }) => entry.replace(/\.md$/, ''),
  }),
  schema: /* ... */ z.object({}),
});
```

- `base` 是搜索起点，相对项目根目录。
- `pattern` 用 micromatch 语法，`**/*.md` 含子目录，`*.md` 只含当前层。
- `generateId` 决定条目的 `id`。默认取相对 `base` 的路径去掉扩展名，`posts/hello.md` 的 id 是 `posts/hello`。
- `base` 指到 `public/` 里的文件不会报错，但拿不到这些文件的内容，因为 `public/` 不做处理。

### 5.3.2 file 加载器

一个文件就是一个集合，常见于配置和字典数据：

```ts
const siteConfig = defineCollection({
  loader: file('./src/data/site-config.yaml'),
  schema: z.object({
    siteName: z.string(),
    description: z.string(),
  }),
});

const colors = defineCollection({
  loader: file('./src/data/colors.json', {
    parser: (text) => JSON.parse(text),
  }),
  schema: z.array(z.object({ id: z.string(), name: z.string() })),
});
```

YAML 文件里如果是一个顶层列表，每个元素会自动变成一条条目，`id` 取元素的 `id` 字段。缺 `id` 会报 `ContentLoaderInvalidDataError`。

### 5.3.3 自定义加载器

从 CMS 或数据库取数的构建时加载器，就是返回条目数组的异步函数：

```ts
const products = defineCollection({
  loader: async () => {
    const res = await fetch('https://api.example.com/products');
    if (!res.ok) throw new Error(`API 返回 ${res.status}`);
    const data = await res.json();
    return data.map((item) => ({
      id: item.slug,
      ...item,
    }));
  },
  schema: z.object({
    name: z.string(),
    price: z.number(),
    inStock: z.boolean(),
  }),
});
```

代价在构建期：每次构建都会请求一次，接口挂了构建就失败。条目多的时候要自己做缓存，否则构建时间线性增长。需要每次都新鲜的数据，用 5.12 的实时集合，不要用这个。

## 5.4 schema 校验失败长什么样

frontmatter 不符合 schema 时构建直接失败，报错会指出集合、条目和具体字段：

```
**blog** → **post** data does not match collection schema.
"title" is required.
"date" must be a valid date.
```

这条信息足够定位问题。要注意两点：

- 报错里的条目名是 `id`，不是文件路径。`posts/hello.md` 显示成 `posts/hello`。
- 报错发生在 `astro dev` 启动时和每次重新构建时。改 schema 后没重新校验，是因为 dev server 缓存了类型，重启一次。

`z.coerce.date()` 能把 `2026-05-20` 这类字符串转成 `Date`，`z.date()` 不能。YAML 里的日期在解析后是 `Date` 对象，JSON 里是字符串，两种源混用时用 `z.coerce.date()` 更稳。

## 5.5 Zod 常用写法

```ts
import { z } from 'astro/zod';

const schema = z.object({
  // 必填字符串
  title: z.string(),
  // 长度约束
  slug: z.string().min(1).max(100),
  // 格式校验
  email: z.string().email(),
  url: z.string().url(),

  // 数字与范围
  price: z.number().nonnegative(),
  rating: z.number().min(0).max(5),
  views: z.number().int().positive(),

  // 日期
  publishDate: z.coerce.date(),

  // 布尔
  draft: z.boolean().default(false),

  // 数组与枚举
  tags: z.array(z.string()),
  status: z.enum(['published', 'draft', 'archived']),

  // 可选与默认值
  description: z.string().optional(),
  cover: z.string().default('/images/default.png'),

  // 联合类型
  category: z.union([z.literal('tech'), z.literal('life'), z.string()]),

  // 嵌套对象
  seo: z.object({
    title: z.string(),
    noindex: z.boolean().default(false),
  }),

  // 自定义校验
  date: z.coerce.date().refine((d) => d <= new Date(), {
    message: '日期不能在未来',
  }),
});
```

`default()` 和 `optional()` 不是一回事。`default()` 保证字段一定存在，值由 schema 补上；`optional()` 允许字段缺失，使用时类型是 `T | undefined`，模板里要判空。模板里到处写 `post.data.cover &&` 是很常见的偷懒成本，能补默认值就补。

`z.date()` 不能用于 YAML 或 JSON 字符串，用了会报 `must be a valid date`，换成 `z.coerce.date()`。

## 5.6 查询条目

`getCollection()` 返回集合的全部条目，可传过滤函数：

```astro
---
import { getCollection } from 'astro:content';

// 全部
const allPosts = await getCollection('blog');

// 只取未草稿
const published = await getCollection('blog', ({ data }) => !data.draft);

// 按标签过滤，再按日期倒序
const techPosts = (await getCollection('blog', ({ data }) => data.tags.includes('tech')))
  .sort((a, b) => b.data.publishDate.getTime() - a.data.publishDate.getTime());
---
```

过滤函数在构建期执行，写法就是普通的数组 `filter`，但 `getCollection` 不会替你排序，顺序依赖文件系统，需要稳定顺序必须自己 `sort`。

`getEntry()` 取单条，返回 `undefined` 表示不存在，不抛错：

```ts
import { getEntry } from 'astro:content';

const post = await getEntry('blog', 'first-post');
if (!post) {
  throw new Error('文章不存在');
}
```

`getEntries()` 批量取，参数是引用对象的数组，不是 id 数组：

```ts
import { getEntry, getEntries } from 'astro:content';

const post = await getEntry('blog', 'first-post');
// post.data.related 来自 schema 里的 reference 数组
const related = await getEntries(post.data.related);
```

写 `getEntries('blog', ['a', 'b'])` 是老 API，现在拿不到结果。

## 5.7 渲染 Markdown 正文

条目的正文不是 HTML 字符串，而是一个组件。v5 起改用 `render(entry)`，旧的 `entry.render()` 方法在 v6 随旧版内容集合 API 一起移除，现在写 `await post.render()` 会报 `post.render is not a function`：

```astro
---
import { getEntry, render } from 'astro:content';

const post = await getEntry('blog', 'first-post');
if (!post) throw new Error('文章不存在');

const { Content, headings, remarkPluginFrontmatter } = await render(post);
---

<article>
  <h1>{post.data.title}</h1>

  {headings.length > 0 && (
    <nav class="toc">
      <ul>
        {headings
          .filter((h) => h.depth <= 3)
          .map((h) => (
            <li style={`padding-left: ${(h.depth - 1) * 1}rem`}>
              <a href={`#${h.slug}`}>{h.text}</a>
            </li>
          ))}
      </ul>
    </nav>
  )}

  <Content />
</article>
```

`render()` 返回三个值：

- `Content`：渲染正文的组件，放进模板的哪个位置，正文就出现在哪里。
- `headings`：标题数组，每项有 `depth`、`slug`、`text`，可直接做目录。
- `remarkPluginFrontmatter`：remark 插件写回的额外数据，没用插件时是空对象。

`<Content />` 之外再包一层 `<div class="prose">` 是常见做法，Markdown 生成的 HTML 没有 class，样式要挂在容器上。

传 `undefined` 给 `render()` 会报 `RenderUndefinedEntryError`，所以 `getEntry()` 之后必须判空。静态生成时条目一定存在，可以断言；按需渲染时用户能改 URL，必须判空。

## 5.8 用集合生成动态路由

条目只有 `id`，没有 `slug`。路由参数和链接都用 `id`：

```astro
---
// src/pages/blog/[id].astro
import { getCollection, render } from 'astro:content';
import BaseLayout from '../../layouts/BaseLayout.astro';

export async function getStaticPaths() {
  const posts = await getCollection('blog', ({ data }) => !data.draft);
  return posts.map((post) => ({
    params: { id: post.id },
    props: { post },
  }));
}

const { post } = Astro.props;
const { Content } = await render(post);
---

<BaseLayout title={post.data.title} description={post.data.description}>
  <h1>{post.data.title}</h1>
  <time datetime={post.data.publishDate.toISOString()}>
    {post.data.publishDate.toLocaleDateString('zh-CN')}
  </time>
  <Content />
</BaseLayout>
```

列表页链接用同一个 `id`：

```astro
<a href={`/blog/${post.id}`}>{post.data.title}</a>
```

`id` 里带 `/` 时（`posts/hello`），`[id].astro` 匹配不了多段路径，文件名要改成 `[...id].astro`。这是 `post.slug` 换 `post.id` 之后最容易踩的坑：老代码里 `slug` 经过处理是单段，`id` 保留了目录结构。

## 5.9 集合之间引用

引用让一个条目指到另一个条目，schema 里用 `reference()`：

```ts
// src/content.config.ts
import { defineCollection, reference } from 'astro:content';
import { z } from 'astro/zod';
import { glob } from 'astro/loaders';

const blog = defineCollection({
  loader: glob({ pattern: '**/*.md', base: './src/content/blog' }),
  schema: z.object({
    title: z.string(),
    author: reference('authors'),
    related: z.array(reference('blog')).default([]),
  }),
});

const authors = defineCollection({
  loader: glob({ pattern: '**/*.yaml', base: './src/content/authors' }),
  schema: z.object({ name: z.string() }),
});

export const collections = { blog, authors };
```

frontmatter 里写的是目标条目的 id：

```yaml
---
title: 第一篇
author: alice
related:
  - second-post
---
```

查询时可以把引用对象直接传给 `getEntry()` 或 `getEntries()`：

```ts
import { getEntry, getEntries } from 'astro:content';

const post = await getEntry('blog', 'first-post');
const author = await getEntry(post.data.author);
const related = await getEntries(post.data.related);
```

这里有个边界：`reference()` 只做格式校验（`{ collection, id }` 形状），不校验目标是否存在。写错的 id 在构建期不会报错，`getEntry()` 返回 `undefined`，模板里 `author.data.name` 就会抛 `Cannot read properties of undefined`。所以引用查询之后仍然要判空。

另外 `reference()` 从 `astro:content` 导入，不是 `z.reference()`。写成 `z.reference('authors')` 会报 `z.reference is not a function`。

## 5.10 图片字段

集合里的图片路径有两种存法。简单做法是存字符串，渲染时拼路径；需要构建期优化时，用 `image()` 辅助函数，它由 `schema` 回调提供：

```ts
import { defineCollection } from 'astro:content';
import { glob } from 'astro/loaders';
import { z } from 'astro/zod';

const blog = defineCollection({
  loader: glob({ pattern: '**/*.md', base: './src/content/blog' }),
  schema: ({ image }) =>
    z.object({
      title: z.string(),
      cover: image(),
      coverAlt: z.string(),
    }),
});
```

`image()` 校验图片文件确实存在于 `src/` 下，并返回可以直接交给 `<Image />` 的对象：

```astro
---
import { Image } from 'astro:assets';
---

<Image src={post.data.cover} alt={post.data.coverAlt} width={800} />
```

代价是图片必须在 `src/` 里，frontmatter 里写相对 `content/` 目录的路径。`public/` 里的图片用 `image()` 会报找不到文件，那种情况退回字符串路径，加 `<Image src={`/images/${post.data.cover}`} />`。

`image()` 不支持 `.refine()`，需要额外校验时用一个平行的字符串字段。

## 5.11 编辑器补全

`astro sync` 会为每个集合生成一个 JSON Schema，文件在 `.astro/collections/<集合名>.schema.json`。在 `.vscode/settings.json` 里把它指给对应目录：

```json
{
  "json.schemas": [
    {
      "fileMatch": ["/src/content/authors/**"],
      "url": "./.astro/collections/authors.schema.json"
    }
  ]
}
```

一个集合一条，`fileMatch` 写目录，`url` 写该集合的 schema 文件。写成一个总的 `.astro/collections.json` 是老版本的做法，现在没有这个文件。

生成的 `.astro/` 目录不进版本库，加进 `.gitignore`；第一次 clone 后先跑 `astro sync`，否则编辑器里 `astro:content` 的类型不存在。

## 5.12 实时集合

实时集合在每次请求时取数，用于库存、评论、实时榜单这类构建期无法固定的数据。配置单独放在 `src/live.config.ts`：

```ts
// src/live.config.ts
import { defineLiveCollection } from 'astro:content';
import { z } from 'astro/zod';
import { apiLoader } from './loaders/api-loader';

const products = defineLiveCollection({
  loader: apiLoader({ endpoint: process.env.API_URL }),
  schema: z.object({
    id: z.string(),
    name: z.string(),
    price: z.number(),
  }),
});

export const collections = { products };
```

`loader` 必填，而且没有内置的实时加载器，只能自己写或找第三方。查询用 `getLiveCollection()` 和 `getLiveEntry()`，后者返回 `{ entry, error }` 而不是直接返回条目：

```astro
---
// src/pages/products/[id].astro
import { getLiveEntry } from 'astro:content';

const { entry, error } = await getLiveEntry('products', Astro.params.id);

if (error) {
  if (error.status === 404) return Astro.rewrite('/404');
  throw error;
}
---

<h1>{entry.data.name}</h1>
<p>{entry.data.price}</p>
```

返回 `{ entry, error }` 的原因是远程数据随时可能失败：网络超时、接口 500、条目被删。校验失败统一走 `LiveCollectionValidationError`，可以单独判断：

```ts
import { LiveCollectionValidationError } from 'astro:content';

if (LiveCollectionValidationError.is(error)) {
  console.error(error.message);
}
```

实时集合的三个代价：

- 必须开按需渲染（`output: 'server'` 或页面 `export const prerender = false`），并且装好适配器，纯静态部署用不了。
- 一个页面要查几个集合，就多几次远程请求，首屏延迟直接叠加。需要缓存的话自己做，框架不管。
- 构建时集合有数据缓存，实时集合没有，每次请求都打到源。

数据在半分钟内能接受缓存时，用构建时集合并定时重建更省事。

## 5.13 构建时集合与实时集合对比

| 项目 | 构建时集合 | 实时集合 |
|---|---|---|
| 定义函数 | `defineCollection()` | `defineLiveCollection()` |
| 配置文件 | `src/content.config.ts` | `src/live.config.ts` |
| loader | 内置 `glob()`、`file()` | 必须自己写 |
| 查询函数 | `getCollection()` / `getEntry()` | `getLiveCollection()` / `getLiveEntry()` |
| 返回值 | 条目或 `undefined` | 条目或 `undefined` | 
| 错误处理 | 构建失败 | `{ entry, error }` 运行时处理 |
| 渲染要求 | 静态即可 | 需要适配器和按需渲染 |
| 适合 | 博客、文档、产品目录 | 库存、评论、实时数据 |

## 5.14 速查表

| API | 说明 |
|---|---|
| `defineCollection({ loader, schema })` | 定义构建时集合 |
| `defineLiveCollection({ loader, schema })` | 定义实时集合 |
| `glob({ base, pattern, generateId })` | 从目录加载文件 |
| `file(path, { parser })` | 从单个文件加载 |
| `getCollection(name, filter?)` | 取集合全部条目 |
| `getEntry(name, id)` | 取单条，不存在返回 `undefined` |
| `getEntry(referenceObject)` | 按引用取单条 |
| `getEntries(referenceArray)` | 按引用批量取 |
| `render(entry)` | 渲染正文，返回 `{ Content, headings, remarkPluginFrontmatter }` |
| `getLiveCollection(name, filter?)` | 取实时集合 |
| `getLiveEntry(name, id)` | 取实时单条，返回 `{ entry, error }` |
| `reference('collection')` | schema 里声明引用 |
| `entry.id` | 条目标识，也是路由参数 |
| `entry.data` | 校验后的 frontmatter |
| `entry.body` | 原始正文（Markdown 源文本） |
| `schema: ({ image }) => ...` | 拿图片校验辅助函数 |

不存在的东西：`entry.slug`、`entry.render()`、`z.reference()`、`src/content/config.ts`。这四个在 2026 年的老文章里非常常见，照抄会直接失败。

## 5.15 本章小结

- 配置写 `src/content.config.ts`，集合由 loader 加 schema 组成。
- `z` 从 `astro/zod` 导入，schema 校验失败会让构建失败并指出字段。
- 条目只有 `id`，没有 `slug`；动态路由参数和链接都用 `id`。
- 正文用 `render(entry)` 得到 `<Content />`，旧的 `entry.render()` 已移除。
- 跨集合引用用 `reference()`，它不校验目标存在，查询后要判空。
- 实时集合需要适配器、按需渲染和自行处理错误、缓存。
