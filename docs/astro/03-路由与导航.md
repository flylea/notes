# 第 3 章 路由与导航

## 3.1 文件即路由

`src/pages/` 下的文件自动成为 URL，不写路由表，也没有路由配置文件。

```
src/pages/
├── index.astro              → /
├── about.astro              → /about
├── posts/
│   └── 1.md                 → /posts/1
└── products/
    ├── index.astro          → /products
    └── category.astro       → /products/category
```

`about.astro` 和 `about/index.astro` 生成同一个 URL。两个都放时构建会警告：

```
Duplicate route: /about
```

最终保留哪一个没有规定，删掉其一。

页面文件支持 `.astro`、`.md`、`.mdx`。Markdown 页面需要先装 MDX 或直接用 Markdown 支持，`.md` 页面默认按文章渲染，适合纯静态说明页。

导航用原生 `<a>`：

```astro
<nav>
  <a href="/">首页</a>
  <a href="/about">关于</a>
  <a href="/blog">博客</a>
</nav>
```

Astro 默认是多页应用，链接就是完整页面跳转。需要无刷新跳转时加 `<ClientRouter />`，见第 7 章。用 `<a>` 的另一个好处是禁用 JS、爬虫抓取、新标签页打开都正常。

## 3.2 动态路由

文件名里的 `[param]` 是参数位：

```
src/pages/blog/[id].astro   → /blog/hello、/blog/42
```

参数值从 `Astro.params` 取：

```astro
---
// src/pages/blog/[id].astro
const { id } = Astro.params;
---

<h1>文章 {id}</h1>
```

`id` 始终是字符串。`/blog/42` 拿到的是 `"42"`，不是数字。用它查数据库前先转换：

```ts
const postId = Number(Astro.params.id);
if (Number.isNaN(postId)) {
  return new Response('Bad Request', { status: 400 });
}
```

`[...slug]` 匹配任意深度，值里带斜杠：

| URL | `Astro.params.slug` |
|---|---|
| `/docs/getting-started` | `"getting-started"` |
| `/docs/guides/routing` | `"guides/routing"` |
| `/docs` | `undefined` |

最后一行容易漏。用了 `[...slug]`，就要处理 `undefined` 的情况，否则在 `/docs` 上执行 `slug.split('/')` 会抛：

```
TypeError: Cannot read properties of undefined (reading 'split')
```

### 3.2.1 getStaticPaths

`static` 输出下，动态路由必须导出 `getStaticPaths()`，告诉构建器有哪些具体页面要生成。

```astro
---
// src/pages/blog/[id].astro
export async function getStaticPaths() {
  const posts = await fetch('https://api.example.com/posts').then((r) => r.json());

  return posts.map((post) => ({
    params: { id: post.id },
    props: { post },
  }));
}

const { post } = Astro.props;
---

<article>
  <h1>{post.title}</h1>
  <p>{post.content}</p>
</article>
```

规则：

- 返回值是数组，每项必须有 `params`，`props` 可选。
- `params.id` 必须和文件名里的 `[id]` 对应，拼错时该页面生成失败。
- `props` 会原样传给页面组件，通过 `Astro.props` 读取。

忘了导出这个函数，构建直接失败：

```
getStaticPaths() is required for dynamic routes in static mode.
```

返回空数组不报错，只是这个路由一页都不生成，访问时 404。这两个行为不同，排查时先确认函数是否被执行。

`getStaticPaths` 在构建时执行一次。里面 `fetch` 取得的数据会被固化进 HTML，接口数据变了要重新构建。

### 3.2.2 按需渲染下的动态路由

配了适配器并把页面设为请求时渲染，就不需要 `getStaticPaths()`，任何参数都能匹配：

```astro
---
// src/pages/search/[query].astro
export const prerender = false;

const { query } = Astro.params;
const results = await searchAPI(query);
---

<h1>搜索 "{query}" 的结果</h1>
```

`prerender = false` 需要适配器。没装时构建报错，提示当前项目不支持按需渲染，此时要先跑 `npx astro add node` 之类的命令。

两种模式的差别：

| | `static` 输出 | 页面设 `prerender = false` |
|---|---|---|
| 路径集合 | 由 `getStaticPaths` 决定，构建时固定 | 运行时任意值 |
| 取数时机 | 构建时 | 每次请求 |
| 能否读请求头、Cookie | 不能 | 能 |
| 需要适配器 | 不需要 | 需要 |

## 3.3 重定向

配置级重定向写在 `astro.config.mjs`：

```js
import { defineConfig } from 'astro/config';

export default defineConfig({
  redirects: {
    '/old-page': '/new-page',
    '/blog/[...slug]': '/articles/[...slug]',
    '/external': 'https://example.com',
  },
});
```

静态输出下，每条重定向生成一个 HTML，靠 `<meta http-equiv="refresh">` 跳转。`303` 和 `308` 之外的状态码在静态模式下会退化成 meta 刷新，因为纯静态托管发不了自定义状态码。

页面里重定向：

```astro
---
if (!isLoggedIn) {
  return Astro.redirect('/login');
}

return Astro.redirect('/dashboard', 307);
---
```

`Astro.redirect` 返回一个 `Response`，必须在页面结束前 `return`，写在模板中间不生效。

## 3.4 路由优先级

同一 URL 有多个文件能匹配时，按下面的顺序取：

1. 静态路径，如 `posts/create.astro`
2. 命名参数，如 `posts/[id].astro`
3. 剩余参数，如 `posts/[...slug].astro`

访问 `/posts/create`，同时存在 `posts/create.astro`、`posts/[id].astro`、`posts/[...slug].astro` 时，用第一个。

两条动态路由深度相同时也有优先级。`blog/[category]/[id].astro` 与 `blog/[id].astro` 对 `/blog/tech` 冲突，构建时警告 `Duplicate dynamic route`。这类冲突靠命名解决，不要指望隐式顺序。

## 3.5 输出格式

`build.format` 决定静态页面落成文件还是目录：

```js
export default defineConfig({
  build: {
    format: 'directory', // 默认，/about 生成 /about/index.html
    // format: 'file',   // /about 生成 /about.html
    // format: 'preserve', // 按源文件路径保留
  },
});
```

选哪种取决于托管平台。Netlify、Vercel、Cloudflare Pages 默认支持目录形式，选 `file` 时访问 `/about` 需要平台把 `/about` 映射到 `/about.html`，配错会 404。共享主机、对象存储上反而 `file` 更省事。

`trailingSlash` 与此相关，取值 `'always' | 'never' | 'ignore'`。设 `'always'` 后，`/about` 会重定向到 `/about/`。

## 3.6 路由排除

`src/pages/` 里以下划线开头的文件或目录不参与路由：

```
src/pages/
├── _components/        ← 不进路由，可放页面专用的组件
│   └── Hero.astro
└── api/
    └── _utils.ts       ← 不进路由
```

这条规则也适用于 `[` 之外的占位需求。临时页面、草稿、公共函数放这里，比放 `src/` 外层更近。

## 3.7 SEO 元信息

SEO 的基础是每页有唯一的标题、描述和 canonical。放在布局里统一处理：

```astro
---
// src/layouts/BaseLayout.astro
export interface Props {
  title: string;
  description: string;
  image?: string;
}

const { title, description, image } = Astro.props;
const canonicalURL = new URL(Astro.url.pathname, Astro.site);
---

<!doctype html>
<html lang="zh-CN">
  <head>
    <meta charset="UTF-8" />
    <meta name="viewport" content="width=device-width, initial-scale=1.0" />

    <title>{title}</title>
    <meta name="description" content={description} />
    <link rel="canonical" href={canonicalURL} />

    <meta property="og:title" content={title} />
    <meta property="og:description" content={description} />
    <meta property="og:url" content={canonicalURL} />
    <meta property="og:type" content="website" />
    {image && <meta property="og:image" content={image} />}

    <meta name="twitter:card" content="summary_large_image" />
  </head>
  <body>
    <slot />
  </body>
</html>
```

`Astro.site` 来自配置里的 `site` 字段。没配时 `new URL(pathname, undefined)` 抛：

```
TypeError: Invalid URL
```

配好之后的两个常见问题：

- `Astro.url.pathname` 在 `static` 输出下是当前页面路径，构建时确定，没问题。在预览服务器或反向代理后可能带前缀，需要 `base` 配合。
- canonical 必须带协议和域名，`new URL` 的第二参数负责补全，所以 `site` 要写成完整地址，如 `https://example.com`。

还需要 sitemap 和 robots 时，装 `@astrojs/sitemap`：

```bash
npx astro add sitemap
```

它在构建后生成 `sitemap-index.xml`，只包含可索引的静态页面。

## 3.8 预获取

预获取让点击后的跳转更快，代价是提前占用带宽。

```astro
<a href="/dashboard" data-astro-prefetch>悬停时预获取</a>
<a href="/dashboard" data-astro-prefetch="load">页面加载即预获取</a>
<a href="/dashboard" data-astro-prefetch="viewport">进入视口时预获取</a>
<a href="/dashboard" data-astro-prefetch="tap">点击时预获取</a>
```

全局配置：

```js
export default defineConfig({
  prefetch: {
    defaultStrategy: 'hover',
    prefetchAll: false,
  },
});
```

四个策略的花费差别很大。`load` 在首屏就开始下载其他页面，页面有 50 个链接时等于把整站拉一遍。移动端和按流量计费的用户不适合。`hover` 是默认值，成本最低，桌面上效果最好，触屏设备没有悬停，实际会退化为点击时才预取。

`prefetchAll: true` 会给所有站内链接加预获取，只适合页面数很少的站。

## 3.9 404 页面

```astro
---
// src/pages/404.astro
import BaseLayout from '../layouts/BaseLayout.astro';
---

<BaseLayout title="页面未找到" description="请求的页面不存在">
  <h1>404</h1>
  <p>页面不存在。</p>
  <a href="/">返回首页</a>
</BaseLayout>
```

静态托管只在托管平台配置了 404 回落时才会用这个文件。Netlify 自动识别 `404.html`，Cloudflare Pages 需要 `_redirects` 或 `404.html` 顶层文件，Vercel 默认也支持。构建格式选 `directory` 时，产物是 `dist/404/index.html`，部分平台认不出，改成 `format: 'file'` 或单独建 `src/pages/404.astro` 并确认产物路径。

按需渲染下 404 页面默认返回 200，要让状态码正确，用 `Astro.response.status`：

```astro
---
Astro.response.status = 404;
---
```

## 3.10 完整示例：博客路由

```
src/pages/
├── index.astro                 → 首页
├── blog/
│   ├── index.astro             → 列表
│   ├── [id].astro              → 详情
│   └── tags/[tag].astro        → 标签筛选
├── rss.xml.js                  → RSS
├── 404.astro
└── api/search.json.ts          → 搜索接口
```

首页列最新文章：

```astro
---
import BaseLayout from '../layouts/BaseLayout.astro';
import { getCollection } from 'astro:content';

const posts = await getCollection('blog', ({ data }) => data.draft !== true);
const latest = posts
  .sort((a, b) => b.data.publishDate.getTime() - a.data.publishDate.getTime())
  .slice(0, 5);
---

<BaseLayout title="博客首页" description="最新文章">
  <h1>最新文章</h1>
  {latest.map((post) => (
    <article>
      <h2><a href={`/blog/${post.id}`}>{post.data.title}</a></h2>
      <p>{post.data.description}</p>
    </article>
  ))}
</BaseLayout>
```

详情页用 `post.id` 作为参数，与文件名 `[id].astro` 对应：

```astro
---
// src/pages/blog/[id].astro
import { getCollection, render } from 'astro:content';

export async function getStaticPaths() {
  const posts = await getCollection('blog');
  return posts.map((post) => ({ params: { id: post.id }, props: { post } }));
}

const { post } = Astro.props;
const { Content } = await render(post);
---

<article>
  <h1>{post.data.title}</h1>
  <Content />
</article>
```

链接、参数名、`getStaticPaths` 返回的键三处必须一致。只改文件名不改 `params` 时，构建出的 URL 全是 `undefined`，页面能打开但内容相同，这类问题只能靠逐页点开确认。

## 3.11 本章小结

- `src/pages/` 下文件自动成为路由，`_` 开头的不参与。
- `[id]` 是单层参数，`[...slug]` 是任意深度，后者要处理 `undefined`。
- `static` 输出的动态路由必须导出 `getStaticPaths()`，忘了直接构建失败。
- `prerender = false` 需要适配器，换来请求时取数和读取请求头的能力。
- 重定向可写在配置里，也可在页面里 `return Astro.redirect()`。
- 优先级依次是静态路径、命名参数、剩余参数。
