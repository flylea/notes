# 第 35 章 响应式与可访问性

这一章讲两件事：页面在窄屏上怎么排，以及不用鼠标的人怎么用它。

需要这两项能力的原因不只是道德。后台类产品里，审批、报销、值班都可能在手机上处理，窄屏是真实入口；键盘操作在企业环境里同样是刚需，财务和运维大量使用键盘完成重复动作。读屏软件用户占比小，但法律和采购流程会把它算进去。

涉及的概念有六个。断点与容器查询决定布局怎么变。横向溢出是窄屏最常见的问题。焦点管理决定键盘用户能不能走完流程。语义与 ARIA 决定读屏软件读到什么。对比度阈值是能量化的验收标准。表单错误的播报方式决定用户知不知道哪里填错了。

## 35.1 三个共同前提

第一个前提是视口。窄屏的问题来自视口宽度小于内容宽度，浏览器因此出现横向滚动条。修法是让内容的宽度由父容器决定，固定宽度一律改成上限宽度。

第二个前提是焦点。键盘的 Tab 键在可聚焦元素之间移动，当前获得焦点的元素会收到键盘事件。焦点在哪，键盘操作就在哪。页面没有可见的焦点指示，键盘用户等于在黑暗里摸。

用键盘的人比想象中多。数据录入、客服、运维这几类岗位几乎全程键盘操作；临时性的场景也不少，鼠标坏了、手上有伤、笔记本触控板不灵。把键盘路径走通，收益不只落在少数用户身上。

第三个前提是可访问性树。浏览器把 DOM 转成一棵供辅助技术使用的树，读屏软件读的是这棵树，而非屏幕上看到的样子。一段文字用 `<div>` 加粗，视觉上是标题，树里还是普通文本。语义标签的作用就是把视觉上的层级写进这棵树。

这一章不展开完整的 WCAG 条款，也不覆盖全部辅助技术。范围限定在四类最常见的缺陷：窄屏横向滚动、键盘走不通、语义缺失、对比度不足。这四类占了实际项目里可访问性问题的七成以上。

## 35.2 断点从内容出发

Tailwind 4 提供五个默认断点：`sm` 640px、`md` 768px、`lg` 1024px、`xl` 1280px、`2xl` 1536px。它们只是常用值，真正的依据是内容在哪一档开始挤。

断点的选择方法是从小往大写。先按 375px 排一版，能放下的元素就排；放不下时再往上加一档，问自己“再多 100px 能不能多放一列”。定完三四个档位之后，回头检查有没有相邻两档几乎一样的样式，合并掉。

移动优先的写法是默认样式针对窄屏，宽屏用 `md:`、`lg:` 覆盖。反过来写，等于每个类名都要带一个 `max-` 前缀，维护成本翻倍。

后台布局的常见分界在 1024px。宽于这个值，侧栏固定 240px、内容区自适应；窄于这个值，侧栏收起成抽屉，内容区占满。

```tsx
// src/app/(app)/layout.tsx
import { Sidebar } from "@/components/sidebar";
import { MobileNav } from "@/components/mobile-nav";

export default function AppLayout({ children }: { children: React.ReactNode }) {
  return (
    <div className="flex min-h-dvh flex-col lg:flex-row">
      <div className="hidden lg:block lg:w-60 lg:shrink-0 lg:border-r lg:border-neutral-200">
        <Sidebar />
      </div>
      <MobileNav />
      <main id="main" tabIndex={-1} className="min-w-0 flex-1 p-4 lg:p-8">
        {children}
      </main>
    </div>
  );
}
```

`min-w-0` 不能省。flex 子项的默认最小宽度是内容宽度，内容里有一个长表格或一段长网址，整行就会被撑破。加上 `min-w-0` 之后，子项允许被压缩，再由内部的 `truncate` 或 `overflow-x-auto` 处理溢出。

抽屉导航需要把展开状态写进 ARIA，读屏才知道按钮控制的是哪一块：

```tsx
// src/components/mobile-nav.tsx
"use client";

import Link from "next/link";
import { usePathname } from "next/navigation";
import { useState } from "react";

const items = [
  { href: "/dashboard", label: "概览" },
  { href: "/members", label: "成员" },
  { href: "/files", label: "文件" },
  { href: "/settings", label: "设置" },
];

export function MobileNav() {
  const [open, setOpen] = useState(false);
  const pathname = usePathname();

  return (
    <div className="border-b border-neutral-200 lg:hidden">
      <button
        type="button"
        aria-expanded={open}
        aria-controls="mobile-nav-panel"
        onClick={() => setOpen((v) => !v)}
        className="flex min-h-11 w-full items-center justify-between px-4"
      >
        <span>菜单</span>
        <span aria-hidden="true">{open ? "收起" : "展开"}</span>
      </button>
      <nav id="mobile-nav-panel" hidden={!open} aria-label="主导航" className="border-t border-neutral-200">
        <ul className="p-2">
          {items.map((item) => (
            <li key={item.href}>
              <Link
                href={item.href}
                aria-current={pathname === item.href ? "page" : undefined}
                className="flex min-h-11 items-center rounded px-3"
                onClick={() => setOpen(false)}
              >
                {item.label}
              </Link>
            </li>
          ))}
        </ul>
      </nav>
    </div>
  );
}
```

抽屉还需要能按 Esc 关闭。移动端用户没有 Esc 键，但外接键盘和读屏用户有。在 `keydown` 里判断 `event.key === "Escape"`，关闭后把焦点还给触发按钮。

展开状态变化时不要自动把焦点移进面板。用户主动按 Tab 进去更可控，自动移焦点会让读屏连续跳两次。

`aria-expanded` 表示展开状态，`aria-controls` 指向面板的 id，`aria-current="page"` 标记当前页。三个属性都是给读屏的，视觉上看不出区别。

组件被摆在很窄的容器里时，视口断点会失效。侧栏里的统计卡片在桌面上只占 200px，用 `md:` 前缀判断的是窗口宽度，交给它就会算错。Tailwind 4 的容器查询按父容器宽度判断：

```tsx
// src/components/stat-card.tsx
export function StatCard({ label, value }: { label: string; value: string }) {
  return (
    <div className="@container rounded-lg border border-neutral-200 p-4">
      <div className="flex flex-col gap-1 @md:flex-row @md:items-baseline @md:justify-between">
        <span className="text-sm text-neutral-600">{label}</span>
        <span className="text-2xl font-semibold tabular-nums">{value}</span>
      </div>
    </div>
  );
}
```

父元素加 `@container`，子元素就能用 `@md:` 这类前缀。判断依据是卡片自己的宽度，摆在哪里都对。

## 35.3 横向溢出的三个来源

窄屏出现横向滚动条，来源通常只有三种。

第一种是 flex 子项不肯缩。修法是给需要缩的那个子项加 `min-w-0`，需要截断的文本再加 `truncate`。

```tsx
// src/components/member-row.tsx
export function MemberRow({ name, email }: { name: string; email: string }) {
  return (
    <div className="flex items-center gap-3">
      <span className="flex size-9 shrink-0 items-center justify-center rounded-full bg-neutral-200">
        {name.slice(0, 1)}
      </span>
      <div className="min-w-0 flex-1">
        <p className="truncate text-sm font-medium">{name}</p>
        <p className="truncate text-sm text-neutral-600">{email}</p>
      </div>
    </div>
  );
}
```

头像和按钮要 `shrink-0`，文字容器要 `min-w-0`。少写一个，长邮箱就会把整行撑出去。

第二种是宽表格。表格里的列宽由内容决定，列一多必然超宽。容器加横向滚动，同时要让键盘也能滚：

```tsx
// src/components/members-table.tsx
import type { Member } from "@/lib/types";

export function MembersTable({ members }: { members: Member[] }) {
  return (
    <div
      role="region"
      aria-label="成员列表"
      tabIndex={0}
      className="overflow-x-auto rounded-lg border border-neutral-200"
    >
      <table className="w-full min-w-[640px] text-left text-sm">
        <thead className="bg-neutral-50">
          <tr>
            <th scope="col" className="px-4 py-3 font-medium">姓名</th>
            <th scope="col" className="px-4 py-3 font-medium">邮箱</th>
            <th scope="col" className="px-4 py-3 font-medium">角色</th>
            <th scope="col" className="px-4 py-3 font-medium">加入时间</th>
          </tr>
        </thead>
        <tbody>
          {members.map((member) => (
            <tr key={member.id} className="border-t border-neutral-200">
              <td className="px-4 py-3">{member.fullName}</td>
              <td className="px-4 py-3">{member.email}</td>
              <td className="px-4 py-3">{member.role === "owner" ? "所有者" : "成员"}</td>
              <td className="px-4 py-3">{member.createdAt}</td>
            </tr>
          ))}
        </tbody>
      </table>
    </div>
  );
}
```

`tabIndex={0}` 让滚动容器能被 Tab 聚焦，聚焦后用左右方向键滚动。没有这一项，鼠标能横向滚，键盘不能。`role="region"` 加 `aria-label` 让它变成一个有名字的区域，读屏在进入时会报出名字。

第四种是长字符串。URL、哈希、错误码这类没有空格的文本不会自动换行，一个 80 字符的 ID 就能把容器撑破。修法是 `break-all` 或 `wrap-anywhere`，并对这类文本单独处理显示，例如只展示前 8 位加省略号，完整值放 `title` 或详情页。

触屏目标的尺寸有下限。iOS 人机界面指南给的是 44×44，Material 给的是 48×48，取 44 是底线。图标按钮、表格行内的操作链接、分页按钮都要按这个尺寸做，视觉上可以小，点击区域不能小。

第三种是固定宽度的图片和 iframe。`w-[600px]` 改成 `w-full max-w-[600px]`，`<iframe>` 配 `aspect-video`。视频嵌入没给宽度时，加载前高度是 0，内容到达后整页往下推。

表格在窄屏上还有另一种处理：直接换成卡片。表格列多时，横向滚动虽然能用，读起来仍然别扭。用两个组件按断点切换，代价是维护两份标记，收益是手机上能正常阅读。

```tsx
// src/components/members-list.tsx
import type { Member } from "@/lib/types";

export function MembersList({ members }: { members: Member[] }) {
  return (
    <ul className="space-y-3 md:hidden">
      {members.map((member) => (
        <li key={member.id} className="rounded-lg border border-neutral-200 p-4">
          <p className="font-medium">{member.fullName}</p>
          <p className="break-all text-sm text-neutral-600">{member.email}</p>
          <p className="mt-1 text-sm text-neutral-600">{member.role === "owner" ? "所有者" : "成员"}</p>
        </li>
      ))}
    </ul>
  );
}
```

两份标记都要有完整的语义。卡片列表用 `<ul>` 与 `<li>`，屏幕阅读器才能报出“列表，共 12 项”。

自检用两行控制台代码：

```js
// 在页面控制台执行
document.documentElement.scrollWidth > document.documentElement.clientWidth;
[...document.querySelectorAll("*")].filter((el) => el.getBoundingClientRect().right > document.documentElement.clientWidth).map((el) => el.tagName + "." + el.className);
```

第二行输出越界的元素。把窗口拖到 375px、768px、1024px 各跑一次，三个宽度都不出现横向滚动，布局才算通过。

## 35.4 键盘与焦点

键盘能用的前提是元素本身可聚焦。`<div onClick>` 不能被 Tab 选中，`<button>` 可以。能用原生元素的地方不要自己造。

原生的对应关系是这样的：跳转用 `<a href>` 或 `<Link>`，动作用 `<button>`，折叠展开用 `<details>`，选择用 `<input type="checkbox">` 配 `<label>`。这些都自带键盘行为和读屏语义。

只有三类情况需要 ARIA：表示状态（`aria-expanded`、`aria-selected`）、表示关系（`aria-controls`、`aria-describedby`）、动态播报（`aria-live`）。ARIA 只改语义，不加行为。给 `<div>` 加 `role="button"` 之后，回车和空格仍然不会触发点击。

焦点顺序由 DOM 顺序决定，跟 CSS 的视觉顺序无关。用 `order` 或 `flex-row-reverse` 调换位置时，键盘顺序不会跟着变。视觉顺序与 DOM 顺序差得太多，键盘用户会觉得跳来跳去。要调顺序就改 DOM，别只改样式。

自定义下拉、日期选择、树形控件是三类高成本组件。它们各自有一套键盘约定：下拉用上下方向键移动、回车选中、Esc 关闭；日期选择用方向键在格子里移动。这些行为不会从 ARIA 自动获得，需要逐条实现。能用原生 `<select>` 和 `<input type="date">` 时优先用原生。

`tabIndex` 只有两个合法值：`0` 表示加入自然顺序，`-1` 表示可以用脚本聚焦但不进 Tab 顺序。正数会把元素插到顺序最前面，打乱视觉顺序与键盘顺序的一致性，不要用。

焦点必须看得见。全局重置里写 `*:focus { outline: none }`，键盘用户就失去了定位。正确的做法是用 `:focus-visible` 只对键盘聚焦显示指示：

```css
/* src/app/globals.css */
@import "tailwindcss";

@layer base {
  :focus-visible {
    outline: 2px solid var(--color-blue-600);
    outline-offset: 2px;
    border-radius: 2px;
  }
}
```

焦点指示本身也算界面组件，与背景的对比度要 3:1 以上。浅蓝细线放在白底上不够明显，换成深蓝或加一层白边再叠深色轮廓，两种背景下都能看见。

鼠标点击时不显示轮廓，键盘操作时显示，这是 `:focus-visible` 的默认行为。

图标按钮必须有三样东西：可访问的名字、足够的点击区域、正确的事件类型。

```tsx
// src/components/icon-button.tsx
import type { ButtonHTMLAttributes } from "react";

type Props = ButtonHTMLAttributes<HTMLButtonElement> & { label: string };

export function IconButton({ label, children, className = "", ...rest }: Props) {
  return (
    <button
      type="button"
      aria-label={label}
      className={`inline-flex size-11 items-center justify-center rounded-md hover:bg-neutral-100 ${className}`}
      {...rest}
    >
      <span aria-hidden="true">{children}</span>
    </button>
  );
}
```

`size-11` 是 44×44，触摸和鼠标都够用。图标本身对读屏没有意义，用 `aria-hidden` 屏蔽掉，名字由 `aria-label` 提供。

快捷键可以加，但不要抢系统组合。`aria-keyshortcuts` 让读屏能播报快捷键，浏览器不会因此拦截按键。给快捷键配一个可见的说明，否则只有开发者自己知道。

页面顶部要有跳过导航链接。侧栏里有二十个链接时，键盘用户每次进页面都要按二十多次 Tab 才能到内容区。

```tsx
// src/components/skip-link.tsx
export function SkipLink() {
  return (
    <a
      href="#main"
      className="sr-only rounded bg-blue-600 px-4 py-2 text-white focus:not-sr-only focus:absolute focus:top-2 focus:left-2 focus:z-50"
    >
      跳到主要内容
    </a>
  );
}
```

`<main id="main" tabIndex={-1}>` 上的 `tabIndex={-1}` 是为了让锚点跳转能把焦点带过去。少了它，页面滚动到内容区，焦点还停在链接上，下一次 Tab 又回到开头。

## 35.5 模态与焦点陷阱

模态打开后，焦点必须被限制在对话框内。否则用户按 Tab 会跑到被遮住的背景内容上，读者看不见焦点在哪。

`<dialog>` 覆盖了大部分场景。少数场景不适合：需要在对话框之外保留可交互区域，或者要做非模态的浮层提示。这类情况下焦点陷阱要自己写，核心是三件事：记录打开前的焦点、在 `keydown` 里拦截 Tab 把焦点限制在容器内、关闭时把焦点还回去。

自己实现的版本容易漏掉第三件事。用户按 Esc 关闭后焦点掉到 `body`，下一次 Tab 从页面开头开始，流程被打断。

浏览器提供了原生解决方案。`<dialog>` 元素调用 `showModal()` 之后，浏览器自动做五件事：把焦点移进对话框、把 Tab 循环限制在对话框内、把背景内容标记为不可交互、监听 Esc 关闭、关闭后把焦点还给触发元素。

```tsx
// src/components/modal.tsx
"use client";

import { useEffect, useRef } from "react";

export function Modal({
  open,
  onClose,
  title,
  children,
}: {
  open: boolean;
  onClose: () => void;
  title: string;
  children: React.ReactNode;
}) {
  const ref = useRef<HTMLDialogElement>(null);

  useEffect(() => {
    const dialog = ref.current;
    if (!dialog) return;

    if (open && !dialog.open) {
      dialog.showModal();
    } else if (!open && dialog.open) {
      dialog.close();
    }
  }, [open]);

  return (
    <dialog
      ref={ref}
      onClose={onClose}
      aria-labelledby="modal-title"
      className="w-full max-w-lg rounded-lg p-0 backdrop:bg-black/50"
    >
      <div className="flex items-center justify-between border-b border-neutral-200 p-4">
        <h2 id="modal-title" className="text-lg font-semibold">{title}</h2>
        <button type="button" onClick={onClose} aria-label="关闭对话框" className="size-11">
          <span aria-hidden="true">×</span>
        </button>
      </div>
      <div className="p-4">{children}</div>
    </dialog>
  );
}
```

三个易漏点。第一，不要用 `open` 属性控制显隐，它只把对话框变成可见的普通元素，模态行为和 Esc 都不会有。第二，`onClose` 必须同步组件的状态，否则用户按 Esc 关闭后，父组件的 `open` 还是 `true`，再点触发按钮打不开。第三，`children` 可以是服务端组件，`<dialog>` 只是外层壳。

## 35.6 语义与对比度

语义标签还有一个副作用：浏览器和辅助技术会据此提供快捷导航。读屏用户可以按地标跳转，直接落到 main 里，不用从头听一遍导航。

语义标签的作用是让可访问性树有结构。页面要有三个地标：`<header>`、`<nav>`、`<main>`。多块导航各给一个 `aria-label` 区分。

装饰性图标与分隔线对读屏没有信息，统一加 aria-hidden="true"。漏加时读屏会念出图标字体的私用区字符，听起来是一串杂音。

标题层级不能跳。`h1` 到 `h2` 到 `h3` 是层级关系，用字号做视觉层级要另配类名，别用 `h4` 装作小标题。

对比度的算法是相对亮度之比，公式在 WCAG 文档里，工具会替你算。开发者工具的元素面板里，`color` 属性旁边有一个对比度徽标，点开能看到具体数值与是否达标。Chrome 和 Safari 都有，Edge 也有。设计稿阶段用插件或在线工具算，别凭肉眼判断灰色够不够深。

对比度是可量化的验收项，阈值来自 WCAG AA：

| 内容类型 | 最小对比度 | 例子 |
| --- | --- | --- |
| 正文文本 | 4.5:1 | 段落、表格内容、表单标签 |
| 大字（18.66px 粗体或 24px 常规以上） | 3:1 | 页面主标题、大号数字 |
| 界面组件与图形 | 3:1 | 输入框边框、图标、图表线条 |

常用色的实测值：`#111827` 配白底是 17.74:1，`#4b5563` 是 7.56:1，`#6b7280` 是 4.83:1，`#9ca3af` 是 2.54:1，`#d1d5db` 是 1.47:1。前三个可以用于正文，后两个只能做装饰。

灰阶的坑在于背景不纯白。`neutral-500` 的文字配纯白是 4.83:1，放在 `neutral-50` 的背景上掉到 4.43:1，刚好不达标。容器有底色时，要按底色算。

背景是图片时，对比度按最亮和最暗处分别算，取最差的结果。压在照片上的白色文字必须加半透明遮罩，否则同一段字在不同照片上时好时坏。

深色模式要单独算一遍。`#0f172a` 背景上，白色 17.85:1，`#cbd5e1` 12.02:1，`#94a3b8` 6.96:1，这三档都能用；`#475569` 只有 3.4:1，正文不能用。

输入框的边框属于界面组件，要 3:1。`neutral-300` 的边框在浅色背景上不到 2:1，看起来精致，实际上不达标，换成 `neutral-500` 就过了。

禁用状态可以放宽。WCAG 对禁用控件不做对比度要求，但字要看得见，别做成 10% 透明度。

## 35.7 表单错误的播报

表单提交失败时，视障用户需要知道三件事：有几处错误、错在哪、怎么改。

```tsx
// src/app/(app)/settings/settings-form.tsx
"use client";

import { useActionState, useId } from "react";
import { updateSettings } from "./actions";

type State = { errors?: Record<string, string>; ok?: boolean };

const initialState: State = {};

export function SettingsForm({ teamName }: { teamName: string }) {
  const [state, formAction, pending] = useActionState(updateSettings, initialState);
  const teamId = useId();
  const slugId = useId();

  return (
    <form action={formAction} noValidate className="space-y-4">
      <p aria-live="polite" className="text-sm text-neutral-600">
        {pending ? "正在保存……" : state.ok ? "已保存" : ""}
      </p>

      {state.errors && Object.keys(state.errors).length > 0 && (
        <div role="alert" className="rounded-md border border-red-300 bg-red-50 p-3 text-sm text-red-700">
          <p className="font-medium">有 {Object.keys(state.errors).length} 处需要修改</p>
          <ul className="mt-2 list-disc pl-5">
            {Object.entries(state.errors).map(([field, message]) => (
              <li key={field}>
                <a href={`#${field}`} className="underline">
                  {message}
                </a>
              </li>
            ))}
          </ul>
        </div>
      )}

      <div>
        <label htmlFor={teamId} className="block text-sm font-medium">团队名称</label>
        <input
          id="teamName"
          name="teamName"
          defaultValue={teamName}
          aria-invalid={state.errors?.teamName ? true : undefined}
          aria-describedby={state.errors?.teamName ? "teamName-error" : undefined}
          className="mt-1 w-full rounded-md border border-neutral-500 px-3 py-2"
        />
        {state.errors?.teamName && (
          <p id="teamName-error" className="mt-1 text-sm text-red-700">
            {state.errors.teamName}
          </p>
        )}
      </div>

      <div>
        <label htmlFor="slug" className="block text-sm font-medium">团队地址</label>
        <input
          id="slug"
          name="slug"
          aria-invalid={state.errors?.slug ? true : undefined}
          aria-describedby={state.errors?.slug ? "slug-error" : undefined}
          className="mt-1 w-full rounded-md border border-neutral-500 px-3 py-2"
        />
        {state.errors?.slug && (
          <p id="slug-error" className="mt-1 text-sm text-red-700">{state.errors.slug}</p>
        )}
      </div>

      <button type="submit" className="min-h-11 rounded-md bg-blue-600 px-4 py-2 text-white">
        保存
      </button>
    </form>
  );
```

```ts
// src/app/(app)/settings/actions.ts
"use server";

import { revalidatePath } from "next/cache";
import { requireMembership } from "@/lib/teams";
import { createClient } from "@/lib/supabase/server";

export async function updateSettings(_prev: unknown, formData: FormData) {
  const team = await requireMembership("owner");
  const teamName = String(formData.get("teamName") ?? "").trim();
  const slug = String(formData.get("slug") ?? "").trim();

  const errors: Record<string, string> = {};
  if (teamName.length < 2) errors.teamName = "团队名称至少 2 个字";
  if (!/^[a-z0-9-]+$/.test(slug)) errors.slug = "地址只能包含小写字母、数字和连字符";
  if (Object.keys(errors).length > 0) return { errors };

  const supabase = await createClient();
  const { error } = await supabase.from("teams").update({ name: teamName, slug }).eq("id", team.id);
  if (error) return { errors: { teamName: "保存失败，请稍后重试" } };

  revalidatePath("/settings");
  return { ok: true };
}
```

`aria-live` 有三个值。`polite` 等读屏空闲时播报，适合保存状态这类非紧急提示；`assertive` 立即打断当前朗读，适合错误摘要；`off` 关闭播报，用于频繁变化的内容。

播报区域不要频繁重建。列表每输一个字就替换内容，读屏会连续打断。做防抖，或者只播报最终结果。

几个细节。`aria-describedby` 把输入框与错误文本关联，读屏在聚焦输入框时会念出错误。`aria-invalid` 表示这份输入无效，读屏会换一种语气。`role="alert"` 让错误摘要自动播报。`aria-live="polite"` 播报保存状态，它所在的区域必须一开始就在 DOM 里，后插入的区域不会被播报。

客户端校验只负责即时反馈，服务端校验才是准绳。两边规则要一致，但不要共享同一份实现：服务端那份要能挡住直接构造的请求，客户端那份可以宽松一点，只做格式提示。

错误文案要写清楚怎么改。“输入有误”没有信息量，“地址只能包含小写字母、数字和连字符”才有。同一条规则在客户端与服务端用同一句文案，用户不会看到两种说法。

提交失败后把焦点移到错误摘要，或者移到第一个出错的输入框。用 `useEffect` 监听 `state.errors` 的变化再调 `focus()`，比只在视觉上标红更有效。

拖拽是键盘的盲区。文件上传、看板排序、滑块这三类交互默认只能用鼠标。做法是提供替代路径：文件上传保留一个原生 `<input type="file">`，排序提供“上移”“下移”按钮，滑块旁边配一个数字输入框。

会话超时也要能被感知。登录过期后提交表单，页面跳回登录页，用户填的内容全丢。提交前检查会话，或者把表单内容暂存到本地，恢复后提示用户。

验证码同样有无障碍要求。图片验证码必须提供语音版本或其它替代方式，纯图形验证码把视障用户挡在门外。

## 35.8 边界与失败模式

**未验证**：本章的对比度比值按 WCAG 公式计算，键盘与读屏流程来自规范与实操经验，本地未在真机上逐项验证。

以下几类情况容易被漏掉。

对话框关闭后的焦点归位也要考虑内容被删除的情况。触发按钮随列表刷新消失时，焦点会掉到 `body`。这种情况下把焦点交给页面主标题，比留在 `body` 好。

`hidden` 属性与 CSS 的 `display: none` 都会把元素移出可访问性树。用透明度隐藏、或者用 `absolute` 挪到视口外，元素仍然可聚焦，Tab 会走进看不见的地方。隐藏就要真隐藏。

动画要尊重系统设置。前庭功能敏感的用户会把“减少动态效果”打开，媒体查询是 `prefers-reduced-motion`。过渡和位移动画要在这条查询里降级成透明度变化或直接取消。

文字放大到 200% 时布局不能坏。浏览器缩放和系统字号都会触发这个场景。固定的行高、固定高度的容器、`overflow: hidden` 都会在这里出问题，用 `min-height` 和自适应行高代替。

路由切换后焦点不会自动移动。单页应用里点链接换页面，焦点通常留在原来的链接上。做法是在新页面的主标题上加 `tabIndex={-1}` 并在挂载时聚焦，同时把 `document.title` 更新掉。Next.js 的 `<Link>` 会更新标题，焦点需要自己处理。

颜色不能单独承担信息。必填项只用红色星号、错误只用红边框，色觉障碍用户看不出区别。加图标、加文字、加 `aria-invalid`，保证去掉颜色之后信息还在。

响应式与可访问性的验收可以放进 CI。用 Playwright 在三个视口尺寸下各跑一遍主流程，断言没有横向滚动、键盘能完成关键动作；再用 axe-core 扫一遍，把严重级别的问题作为失败条件。自动化覆盖不了全部，但能挡住回退。

## 35.9 检查点

1. 只用键盘走完一次完整流程：Tab 到跳过链接并回车，Tab 进入列表，打开模态，Esc 关闭，焦点回到触发按钮。中间没有卡住的位置。
2. 每次 Tab 都能看到焦点指示。`grep -r "outline-none" src/` 的结果里没有全局重置，焦点样式只出现在 `:focus-visible`。
3. 控制台执行 `document.documentElement.scrollWidth <= document.documentElement.clientWidth`，在 375px、768px、1024px 三个宽度下都返回 `true`。
4. 用开发者工具检查正文文本的对比度，标出的数值都在 4.5:1 以上；输入框边框 3:1 以上；切到深色模式再检查一遍。
5. 表单故意留空提交，读屏能播报错误摘要，聚焦出错输入框时能念出对应错误文本。
6. 打开 VoiceOver（macOS 是 `Cmd + F5`），按 `Ctrl + Option + U` 打开转子，能看到地标列表与标题层级，顺序与视觉一致。

## 35.10 常见错误

1. `<label>` 的 `htmlFor` 与输入框 `id` 对不上。 点标签没有反应，读屏也念不出输入框的名字。两处字符串必须完全一致，`useId()` 生成的值要用在同一个元素上。

2. 图标按钮没有可访问的名字。 读屏只念“按钮”。加上 `aria-label`，图标本身用 `aria-hidden="true"`。

3. 用 `open` 属性打开 `<dialog>`。 遮罩不出现，Esc 不关闭，背景还能点。改成 `showModal()`，由 `useEffect` 根据状态调用。

4. 报 `Failed to execute 'showModal' on 'HTMLDialogElement'`。 对话框还没挂载到文档里，或者重复调用了 `showModal()`。在调用前判断 `dialog.isConnected` 和 `dialog.open`。

5. 水合报 `Prop 'aria-expanded' did not match`。 服务端渲染时是 `false`，客户端读到的状态是 `true`，两边不一致。初值要与服务端一致，交互后再更新。

6. `Warning: A form field element should have an id or name attribute`。 输入框缺少 `id` 或 `name`，浏览器自动填充和表单提交都拿不到值。两个属性都补上。

## 35.11 这一章在做什么

还有一条实践建议：把可访问性要求写进组件的验收标准。按钮组件自带可访问名字与 44px 尺寸，输入框组件自带错误关联，表单组件自带播报区域。规则写在组件里，使用者不用每次重新记一遍。

这一章建立三条判断。窄屏问题来自宽度约束，修法是 `min-w-0`、横向滚动容器和上限宽度。键盘可用性来自焦点，修法是原生元素、`focus-visible`、`<dialog>`。可访问性来自语义，修法是正确的地标、标签、播报区域和对比度。

验收不靠感觉，靠四组动作：键盘走一遍、缩放 200% 看一遍、读屏听一遍、对比度算一遍。

下一章回到渲染路径，讲导航为什么会有空白期，以及拦截路由、预取、流式渲染怎么配合把这个空白压掉。
