# 第 37 章 视图过渡、视频与草稿预览

这一章讲三件与呈现有关的事：页面切换时的视觉过渡、视频内容的嵌入方式、草稿内容的预览通道。

三件事的共同点是它们都贴着浏览器与网络的能力边界。视图过渡依赖浏览器对 View Transitions API 的支持，支持与不支持两种结果都要能用。视频是页面里最重的资源，图片优化管线管不到它。草稿预览要在同一套页面代码里分岔，让编辑看到未发布内容，普通访客看不到。

涉及的概念：`<ViewTransition>` 组件与 `transitionTypes`、视频的 `preload` 与字幕轨、`<iframe>` 嵌入的三项必备属性、`draftMode()` 与 `__prerender_bypass` cookie、`'use cache'` 作用域里的预览分支、MDX 作为页面来源。

## 37.1 视图过渡是什么

View Transitions API 是浏览器能力：切换前后各截一张快照，浏览器在这两张快照之间插值。注册在同一名字下的元素会做位置与尺寸的补间，其余部分做交叉淡入。

它解决的是一个长期存在的问题：路由切换时页面瞬间替换，用户看不出新旧页面之间的关系。过渡把这个关系画出来，前进与后退不再只是内容变化，而有了方向与来源。

浏览器层面的实现由框架托管。Next.js 把每次路由导航当成一次 transition，所以项目里不需要写 `startViewTransition`，也不需要手动管理快照生命周期。

React 19.3 内置了 `<ViewTransition>` 组件，把这套能力包成声明式接口。Next.js 的路由切换本身就是一个 transition，所以导航时不需要额外代码就会触发。

三个触发条件：`useTransition` 包裹的状态更新、`<Suspense>` 边界的内容变化、`useDeferredValue` 的延迟更新。普通的 `setState` 不触发，因为浏览器需要在状态变化时知道“这是一次导航或一次有意义的切换”。

```tsx
// src/app/(app)/files/[id]/file-hero.tsx
import { ViewTransition } from "react";

export function FileHero({ file }: { file: { id: string; name: string } }) {
  return (
    <ViewTransition name={`file-${file.id}`}>
      <div className="rounded-lg border border-neutral-200 p-4">
        <h1 className="text-xl font-semibold">{file.name}</h1>
      </div>
    </ViewTransition>
  );
}
```

组件没有引入新的样式体系，过渡的视觉参数全部由 CSS 里的伪元素控制。React 只负责在合适的时机给元素打上过渡名。

过渡有代价。浏览器在切换瞬间要截两张全页快照，页面越大，截图越慢。长列表页做过渡时，首帧可能比不做还慢。做法是只给首屏可见的元素命名，其余部分交给默认的交叉淡入。

命名冲突会让配对错乱。过渡名依赖数据的 id 就不会重复，用固定字符串则在列表里撞车，浏览器可能把两行缩略图配到一起。

## 37.2 浏览器限制

这套能力用到了较新的特性：过渡类型（transition types）与 `view-transition-class`。它们要求 Chromium 125 及以上，Safari 与 Firefox 需要较新版本。

| 环境 | 结果 |
| --- | --- |
| Chromium 125 及以上 | 完整支持 |
| 较新的 Safari 与 Firefox | 大部分支持，部分动画表现不同 |
| 更旧的浏览器 | 没有动画，页面照常切换 |

降级是自动的。浏览器不支持时，`<ViewTransition>` 就是一个普通容器，导航仍然正常，只是没有补间。所以过渡可以放心加，不需要为老浏览器准备两套渲染。

验收时分开测两件事：支持的环境里动画是否流畅，不支持的环境里功能是否完整。前者看录屏，后者在旧版浏览器里点一遍主要路径。

动画不改变可用性。加载顺序、焦点、滚动位置都由路由决定，过渡只影响观感。所以过渡出问题时，先关掉它确认功能正常，再回头调 CSS。

要按能力决定是否加过渡，用一行检测：

```ts
// src/lib/supports-view-transition.ts
export const supportsViewTransition =
  typeof document !== "undefined" && "startViewTransition" in document;
```

这个值只能用在客户端组件里。服务端渲染时 `document` 不存在，所以判断要放在 `useEffect` 或事件处理里，不能直接写在渲染路径上。

过渡加不加由产品决定，代码层面不分支。加过渡不需要特性检测，只有性能敏感的场景才需要按能力关掉。

## 37.3 共享元素过渡

共享元素过渡（morph）用于表达“点开的是同一个东西”。列表里的缩略图变成详情页的大图，浏览器在两个位置之间补间。

做法是给两端同一个 `name`：

```tsx
// src/app/(app)/files/file-grid.tsx
import Link from "next/link";
import { ViewTransition } from "react";

export function FileGrid({ files }: { files: { id: string; name: string; mime: string }[] }) {
  return (
    <ul className="grid grid-cols-2 gap-3 md:grid-cols-4">
      {files.map((file) => (
        <li key={file.id}>
          <Link href={`/files/${file.id}`} className="block">
            <ViewTransition name={`file-${file.id}`}>
              <div className="aspect-square rounded-lg border border-neutral-200 p-2 text-sm">
                <span className="line-clamp-2">{file.name}</span>
              </div>
            </ViewTransition>
          </Link>
        </li>
      ))}
    </ul>
  );
}
```

两端同名就会配对，不需要额外属性。配对成立有个前提：目标内容和这次导航在同一次提交里渲染。目标页已经预取或已经缓存时满足这个前提；目标页先挂起到 fallback 时不成立，这时浏览器退化成进入动画。

自定义补间要显式声明：

```tsx
// src/app/(app)/files/[id]/file-hero.tsx
<ViewTransition name={`file-${file.id}`} share="morph" default="none">
  {/* 详情内容 */}
</ViewTransition>
```

```css
/* src/app/globals.css */
::view-transition-group(.morph) {
  animation-duration: 400ms;
}

::view-transition-image-pair(.morph) {
  animation-name: via-blur;
}

@keyframes via-blur {
  30% {
    filter: blur(3px);
  }
}
```

`default="none"` 关掉默认的交叉淡入，只保留你声明的效果。加了它还要显式写 `share="morph"`，否则配对会悄悄失效：动画照常跑，但两端没有连起来。

## 37.4 方向过渡

前进与返回应该有不同的方向。`<Link>` 的 `transitionTypes` 属性把意图传给浏览器：

```tsx
// src/app/(app)/files/page.tsx
<Link href={`/files/${file.id}`} transitionTypes={["nav-forward"]}>
  {file.name}
</Link>
```

```tsx
// src/app/(app)/files/[id]/page.tsx
<Link href="/files" transitionTypes={["nav-back"]}>
  返回列表
</Link>
```

页面内容按类型选择动画：

```tsx
// src/app/(app)/files/[id]/page.tsx
import { ViewTransition } from "react";

export default async function FilePage({ params }: { params: Promise<{ id: string }> }) {
  const { id } = await params;
  return (
    <ViewTransition
      enter={{ "nav-forward": "nav-forward", "nav-back": "nav-back", default: "none" }}
      exit={{ "nav-forward": "nav-forward", "nav-back": "nav-back", default: "none" }}
      default="none"
    >
      <main id="main" tabIndex={-1} className="p-4 lg:p-8">
        {/* 详情内容 */}
      </main>
    </ViewTransition>
  );
}
```

包装器要放在每个页面里，不能放 layout。布局在导航之间是持续的，`enter` 与 `exit` 永远不会触发。

浏览器自带的前进后退按钮和手势不带过渡类型，所以这条规则只管站内链接。但同名元素的配对仍然生效，用户按后退时照样看到 morph。

过渡类型是数组，可以一次传多个。需要区分来源时，在数组里加一个自定义值，CSS 里按类名分开写动画。值本身没有限制，只要两端约定一致。

用 `useRouter().push()` 跳转时，类型作为第二个参数传进去。表单提交后跳转、操作成功后跳转这类场景用得上。

## 37.5 固定元素与点击

页头、侧栏这类跨页面持续的元素，默认会被当成进出内容一起做动画，看起来像在闪。

```tsx
// src/app/(app)/layout.tsx
<header style={{ viewTransitionName: "site-header" }} className="border-b border-neutral-200">
  {/* 页头 */}
</header>
```

```css
/* src/app/globals.css */
::view-transition-group(site-header) {
  animation: none;
  z-index: 100;
}

::view-transition-old(site-header) {
  display: none;
}

::view-transition-new(site-header) {
  animation: none;
}
```

旧快照 `display: none` 是关键。少了这一行，过渡期间新旧两份页头会同时出现，视觉上闪一下。

过渡期间浏览器会在最上层覆盖一层伪元素，所有点击都被它吃掉。加一行放开：

```css
/* src/app/globals.css */
::view-transition {
  pointer-events: none;
}
```

命名过的元素在过渡期间仍不参与点击命中，所以过渡要短。给高频点击的按钮起过渡名，用户会觉得点了没反应。

过渡时长控制在 400 毫秒以内。超过这个数，用户开始感觉在等动画。列表与详情之间的 morph 用 300 到 400 毫秒，页面整体切换用 200 到 300 毫秒。

过渡不会改变布局。它移动的是快照，最终位置仍由文档流决定。所以过渡期间看到的位移，必须与过渡结束后的位置一致，否则会看到元素“弹”一下。

系统开启“减少动态效果”时要把动画关掉：

```css
/* src/app/globals.css */
@media (prefers-reduced-motion: reduce) {
  ::view-transition-old(*),
  ::view-transition-new(*),
  ::view-transition-group(*) {
    animation-duration: 0s !important;
    animation-delay: 0s !important;
  }
}
```

## 37.6 Suspense 区域的进出

数据加载完成时，骨架换成内容。给两段分别声明动画，进出就不会突兀。

```tsx
// src/app/(app)/files/[id]/page.tsx
<Suspense
  fallback={
    <ViewTransition exit="slide-down" default="none">
      <FileSkeleton />
    </ViewTransition>
  }
>
  <ViewTransition enter="slide-up" default="none">
    <FileDetail id={id} />
  </ViewTransition>
</Suspense>
```

```css
/* src/app/globals.css */
::view-transition-old(.slide-down) {
  animation: 150ms ease-out both fade;
}

::view-transition-new(.slide-up) {
  animation: 210ms ease-in 150ms both fade, 400ms ease-in both slide-y;
}

@keyframes fade {
  from {
    opacity: 0;
    filter: blur(3px);
  }
}

@keyframes slide-y {
  from {
    translate: 0 10px;
  }
}
```

两段时长故意不对称。旧内容 150 毫秒退场，新内容延迟 150 毫秒再进场，中间没有重叠，视觉上是一个接一个。

## 37.7 视频

视频是页面里最重的资源，而且不走图片优化管线。`next/image` 处理的是静态图片：它转格式、按尺寸生成多份、加缓存头。`<video>` 与 `<iframe>` 都不在这条管线里。

自托管视频的写法：

```tsx
// src/app/(app)/files/[id]/file-video.tsx
export function FileVideo({ src, poster, captions }: { src: string; poster: string; captions: string }) {
  return (
    <video
      width={960}
      height={540}
      poster={poster}
      controls
      preload="none"
      playsInline
      className="w-full rounded-lg"
    >
      <source src={src} type="video/mp4" />
      <track src={captions} kind="subtitles" srcLang="zh" label="中文" default />
      你的浏览器不支持 video 标签。
    </video>
  );
}
```

`preload="none"` 让浏览器不主动下载视频内容，只取海报。首屏因此不会被几十兆的视频拖住。`width` 与 `height` 要给，浏览器据此预留盒子，避免加载后页面跳动。

海报图本身可以走 `next/image`。它是静态图片，按尺寸生成多份，格式也能自动转。视频封面常常是页面上最大的一张图，优化它收益明显。

视频文件放对象存储，不放数据库。表里只记一条 `files` 记录，指向存储路径，播放地址由服务端签名后下发。这样换存储供应商时不用动业务表。

字幕用 WebVTT 文件：

```text
-- public/captions/file-video-zh.vtt
WEBVTT

00:00:00.000 --> 00:00:03.000
这是第一段字幕

00:00:03.000 --> 00:00:06.500
第二段字幕
```

自动播放要同时满足 `muted` 与 `playsInline`。iOS 上缺了 `playsInline`，视频会全屏接管。即便如此，各浏览器的自动播放策略仍会拦截带声音的播放，所以自动播放只适合静音背景视频。

一段 1 分钟、1080p 的 MP4 通常在 20 MB 到 60 MB 之间。同样画面换编码，体积能差两三倍。编码换来的是编码时间与浏览器支持面的取舍，团队内部视频用 H.264 就够，公开站点再考虑多码率。

平台托管的视频用 `<iframe>`。三项必备：`title`（读屏软件靠它说明这块内容）、宽高或宽高比（否则盒子塌陷）、`loading="lazy"`（首屏不加载）。

```tsx
// src/components/youtube-embed.tsx
export function YouTubeEmbed({ videoId, title }: { videoId: string; title: string }) {
  return (
    <iframe
      src={`https://www.youtube-nocookie.com/embed/${videoId}`}
      title={title}
      loading="lazy"
      allow="accelerometer; clipboard-write; encrypted-media; gyroscope; picture-in-picture"
      allowFullScreen
      className="aspect-video w-full rounded-lg border border-neutral-200"
    />
  );
}
```

`youtube-nocookie.com` 是 YouTube 的隐私增强域名，按 YouTube 的说明它不在浏览器里写入跟踪 cookie，具体行为以平台文档为准。对外站点用它更稳妥。

嵌入第三方 iframe 会让 CSP 里的 `frame-src` 拦截。报错原文：

```text
Refused to frame 'https://www.youtube.com/' because it violates the following Content Security Policy directive: "frame-src 'self'".
```

把域名加进 `frame-src` 即可。改完先在 report-only 模式下观察一段时间，确认没有漏配再切到强制模式。

## 37.8 草稿预览要解决的问题

已发布的文章与草稿存在同一张表里。普通访客只能看到 `status = 'published'` 的行，编辑需要在发布前看到草稿渲染出来的样子。

缓存让这件事变复杂。页面可能是静态预渲染的，数据可能来自 `'use cache'` 结果，`fetch` 结果可能被缓存过。编辑器改完稿刷新页面，看到的是缓存版本。

`draftMode()` 提供一条会话级通道。开启之后，当前浏览器的后续请求绕过所有缓存层，直接读上游数据；其他访客继续看缓存版本。

四条绕过行为如下。`fetch()` 跳过 Next.js 的 fetch 缓存，直接请求上游。`'use cache'` 函数每次请求重新执行，结果不写缓存。`unstable_cache` 的读与写都绕过。整页响应不缓存，返回的响应头是 `Cache-Control: private, no-cache, no-store, max-age=0, must-revalidate`。

对这四种状态都生效：静态生成、缓存命中、增量再生成、按需渲染。这是它比“加个查询参数”可靠的地方：参数只能影响请求，影响不到构建产物。

`draftMode()` 是异步函数，16 里必须 `await`。返回对象里有 `isEnabled`、`enable()`、`disable()`。

读取 `isEnabled` 本身也算读取请求时数据。在布局顶层读取，整棵子树会退出静态渲染。位置要放在 Suspense 里，或者只在需要预览提示的组件里读。

## 37.9 预览入口与退出

先建表。这是本章新增的一张最小表，其他章节不依赖它。

```sql
-- supabase/migrations/20261127090000_posts.sql
create table public.posts (
  id uuid primary key default gen_random_uuid(),
  slug text not null unique,
  title text not null,
  body text not null,
  status text not null default 'draft' check (status in ('draft', 'published')),
  author_id uuid not null references public.profiles (id) on delete cascade,
  published_at timestamptz,
  created_at timestamptz not null default now()
);

alter table public.posts enable row level security;

create policy "published posts are readable by everyone"
  on public.posts for select
  using (status = 'published');

create policy "authors can read their own drafts"
  on public.posts for select
  using (auth.uid() = author_id);

create index posts_status_published_at_idx on public.posts (status, published_at desc);
```

入口是一个 Route Handler。它校验共享密钥，再校验 slug 在库里存在，然后开启草稿模式并跳转。

```ts
// src/app/api/draft/route.ts
import { draftMode } from "next/headers";
import { redirect } from "next/navigation";
import { getPostBySlug } from "@/lib/posts";

export async function GET(request: Request) {
  const { searchParams } = new URL(request.url);
  const secret = searchParams.get("secret");
  const slug = searchParams.get("slug");

  if (secret !== process.env.DRAFT_SECRET || !slug) {
    return new Response("Invalid token", { status: 401 });
  }

  const post = await getPostBySlug(slug);
  if (!post) {
    return new Response("Invalid slug", { status: 401 });
  }

  const draft = await draftMode();
  draft.enable();
  redirect(post.slug);
}
```

校验顺序有讲究。密钥先校验，slug 后校验，避免未授权的人探测哪些 slug 存在。

`redirect()` 用的是从数据库查到的 slug。查询参数里的值只用于校验，直接拿它跳转会让攻击者构造任意地址。

开启之后，页面代码不需要任何改动。缓存被绕过，正常的查询就能读到草稿。

cookie 名为 `__prerender_bypass`，由框架写入。它存在当前浏览器里，换浏览器或清掉 cookie 就失效。所以预览是给具体某个人的通道，不能当公开开关用。

退出用 Server Action，不用 `<Link>`：

```tsx
// src/app/preview-banner.tsx
import { draftMode } from "next/headers";
import { redirect } from "next/navigation";

async function exitPreview() {
  "use server";
  const draft = await draftMode();
  draft.disable();
  redirect("/");
}

export async function PreviewBanner() {
  const { isEnabled } = await draftMode();
  if (!isEnabled) return null;

  return (
    <aside role="status" className="bg-amber-50 px-4 py-2 text-sm text-amber-900">
      正在预览草稿。
      <form action={exitPreview} className="inline">
        <button type="submit" className="ml-2 underline">
          退出预览
        </button>
      </form>
    </aside>
  );
}
```

`<Link>` 会预取链接地址，预取请求带着当前的草稿 cookie，可能在用户点之前就把 cookie 清掉。表单不会被预取，所以退出必须用表单或 POST 请求。

同一个原因让入口用 GET 有点别扭。GET 本该只读，而这里改变了后续请求的状态。入口用 GET 是因为内容管理系统要在新标签页打开地址。退出这条路径用 Server Action，符合“改变状态用 POST”的原则。

密钥放在环境变量里，不写进代码。内容管理系统那边的预览地址配置也要用环境变量，两边指向同一个值。换密钥时两边一起换，否则预览会返回 401。

401 只回一句 `Invalid token`，不区分密钥错还是 slug 错。区分开来会让人能探测哪些 slug 存在。排查自己在调试时，先确认环境变量加载了，再看 slug 拼写。

`enable()` 与 `disable()` 不能写在缓存作用域里。放在 `'use cache'` 函数里调用会报错，原因是缓存函数的结果要可复用，而开启草稿的结果只对当前会话有效。

预览状态与缓存状态是两套独立机制。缓存决定“要不要重新算”，草稿模式决定“算的时候读哪一份数据、要不要写回缓存”。理解这点，就不会去缓存函数里调 `enable()`。

## 37.10 取数时的分支

存储层有两套数据源时，按 `isEnabled` 分支：

```ts
// src/lib/posts.ts
import { draftMode } from "next/headers";
import { createClient } from "@/lib/supabase/server";

export async function getPostBySlug(slug: string) {
  const { isEnabled } = await draftMode();
  const supabase = await createClient();

  const query = supabase.from("posts").select("*").eq("slug", slug);
  const { data, error } = isEnabled ? await query.single() : await query.eq("status", "published").single();

  if (error) return null;
  return data;
}
```

预览分支少一个 `status` 过滤，其余逻辑相同。缓存绕过对两个分支都生效，分支只决定查哪一份数据。

行级安全策略仍然生效。草稿模式绕过的是 Next.js 的缓存，绕不过数据库。作者能读到自己的草稿，靠的是 `posts` 表上那条 `auth.uid() = author_id` 策略。少了它，预览分支会返回空结果。

这个组合有个好处：即使 `DRAFT_SECRET` 泄露，别人也只能看到自己有权限的行。密钥管的是“能不能进预览”，RLS 管的是“能看到哪些行”。

页面里读取预览状态可以放在 `'use cache'` 作用域里：

```tsx
// src/app/(marketing)/blog/[slug]/post-content.tsx
import { draftMode } from "next/headers";
import { getPostBySlug } from "@/lib/posts";

export async function PostContent({ slug }: { slug: string }) {
  "use cache";
  const { isEnabled } = await draftMode();
  const post = await getPostBySlug(slug);

  return (
    <article className="prose">
      {isEnabled ? <p role="status">草稿预览</p> : null}
      <h1>{post.title}</h1>
      <p>{post.body}</p>
    </article>
  );
}
```

草稿会话里这个函数每次请求都重跑，预览提示随之出现。普通访客的请求复用缓存结果，提示不渲染。

预览状态也可以传给客户端组件，用于显示返回栏或禁用发布按钮。传递的值必须是布尔量，不要传整个 `draftMode()` 对象，那个对象不可序列化。

## 37.11 Pages Router 的对照

同一个需求在 Pages Router 里的接口不同。

| 项目 | App Router | Pages Router |
| --- | --- | --- |
| 开启 | `draftMode().enable()` | `res.setPreviewData({})` |
| 关闭 | `draftMode().disable()` | `res.clearPreviewData()` |
| 读取状态 | `const { isEnabled } = await draftMode()` | `context.preview` |
| 携带的数据 | 无 | `context.previewData` |
| 生效范围 | 静态生成、缓存、增量再生成全部绕过 | 静态生成改为请求时执行 |

Pages Router 里这些操作只能在 API Route 里做，因为需要 `res` 对象。App Router 里对应的位置是 Route Handler 与 Server Action。

迁移时保留行为，不保留写法。两套 API 都能让编辑看到草稿，差别在 App Router 把状态放进了请求上下文，不再依赖响应对象。

## 37.12 用 MDX 写一页

变更日志这类内容适合用 Markdown 写。MDX 在 Markdown 上加了组件能力。

安装：

```bash
pnpm add @next/mdx @mdx-js/loader @mdx-js/react @types/mdx
```

```ts
// next.config.ts
import createMDX from "@next/mdx";
import type { NextConfig } from "next";

const nextConfig: NextConfig = {
  pageExtensions: ["js", "jsx", "md", "mdx", "ts", "tsx"],
};

const withMDX = createMDX({});

export default withMDX(nextConfig);
```

`pageExtensions` 要加上 `md` 与 `mdx`，否则文件不会被当作路由。默认只编译 `.mdx`，要编译 `.md` 得传 `extension: /\.(md|mdx)$/`。

App Router 下必须有 `mdx-components.tsx`，缺了它构建直接失败。

```tsx
// src/mdx-components.tsx
import type { MDXComponents } from "mdx/types";

const components: MDXComponents = {
  h2: (props) => <h2 className="mt-8 text-xl font-semibold" {...props} />,
  a: (props) => <a className="underline" {...props} />,
};

export function useMDXComponents(): MDXComponents {
  return components;
}
```

文件放在 `src/` 下，与 `app` 同级。

页面文件本身就是内容：

```mdx
{/* src/app/changelog/page.mdx */}
# 变更日志

## 2024 年 3 月

- 团队设置支持批量导入成员
- 文件列表支持按修改时间排序

## 2024 年 2 月

- 新增邀请链接过期时间设置
```

`app/changelog/page.mdx` 对应 `/changelog`，frontmatter 可选，组件映射由 `mdx-components.tsx` 提供。

MDX 适合内容为主的页面，不适合需要取数的页面，因为文件里写不了异步函数。要读数据库的页面用 `.tsx`，只放文档的页面用 `.mdx`，两种可以共存。

正文排版可以交给 `@tailwindcss/typography` 的 `prose` 类，省去逐个元素写样式。表格与代码块在 `prose` 下已经有基本样式，只有在需要品牌色时才覆盖。

用 remark 与 rehype 插件时，Turbopack 要求配置写成字符串，函数无法传给编译器：

```ts
// next.config.ts
const withMDX = createMDX({
  options: {
    remarkPlugins: ["remark-gfm", ["remark-toc", { heading: "目录" }]],
    rehypePlugins: ["rehype-slug"],
  },
});
```

带不可序列化选项的插件当前不支持。遇到这类插件，改成在提交前预处理，或者换一个纯字符串配置的插件。

## 37.13 边界与失败模式

**未验证**：本章的过渡表现、`curl` 状态码与视频请求时序来自官方文档与推算，本地没有可运行的实例逐条执行。

视图过渡在不同浏览器里的表现不完全一致。Safari 的部分动画会略快或略慢，Firefox 对 `view-transition-class` 的支持较新。功能不受影响，验收时按“有没有动画”判断，不按“动画是否逐帧一致”判断。

动画的帧率在部分设备上不稳定。低端安卓机上，全页过渡常常掉到 30 帧。遇到这种情况，把过渡范围缩小到个别元素，比关掉整个特性更合适。

过渡期间页面不能滚动。浏览器在过渡时会固定滚动位置，长页面从列表底部导航到详情顶部时体验会突变。做法是导航前滚到目标位置，或者只给首屏元素加过渡名。

**未验证**：`__prerender_bypass` 是否带 `httpOnly` 属性，官方文档没有写明。无论它是否可读，前端都不要靠读 cookie 判断预览状态，应由服务端把 `isEnabled` 作为布尔属性传下去。

预览链接要能撤销。密钥轮换一次，所有旧链接立刻失效。内容管理系统里每次都从环境变量读当前密钥生成预览地址，不要缓存地址。

视频的 `preload` 在移动网络下会失效。部分浏览器忽略 `none`，仍然请求元数据。这种情况下首屏流量会多几百 KB，用海报加点击加载可以把这部分省掉。

`draftMode()` 在静态导出下不可用。静态导出没有请求上下文，没有地方存 `__prerender_bypass` cookie。这一章不涉及静态导出，遇到时按“不支持”处理。

预览期间不要做写操作。编辑在预览里点了“发布”，草稿模式同样绕过缓存，页面立刻变；但他自己那一份请求也被排除出缓存，其他人看不到变化，容易误判。

开启草稿模式后所有缓存都被绕过。大页面在预览时每次刷新都要重新取数，编辑会觉得慢。这是设计取舍：预览要看到最新内容，就得放弃缓存。

MDX 页面的元数据要用导出的方式声明。文件里写 `export const metadata = { title: "变更日志" }` 即可，写不了 `generateMetadata`，因为 MDX 文件本身没有函数体。

需要动态元数据时，把 MDX 当组件引入，外层用普通的 `page.tsx` 包一层。这样元数据、布局、取数都能用，MDX 只负责正文。

MDX 里的链接用普通 `<a>` 或 `<Link>`。需要在映射里统一替换成 `next/link`，否则站内链接会整页刷新，丢掉客户端状态。

## 37.14 检查点

1. 打开列表页点进详情，元素从列表位置过渡到详情位置。在 Safari 里重复一次，动画表现不同，功能正常。
2. 在设置里开启“减少动态效果”，刷新页面，导航不再有动画，页面切换照常。
3. 预览入口：`curl -s -o /dev/null -w "%{http_code}\n" "http://localhost:3000/api/draft?secret=wrong&slug=hello"` 返回 401；用正确密钥访问后，浏览器带着 `__prerender_bypass` cookie，页面上出现草稿标记。
4. 用隐身窗口打开同一篇草稿的地址，看不到草稿内容，只有 404 或已发布版本。
5. 视频所在页面的 Network 面板里，首屏没有视频文件的请求；点击播放后才出现，`preload="none"` 生效。
6. `/changelog` 由 MDX 渲染，标题层级正确，`pnpm build` 输出里该路由是静态的。

## 37.15 常见错误

1. `draftMode() should be awaited before using its properties`。 少写 `await`。16 里 `draftMode()` 返回 Promise，`const draft = await draftMode()` 之后再读 `isEnabled`。

2. `Route used draftMode() without a Suspense boundary`。 在预渲染路径上读了草稿状态。把读取放进 Suspense 边界，或者给这一页加 `loading.tsx`。

3. `Error: draftMode().enable() cannot be called inside a caching scope`。 `enable()` 写在了 `'use cache'` 函数里。把它挪到 Route Handler 或 Server Action。

4. 点“退出预览”没反应，cookie 还在。 用的是 `<Link>`，预取把 cookie 清掉了或者请求没走到 POST。改用 `<form action={...}>` 提交。

5. `Module not found: Can't resolve 'mdx/types'`。 装了 `@next/mdx` 但没装 `@types/mdx`，或者 `mdx-components.tsx` 放错位置。它要和 `app` 同级。

6. `[next-mdx] Plugin ... cannot be serialized`。 插件以函数形式传给了 Turbopack。改写成字符串形式，去掉函数与闭包选项。

## 37.16 这一章在做什么

这一章建立三条判断：视觉过渡是渐进增强，浏览器不支持时页面照常工作；视频与第三方 iframe 不走图片优化，体积要靠 `preload`、海报与点击加载控制；草稿预览是一条会话级旁路，它绕过缓存但不改变页面代码。

三条判断的验收都落在同一个地方：用两种身份访问同一个地址。编辑看到草稿，普通访客看到已发布版本，两边的 HTML 都要能独立成立。

至此第五部分结束。下一章回到路由本身，把 App Router 与 Pages Router 的接口逐项对照，方便维护老项目时迁移。
