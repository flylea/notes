# 第26章 类型编程实战

前面章节我们已经系统学习了泛型、映射类型、条件类型、`infer`、模板字符串类型等类型编程的基础武器。本章将这些武器组合起来，梳理类型编程的核心范式，并给出有实际项目价值的工具类型实现。

## 类型编程 vs 类型体操

在深入学习之前，有必要区分两个概念：

- **类型编程**：对实际开发有切实帮助的类型操作。下限很低——用个泛型就算类型编程；上限也可以很高——框架底层的复杂类型运算。
- **类型体操**：基于 TypeScript 类型系统实现四则运算、斐波那契数列、甚至 Lisp 编译器等炫技操作。它们证明了 TS 类型系统的图灵完备，但对日常业务开发的帮助有限。

本章聚焦于**类型编程**——即那些你在实际项目中真正能用上的工具类型和设计思路。你不会看到如何用类型算质数，但会学到如何写出 `DeepPartial`、`PickByValueType`、`XOR`、`CamelCase` 这些能直接提升代码质量的工具类型。

## 类型编程四大范式

类型编程虽然千变万化，但归纳起来无非四种范式：

1. **属性修饰**：对对象属性的可选性、只读性等进行深层或局部处理
2. **结构工具**：基于键名或键值类型对对象结构进行裁剪、互斥处理
3. **集合工具**：将一维的联合类型交并补差集扩展到二维的对象类型
4. **模式匹配**：通过 `infer` 从类型结构中提取目标部分，进行转换与重组

这四种范式不是互相孤立的——实际编写工具类型时，往往是多个范式的组合运用。核心心法只有一句话：**将复杂的工具类型拆解为由基础工具类型组合而成的实现**。

## 范式一：属性修饰进阶

### 深层属性修饰

内置的 `Partial`、`Required`、`Readonly` 只作用于第一层属性。借助递归，可以让它们穿透到嵌套对象：

```typescript
type DeepPartial<T extends object> = {
  [K in keyof T]?: T[K] extends object ? DeepPartial<T[K]> : T[K];
};

type DeepRequired<T extends object> = {
  [K in keyof T]-?: T[K] extends object ? DeepRequired<T[K]> : T[K];
};

type DeepReadonly<T extends object> = {
  readonly [K in keyof T]: T[K] extends object ? DeepReadonly<T[K]> : T[K];
};

type DeepMutable<T extends object> = {
  -readonly [K in keyof T]: T[K] extends object ? DeepMutable<T[K]> : T[K];
};
```

使用示例：

```typescript
interface Config {
  server: {
    host: string;
    port: number;
    tls: {
      enabled: boolean;
      certPath: string;
    };
  };
}

// 整个配置树变为可选——适合声明默认配置
type DefaultConfig = DeepPartial<Config>;

const defaults: DefaultConfig = {
  server: {
    tls: {},
  },
};
```

同样可以递归处理 `null | undefined`：

```typescript
type DeepNonNullable<T extends object> = {
  [K in keyof T]: T[K] extends object
    ? DeepNonNullable<T[K]>
    : NonNullable<T[K]>;
};
```

### 基于已知属性的部分修饰

思路同样来自"拆分-处理-组合"：使用 `Pick` 取出需要处理的部分，使用 `Omit` 取出不需要处理的部分，分别处理后通过交叉类型合并。用 `Flatten` 展平交叉类型让结果更可读：

```typescript
type Flatten<T> = { [K in keyof T]: T[K] };

type MarkPropsAsOptional<
  T extends object,
  K extends keyof T = keyof T
> = Flatten<Partial<Pick<T, K>> & Omit<T, K>>;

type MarkPropsAsRequired<
  T extends object,
  K extends keyof T = keyof T
> = Flatten<Required<Pick<T, K>> & Omit<T, K>>;

type MarkPropsAsReadonly<
  T extends object,
  K extends keyof T = keyof T
> = Flatten<Readonly<Pick<T, K>> & Omit<T, K>>;
```

使用示例——从同一个基础接口衍生出多个变体：

```typescript
interface User {
  id: number;
  name: string;
  email: string;
  createdAt: Date;
  updatedAt: Date;
}

// 创建用户：id 和日期由后端生成
type CreateUserInput = MarkPropsAsOptional<User, 'id' | 'createdAt' | 'updatedAt'>;

// 更新用户：所有业务字段可选，id 必填
type UpdateUserInput = MarkPropsAsRequired<Partial<Omit<User, 'id'>>, 'id'>;
```

## 范式二：结构工具进阶

### 基于键值类型的 Pick 与 Omit

有时需要按**值的类型**而非键名来裁剪对象，比如"提取所有函数类型的属性"。这需要分两步：先拿到符合条件的属性名，再交给 `Pick`：

```typescript
// 第一步：获取符合值类型条件的所有属性名
type ExpectedPropKeys<T extends object, ValueType> = {
  [Key in keyof T]-?: T[Key] extends ValueType ? Key : never;
}[keyof T];

// 第二步：用 Pick 组装
type PickByValueType<T extends object, ValueType> = Pick<
  T,
  ExpectedPropKeys<T, ValueType>
>;

type FilteredPropKeys<T extends object, ValueType> = {
  [Key in keyof T]-?: T[Key] extends ValueType ? never : Key;
}[keyof T];

type OmitByValueType<T extends object, ValueType> = Pick<
  T,
  FilteredPropKeys<T, ValueType>
>;
```

这里的关键技巧是 `{ [K in keyof T]: ...K : never }[keyof T]`。用映射类型构造一个"属性名 → 属性名字面量（或 never）"的中间结构，再通过 `[keyof T]` 取出所有非 never 的值，就得到了符合条件的属性名联合类型。

```typescript
interface ApiConfig {
  baseURL: string;
  timeout: number;
  retry: number;
  onError: (err: Error) => void;
  onSuccess: (data: unknown) => void;
  transform: (data: unknown) => unknown;
}

// 提取所有函数属性
type Callbacks = PickByValueType<ApiConfig, (...args: any[]) => any>;
// { onError: ...; onSuccess: ...; transform: ... }

// 排除所有函数属性
type DataFields = OmitByValueType<ApiConfig, (...args: any[]) => any>;
// { baseURL: string; timeout: number; retry: number }
```

**严格匹配版本**：由于分布式条件类型的特性，`1 | 2 extends 1 | 2 | 3` 会被视为成立。如需严格全等比较（两个联合类型完全一致才算匹配），需要双向判断：

```typescript
type StrictConditional<A, B, Resolved, Rejected, Fallback = never> = [A] extends [B]
  ? [B] extends [A]
    ? Resolved
    : Rejected
  : Fallback;
```

包裹在数组元组中可以禁用分布式条件类型，双向判断确保联合类型完全一致。

### 互斥类型（XOR）

有时需要约束一个对象"要么有属性 A，要么有属性 B，但不能同时拥有"。联合类型做不到这一点——它只要求"至少满足其中一个"：

```typescript
interface VIP {
  vipExpires: number;
}
interface CommonUser {
  promotionUsed: boolean;
}

// 联合类型允许同时拥有两个属性——这不是我们想要的
const user: VIP | CommonUser = {
  vipExpires: 599,
  promotionUsed: false, // 没有报错！
};
```

实现互斥需要用到 `never` 标记：给"不应该同时出现的属性"标上 `never` 可选类型：

```typescript
type Without<T, U> = { [P in Exclude<keyof T, keyof U>]?: never };

type XOR<T, U> = (Without<T, U> & U) | (Without<U, T> & T);
```

展开 XOR 的逻辑：
- `Without<T, U> & U`：把 T 独有的属性标为 `never`，和 U 交叉。此时对象必须有 U 的全部属性，T 独有的属性被禁止。
- `Without<U, T> & T`：同理，必须有 T 的全部属性，U 独有的属性被禁止。
- 两者取联合 → "要么全有 T 的独有属性，要么全有 U 的独有属性，不能混合"。

```typescript
type XORUser = XOR<VIP, CommonUser>;

// ✅ 只有 VIP 属性
const vipUser: XORUser = { vipExpires: 0 };

// ✅ 只有普通用户属性
const commonUser: XORUser = { promotionUsed: false };

// ❌ 不能两者都缺
// const empty: XORUser = {};

// ❌ 不能两者都有
// const both: XORUser = { vipExpires: 0, promotionUsed: false };
```

XOR 也可以嵌套处理三个互斥类型，或实现"要么同时有 A 和 B，要么都没有"的绑定效果：

```typescript
// 三个互斥
type UserRole = XOR<VIP, XOR<CommonUser, Visitor>>;

// 绑定：要么同时有 foo 和 bar，要么都没有
type Bound = XOR<{}, { foo: string; bar: number }>;
const a: Bound = {};                           // ✅
const b: Bound = { foo: 'hello', bar: 42 };    // ✅
```

## 范式三：集合工具进阶

将一维联合类型的交并补差集运算，扩展到二维对象类型：

### 属性名集合运算

```typescript
// 一维集合基础
type Intersection<A, B> = A extends B ? A : never;
type Difference<A, B> = A extends B ? never : A;
type Complement<A, B extends A> = Difference<A, B>;
```

扩展到对象属性名：

```typescript
// 属性名并集
type ObjectKeysConcurrence<T, U> = keyof T | keyof U;
// 属性名交集
type ObjectKeysIntersection<T, U> = Intersection<keyof T, keyof U>;
// 属性名差集
type ObjectKeysDifference<T, U> = Difference<keyof T, keyof U>;
```

### 对象层面的集合运算

有了属性名集合，通过 `Pick` 即可实现对象层面的交差补：

```typescript
type ObjectIntersection<T, U> = Pick<T, ObjectKeysIntersection<T, U>>;
type ObjectDifference<T, U> = Pick<T, ObjectKeysDifference<T, U>>;
type ObjectComplement<T extends U, U> = Pick<T, Complement<keyof T, keyof U>>;
```

### Merge、Assign 与 Override

两个对象合并时最核心的问题是：**同名属性的优先级**。以 `Merge<Base, Overlay>` 为例（Overlay 优先级更高）：

```typescript
// Merge: 合并两个对象的全部属性，同名属性以 U 的优先
type Merge<T extends object, U extends object> =
  ObjectDifference<T, U> &     // T 比 U 多的
  ObjectIntersection<U, T> &   // 交集中的属性以 U 为准
  ObjectDifference<U, T>;      // U 比 T 多的

// Assign: 类似 Object.assign，同名属性以 T 优先
type Assign<T extends object, U extends object> =
  ObjectDifference<T, U> &
  ObjectIntersection<T, U> &   // 交集中的属性以 T 为准
  ObjectDifference<U, T>;

// Override: 用 U 覆盖同名属性，但不引入 U 独有的新属性
type Override<T extends object, U extends object> =
  ObjectDifference<T, U> &     // T 独有的原样保留
  ObjectIntersection<U, T>;    // 同名属性被 U 覆盖
```

三者区别：

| 工具类型 | T 独有 | 同名属性 | U 独有 |
|---------|--------|---------|--------|
| `Merge<T, U>` | 保留 | U 优先 | 保留 |
| `Assign<T, U>` | 保留 | T 优先 | 保留 |
| `Override<T, U>` | 保留 | U 优先 | 丢弃 |

使用场景：

```typescript
interface Theme {
  colors: { primary: string; secondary: string };
  fontSizes: { small: string; large: string };
}

interface UserTheme {
  colors: { primary: string };
}

// 用户自定义主题覆盖默认，但只覆盖声明的部分
type FinalTheme = Override<Theme, UserTheme>;
```

## 范式四：模式匹配进阶

### 函数参数提取

通过 `infer` 提取函数的各类参数信息：

```typescript
type FunctionType = (...args: any) => any;

// 提取第一个参数
type FirstParameter<T extends FunctionType> = T extends (
  arg: infer P,
  ...args: any
) => any
  ? P
  : never;

// 提取最后一个参数（嵌套 infer）
type LastParameter<T extends FunctionType> = T extends (arg: infer P) => any
  ? P
  : T extends (...args: infer R) => any
  ? R extends [...any, infer Q]
    ? Q
    : never
  : never;
```

`LastParameter` 的套路：先用 `...args: infer R` 拿到完整的参数元组，再对元组做模式匹配提取最后一项。这种"先拿整体结构，再从中匹配细节"的嵌套 infer 模式非常常用。

### Awaited 的严谨实现

TypeScript 内置的 `Awaited` 类型并非简单地 `Promise<infer V>`，而是通过 then 方法签名来做更深层的提取：

```typescript
type Awaited<T> =
  T extends null | undefined
    ? T
    : T extends object & { then(onfulfilled: infer F): any }
    ? F extends (value: infer V, ...args: any) => any
      ? Awaited<V>
      : never
    : T;
```

这个实现能正确处理自定义 thenable 对象，而不仅仅是标准的 `Promise<T>`。两次 `infer`——先从 `then` 提取回调函数类型，再从回调函数提取值类型——也是模式匹配中"层层递进"的经典手法。

### 模板字符串类型实战

模板字符串类型与模式匹配结合，可以在类型层面实现字符串的各类操作。

**Trim**——递归去除两侧空格：

```typescript
type TrimLeft<Str extends string> = Str extends ` ${infer R}` ? TrimLeft<R> : Str;
type TrimRight<Str extends string> = Str extends `${infer R} ` ? TrimRight<R> : Str;
type Trim<Str extends string> = TrimLeft<TrimRight<Str>>;
```

**Include**——判断字符串是否包含子串：

```typescript
type _Include<Str extends string, Search extends string> =
  Str extends `${infer _}${Search}${infer _}` ? true : false;

type Include<Str extends string, Search extends string> = Str extends ''
  ? Search extends '' ? true : false
  : _Include<Str, Search>;
```

**Replace 与 ReplaceAll**——类型层面的字符串替换：

```typescript
type Replace<
  Str extends string,
  Search extends string,
  Replacement extends string
> = Str extends `${infer Head}${Search}${infer Tail}`
  ? `${Head}${Replacement}${Tail}`
  : Str;

type ReplaceAll<
  Str extends string,
  Search extends string,
  Replacement extends string
> = Str extends `${infer Head}${Search}${infer Tail}`
  ? ReplaceAll<`${Head}${Replacement}${Tail}`, Search, Replacement>
  : Str;
```

**Split**——按分隔符拆分字符串为元组：

```typescript
type Split<
  Str extends string,
  Delimiter extends string
> = Str extends `${infer Head}${Delimiter}${infer Tail}`
  ? [Head, ...Split<Tail, Delimiter>]
  : Str extends Delimiter
  ? []
  : [Str];

// 使用
type Parts = Split<'2024-01-15', '-'>; // ["2024", "01", "15"]
type Chars = Split<'hello', ''>;        // ["h", "e", "l", "l", "o"]
```

利用 Split 还能获取字符串长度：

```typescript
type StrLength<T extends string> = Split<Trim<T>, ''>['length'];
type Len = StrLength<'hello world'>; // 11
```

**Join**——将字符串数组按分隔符合并：

```typescript
type Join<
  List extends Array<string | number>,
  Delimiter extends string
> = List extends []
  ? ''
  : List extends [string | number]
  ? `${List[0]}`
  : List extends [string | number, ...infer Rest]
  ? `${List[0]}${Delimiter}${Join<Rest, Delimiter>}`
  : string;

type Path = Join<['api', 'v1', 'users'], '/'>; // "api/v1/users"
```

注意 Join 需要处理空数组和单元素数组两种边界情况，否则递归会在末尾多出一个分隔符。

**CamelCase**——将下划线/中划线/空格分隔的字符串转为小驼峰：

```typescript
type WordSeparators = '-' | '_' | ' ';

type CapitalizeStringArray<Words extends any[]> = Words extends [
  `${infer First}`,
  ...infer Rest
]
  ? `${Capitalize<First>}${CapitalizeStringArray<Rest>}`
  : '';

type CamelCaseStringArray<Words extends string[]> = Words extends [
  `${infer First}`,
  ...infer Rest
]
  ? `${First}${CapitalizeStringArray<Rest>}`
  : never;

type CamelCase<K extends string> = CamelCaseStringArray<
  Split<K, WordSeparators>
>;

// 验证
type T1 = CamelCase<'foo_bar_baz'>; // "fooBarBaz"
type T2 = CamelCase<'foo-bar-baz'>; // "fooBarBaz"
type T3 = CamelCase<'foo bar baz'>; // "fooBarBaz"
```

实现思路：先 `Split` 拆成单词数组，首单词保留原样，其余单词用 `Capitalize` 转为首字母大写，最后拼回去。

结合映射类型的 `as` 子句，还可以将整个对象的键名批量转为 CamelCase：

```typescript
type CamelCasedProperties<T extends object> = {
  [K in keyof T as CamelCase<string & K>]: T[K] extends object
    ? CamelCasedProperties<T[K]>
    : T[K];
};

// { foo_bar: string; foo_baz: { nested_foo: number } }
//   → { fooBar: string; fooBaz: { nestedFoo: number } }
```

## 实战心法总结

### 1. 拆分-处理-组合

这是类型编程中最核心的思维模型。面对复杂需求时，先思考能否将其拆分为独立的部分，每个部分用基础工具类型解决，最后再组合回来。

```
需要：将对象的某些属性标记为只读
  → 拆分：Pick 这些属性 + Omit 其余属性
  → 处理：Readonly 包裹 Pick 的结果
  → 组合：交叉类型 + Flatten 展平
```

### 2. 降维打击

把高维问题降维到已知的低维解法。例如对象集合的交并补差——降到属性名的联合类型交并补差，再通过 `Pick` 回到对象层面。

### 3. 递归是"穿透"的法宝

无论是深层的属性修饰，还是 `ReplaceAll` 这种需要重复操作的工具类型，递归是不二法门。写递归类型时注意终态条件——即什么时候停止递归。

### 4. 边界情况决定"能用"到"好用"

`Join` 因为空数组和单元素数组处理不当，连写了三版才正确。`Include` 和 `StartsWith` 对空字符串需要特殊对待。一个工具类型从"大概能跑"到"生产可用"，往往是被这些边界情况决定的。

## 本章小结

- **类型编程四大范式**：属性修饰、结构工具、集合工具、模式匹配——它们不是孤立的，实际工具类型往往组合使用
- **核心思维**：拆分-处理-组合，降维打击，递归穿透，边界补全
- **深层属性修饰**：借助递归实现 `DeepPartial`、`DeepRequired`、`DeepReadonly`
- **部分属性修饰**：`MarkPropsAsOptional/Required/Readonly` 使用 Pick + Omit + 交叉类型的组合模式
- **基于值类型的裁剪**：`PickByValueType` / `OmitByValueType` 通过 `{ [K in keyof T]: ...K : never }[keyof T]` 模式收集符合条件的键名
- **互斥类型 XOR**：使用 never 标记禁止属性同时出现，适用于"二选一"的接口设计
- **对象集合运算**：Merge（全合并+覆盖）、Assign（全合并+保留）、Over​​ride（只覆盖不新增）
- **模式匹配进阶**：嵌套 infer 实现 `LastParameter`，通过 then 签名实现严谨的 `Awaited`
- **模板字符串实战**：`Trim`、`Include`、`Replace`、`Split`、`Join`、`CamelCase`——在类型层面实现字符串操作
