# 第 11 章 类型别名与工具类型入门

同一个对象形状在五个文件里重复定义五遍，改一个字段要改五处。`type` 给类型表达式起名字，工具类型是内置的类型函数。这一章讲 `type` 的用法与边界，工具类型只介绍最常用的三个，完整内容在第 20 章。

一句话：`type` 是给类型表达式起的外号，`interface` 是登记在册的类型节点。

`type Id = string` 之后，`Id` 和 `string` 在检查器眼里是同一个东西，没有新类型。`interface Article {}` 则真的多了一个可被合并、可被继承的符号。

外号不能直接指回自己，`type Loop = Loop` 报 TS2456；登记过的类型可以声明合并，两份 `interface Article` 会自动并起来。

## 类型别名：给类型起个名字

### 基本语法

```typescript
type ArticleId = string;
```

别名和原类型是同一个类型，编译后没有痕迹（[TypeScript Handbook：Everyday Types](https://www.typescriptlang.org/docs/handbook/2/everyday-types.html)）：

```typescript
type ArticleId = string;

function loadArticle(id: ArticleId): void {}

const rawId: string = "a-1";
loadArticle(rawId);
```

`ArticleId` 在类型检查里就是 `string`，别名不参与运行时。

### type 能表达什么

`type` 可以给任意类型表达式命名：

```typescript
type ID = string | number;
type Status = "draft" | "published" | "archived";
type Point = [number, number];
type Options = { retries: number; timeout: number };
type Handler = (value: string) => void;
type Author = { name: string } & { email: string };
```

联合类型、元组和基本类型别名只能用 `type` 声明。

### 泛型类型别名

别名可以带类型参数和默认值：

```typescript
type Article = { id: number; title: string };

type Page<T> = {
  items: T[];
  total: number;
};

type ArticlePage = Page<Article>;

type Result<T, E = Error> =
  | { ok: true; data: T }
  | { ok: false; error: E };
```

`Page` 可以复用到任何列表场景，`Result` 的 `E` 不传时默认是 `Error`。

### 类型别名与 interface

| 能力 | `type` | `interface` |
|---|---|---|
| 描述对象结构 | 支持 | 支持 |
| 同名声明合并 | 不支持 | 支持 |
| 表示联合、元组 | 支持 | 不支持 |
| 作为基本类型别名 | 支持 | 不支持 |
| 表示映射类型、条件类型 | 支持 | 不支持 |
| 扩展方式 | `&` 交叉类型 | `extends` |

对外暴露的对象结构用 `interface`，需要联合、映射或条件类型时用 `type`。

### 别名是展开，interface 是符号

`type A = { id: string }` 不造新类型，只记下“A 指向这段类型表达式”。用到 A 时检查器先展开再比较，泛型别名按实参实例化（`getDeclaredTypeOfTypeAlias` 在 `src/compiler/checker.ts` 13500 行，`getTypeAliasInstantiation` 在 17027 行）。所以 A 和 `{ id: string }` 完全等价。

别名不能直接指向自己，`type Loop = Loop` 报 TS2456（13529 行）。循环必须经过对象、数组、元组这类会延迟求值的容器，`type Json = string | number | Json[]` 才成立。

interface 在绑定阶段登记成符号，同名声明合并进同一个符号，声明类型算一次后缓存在符号上。这是 interface 能声明合并、type 不能的原因。反过来说，让别名也合并会与展开模型冲突：两处 `type A` 的右值都要参与展开，条件类型和映射类型就没有稳定的缓存键了。这一点没有官方文档明说，属于从实现推出的判断。

差别在报错和性能上也能看到。用 type 时错误信息默认显示别名本身，展开后的结构要悬停才看得到；检查器比较的仍是展开结果，两个结构相同的别名互相赋值不会报错。interface 继承在检查时直接比较成员是否兼容，还会命中类型关系缓存，项目大了以后差异会累积（ch12 讲过交叉类型的同类问题）。

反过来说，想让别名支持声明合并是做不到的。合并要求同一符号下挂多份声明，而别名在展开阶段就被替换掉，没有可挂的声明位置。

### import type 与 export type

```typescript
import type { Article } from "./article";
import { render } from "./render";
import type { Props } from "./render";

export type { Article };
```

这三行分别标记类型导入和类型导出（[TypeScript 3.8 发布说明](https://www.typescriptlang.org/docs/handbook/release-notes/typescript-3-8.html) 的 Type-Only Imports and Export）。它们编译后完全擦除，`isolatedModules` 下的单文件编译器要求类型导入这样写。

## 工具类型：先认识三个

工具类型是 TypeScript 自带的类型函数。完整清单、实现原理和边界在第 20 章，这里用同一份 `Article` 看最常用的三个：

```typescript
type Article = {
  id: number;
  title: string;
  body: string;
  authorId: number;
};

type DraftArticle = Partial<Article>;                 // 全部属性可选
type ArticleSummary = Pick<Article, "id" | "title">;  // 只保留两个字段
type PublicArticle = Omit<Article, "authorId">;        // 去掉一个字段
```

`DraftArticle` 适合编辑草稿，`ArticleSummary` 适合列表卡片，`PublicArticle` 适合对外返回。

其余工具类型，包括 `Required`、`Readonly`、`Record`、`Exclude`、`Extract`、`NonNullable`、`ReturnType`、`Parameters`、`Awaited`，见[第 20 章 内置工具类型](20-内置工具类型完全指南.md)。它们的底层依赖映射类型（第 15 章）与条件类型（第 16 章）。

### 别名的三个报错

```ts
type Loop = Loop;

type Dup = { id: string };
type Dup = { name: string };

type Box<T> = { value: T };
const box: Box = { value: 1 };
```

```text
alias.ts(1,6): error TS2456: Type alias 'Loop' circularly references itself.
alias.ts(3,6): error TS2300: Duplicate identifier 'Dup'.
alias.ts(4,6): error TS2300: Duplicate identifier 'Dup'.
alias.ts(7,12): error TS2314: Generic type 'Box' requires 1 type argument(s).
```

TS2456 说别名直接或间接指向了自己；把递归包进对象、数组或元组，让求值延后一层。

TS2300 说同名类型别名重复声明，type 不支持合并；要合并语义就改成 interface，否则删掉一份。

TS2314 说泛型别名要求传入类型参数数量对得上；写成 `Box<number>`，或者在声明处给默认值 `type Box<T = unknown>`。

TS2456 和 TS2314 只在别名上出现，interface 遇到同名重复走的是合并，不会报 TS2300。判断用哪个：要合并或要被 class 实现就选 interface，要联合、元组、条件类型或映射类型就选 type。

## 小结

- `type` 给任意类型表达式命名，支持泛型、联合、元组和条件类型。
- 别名不创建新类型，只是同一个类型的另一个名字。
- 与 `interface` 的差别集中在声明合并、扩展方式和可表达的类型范围。
- `import type` 与 `export type` 标记纯类型导入导出，编译后不留代码。
- 工具类型的完整内容在第 20 章，这里只演示了 `Partial`、`Pick`、`Omit`。

## 用不上的时候

### 需要扩展与声明合并

同名 interface 会自动合并，类型别名不会。给第三方库补类型时，interface 更合适。

### 工具类型只处理一层

`Partial<T>`、`Pick<T, K>` 都是浅层的。嵌套对象要自己递归，见第 15 章。

### 别名套别名

`type A = B`、`type B = C` 连续几层后，报错信息里只剩最外层名字，排查变难。
