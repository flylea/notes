# 第11章 类型别名与工具类型入门

假设你有一个 `User` 类型：

```typescript
interface User {
  id: number;
  name: string;
  email: string;
  password: string;
  createdAt: Date;
}
```

现在你需要一个"更新用户"的表单类型——`id` 和 `createdAt` 不应该出现，`password` 也不该在这里更新，而且所有字段都应该是可选的。

你当然可以手写：

```typescript
interface UpdateUserForm {
  name?: string;
  email?: string;
}
```

但这意味着每次 `User` 新增字段，你都要手动同步 `UpdateUserForm`。有没有办法让 TypeScript **自动**从 `User` 推导出这个类型？

这就是本章的主题：**类型别名** 让你给类型命名，**工具类型** 让你在已有类型上做变换。它们是 TypeScript 类型编程的起手式。

## 类型别名——给类型起名字

### 基本语法

```typescript
type 类型名 = 类型表达式;
```

类型别名不创造新类型——它只是一个引用，在编译器眼里别名和原类型是同一个东西：

```typescript
type UserId = string;

function getUser(id: UserId) {}

const id: string = "abc";
getUser(id);  // ✅ UserId 和 string 完全兼容
```

### type 能表达什么

`type` 几乎是 TypeScript 中最全能的声明方式——它可以给任意类型表达式取名字：

```typescript
// 基本类型别名
type ID = string;

// 联合类型
type Status = "loading" | "success" | "error";

// 元组
type Point2D = [number, number];

// 对象类型
type Config = { url: string; timeout: number };

// 函数签名
type Callback = (data: string) => void;

// 交叉类型
type User = { name: string } & { age: number };
```

`interface` 也能描述对象和函数结构，但**联合类型、基本类型别名、元组**是 `type` 独有的。

### 泛型类型别名

类型别名可以带泛型参数，让你写一次结构、适配多种类型：

```typescript
type Response<T> = {
  code: number;
  data: T;
  message: string;
};

type UserResponse = Response<User>;    // data 是 User
type ListResponse = Response<string[]>; // data 是 string[]

// 多泛型 + 默认值
type Result<T, E = Error> =
  | { success: true; data: T }
  | { success: false; error: E };
```

### 类型别名 vs interface

| | `type` | `interface` |
|---|---|---|
| 描述对象结构 | ✅ | ✅ |
| 同名自动合并 | ❌ | ✅ |
| 联合类型 | ✅ | ❌ |
| 基本类型别名 | ✅ | ❌ |
| 映射类型 / 条件类型 | ✅ | ❌ |
| 继承 | `&` 交叉类型 | `extends` |

工程上的共识：**描述对象对外暴露的结构用 `interface`，做类型计算和变换用 `type`**。

### import type / export type

从 TypeScript 3.8 开始，你可以明确标记"这个导入/导出仅用于类型"：

```typescript
// 类型导入——编译后完全擦除，不产生任何 JS 代码
import type { User, Config } from "./types";

// 值导入和类型导入分开
import { useEffect } from "react";
import type { ChangeEvent, ReactNode } from "react";

// 类型导出
export type { User, Config };
```

`import type` 的好处：
- **编译后零痕迹**——不会出现在 JS 输出中，避免潜在的循环依赖问题
- **编辑器中可区分**——一眼看出哪些导入是类型、哪些是运行时的值
- **配合 `isolatedModules`**——单文件编译工具（如 esbuild、Babel）要求类型导入显式标记

## 工具类型——像搭积木一样组合类型

回到开头的需求：从 `User` 推导出 `UpdateUserForm`。解决方案是工具类型的组合：

```typescript
type UpdateUserForm = Partial<Omit<User, "id" | "createdAt" | "password">>;
// { name?: string; email?: string; }
```

这一行代码的含义是：**先把 `id`、`createdAt`、`password` 排除掉，再把剩余的属性全部变为可选**。以后 `User` 新增了 `bio` 字段，`UpdateUserForm` 会自动包含 `bio?: string`。

TypeScript 内置了 20+ 个这样的工具类型。它们不需要死记——只要理解每种工具类型**解决什么问题**，用的时候查就行。下面按使用场景分组。

---

## 场景一：只想改对象属性的可选/只读性

### Partial\<T\>——全部变可选

你的 API 有一个"部分更新"接口——用户可能只传 `name`，也可能只传 `email`：

```typescript
interface User {
  name: string;
  age: number;
  email: string;
}

declare function updateUser(id: number, changes: Partial<User>): void;

updateUser(1, { age: 26 });  // ✅ 只更新年龄
updateUser(1, {});            // ✅ 什么都不更新
```

`Partial` 的实现本质是映射类型，给每个属性加 `?`：

```typescript
// type Partial<T> = { [K in keyof T]?: T[K] }
```

### Required\<T\>——全部变必选

`Partial` 的反向操作。当你从配置文件读取选项时，可能某些字段是可选的，但初始化后必须完整：

```typescript
interface Config {
  url: string;
  method?: string;
  timeout?: number;
}

function init(config: Required<Config>) {
  console.log(config.method.toUpperCase());  // ✅ 保证 method 存在
}
```

### Readonly\<T\>——全部变只读

防止意外修改——比如一个共享配置对象：

```typescript
const config: Readonly<Config> = {
  url: "/api",
  timeout: 5000,
};

// config.url = "/other";  // ❌ 只读
```

注意：`Readonly` 只做**浅层只读**。如果属性是对象，对象内部的属性仍然可写。深层只读需要自定义实现（见第 26 章）。

---

## 场景二：只要对象的部分属性

### Pick\<T, K\>——挑选

从大接口中挑出需要的几个字段：

```typescript
interface User {
  id: number;
  name: string;
  email: string;
  password: string;
}

// API 返回的公开用户信息——只要 id 和 name
type PublicUser = Pick<User, "id" | "name">;
// { id: number; name: string }
```

### Omit\<T, K\>——排除

从大接口中排除不需要的字段：

```typescript
// 返回用户信息但不包含密码
type SafeUser = Omit<User, "password">;
// { id: number; name: string; email: string }
```

**Pick 和 Omit 如何选择？**

- 需要的字段少 → 用 `Pick`（列举你想要的）
- 不需要的字段少 → 用 `Omit`（排除你不想要的）

在实际开发中，`Omit` 出镜率远高于 `Pick`——"和 XX 一样只是没有 YY"是最常见的类型变体需求：

```typescript
// React 组件 Props 变体
interface ButtonProps {
  variant: "primary" | "secondary";
  size: "small" | "medium" | "large";
  onClick: () => void;
  disabled: boolean;
}

type IconButtonProps = Omit<ButtonProps, "variant" | "size">;
```

## 场景三：想构造一个新的键值对类型

### Record\<K, V\>——键值映射

当你需要一个"键→值"的字典结构时：

```typescript
// 名字 → 分数
type ScoreMap = Record<string, number>;
const scores: ScoreMap = { Alice: 95, Bob: 87 };

// 状态 → 文案（所有键都必须出现）
type StatusText = Record<"loading" | "success" | "error", string>;
const text: StatusText = {
  loading: "加载中...",
  success: "加载成功",
  error: "加载失败",
};
```

`Record` 在需要**穷尽联合类型的所有键**时特别有用——如果你漏了某个键，TypeScript 会立即报错。

---

## 场景四：想从联合类型中筛掉某些成员

联合类型是 TypeScript 中最常用的结构之一。当你需要对联合类型做"筛选"时，这组工具类型就派上了用场。

### Exclude\<T, U\>——排除

从联合类型中剔除某些成员：

```typescript
type AllEvents = "click" | "submit" | "change" | "keydown" | "focus";

type PointerEvents = Exclude<AllEvents, "submit" | "change">;
// "click" | "keydown" | "focus"
```

### Extract\<T, U\>——提取

从联合类型中只保留某些成员：

```typescript
type FormEvents = Extract<AllEvents, "submit" | "change">;
// "submit" | "change"
```

`Extract` 的一个经典用法是从混合类型中筛出函数：

```typescript
type Mixed = string | number | (() => void) | (() => Promise<string>);
type Funcs = Extract<Mixed, (...args: unknown[]) => unknown>;
// (() => void) | (() => Promise<string>)
```

### NonNullable\<T\>——去空

从类型中剔除 `null` 和 `undefined`：

```typescript
type MaybeString = string | null | undefined;
type Safe = NonNullable<MaybeString>;  // string
```

## 场景五：想从函数中提取类型信息

如果你调用一个第三方函数，想获取它的返回值类型或参数类型，不需要手写——让 TypeScript 从函数身上"偷"过来。

### ReturnType\<T\>——提取返回值

```typescript
declare function createUser(name: string, age: number): { id: number; name: string; age: number };

type User = ReturnType<typeof createUser>;
// { id: number; name: string; age: number }
```

这在 Node.js 中间件、Express handler 等场景下特别实用——你不需要重复声明函数返回的类型：

```typescript
// 自动提取 controller 的返回类型
type ControllerResponse = ReturnType<typeof myController>;
```

### Parameters\<T\>——提取参数

```typescript
type CreateUserParams = Parameters<typeof createUser>;
// [name: string, age: number]

// 复用参数类型
function createAdmin(...args: CreateUserParams) {
  const user = createUser(...args);
  return { ...user, role: "admin" as const };
}
```

## 工具类型的组合——积木搭起来才有威力

单个工具类型解决单个问题。但真正的价值在于**链式组合**。以下是三个真实项目中最常见的组合模式。

### 模式一：用于更新的 DTO

从实体类型推导出"更新接口请求体"——排除自增字段、排除敏感字段、其余全部可选：

```typescript
interface User {
  id: number;
  name: string;
  email: string;
  password: string;
  createdAt: Date;
  updatedAt: Date;
}

type UpdateUserDTO = Partial<Omit<User, "id" | "createdAt" | "updatedAt" | "password">>;
// { name?: string; email?: string }
```

### 模式二：用于列表查询的参数

排除不需要在查询参数中传递的字段，再把部分字段变为可选：

```typescript
type UserQueryParams = Partial<Pick<User, "name" | "email">> & {
  page: number;
  pageSize: number;
};
```

### 模式三：用于表单的初始值

和实体类型一样，但排除自增 ID、时间戳等运行时才产生的字段：

```typescript
type CreateUserForm = Omit<User, "id" | "createdAt" | "updatedAt">;
// { name: string; email: string; password: string }
```

### 模式四：API 响应包装

给任意数据类型套上统一的响应外壳：

```typescript
interface ApiResponse<T> {
  code: number;
  message: string;
  data: T;
}

type UserListResponse = ApiResponse<User[]>;
type UserDetailResponse = ApiResponse<User>;
```

### 模式五：事件类型映射

用 `Record` 构建事件名到事件数据的映射，再用 `keyof` 和索引访问做类型安全的事件系统：

```typescript
type EventMap = Record<string, unknown>;

class TypedEmitter<Events extends EventMap> {
  on<E extends keyof Events>(event: E, handler: (data: Events[E]) => void): void {}
  emit<E extends keyof Events>(event: E, data: Events[E]): void {}
}

// 使用
interface AppEvents {
  userLogin: { userId: string; timestamp: number };
  userLogout: { userId: string };
  error: { message: string; code: number };
}

const emitter = new TypedEmitter<AppEvents>();
emitter.on("userLogin", (data) => {
  // data 的类型自动推导为 { userId: string; timestamp: number }
  console.log(data.userId, data.timestamp);
});
// emitter.on("userLogin", (data) => console.log(data.xxx)); // ❌
```

## 本章小结

- **类型别名** `type` 给任何类型表达式命名，支持泛型、递归
- **`import type` / `export type`** 标记纯类型导入导出，编译后零痕迹，也是 `isolatedModules` 模式下的要求
- **工具类型** 是 TypeScript 内置的"类型函数"，在已有类型上做变换，无需手写
- 按场景记忆工具类型：改可选/只读 → `Partial`/`Required`/`Readonly`；挑属性 → `Pick`/`Omit`；构造映射 → `Record`；筛联合类型 → `Exclude`/`Extract`/`NonNullable`；提取函数类型 → `ReturnType`/`Parameters`
- **工具类型的真正威力在于组合**——链式调用能从一个基础类型推导出各种变体，消除模板类型代码

工具类型的实现原理涉及映射类型（第 15 章）、条件类型（第 16 章）和索引访问类型（第 14 章）。下一章将深入联合类型与交叉类型的进阶用法。
