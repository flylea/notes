# 第9章 类型断言与类型守卫

TypeScript 的类型推导在大部分场景下非常准确，但有时你的判断比编译器更精确——你需要"告诉编译器"变量的类型。本章介绍两个方向的工具：**类型断言**让你手动指定类型；**类型守卫**让你通过运行时逻辑让 TypeScript 自动收窄类型。

## 类型断言（Type Assertion）

类型断言允许你手动覆盖 TypeScript 推导出的类型，告诉编译器"我知道它是什么类型"。

### 基本语法

类型断言有两种等价写法：

```typescript
// 方式一：as 语法（推荐）
const value = expr as Type;

// 方式二：尖括号语法
const value = <Type>expr;
```

实际项目中推荐使用 `as` 语法。尖括号语法与 JSX 冲突，在 React 项目中无法使用。

最常见的场景：你知道一个 DOM 元素的具体类型，但 TypeScript 只知道它是 `HTMLElement`：

```typescript
const usernameInput = document.getElementById("username") as HTMLInputElement;
// 现在可以访问 value 属性了
console.log(usernameInput.value);

// 如果没有断言，document.getElementById 返回 HTMLElement | null
// 而 HTMLElement 上没有 value 属性
```

### 类型断言的条件

类型断言不是随心所欲的——你要断言的类型必须与原类型有"重叠"：

```typescript
const n = 1;
// const s: string = n as string;  // ❌ number 和 string 没有重叠
```

断言能够成立的条件是：**原类型是目标类型的子类型，或者目标类型是原类型的子类型**。换句话说，两个类型之间必须存在继承/兼容关系。`number` 和 `string` 之间没有这种关系，所以不能直接断言。

但如果两个类型有公共父类型（比如 `{}` 和 `{ name: string }` 的公共父类型是 `{}`），断言就能成立：

```typescript
const obj = {};
const named = obj as { name: string };  // ✅ {} 是 { name: string } 的父类型
```

### 指鹿为马与霸王龙——断言失败时怎么办

先看一个例子：

```typescript
const str: string = "hello";

// 你想把它当对象用
str as { handler: () => void };
//    ❌ 类型 "string" 到类型 "{ handler: () => void; }" 的转换可能是错误的
//       因为两个类型没有充分重叠
```

把一个 `string` 断言成 `{ handler: () => void }`——这是什么？**这就是"指鹿为马"**。TypeScript 看着你说："喂，这俩东西完全不是一回事，你是不是搞错了？"

那"指鹿为霸王龙"呢？`string` 和 `{ handler: () => void }` 之间尚且有公共祖先 `{}`，如果两个类型差距大到连公共祖先都没有，TypeScript 就会直接拒绝：

```typescript
const n: number = 42;
// n as RegExp;  // ❌ number 和 RegExp 之间没有任何重叠
```

这就是指鹿为霸王龙——离谱到编译器觉得你在开玩笑。

### 双重断言——unknown 是万能桥梁

那如果我真的需要这种极端转换呢？TypeScript 给你留了最后一个逃生舱：**双重断言**。先断言到 `unknown`（Top Type，万物的祖先），再从 `unknown` 断言到目标类型：

```typescript
const str: string = "hello";

// 通过 unknown 中转：先上转，再下转
(str as unknown as { handler: () => void }).handler();
```

为什么这样能行？因为 `unknown` 是类型层级的顶点——**任何类型都可以断言为 `unknown`，`unknown` 也可以断言为任何类型**。双重断言就是"先爬上山顶，再顺着另一面下去"。

```typescript
// 另一个例子：string → number
const str = "hello";
const n = str as unknown as number;  // ✅ 编译通过
```

双重断言是**最终的逃生舱**——它会绕过 TypeScript 全部的类型安全检查。编译通过了，但运行时的 `str` 仍然是字符串，不会魔法般地变成数字。把它当作"我清楚地知道自己在做什么，请 TypeScript 闭嘴"的最后手段，别当成日常工具。

### 类型断言 vs 类型标注

对于对象，类型断言和类型标注有重要区别——类型断言会绕过额外属性检查：

```typescript
// 类型标注：会触发额外属性检查
// const p1: { x: number } = { x: 0, y: 0 };  // ❌ y 是额外属性

// 类型断言：绕过额外属性检查
const p2 = { x: 0, y: 0 } as { x: number };        // ✅
const p3 = { x: 0, y: 0 } as { x: number; y: number };  // ✅ 子类型也可以
```

利用这一特性，类型断言在实现接口时可以作为渐进式开发的辅助工具——你可以先用断言写一个不完整的对象获得类型提示，之后再逐步填充完善：

```typescript
interface User {
  name: string;
  profile: {
    avatar: string;
    bio: string;
  };
}

// 用断言开始，IDE 仍会提供属性提示
const user = {
  name: "Alice",
  profile: {},
} as User;
// 后续填充 profile.avatar, profile.bio 时 IDE 都能正确补全
```

### satisfies——比类型断言更安全的替代方案

TypeScript 4.9 引入了 `satisfies` 操作符。它和类型断言一样让你"告诉编译器类型"，但有一个关键区别：**`satisfies` 不会改变变量的推导类型，而是让编译器验证这个值是否满足目标类型**。

```typescript
interface Config {
  host: string;
  port: number;
  timeout: number;
}

// 类型标注：你失去了具体的字面量信息
const config1: Config = { host: "localhost", port: 3000, timeout: 5000 };
config1.port.toFixed();  // ✅ port 是 number

// satisfies：既验证类型，又保留推导出的精确类型
const config2 = {
  host: "localhost",
  port: 3000,
  timeout: 5000,
} satisfies Config;

// config2.port 的类型是 3000（字面量类型），而不只是 number
// 同时如果属性缺失或类型不对，会立即报错
```

`satisfies` 的核心价值在于"验证而不丢失信息"。它特别适合以下场景：

**场景一：保留字面量类型**

```typescript
const palette = {
  red: [255, 0, 0],
  green: [0, 255, 0],
  blue: [0, 0, 255],
} satisfies Record<string, [number, number, number]>;

// palette.red 的类型是 [number, number, number] 而非 unknown
// 如果你用了 as 断言，palette.red 的类型仍然是 unknown
const r = palette.red[0];  // number
```

**场景二：验证对象中某些属性的类型而不丢失其他属性**

```typescript
type Colors = "red" | "green" | "blue";
type Hex = `#${string}`;

const colorMap = {
  red: "#FF0000",
  green: "#00FF00",
  blue: "#0000FF",
  alpha: 0.5,  // 额外属性——类型标注会报错，satisfies 不会
} satisfies Record<Colors, Hex> & { alpha: number };
```

**satisfies vs 类型断言 vs 类型标注**

| | 类型标注 (`: Type`) | 类型断言 (`as Type`) | `satisfies` |
|---|---|---|---|
| 验证类型是否匹配 | ✅ | ❌（绕过检查） | ✅ |
| 保留推导出的精确类型 | ❌（类型被拓宽） | ❌（被断言覆盖） | ✅ |
| 额外属性检查 | ✅ | ❌ | ✅ |
| 适用场景 | 精确性不重要时 | 你能保证但编译器不能 | 你想验证又想推导 |

**什么时候用 satisfies 而不是类型断言？**
- 你不需要改变推导出的类型，只想验证它满足某个约束 → `satisfies`
- 你需要覆盖 TypeScript 的推导，告诉它"这个值就是 X 类型" → `as`

### 非空断言（`!`）

非空断言 `!` 是类型断言的快捷方式——它从类型中剔除 `null` 和 `undefined`：

```typescript
// 场景一：DOM 查询
const element = document.getElementById("app")!;
// 等价于：as HTMLElement（排除了 null）

// 场景二：Array.find 结果
const nums = [1, 2, 3];
const found = nums.find(n => n > 10)!;
// found 的类型是 number（而非 number | undefined）

// 场景三：可选链中
declare const foo: {
  func?: () => { prop?: number | null };
};

foo.func!().prop!.toFixed();
```

注意：非空断言只消除了编译时的 `null | undefined`，运行时的值仍然可能为空。和双重断言一样，`!` 也是**你对编译器的单方面承诺**——你在说"相信我，这里不可能是 null"。但如果你的承诺错了，运行时就会炸。

非空断言 vs 可选链——两种不同的运行时行为：

```typescript
declare const foo: { func?: () => { prop?: number | null } };

// 非空断言：运行时持续走调用链，遇到 null/undefined 直接报错
foo.func!().prop!.toFixed();

// 可选链：遇到 null/undefined 就短路，返回 undefined
foo.func?.().prop?.toFixed();
```

**非空断言使用清单**——什么情况下用 `!` 是可接受的，什么情况下是代码异味：

| 场景 | 可接受？ | 理由 |
|---|---|---|
| `document.getElementById("app")!` | ⚠️ 勉强 | DOM 可能真的没有这个元素，用 if 检查更安全 |
| `arr.find(x => x.id === id)!` | ⚠️ 勉强 | find 确实可能返回 undefined，应处理未找到的情况 |
| `useRef<HTMLInputElement>(null)!` | ✅ 可以 | React 保证渲染后 ref 被填充 |
| 已验证的变量后再使用 `!` | ❌ 多余 | 已经做过 if 检查就不需要 `!` 了 |
| 多层链式 `a!.b!.c!` | ❌ 代码异味 | 说明数据结构设计有问题，或缺少前置校验 |
| 测试代码中 | ✅ 可以 | 测试中快速失败是合理的 |

更推荐的做法是：**用运行时检查替代非空断言**，这样类型收窄是"证明"出来的，不是"赌"出来的：

```typescript
// ❌ 赌它存在
const element = document.getElementById("app")!;
element.addEventListener("click", () => {});

// ✅ 证明它存在
const element = document.getElementById("app");
if (!element) {
  throw new Error("Element #app not found");
}
// 此后 element 的类型自动收窄为 HTMLElement
element.addEventListener("click", () => {});
```

## 类型缩小（Narrowing）

TypeScript 的类型系统不仅是"声明时检查"，更是**流式感知**的——当代码执行经过条件判断，TypeScript 会沿着代码路径自动缩小变量的类型。这个过程称为 **Narrowing（类型缩小/收窄）**。

理解 Narrowing 的关键心智模型是：**TypeScript 跟随控制流分析代码，在每个代码分支中推导出更精确的类型**。

### typeof 类型守卫

`typeof` 的返回值是 TypeScript 能识别的类型守卫：

```typescript
function process(value: string | number) {
  if (typeof value === "string") {
    // 在这个分支，value 的类型被收窄为 string
    return value.toUpperCase();
  }

  // 在这个分支，value 的类型被收窄为 number
  return value.toFixed(2);
}
```

TypeScript 能识别的 `typeof` 返回值包括：`"string"`, `"number"`, `"bigint"`, `"boolean"`, `"symbol"`, `"undefined"`, `"object"`, `"function"`。

注意 `typeof null === "object"`——这是 JavaScript 的历史 bug。但 TypeScript 处理 `typeof value === "object"` 时会把 `null` 排除在收窄结果之外：

```typescript
function print(value: string | null) {
  if (typeof value === "object") {
    // TypeScript 知道 typeof null 返回 "object"
    // 所以这里 value 的类型是 null（被收窄了）
    console.log("null");
  } else {
    // 这里 value 的类型是 string
    console.log(value.toUpperCase());
  }
}
```

### 真值检查（Truthiness Narrowing）

在条件判断中使用值本身，TypeScript 会自动排除 `false`、`0`、`""`、`null`、`undefined`、`NaN` 等假值：

```typescript
function processValue(value: string | null | undefined) {
  if (value) {
    // 这里 value 的类型是 string（排除了 null 和 undefined）
    console.log(value.toUpperCase());
  }
}
```

这个特性在数组元素访问中特别有用：

```typescript
const names = ["Alice", "Bob", undefined, "Charlie"];

names.forEach(name => {
  if (name) {
    // 这里 name 被收窄为 string
    console.log(name.toUpperCase());
  }
});
```

### 等值检查（Equality Narrowing）

使用 `===`、`!==`、`==`、`!=` 进行比较也能触发类型收窄：

```typescript
function example(x: string | number, y: string | boolean) {
  if (x === y) {
    // 两者相等的唯一可能是它们都是 string
    // x: string  |  y: string
    console.log(x.toUpperCase(), y.toUpperCase());
  }
}
```

`switch` 语句同样能触发等值收窄：

```typescript
function getStatus(code: 200 | 404 | 500): string {
  switch (code) {
    case 200:
      return "OK";
    case 404:
      return "Not Found";
    case 500:
      return "Server Error";
  }
}
```

### in 运算符收窄

`in` 运算符检查对象是否拥有某个属性，TypeScript 据此收窄联合类型：

```typescript
interface Circle {
  kind: "circle";
  radius: number;
}

interface Square {
  kind: "square";
  sideLength: number;
}

type Shape = Circle | Square;

function getArea(shape: Shape): number {
  if ("radius" in shape) {
    // 收窄为 Circle——只有 Circle 有 radius 属性
    return Math.PI * shape.radius ** 2;
  }
  // 收窄为 Square
  return shape.sideLength ** 2;
}
```

`in` 运算符的一个重要限制是：**只能用于联合类型**。如果对一个非联合类型的对象使用 `in`，TypeScript 不会收窄：

```typescript
function check(obj: object) {
  if ("name" in obj) {
    // obj 的类型仍然是 object，不是 { name: unknown }
    // obj.name;  // ❌ 无法访问
  }
}
```

### instanceof 收窄

`instanceof` 用于检查一个对象是否是某类的实例（或者说，检查构造函数的 `prototype` 是否出现在对象的原型链上）：

```typescript
class ApiError extends Error {
  constructor(public statusCode: number, message: string) {
    super(message);
  }
}

class NetworkError extends Error {
  constructor(public url: string, message: string) {
    super(message);
  }
}

function handleError(err: Error) {
  if (err instanceof ApiError) {
    // 收窄为 ApiError——可以访问 statusCode
    console.error(`API Error ${err.statusCode}: ${err.message}`);
  } else if (err instanceof NetworkError) {
    // 收窄为 NetworkError——可以访问 url
    console.error(`Network error for ${err.url}: ${err.message}`);
  }
}
```

`instanceof` 也适用于原生构造函数：

```typescript
function process(value: Date | RegExp | string) {
  if (value instanceof Date) {
    console.log(value.toISOString());
  } else if (value instanceof RegExp) {
    console.log(value.source);
  } else {
    console.log(value.toUpperCase());
  }
}
```

### Array.isArray 收窄

一种特殊但常用的收窄方式：

```typescript
function welcomePeople(x: string[] | string) {
  if (Array.isArray(x)) {
    // x: string[]
    console.log("Hello, " + x.join(" and "));
  } else {
    // x: string
    console.log("Welcome lone traveler " + x);
  }
}
```

### 赋值收窄

当给变量赋值时，TypeScript 会用赋值表达式右侧的类型来缩小左侧变量的类型：

```typescript
let value: string | number = "hello";
// value: string | number

value = 42;
// value 的类型仍然是 string | number，但 TS 知道它当前是 number
// 在后续代码中如果有检查，会被正确地分析

// 另一个例子
let x: string | number;

x = "hello";   // TS 记得这里赋的是 string
x.toLowerCase();  // ✅

x = 5;         // TS 记得这里赋的是 number
x.toFixed();   // ✅
```

## 类型谓词（Type Predicate）——自定义类型守卫

`typeof`、`instanceof`、`in` 等内建守卫的能力有限。当你需要更复杂的类型判断逻辑时，可以写**自定义类型守卫**——返回类型为 `parameterName is Type` 的函数：

```typescript
// 类型谓词：返回值的类型声明为 "参数 is 类型"
function isString(value: unknown): value is string {
  return typeof value === "string";
}

function process(value: unknown) {
  if (isString(value)) {
    // TypeScript 自动将 value 收窄为 string
    console.log(value.toUpperCase());
  }
}
```

`value is string` 的含义是：**如果此函数返回 `true`，则调用方可将 `value` 视为 `string` 类型**。

### 实用案例

```typescript
// 过滤 undefined 值——filter 结合类型谓词
function isDefined<T>(value: T | undefined | null): value is T {
  return value !== undefined && value !== null;
}

const arr = [1, undefined, 2, null, 3];
const clean = arr.filter(isDefined);
// clean 的类型: number[]（而非 (number | null | undefined)[]）

// 区分联合类型的不同变体
interface User {
  type: "user";
  name: string;
}

interface Admin {
  type: "admin";
  name: string;
  permissions: string[];
}

type Person = User | Admin;

function isAdmin(person: Person): person is Admin {
  return person.type === "admin";
}

function processPerson(person: Person) {
  if (isAdmin(person)) {
    // person 被收窄为 Admin
    console.log(person.permissions);
  }
}
```

### 类型谓词使用注意事项

类型谓词函数的作者承担了正确性责任——TypeScript 信任你的返回值类型声明，不会验证函数体逻辑是否与类型谓词一致：

```typescript
// ⚠️ TypeScript 不会报错，因为类型谓词是你对编译器的承诺
function isNumber(value: unknown): value is number {
  return typeof value === "string";  // 逻辑错误！但 TS 不检查函数体
}
```

## 断言函数（Assertion Functions）

类型谓词通过返回布尔值来收窄类型，而**断言函数**（TS 3.7+）则通过抛出异常来收窄——如果函数正常返回（没有抛错），则该变量一定是指定的类型：

```typescript
// 基本形式：asserts value is Type
function assertIsString(value: unknown): asserts value is string {
  if (typeof value !== "string") {
    throw new Error(`Expected string, got ${typeof value}`);
  }
  // 函数正常返回 → value 一定是 string
}

function process(value: unknown) {
  assertIsString(value);
  // 此后 value 的类型自动收窄为 string
  console.log(value.toUpperCase());
}
```

### 断言函数 vs 类型谓词

| | 类型谓词 (`is`) | 断言函数 (`asserts`) |
|---|---|---|
| 返回值 | `boolean` | `void`（正常返回时） |
| 收窄方式 | `if` 条件分支中 | 函数调用之后的代码 |
| 适用场景 | 条件判断 | 前置条件校验 |

两种方式的代码对比：

```typescript
// 类型谓词：需要手动写 if
function isString(value: unknown): value is string {
  return typeof value === "string";
}

function process1(value: unknown) {
  if (isString(value)) {
    console.log(value.toUpperCase());  // 仅在 if 内收窄
  }
}

// 断言函数：自动在调用后收窄
function assertIsString(value: unknown): asserts value is string {
  if (typeof value !== "string") throw new Error("Not a string");
}

function process2(value: unknown) {
  assertIsString(value);
  console.log(value.toUpperCase());  // 调用之后的代码都能收窄
}
```

结论：当你需要"如果类型不对就中断执行"的逻辑时，断言函数更简洁；当你想在条件分支中分别处理不同情况时，类型谓词更合适。

### asserts 简写形式

不指定具体类型的 `asserts value`——断言的唯一条件是该值为真：

```typescript
function assert(condition: unknown): asserts condition {
  if (!condition) {
    throw new Error("Assertion failed");
  }
}

function process(maybeString: string | undefined) {
  assert(maybeString);
  // maybeString 被收窄为 string（排除了 undefined 等假值）
  console.log(maybeString.toUpperCase());
}
```

这在 Node.js 中也作为 `assert` 模块的类型定义方式：

```typescript
import assert from "node:assert";

function greet(name: string | null) {
  assert(name);     // 如果 name 为空，抛错
  console.log(name.toUpperCase());  // 此后 name 是 string
}
```

### 断言函数表达式

将断言函数写在函数表达式中时，需要显式标注类型：

```typescript
type AssertIsNumber = (value: unknown) => asserts value is number;

const assertIsNumber: AssertIsNumber = (value) => {
  if (typeof value !== "number") {
    throw new Error("Not a number");
  }
};
```

## 可辨识联合类型（Discriminated Union）

这是 TypeScript 中最优雅的类型收窄模式之一。当联合类型的每个成员都有一个**共同的、字面量类型的属性**时，通过检查该属性即可精确识别分支：

```typescript
// 每个 Shape 都有一个 kind 属性作为"辨识字段"
interface Circle {
  kind: "circle";
  radius: number;
}

interface Square {
  kind: "square";
  sideLength: number;
}

interface Rectangle {
  kind: "rectangle";
  width: number;
  height: number;
}

type Shape = Circle | Square | Rectangle;

// 通过 kind 字段辨识
function getArea(shape: Shape): number {
  switch (shape.kind) {
    case "circle":
      // shape 被收窄为 Circle
      return Math.PI * shape.radius ** 2;
    case "square":
      // shape 被收窄为 Square
      return shape.sideLength ** 2;
    case "rectangle":
      // shape 被收窄为 Rectangle
      return shape.width * shape.height;
  }
}
```

这种模式在现实开发中非常常见——Redux action、API 响应、表单状态等都可以用可辨识联合类型精确建模：

```typescript
// API 请求状态模型
type RequestState<T> =
  | { status: "idle" }
  | { status: "loading" }
  | { status: "success"; data: T }
  | { status: "error"; error: Error };

function render<T>(state: RequestState<T>): string {
  switch (state.status) {
    case "idle":
      return "Waiting...";
    case "loading":
      return "Loading...";
    case "success":
      return `Data: ${state.data}`;      // 此处 state.data 可用
    case "error":
      return `Error: ${state.error.message}`;  // 此处 state.error 可用
  }
}
```

## 穷尽检查（Exhaustiveness Checking）

当你想确保 `switch` 处理了所有可能的分支时，可以利用 `never` 类型在 `default` 分支做穷尽检查：

```typescript
function getArea(shape: Shape): number {
  switch (shape.kind) {
    case "circle":
      return Math.PI * shape.radius ** 2;
    case "square":
      return shape.sideLength ** 2;
    case "rectangle":
      return shape.width * shape.height;
    default:
      // 如果所有分支都已处理，shape 在此处的类型是 never
      // 将它赋值给 never 类型的变量，如果编译通过则穷尽
      const _exhaustiveCheck: never = shape;
      throw new Error(`Unhandled shape: ${_exhaustiveCheck}`);
  }
}
```

这是保护未来修改的机制——假设某人新增了 `Triangle` 变体但没有在 `switch` 中处理，`shape` 在 `default` 中就不再是 `never` 而是 `Triangle`，编译器会报错：**`Triangle` 不能赋值给 `never`**。这会在编译时提醒你遗漏了新的分支。

## 本章小结

- **类型断言** (`as Type`) 手动覆盖推导类型，前提是两个类型有子类型/父类型关系
- **指鹿为马 → 霸王龙**：类型差异过大时断言会失败，双重断言 (`as unknown as Type`) 通过 Top Type 桥梁绕过检查，是最后的"逃生舱"
- **`satisfies`** (TS 4.9+) 是更安全的替代方案——验证类型而不丢失推导出的精确类型，优先使用
- **非空断言** (`!`) 从类型中剔除 `null | undefined`，但本质是"赌"而非"证明"，能用运行时检查替代就替代
- **类型缩小（Narrowing）** 是 TypeScript 沿控制流自动收窄类型的能力
- 内建守卫包括：`typeof`、真值检查、`===`、`in`、`instanceof`、`Array.isArray`
- **类型谓词** (`value is Type`) 让你写自定义类型守卫，配合 `if` 分支使用
- **断言函数** (`asserts value is Type`) 通过抛异常来收窄，适合前置校验
- **可辨识联合类型** 通过共同的字面量属性精确区分联合成员，是 Redux/Action 建模利器
- **穷尽检查** 利用 `never` 类型确保所有分支被处理，防止未来遗漏新增变体
