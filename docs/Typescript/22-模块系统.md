# 第22章 模块系统

TypeScript 对 JavaScript 的模块系统提供了完整的类型支持——包括 ES Module 和 CommonJS。本章将介绍 TypeScript 中的模块类型处理、`import type`、模块解析策略以及如何在不同模块系统之间安全地使用类型。

## ES Module 中的类型

### 导入和导出类型

```typescript
// user.ts —— 导出
export interface User {
  id: number;
  name: string;
}

export function createUser(name: string): User {
  return { id: Math.random(), name };
}

// app.ts —— 导入
import { User, createUser } from "./user";

const user: User = createUser("Alice");
```

### import type —— 仅导入类型

`import type` 是 TypeScript 3.8 引入的特性——它**只导入类型信息，不导入运行时代码**。编译后这类 import 会完全消失：

```typescript
// 只导入类型
import type { User } from "./user";

// 可以用于类型标注，但不能当值使用
const user: User = { id: 1, name: "Alice" };
// createUser("Alice");  // ❌ import type 不能导入值

// 混合导入：类型和值分开
import { type User, createUser } from "./user";
```

为什么用 `import type`？
1. **明确意图**：阅读者一眼就知道这个导入只用于类型
2. **避免循环依赖**：纯类型导入不产生运行时代码，某些循环依赖（值 → 类型 → 值）可以借助 `import type` 解开
3. **编译优化**：某些构建工具（如 Babel、esbuild）可以利用它跳过不必要的导入
4. **`isolatedModules` 兼容**：当启用 `isolatedModules` 时，类型导出（`export type`）是必需的

### export type —— 仅导出类型

```typescript
// 同名有值和类型时，可以用 export type 明确导出类型
export type { User };
export { createUser };
```

等价于：
```typescript
export type { User };
export { createUser };
```

### inline type 导入（TS 4.5+）

```typescript
// 在同一个 import 语句中混合值和类型
import { createUser, type User } from "./user";
```

## CommonJS 的类型处理

CommonJS 使用 `require` 和 `module.exports`，TypeScript 有两种方式为它们提供类型：

### 方式一：使用 ES Module 语法编译为 CommonJS

这是推荐做法——写 ES Module 语法，通过 tsconfig 的 `module: "commonjs"` 编译为 CJS：

```typescript
// 编写时用 ES Module 语法
import express from "express";
export const app = express();

// 编译后（module: "commonjs"）
// const express = require("express");
// exports.app = express();
```

### 方式二：CommonJS 类型标注

如果因为某些原因必须直接写 CommonJS 风格的代码：

```typescript
// 使用 import = require 语法
import express = require("express");

// 使用 export = 导出
const app = express();
export = app;
```

`export =` 是 TypeScript 为 CommonJS 的 `module.exports =` 模式提供的类型语法。导入方需要用 `import = require` 或 `import * as`：

```typescript
// 导入 export = 的模块
import myModule = require("./my-module");
// 或
import * as myModule from "./my-module";
```

## 模块解析策略

TypeScript 需要知道如何查找 `.ts`/`.d.ts` 文件。`moduleResolution` 配置控制这一行为：

### node 策略（Node.js 风格）

模拟 Node.js 的模块解析逻辑：
- 相对路径：逐级向上查找 `node_modules`
- 非相对路径：从 `node_modules` 目录查找
- 按顺序尝试 `.ts`、`.tsx`、`.d.ts`、`.js` 扩展名
- 查找 `package.json` 的 `types`/`typings` 字段
- 查找目录下的 `index.ts`/`index.d.ts`

### bundler 策略（推荐用于现代项目）

TypeScript 5.0 引入了 `moduleResolution: "bundler"`，专门为 Vite、Webpack、esbuild 等打包工具设计：

- 支持 `package.json` 的 `exports` 字段
- 不需要写文件扩展名（打包工具会处理）
- 与打包工具的实际解析行为一致

```json
{
  "compilerOptions": {
    "module": "esnext",
    "moduleResolution": "bundler"
  }
}
```

### nodenext 策略（TypeScript 4.7+）

`moduleResolution: "nodenext"` 完全遵循 Node.js 的 ESM 模块解析规则：

- `.ts` 文件如果是 ESM，必须显式写 `.js` 扩展名：
  ```typescript
  // ESM 模式下必须写完整扩展名
  import { User } from "./user.js";  // ⚠️ 注意是 .js 不是 .ts
  ```
- 支持 `package.json` 的 `"type": "module"` 控制

### 策略速查表

| 策略 | 适用场景 | 需写扩展名 | 支持 exports |
|------|---------|-----------|-------------|
| `node` | 传统 Node.js | ❌ | ❌ |
| `bundler` | Vite/Webpack 等 | ❌ | ✅ |
| `nodenext` | Node.js ESM | ✅ (.js) | ✅ |
| `classic` | 已过时 | — | — |

## 类型导入导出的最佳实践

### 1. 开启 isolatedModules

当使用 Babel、esbuild、Vite 等非 tsc 编译器时，建议开启 `isolatedModules: true`。它要求：
- 每个文件都被独立编译（不能依赖跨文件的类型信息）
- 类型导出必须用 `export type`
- 常量枚举不能使用

### 2. 开启 verbatimModuleSyntax（TS 5.0+）

`verbatimModuleSyntax: true` 强制要求 `import type` 用于纯类型导入（在 ESM 输出中这些导入会被移除）。这比 `importsNotUsedAsValues` 和 `isolatedModules` 更严格，也更能防止运行时错误。

```typescript
// verbatimModuleSyntax 开启时：
import type { User } from "./user";  // ✅ 纯类型，编译后消失
import { createUser } from "./user";  // ✅ 值导入，编译后保留
// import { User } from "./user";  // ❌ 虽然是类型，但不能省略 type 关键字
```

### 3. 路径别名

通过 tsconfig 的 `paths` 配置路径别名（需要与打包工具的 alias 保持一致）：

```json
{
  "compilerOptions": {
    "baseUrl": ".",
    "paths": {
      "@/*": ["src/*"],
      "@components/*": ["src/components/*"],
      "@utils/*": ["src/utils/*"]
    }
  }
}
```

## 动态导入的类型

动态导入 `import()` 返回 `Promise`，TypeScript 会自动推导模块的类型：

```typescript
async function loadUserModule() {
  const { createUser } = await import("./user");
  const user = createUser("Alice");
  return user;
}
```

## 本章小结

- **ES Module**：用标准 `import`/`export` 语法，推荐开启 `verbatimModuleSyntax`
- **`import type`**：让类型导入编译后完全消失，避免循环依赖
- **CommonJS**：推荐用 ES Module 写法 + `module: "commonjs"` 编译，避免裸写 CJS 语法
- **模块解析**：现代项目推荐 `bundler`；纯 Node.js ESM 用 `nodenext`
- **路径别名**：tsconfig `paths` 需与打包工具的 alias 保持一致
