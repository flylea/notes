# 第21章 类型声明文件与命名空间

TypeScript 项目中的一个核心需求是：如何为没有类型的 JavaScript 代码提供类型信息。类型声明文件（`.d.ts`）就是答案——它们只包含类型信息，不包含运行时代码。本章介绍如何编写和使用声明文件，以及 `namespace` 命名空间的组织方式。

## declare 关键字

`declare` 告诉 TypeScript"这个变量/函数/类在运行时一定存在，请信任它的类型"——它只声明类型，不产生任何 JavaScript 代码：

```typescript
// 声明全局变量
declare var jQuery: (selector: string) => any;
declare const VERSION: string;

// 声明全局函数
declare function greet(name: string): void;

// 声明全局类
declare class Animal {
  name: string;
  constructor(name: string);
  sayHello(): void;
}

// 声明全局枚举
declare enum Direction {
  Up, Down, Left, Right
}
```

编译后，上面的所有 `declare` 语句都不会出现在 JavaScript 输出中——它们只用于类型检查。

## .d.ts 文件

`.d.ts` 文件是 TypeScript 的类型声明文件。它只能包含类型声明，不能包含可执行代码：

```typescript
// types.d.ts
interface User {
  id: number;
  name: string;
  email: string;
}

declare function getUser(id: number): User;
declare function createUser(data: Omit<User, "id">): User;
```

### .d.ts vs .ts

| | .ts | .d.ts |
|---|---|---|
| 可执行代码 | ✅ | ❌ |
| 类型声明 | ✅ | ✅ |
| 编译输出 | .js | 无 |
| 用途 | 实现代码 | 类型描述 |

### 全局声明 vs 模块声明

`.d.ts` 文件中如果没有 `import`/`export`，所有声明都是**全局的**——在整个项目中可以直接使用：

```typescript
// global.d.ts（无 import/export，声明为全局）
interface Window {
  __CUSTOM_CONFIG__: Record<string, unknown>;
}

declare const APP_VERSION: string;
```

一旦文件包含 `import` 或 `export`，它就变成了模块——声明不会泄露到全局：

```typescript
// types.d.ts（有 export，是模块）
export interface User {
  id: number;
  name: string;
}

// 使用方需要显式 import
import { User } from "./types";
```

### 扩展全局类型

`.d.ts` 最重要的用途之一是扩展已有的全局类型——最常见的是扩展 `Window`：

```typescript
// global.d.ts
declare global {
  interface Window {
    __INITIAL_STATE__: Record<string, unknown>;
    gtag: (event: string, params: Record<string, unknown>) => void;
  }

  // 扩展 String 原型
  interface String {
    capitalize(): string;
  }
}

export {};  // 确保文件是模块（必须有至少一个 export 才能使用 declare global）
```

## 三斜线指令

三斜线指令（`/// <reference path="..." />`）是早期 TypeScript 中引用声明文件的方式，如今大多数场景都被 `import`/`export` 替代，但在某些特殊场景仍然有用：

```typescript
// 引用另一个声明文件
/// <reference path="./other-types.d.ts" />

// 引用库的声明文件
/// <reference types="node" />

// 引用 lib（内置库声明）
/// <reference lib="es2015.promise" />
```

## @types 包

DefinitelyTyped（https://github.com/DefinitelyTyped/DefinitelyTyped）是社区维护的最大的类型声明仓库。绝大多数流行的 npm 包都有对应的 `@types` 包：

```bash
npm install --save-dev @types/lodash
npm install --save-dev @types/react
npm install --save-dev @types/node
```

安装后，TypeScript 会自动从 `node_modules/@types` 中加载类型声明，无需手动引用。

### 类型声明文件的查找顺序

TypeScript 查找类型声明文件的顺序是：
1. 项目中的 `.d.ts` 文件（受 `include`/`exclude`/`files` 配置影响）
2. `node_modules/@types/` 下的包（按 `typeRoots` 配置）
3. npm 包自身的 `types`/`typings` 字段指向的文件

### 为自己的 npm 包提供类型声明

在 `package.json` 中指定 `types` 字段：

```json
{
  "name": "my-library",
  "version": "1.0.0",
  "main": "./dist/index.js",
  "types": "./dist/index.d.ts"
}
```

## namespace——命名空间

`namespace` 是 TypeScript 早期用于组织代码的方式（在 ES6 模块普及之前）。如今，大多数场景用 ES6 模块更合适，但 `namespace` 在声明文件中仍然有重要作用。

### 基本用法

```typescript
namespace Utils {
  export function formatDate(date: Date): string {
    return date.toISOString();
  }

  export function parseDate(str: string): Date {
    return new Date(str);
  }

  // 私有函数——不加 export 就不能在命名空间外访问
  function pad(n: number): string {
    return n < 10 ? `0${n}` : `${n}`;
  }
}

// 使用
Utils.formatDate(new Date());
```

### 嵌套 namespace

```typescript
namespace App {
  export namespace Models {
    export interface User {
      id: number;
      name: string;
    }
  }

  export namespace Services {
    export function getUser(id: number): App.Models.User {
      return { id, name: "Alice" };
    }
  }
}
```

### namespace 声明合并

同名 `namespace` 会自动合并——这也是它在声明文件中强大的原因：

```typescript
// 两个文件中的声明会自动合并
namespace App {
  export function init() {}
}

namespace App {
  export function destroy() {}
}

// 等价于
namespace App {
  export function init() {}
  export function destroy() {}
}
```

### namespace 在声明文件中的典型用途

为大型库或 jQuery 风格的插件系统声明类型：

```typescript
// jQuery 风格——构造函数 + 静态方法
declare function $<T extends HTMLElement>(selector: string): $Collection<T>;

declare namespace $ {
  function ajax(url: string, settings?: AjaxSettings): void;
  function get(url: string): Promise<unknown>;

  interface AjaxSettings {
    method?: string;
    data?: unknown;
  }
}

// 使用
$("#app").show();
$.ajax("/api/data", { method: "POST" });
```

### namespace vs ES6 模块

| | namespace | ES6 模块 |
|---|---|---|
| 使用场景 | 声明文件、全局组织 | 实现代码 |
| 编译输出 | IIFE 对象 | ES 模块语法 |
| 声明合并 | ✅ | ❌ |
| Tree-shaking | ❌ | ✅ |
| 运行时开销 | 有（生成对象） | 无（编译时解决） |

**建议**：实现代码中用 ES6 模块（`import`/`export`），声明文件中用 `namespace` 来组织全局类型。

## 声明文件的实战模式

### 模式一：为无类型的 JS 模块声明

你的项目中使用了一个没有 `@types` 的旧 JS 库：

```typescript
// src/types/legacy-lib.d.ts
declare module "legacy-lib" {
  export function doSomething(input: string): number;
  export const VERSION: string;
}
```

### 模式二：为非 JS 文件声明

为 CSS Modules、图片等非 JS 资源声明类型：

```typescript
// declarations.d.ts
declare module "*.module.css" {
  const classes: { readonly [key: string]: string };
  export default classes;
}

declare module "*.svg" {
  const content: string;
  export default content;
}

declare module "*.png" {
  const content: string;
  export default content;
}
```

### 模式三：扩展第三方库的接口

```typescript
// 扩展 Express 的 Request 对象
declare global {
  namespace Express {
    interface Request {
      user?: {
        id: number;
        role: string;
      };
    }
  }
}
```

## 本章小结

- **`declare`** 声明某变量/函数/类在运行时存在，编译后不产生 JS 代码
- **`.d.ts` 文件** 只包含类型声明；无 `import`/`export` 的声明为全局
- **`declare global`** 用于扩展全局类型（如 `Window`、`String` 原型）
- **`@types` 包** 提供社区维护的第三方库类型声明
- **`namespace`** 用于组织全局声明，支持自动合并；实现代码中优先用 ES6 模块
- 声明文件的实战模式：为 JS 库写声明、为非 JS 资源写声明、扩展第三方类型
