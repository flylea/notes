# 第 2 章 开发环境搭建

装好 Node 之后第一次跑 `.ts` 文件，常遇到三种报错：找不到 `tsc`、`enum` 在 Node 下语法错误、`tsc index.ts` 提示 TS5112。这些报错都出在环境与运行方式上，不在类型语法里。这一章把三种运行路径和对应的配置讲清楚。

## 一句话说清

`node app.ts` 和 `tsc` 是两条路：一条在加载文件时擦掉类型，一条先检查再写出新文件。分叉点不在语法，在加载阶段。同一个 `enum`，`node` 报语法错误，`tsc` 编译正常，原因就在这里。

```ts
enum Level { Info, Error }
```

这段代码存成 `level.ts` 直接运行，得到的是语法错误，不是类型错误。
同一份文件交给 `tsc` 能过，因为枚举对编译器是合法的类型语法。

## 安装 TypeScript

你需要 Node.js 环境。安装 TypeScript 编译器：

```bash
npm install -g typescript
# 或使用 pnpm
pnpm add -g typescript
```

安装完成后验证：

```bash
tsc --version
# Version 7.0.2
```

### 创建项目

```bash
mkdir my-ts-project && cd my-ts-project
tsc --init    # 生成 tsconfig.json
```

`tsc --init` 会创建一个包含默认配置的 `tsconfig.json` 文件，带有详细的注释说明每个选项的含义。

### 编译第一个 TS 文件

```typescript
// index.ts
function greet(name: string): string {
  return `Hello, ${name}!`;
}

console.log(greet("TypeScript"));
```

```bash
tsc                 # 按 tsconfig.json 编译，生成 index.js
node index.js       # 运行编译后的 JS
```

目录里有 `tsconfig.json` 时，`tsc index.ts` 会报：

```text
error TS5112: tsconfig.json is present but will not be loaded if files are specified on commandline. Use '--ignoreConfig' to skip this error.
```

只编译单个文件时加 `--ignoreConfig`：`tsc --ignoreConfig index.ts`。

不想先编译，可以看下一节的即时执行方案。

## 快速执行 TS 文件

### 方式一：Node.js 原生运行（推荐）

Node 22.6 加入[类型剥离](https://nodejs.org/api/typescript.html)，需要 `--experimental-strip-types`。23.6 和 22.18 默认开启，24.3 和 22.18 去掉 experimental 警告，25.2 和 24.12 转为 Stable。26 移除了 `--experimental-transform-types`，只剩 `--no-strip-types` 一个开关。

```bash
node index.ts          # 直接运行
node --watch index.ts  # 文件变了就重跑
```

装的是 Node 22.6 到 22.17 时，要带 flag：

```bash
node --experimental-strip-types index.ts
```

Node 在加载 `.ts` 文件时做类型剥离（type stripping）。它把类型标注、`interface`、类型导入删掉，替换成空白，剩下的 JavaScript 交给 V8：

```typescript
function greet(name: string): string {
  return `Hello, ${name}!`;
}
```

剥离后等价于：

```javascript
function greet(name) {
  return `Hello, ${name}!`;
}
```

Node 只剥离类型，不做类型检查。类型写错了照样跑，所以开发时和 CI 里还要再跑一遍：

```bash
tsc --noEmit        # 只检查，不生成文件
```

### 为什么剥离要逐文件做，还要留出空位

Node 在模块加载阶段调用剥离函数（报错栈里是 `stripTypeScriptModuleTypes`，本书实测），把类型语法原地替换成等长空白。留空位是为了字符偏移不变：报错行列、source map、调试断点都靠它。

这件事只能逐文件做。加载 `index.ts` 时，Node 手上没有别的文件的类型，也不读 `tsconfig`。它只承认删掉之后不影响其他文件的语法。`enum` 要生成一个运行时对象，`namespace` 要包一层函数，都得新增语句，剥离器不做新增，只做删除。

剥离后的代码交给 V8，V8 看到的和手写 JavaScript 没有区别，所以运行时不存在类型检查。要检查就得另起一个能读整个项目的程序，这就是 `tsc --noEmit` 的位置。

`tsc` 是另一条路：把整个项目读进同一个程序，解析、绑定、检查，再为每个文件写出一份新的 JavaScript。跨文件查类型、生成枚举对象都在这里完成。两条路的分叉点就是处理单位：一个改当前文件，一个重写项目。

两条路对导入路径的要求也不同。Node 剥离时相对导入要写 `.ts` 后缀，`tsc` 输出时靠 `rewriteRelativeImportExtensions` 改成 `.js`，所以源码和产物的路径写法不一样。

依据：Node 官方文档 Type stripping 一节，函数名来自实测报错栈。

剥离不改变模块格式。`import` 和 `export` 原样留给 Node 的模块加载器，`.ts` 文件按最近的 `package.json` 里 `type` 字段决定按 ESM 还是 CommonJS 运行。这条路不生成中间文件，也没有缓存目录。

下面这些语法要生成运行时代码，Node 处理不了：

| 特性 | 报错 | 替代方案 |
|------|------|---------|
| `enum`、`const enum` | `TypeScript enum is not supported in strip-only mode` | 字符串联合，或 `as const` 对象加联合类型 |
| 带值的 `namespace` | `TypeScript namespace declaration is not supported` | 拆成独立模块 |
| 构造函数参数属性（`constructor(public x: number)`） | `TypeScript parameter property is not supported` | 显式声明类属性再赋值 |
| `import x = require()` | `TypeScript import equals declaration is not supported` | 改 `import x from` |
| 装饰器 | `SyntaxError: Invalid or unexpected token` | 用 `tsx` 或 `tsc` |
| JSX（`.tsx` 文件） | `SyntaxError: Unexpected token '<'` | 用 `tsx` 或打包器 |

`const enum` 同样不行。`erasableSyntaxOnly` 会把它报成 `error TS1294`，Node 直接报上面那个 enum 错误。`enum` 的替代写法：

```ts
const Color = { Red: 0, Green: 1 } as const;
type Color = (typeof Color)[keyof typeof Color];

function paint(c: Color): string {
  return c === Color.Red ? "red" : "green";
}

console.log(paint(Color.Red));
```

```bash
$ node color.ts
red
```

为配合 Node.js 原生类型剥离，推荐以下 `tsconfig.json` 设置：

```json
{
  "compilerOptions": {
    "noEmit": true,
    "target": "esnext",
    "module": "nodenext",
    "rewriteRelativeImportExtensions": true,
    "erasableSyntaxOnly": true,
    "verbatimModuleSyntax": true
  }
}
```

- `noEmit`：`tsc` 只检查，产物交给 Node。
- `target: esnext`：不降级语法。
- `module: nodenext`：按 Node 的规则解析模块。
- `rewriteRelativeImportExtensions`：源码写 `./math.ts`，`tsc` 产物改成 `./math.js`。
- [`erasableSyntaxOnly`](https://devblogs.microsoft.com/typescript/announcing-typescript-5-8/)：把 `enum`、参数属性报成 `error TS1294`，不让它等到运行时才炸。
- `verbatimModuleSyntax`：纯类型导入必须写 `import type`，否则报 `error TS1484`。

`package.json` 里没写 `"type": "module"` 时，`nodenext` 按 CommonJS 处理。文件里写 `import` 或 `export` 会报 `error TS1287`。按 ESM 用时加 `"type": "module"`。

### 方式二：tsx

[tsx](https://github.com/privatenumber/tsx) 是基于 esbuild 的执行工具，支持 JSX、装饰器等 Node 原生不支持的语法。当前版本 4.23.15。

```bash
npm install -g tsx
tsx index.ts       # 直接运行 .ts
tsx watch index.ts # 文件变了就重跑
```

### 方式三：ts-node

`ts-node` 最后一个版本是 10.9.2，2023 年 12 月以后没有再更新。新项目改用 `tsx`。老项目迁移前可以这样跑：

```bash
npm install -g ts-node
ts-node index.ts

# 跳过类型检查，快一些
ts-node --transpileOnly index.ts
```

### TypeScript Playground

想快速试验一段代码，用 [TypeScript Playground](https://www.typescriptlang.org/play)。它在线运行 TS 代码，支持：

- 实时查看编译后的 JS
- 可视化配置 tsconfig
- 查看类型推导信息
- 分享代码链接

## 环境类报错最常见的三条

```ts
// e02enum.ts
enum Level { Info, Error }
// e02import.ts
import { Agent } from "./agent";
```

- `e02enum.ts(1,6): error TS1294: This syntax is not allowed when 'erasableSyntaxOnly' is enabled.` 配置要求可擦除语法，`enum` 不是。改法：字符串联合，或 `as const` 对象加类型提取。
- `e02import.ts(1,10): error TS1484: 'Agent' is a type and must be imported using a type-only import when 'verbatimModuleSyntax' is enabled.` 导入的名字只当类型用，必须写 `import type { Agent }`。改法：把它拆成 `import type` 一行。
- `SyntaxError [ERR_UNSUPPORTED_TYPESCRIPT_SYNTAX]: TypeScript enum is not supported in strip-only mode` 这是 Node 直接执行时报的运行时错误，没有 TS 编号。改法：换 `tsx`，或先跑 `tsc` 再用 `node` 跑产物。

## VS Code 配置

VS Code 本身就是用 TypeScript 写的，对 TS 有原生支持。推荐以下配置和插件：

### 推荐插件

| 插件 | 用途 |
|------|------|
| **Error Lens** | 将错误信息直接显示在代码行内，无需看底部问题面板 |

### 开启 Inlay Hints

在 VS Code 设置中搜索 `typescript.inlayHints`，推荐开启：

- **Function Like Return Types**：显示推导出的函数返回值类型
- **Parameter Names**：显示函数调用时的参数名
- **Parameter Types**：显示函数调用时的参数类型
- **Variable Types**：显示变量声明时的推导类型

开启后的效果：

```typescript
// 编辑器中会以灰色文字显示推导的类型
const name = "TypeScript";        // : string（自动显示）
function add(a, b) {              // : number（自动显示）
  return a + b;
}
```

## tsconfig.json 快速入门

[`tsconfig.json`](https://www.typescriptlang.org/tsconfig) 是 TypeScript 项目的配置文件。常用的初始配置：

```json
{
  "compilerOptions": {
    "target": "ES2022",
    "module": "ESNext",
    "moduleResolution": "bundler",
    "strict": true,
    "esModuleInterop": true,
    "skipLibCheck": true,
    "outDir": "./dist",
    "rootDir": "./src",
    "declaration": true
  },
  "include": ["src/**/*"]
}
```

关键配置说明：

- **`target`**：编译后的 JavaScript 版本，推荐 `ES2022`
- **`module`**：模块系统，现代项目推荐 `ESNext`
- **`strict`**：开启所有严格检查（强烈推荐）
- **`outDir`**：编译输出目录
- **`include`**：指定要编译的文件范围

Node 后端把 `module` 和 `moduleResolution` 都写 `nodenext`，见第 27 章。

详细的 TSConfig 配置将在第 23 章讲解。

## 小结

- 版本：`tsc --version` 是 [7.0.2](https://devblogs.microsoft.com/typescript/announcing-typescript-7-0/)，`node --version` 是 26.13.1。
- `node app.ts` 靠类型剥离运行。`enum`、参数属性、`import x = require`、装饰器、`.tsx` 都会报错，改用 `tsx` 或 `tsc`。
- Node 不检查类型。检查交给 `tsc --noEmit`，发布交给 `tsc` 产物。
- 目录里有 `tsconfig.json` 时，`tsc index.ts` 会报 TS5112。单文件编译加 `--ignoreConfig`。

## 用不上的时候

### 只跑一次的脚本

`node app.ts` 在 Node 26 能直接执行可擦除语法，不需要 `tsc`、`tsconfig` 或构建步骤。

### 已有框架的项目

Vite、Next.js 自带转译。再装全局 `tsc` 容易和项目内版本冲突，把 `--noEmit` 交给 CI 就够。

### 用装饰器的框架

NestJS、TypeORM 的源码依赖参数属性与装饰器，原生剥离跑不了，只能编译或用 `tsx`。
