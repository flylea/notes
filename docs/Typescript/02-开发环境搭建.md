# 第2章 开发环境搭建

## 安装 TypeScript

你需要 Node.js 环境。安装 TypeScript 编译器：

```bash
npm install -g typescript
# 或使用 pnpm
pnpm add -g typescript
```

安装完成后验证：

```bash
tsc --version
# Version 5.8.3 (或更高版本)
```

### 创建项目

```bash
mkdir my-ts-project && cd my-ts-project
tsc --init    # 生成 tsconfig.json
```

`tsc --init` 会创建一个包含默认配置的 `tsconfig.json` 文件，带有详细的注释说明每个选项的含义。

### 编译第一个 TS 文件

```typescript
// index.ts
function greet(name: string): string {
  return `Hello, ${name}!`;
}

console.log(greet("TypeScript"));
```

```bash
tsc index.ts        # 编译生成 index.js
node index.js       # 运行编译后的 JS
# 或一步到位：
tsc index.ts && node index.js
```

如果想同时编译和运行，推荐使用以下工具。

## 快速执行 TS 文件

### 方式一：Node.js 原生运行（推荐）

从 **Node.js 23.6** 开始，Node.js 原生支持直接运行 `.ts` 文件，无需安装任何第三方工具：

```bash
node index.ts       # 直接运行 TypeScript 文件
node --watch index.ts  # 监听文件变化自动重新运行
```

Node.js **22.6+** 也可以通过实验性 flag 启用：

```bash
node --experimental-strip-types index.ts
```

**工作原理**：Node.js 在加载 `.ts` 文件时会进行**类型剥离（Type Stripping）**——将 TypeScript 特有的类型标注、interface、类型导入等语法删除，替换为空白，使 V8 引擎能够执行剩余的纯 JavaScript 代码：

```typescript
// 你写的代码
function greet(name: string): string {
  return `Hello, ${name}!`;
}

// Node.js 类型剥离后等价于
function greet(name) {
  return `Hello, ${name}!`;
}
```

**重要提示**：Node.js 只剥离类型，**不进行类型检查**。你仍然需要 `tsc --noEmit` 在开发或 CI 中进行类型检查：

```bash
tsc --noEmit        # 仅检查类型，不生成文件
```

**当前不支持的特性**：以下 TypeScript 语法需要代码生成（不仅仅是类型擦除），Node.js 原生运行**不支持**：

| 特性 | 替代方案 |
|------|---------|
| `enum` | 使用 `const enum` 或联合类型 |
| `namespace` | 使用 ES Module（`export {}`） |
| 构造函数参数属性（`constructor(public x: number)`） | 显式声明类属性 |
| JSX（`.tsx` 文件） | 需要 `tsx` 或 `tsc` |
| 实验性装饰器 | 等待原生 JS 装饰器支持 |

为配合 Node.js 原生类型剥离，推荐以下 `tsconfig.json` 设置：

```json
{
  "compilerOptions": {
    "target": "esnext",
    "module": "nodenext",
    "moduleResolution": "nodenext",
    "allowImportingTsExtensions": true,
    "verbatimModuleSyntax": true,
    "noEmit": true,
    "isolatedModules": true,
    "erasableSyntaxOnly": true
  }
}
```

其中 `erasableSyntaxOnly`（TypeScript 5.8+）可以在编译时捕获 Node.js 不支持的语法。

### 方式二：tsx

[tsx](https://github.com/privatenumber/tsx) 是基于 esbuild 的 TS 执行工具，支持 JSX、装饰器等 Node.js 原生不支持的语法：

```bash
npm install -g tsx
tsx index.ts       # 直接运行，无需编译步骤
tsx watch index.ts # 监听文件变化自动重新运行
```

### 方式三：ts-node

```bash
npm install -g ts-node
ts-node index.ts

# 跳过类型检查以加快执行速度
ts-node --transpileOnly index.ts

# 配合 SWC 进一步加速
ts-node --swc index.ts
```

### TypeScript Playground

如果只是想快速试验一段代码，[TypeScript Playground](https://www.typescriptlang.org/play) 是最方便的选择。它在线运行 TS 代码，支持：

- 实时查看编译后的 JS
- 可视化配置 tsconfig
- 查看类型推导信息
- 分享代码链接

## VS Code 配置

VS Code 本身就是用 TypeScript 写的，对 TS 有原生支持。推荐以下配置和插件：

### 推荐插件

| 插件 | 用途 |
|------|------|
| **Error Lens** | 将错误信息直接显示在代码行内，无需看底部问题面板 |

### 开启 Inlay Hints

在 VS Code 设置中搜索 `typescript.inlayHints`，推荐开启：

- **Function Like Return Types**：显示推导出的函数返回值类型
- **Parameter Names**：显示函数调用时的参数名
- **Parameter Types**：显示函数调用时的参数类型
- **Variable Types**：显示变量声明时的推导类型

开启后的效果：

```typescript
// 编辑器中会以灰色文字显示推导的类型
const name = "TypeScript";        // : string（自动显示）
function add(a, b) {              // : number（自动显示）
  return a + b;
}
```

## tsconfig.json 快速入门

`tsconfig.json` 是 TypeScript 项目的配置文件。常用的初始配置：

```json
{
  "compilerOptions": {
    "target": "ES2022",
    "module": "ESNext",
    "moduleResolution": "bundler",
    "strict": true,
    "esModuleInterop": true,
    "skipLibCheck": true,
    "outDir": "./dist",
    "rootDir": "./src",
    "declaration": true
  },
  "include": ["src/**/*"]
}
```

关键配置说明：

- **`target`**：编译后的 JavaScript 版本，推荐 `ES2022`
- **`module`**：模块系统，现代项目推荐 `ESNext`
- **`strict`**：开启所有严格检查（强烈推荐）
- **`outDir`**：编译输出目录
- **`include`**：指定要编译的文件范围

详细的 TSConfig 配置将在第 23 章讲解。

## 使用 declare 进行类型检查

在某些场景中，我们只想做类型兼容性检查，而不想真的创建变量。此时可以使用 `declare` 关键字：

```typescript
interface Foo {
  name: string;
  age: number;
}

interface Bar {
  name: string;
  age: number;
  job: string;
}

// 仅在类型空间中声明，运行时不存在
declare let foo: Foo;
declare let bar: Bar;

foo = bar; // ✅ 合法：Bar 满足 Foo 的所有属性
```

`declare` 声明的变量只存在于"类型空间"，编译后会被完全删除，不会产生任何运行时代码。
