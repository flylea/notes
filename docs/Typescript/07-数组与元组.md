# 第7章 数组与元组

数组是 JavaScript 中最常用的数据结构。TypeScript 在数组之上额外提供了**元组（Tuple）**——定长、每位置类型确定的特殊数组。本章将系统讲解数组与元组的类型标注、类型推导、只读修饰以及 TypeScript 4.0 引入的可变元组类型。

## 数组类型

### 两种等价写法

数组类型的声明有两种形式，在功能上完全等价：

```typescript
// T[] 写法（推荐，更简洁）
const nums: number[] = [1, 2, 3];
const strs: string[] = ["a", "b", "c"];

// Array<T> 泛型写法
const nums2: Array<number> = [1, 2, 3];
const strs2: Array<string> = ["a", "b", "c"];
```

将鼠标悬停在 `Array<number>` 上，IDE 会显示 `number[]`——两者在 TypeScript 内部是同一个类型。`T[]` 是社区主流写法，但 `Array<T>` 在成员类型较复杂时可读性更好：

```typescript
// Array<T> 在复杂类型中更清晰
const arr1: (string | number | boolean)[] = [1, "a", true];
const arr2: Array<string | number | boolean> = [1, "a", true];
```

注意区分 `(string | number)[]` 和 `string | number[]`——前者表示"元素可以是 string 或 number 的数组"，后者表示"string 或 number[]"（因为 `|` 的优先级低于 `[]`）。括号是必需的。

### 数组的类型推导

TypeScript 会根据数组元素的初始值自动推导数组类型：

```typescript
const a1 = [1, 2, 3];            // number[]
const a2 = ["a", "b"];            // string[]
const a3 = [1, "a"];              // (string | number)[]
```

**空数组的推导**是一个需要特别注意的场景：

```typescript
// 空数组被推导为 any[]（noImplicitAny 关闭时）
const arr = [];

// 后续 push 会动态更新推导类型
arr.push(123);         // 现在推导为 number[]
arr.push("abc");       // 现在推导为 (string | number)[]
```

这种"类型随着操作演进"的行为称为 **evolving array**。但它在 `noImplicitAny` 开启时表现不同——如果在 type 还是 `any[]` 时就读取该变量，会直接报错：

```typescript
const arr = [];
// console.log(arr[0]);  // ❌ noImplicitAny 下报错：变量类型尚不明确
arr.push(1);
console.log(arr[0]);      // ✅ 此时已推导为 number[]
```

如果数组的初始值非空，则类型推导**不会**因为后续 push 而改变：

```typescript
const arr = [123];         // 推导为 number[]
// arr.push("abc");       // ❌ 此时再 push string 会报错
```

### 多维数组

多维数组用 `T[][]` 的形式标注，最外层 `[]` 表示数组，内层 `[]` 表示元素的类型——`T[][]` 读作"T 的二维数组"，即"元素为 `T[]` 的数组"：

```typescript
const matrix: number[][] = [
  [1, 2, 3],
  [4, 5, 6],
];

// 访问和赋值都有类型检查
const firstRow: number[] = matrix[0];   // [1, 2, 3]
const cell: number = matrix[0][1];      // 2
```

等价地可以使用 `Array<Array<T>>` 泛型写法，当类型嵌套较深时可能更清晰：

```typescript
const matrix: Array<Array<number>> = [
  [1, 2, 3],
  [4, 5, 6],
];
```

#### 实际应用场景

二维数组在以下场景中非常常见：

**图像像素矩阵**——一张图片的每个像素用 `[R, G, B, A]` 表示：

```typescript
// 一张 100×100 的图像：100 行，每行 100 个像素
type Pixel = [number, number, number, number];
type ImageData = Pixel[][];

const image: ImageData = new Array(100).fill(null).map(() =>
  new Array(100).fill([0, 0, 0, 255] as const)
);
```

**游戏棋盘**——每个格子有自己的状态：

```typescript
type Cell = { x: number; y: number; occupied: boolean; piece: string | null };
type Board = Cell[][];  // 8×8 棋盘

function createBoard(rows: number, cols: number): Board {
  return Array.from({ length: rows }, (_, y) =>
    Array.from({ length: cols }, (_, x) => ({
      x, y, occupied: false, piece: null,
    }))
  );
}
```

**电子表格数据**——每行是一组数据：

```typescript
type Row = [name: string, age: number, city: string];
type Spreadsheet = Row[];  // 等价于二维数组
```

#### 矩形数组 vs 交错数组

在 TypeScript 类型层面，`number[][]` 不保证每行的长度一致——它表示的是**交错数组（jagged array）**：

```typescript
// ✅ 合法的 number[][]——每行长度不同
const jagged: number[][] = [
  [1, 2, 3],
  [4],
  [5, 6, 7, 8],
];
```

如果需要**矩形数组**（每行固定长度），需要用元组约束每一行：

```typescript
// 3×3 矩阵——每行必须是 3 个 number
type Matrix3x3 = [
  [number, number, number],
  [number, number, number],
  [number, number, number],
];

const mat: Matrix3x3 = [
  [1, 2, 3],
  [4, 5, 6],
  [7, 8, 9],
];
```

三维及更高维度的数组通过继续追加 `[]` 表示：

```typescript
const cube: number[][][] = [[[1, 2]], [[3, 4]]];  // 三维
```

不过维度超过二维后，`Array<Array<Array<T>>>` 的读法往往更直观：从内向外读——T 的一维数组的数组的数组。

### 类数组对象（Array-like）

JavaScript 中有一些对象"长得像数组"——有数字索引和 `length` 属性——但不是真正的数组，没有 `push`、`map` 等数组方法。TypeScript 为常见的类数组对象提供了专门的类型。

**arguments 对象**

函数内部的 `arguments` 是类数组对象的典型代表。TypeScript 中它的类型是 `IArguments`：

```typescript
function sum() {
  // arguments 的类型是 IArguments，不是 any[]
  let total = 0;
  for (let i = 0; i < arguments.length; i++) {
    total += arguments[i];  // ✅ 可以索引访问
  }
  // arguments.map(x => x * 2);  // ❌ arguments 没有 map 方法
  return total;
}
```

注意：在箭头函数中没有 `arguments` 对象，用 rest 参数 `(...args: number[])` 替代更符合 TypeScript 的习惯。

**DOM 集合**

浏览器 API 返回的 DOM 集合几乎都是类数组对象：

```typescript
// querySelectorAll 返回 NodeListOf<T>
const divs: NodeListOf<HTMLDivElement> = document.querySelectorAll("div");
divs.forEach(div => console.log(div));  // ✅ NodeList 有 forEach
// divs.map(div => div);               // ❌ 但没有 map

// getElementsByClassName 返回 HTMLCollection
const imgs: HTMLCollectionOf<HTMLImageElement> = document.getElementsByClassName("avatar");
// HTMLCollection 甚至没有 forEach——只能通过索引遍历
for (let i = 0; i < imgs.length; i++) {
  console.log(imgs[i].src);
}
```

`NodeListOf<T>` 和 `HTMLCollectionOf<T>` 都是泛型类数组类型，前者元素类型是 `T`，后者元素类型是 `T`。它们都支持 `length` 和数字索引访问，但 API 略有不同。

**将类数组转为真正的数组**

当需要对类数组对象使用数组方法时，用 `Array.from` 或展开运算符转换：

```typescript
const divs = document.querySelectorAll("div");

// 转为真正的数组
const divArray = Array.from(divs);       // HTMLDivElement[]
const divArray2 = [...divs];             // HTMLDivElement[]

// 现在可以使用全部数组方法
const ids = divArray.map(div => div.id);
```

**自定义类数组类型**

如果你自己实现了一个类数组结构，可以通过定义数字索引签名和 `length` 属性来描述它：

```typescript
interface ArrayLike<T> {
  readonly length: number;
  readonly [n: number]: T;
}

function take<T>(arr: ArrayLike<T>, n: number): T[] {
  const result: T[] = [];
  for (let i = 0; i < Math.min(n, arr.length); i++) {
    result.push(arr[i]);
  }
  return result;
}
```

TypeScript 标准库中已经定义了 `ArrayLike<T>` 接口，所以在实际项目中不需要重复声明。

## 只读数组

JavaScript 中 `const` 声明的数组仍然可以修改元素。TypeScript 提供了 `readonly` 修饰符来声明真正不可变的数组。

### 基本用法

```typescript
const nums: readonly number[] = [1, 2, 3];
// nums[0] = 0;    // ❌ 只读数组不允许索引赋值
// nums.push(4);    // ❌ 不存在 push 方法
// nums.pop();      // ❌ 不存在 pop 方法
```

`readonly number[]` 本质上是 `ReadonlyArray<number>` 的简写。TypeScript 也提供了另外几种等价写法：

```typescript
const a1: readonly number[] = [1, 2, 3];
const a2: ReadonlyArray<number> = [1, 2, 3];
const a3: Readonly<number[]> = [1, 2, 3];
```

注意三者的区别：
- `ReadonlyArray<number>` — 泛型尖括号内是**元素类型**（`number`）
- `Readonly<number[]>` — 泛型尖括号内是**整个数组类型**（`number[]`）
- `readonly` 不能与 `Array<T>` 泛型连用：`readonly Array<number>` 会报错

### 只读数组与可变数组的兼容性

这是一个需要重点理解的地方：**可变数组可以赋值给只读数组，但反过来不行**。

```typescript
let mutable: number[] = [1, 2, 3];
let readonly: readonly number[] = [1, 2, 3];

readonly = mutable;   // ✅ 可变 → 只读，安全（放宽了约束）
// mutable = readonly;  // ❌ 只读 → 可变，不安全（逃避了不可变保证）
```

理解这个兼容性方向的关键是：`readonly number[]` 缺少 `push`、`pop`、`splice` 等修改自身的方法，而 `number[]` 拥有这些方法。从"拥有多少方法"的角度看，`number[]` 是 `readonly number[]` 的**子类型**——它多了修改数组的能力。子类型可以安全地赋值给父类型（丢失部分能力），反过来则不行。

这会导致一种常见的困惑场景：

```typescript
function sum(nums: number[]) {
  return nums.reduce((acc, n) => acc + n, 0);
}

const arr: readonly number[] = [1, 2, 3];
// sum(arr);  // ❌ 类型 'readonly number[]' 不能赋给 'number[]'
```

虽然 `sum` 函数并没有修改数组，但由于参数类型声明为 `number[]`，传入只读数组就会报错。最佳实践是：**如果函数不会修改数组，参数类型就应声明为 `readonly number[]`**：

```typescript
function sum(nums: readonly number[]): number {
  return nums.reduce((acc, n) => acc + n, 0);
}

const arr: readonly number[] = [1, 2, 3];
sum(arr);  // ✅
sum([1, 2, 3]);  // ✅ 可变数组也能传入
```

## 元组（Tuple）

**元组**是 TypeScript 特有的类型，表示一个**长度固定、每个位置类型确定**的数组。JavaScript 运行时不区分数组和元组——这只是 TypeScript 编译时的约束。

### 基本元组

```typescript
// 第一个是 string，第二个是 number
const pair: [string, number] = ["hello", 42];

// 越界访问会报错
// const c = pair[2];  // ❌ 长度为 2 的元组在索引 2 处没有元素

// 每个位置的类型精确对应
const [s, n] = pair;
// s: string
// n: number
```

元组与数组在语法上的关键区别：**成员类型写在方括号里面**的是元组（`[string, number]`），**成员类型写在方括号外面**的是数组（`string[]`）：

```typescript
let a: number[] = [1];     // 数组——不限长度
let t: [number] = [1];     // 元组——长度为 1
```

### 元组必须显式标注类型

TypeScript 不会自动将数组字面量推导为元组：

```typescript
// 即使从语义上看像是元组，但 TypeScript 推导为联合类型数组
const mixed = [1, true];   // 类型: (number | boolean)[]

// 必须显式标注才会成为元组
const tuple: [number, boolean] = [1, true];
```

### 可选元素

元组元素后加 `?` 表示可选，可选元素只能出现在元组尾部（和函数参数规则一致）：

```typescript
type Coordinate = [number, number, number?];

const c1: Coordinate = [1, 2];      // ✅ 二维
const c2: Coordinate = [1, 2, 3];   // ✅ 三维

// 可选元素影响 length 的类型
function process(coord: Coordinate) {
  console.log(coord.length);  // 类型: 2 | 3
}
```

由于 `length` 的类型被精确为 `2 | 3`，TypeScript 可以在编译时发现无意义的长度检查：

```typescript
function process(coord: Coordinate) {
  // if (coord.length === 4) { }  // ❌ 这个比较永远为 false
}
```

### 具名元组（Labeled Tuple）

TypeScript 4.0 引入了具名元组，可以为每个位置加上标签来提高可读性。标签**纯粹是文档作用**，不影响类型行为：

```typescript
type HTTPResponse = [statusCode: number, body: string];

const res: HTTPResponse = [200, "OK"];

// 标签在 IDE 提示和解构时可见
const [code, content] = res;  // code: number, content: string
```

### rest 元素在元组中

元组可以包含 rest 元素（`...`），表示"从这个位置开始，可以有任意数量的同类型元素"：

```typescript
// 第一个是 string，后面可以跟任意数量的 string
type StringList = [string, ...string[]];
const list: StringList = ["head", "a", "b", "c"];

// 第一个是 string，最后一个是 number，中间任意数量的 boolean
type Sandwich = [string, ...boolean[], number];
const s1: Sandwich = ["start", 42];          // ✅ 0 个 boolean
const s2: Sandwich = ["start", true, 42];    // ✅ 1 个 boolean
const s3: Sandwich = ["start", true, false, true, 42];  // ✅ 多个
```

rest 元素在元组中不限于尾部——可以出现在任意位置，但**只能出现一个 rest 元素**：

```typescript
type T1 = [string, ...number[], boolean];     // rest 在中间
type T2 = [...boolean[], string, number];     // rest 在头部
type T3 = [string, number, ...boolean[]];     // rest 在尾部
```

一旦元组包含 rest 元素，TypeScript 就无法推断出具体的成员数量了，该元组在 `length` 检查上会被当作数组处理。

### 只读元组

和数组一样，元组可以加 `readonly` 修饰：

```typescript
const point: readonly [number, number] = [3, 4];
// point[0] = 5;  // ❌ 不能修改

// 等价写法
type ReadonlyPoint = Readonly<[number, number]>;
```

兼容性规则同样适用：可变元组可以赋值给只读元组，反过来不行。这导致一个常见问题：

```typescript
function distanceFromOrigin([x, y]: [number, number]) {
  return Math.sqrt(x ** 2 + y ** 2);
}

const point = [3, 4] as const;
// distanceFromOrigin(point);  // ❌ readonly [3, 4] 不能赋给 [number, number]
```

尽管 `distanceFromOrigin` 不会修改参数，但由于它声明了可变元组类型，传入 `as const` 产生的只读元组就会报错。最佳实践依然是：**函数参数如果不修改元组，就应该声明为 `readonly`**：

```typescript
function distanceFromOrigin([x, y]: readonly [number, number]) {
  return Math.sqrt(x ** 2 + y ** 2);
}
```

## as const 与数组/元组

`as const` 对数组有三重效果，前面第 4 章已经介绍过，这里从数组/元组角度做深入理解：

```typescript
// 普通数组推导
const arr1 = [1, 2, 3];     // number[]

// as const 后：变为只读元组，每个元素获得字面量类型
const arr2 = [1, 2, 3] as const;
// 类型: readonly [1, 2, 3]
```

`as const` 将数组推导为**只读元组**（而非只读数组），这意味着：
- 长度是固定的（3，不是无限）
- 每个位置有精确的字面量类型（`1` 而非 `number`）
- 整体是 `readonly`

这个行为在需要精确类型推断的场景中非常有用：

```typescript
// 从数组提取联合类型
const COLORS = ["red", "green", "blue"] as const;
type Color = (typeof COLORS)[number];  // "red" | "green" | "blue"

// 固定参数个数的函数中展开元组
function add(x: number, y: number): number {
  return x + y;
}

const nums = [1, 2] as const;
add(...nums);  // ✅ readonly [1, 2] 确定是 2 个参数
```

## 可变元组类型（Variadic Tuple Types）

TypeScript 4.0 引入了可变元组类型，可以在泛型中对元组进行展开、提取、拼接等类型操作。这是类型编程领域的重要能力。

### 泛型展开

在泛型中使用 `...` 展开元组或数组：

```typescript
// 将元组转换为函数的参数列表
type Args = [string, number, boolean];

// 在泛型约束中展开
function call<T extends unknown[], R>(fn: (...args: T) => R, ...args: T): R {
  return fn(...args);
}
```

### 类型层面的元组操作

```typescript
// 获取元组的"尾巴"（去掉第一个元素后剩余的部分）
type Tail<T extends unknown[]> = 
  T extends [unknown, ...infer Rest] ? Rest : never;

type T1 = Tail<[string, number, boolean]>;  // [number, boolean]
type T2 = Tail<[1]>;                         // []
type T3 = Tail<[]>;                          // never

// 获取最后一个元素之前的"头部"
type Init<T extends unknown[]> = 
  T extends [...infer Head, unknown] ? Head : never;

type T4 = Init<[string, number, boolean]>;  // [string, number]

// 拼接两个元组
type Concat<T extends unknown[], U extends unknown[]> = [...T, ...U];

type T5 = Concat<[1, 2], ["a", "b"]>;  // [1, 2, "a", "b"]
type T6 = Concat<[1], [2, 3, 4]>;      // [1, 2, 3, 4]
```

### 实际应用：curry 函数的类型

可变元组类型的经典用例之一是为 curry 函数提供精确的类型：

```typescript
// 偏函数：先固定部分参数，返回接收剩余参数的新函数
function partial<T extends unknown[], U extends unknown[], R>(
  fn: (...args: [...T, ...U]) => R,
  ...fixedArgs: T
): (...rest: U) => R {
  return (...rest) => fn(...fixedArgs, ...rest);
}

// 使用
function greet(greeting: string, name: string, punctuation: string): string {
  return `${greeting}, ${name}${punctuation}`;
}

const sayHello = partial(greet, "Hello");
// sayHello 的类型: (rest: [string, string]) => string
const result = sayHello("Alice", "!");  // "Hello, Alice!"
```

### 标签在泛型展开中的保留

具名元组的标签在泛型展开后会保留：

```typescript
type Named = [name: string, age: number];
type WithId = [id: number, ...Named];

// WithId = [id: number, name: string, age: number]
// 标签被保留下来，帮助理解每个位置的含义
```

## 元组的实际使用场景

### React useState 返回值

React 的 `useState` 返回的就是一个元组：

```typescript
// useState 的简化类型签名
function useState<S>(initialState: S): [S, (value: S) => void] {
  // ...
}

const [count, setCount] = useState(0);
// count: number
// setCount: (value: number) => void
```

元组返回类型使得解构赋值时，每个变量都能获得对应位置的精确类型。

### API 结果的错误/数据模式

Go 语言风格的错误处理模式可以用元组表达：

```typescript
type ApiResult<T> = [error: Error | null, data: T | null];

async function fetchUser(id: number): Promise<ApiResult<User>> {
  try {
    const res = await fetch(`/api/users/${id}`);
    const data = await res.json();
    return [null, data];
  } catch (e) {
    return [e as Error, null];
  }
}

// 使用
const [err, user] = await fetchUser(1);
if (err) {
  console.error(err.message);
} else {
  // user 在此分支被收窄为 User
}
```

### CSV 数据行

CSV 的每行数据天然适合用元组表达：

```typescript
type CSVRow = [name: string, age: number, city: string, active: boolean];

const rows: CSVRow[] = [
  ["Alice", 25, "NYC", true],
  ["Bob", 30, "LA", false],
];

// 读取时类型精确
rows.forEach(([name, age, city, active]) => {
  // name: string, age: number, city: string, active: boolean
});
```

## 数组方法中的泛型推导

TypeScript 内置的数组方法都有完善的泛型类型签名，可以自动推导返回值类型：

```typescript
const nums = [1, 2, 3];

// map 推导为 number[]
const doubled = nums.map(n => n * 2);

// map 改变类型，推导为 string[]
const strs = nums.map(n => String(n));

// find 推导为 number | undefined（可能找不到）
const found = nums.find(n => n > 1);

// filter 推导为 number[]（TypeScript 不会收窄 filter 的结果类型）
const filtered = nums.filter(n => n > 1);  // 仍然是 number[]

// reduce 推导依赖初始值类型
const sum = nums.reduce((acc, n) => acc + n, 0);  // number
```

对于 `filter`，TypeScript 并不会将"过滤后的数组"推导为更精确的类型——它在类型层面始终返回 `T[]`。如果需要更精确的类型（比如过滤掉 `undefined`），需要用自定义类型守卫：

```typescript
const arr = [1, undefined, 2, undefined, 3];
// filter 后仍然是 (number | undefined)[]
const filtered = arr.filter(n => n !== undefined);

// 使用类型守卫才能收窄
const narrowFiltered = arr.filter((n): n is number => n !== undefined);
// 类型: number[]
```

## 数组与元组的边界情况

### 越界访问

数组的越界访问不会报编译错误（数组长度是不确定的），而元组的越界访问会报错：

```typescript
const arr: number[] = [1, 2, 3];
const x = arr[999];  // ✅ 类型是 number（运行时是 undefined，但 TS 不检查）

const tuple: [string, number] = ["a", 1];
// const y = tuple[2];  // ❌ 长度为 2 的元组在索引 2 处没有元素
```

这是 TypeScript 的刻意设计：数组的长度在运行时可以动态变化，编译时检查边界没有意义；而元组的长度在类型层面就是确定的。

### 数组类型的索引访问

使用 `T[number]` 可以获取数组成员类型：

```typescript
type Names = string[];
type Name = Names[number];     // string

type Mixed = (string | number)[];
type Item = Mixed[number];     // string | number
```

元组也可以用索引访问类型获取某个位置或所有位置的类型：

```typescript
type Tuple = [string, number, boolean];
type First = Tuple[0];        // string
type Second = Tuple[1];       // number
type All = Tuple[number];     // string | number | boolean
```

## 本章小结

- 数组用 `T[]` 或 `Array<T>` 标注，前者是社区主流写法
- 空数组推导为 `any[]` 时会随 push 操作动态演进类型（evolving array）
- **多维数组**通过追加 `[]` 表示（`number[][]`），实际场景包括图像像素矩阵、游戏棋盘、电子表格等。类型层面不保证每行长度一致（交错数组），矩形数组需要用元组约束
- **类数组对象**（`IArguments`、`NodeListOf<T>`、`HTMLCollectionOf<T>` 等）有数字索引和 `length` 但没有数组方法，可用 `Array.from` 转换
- 只读数组用 `readonly T[]` 或 `ReadonlyArray<T>`，可变数组可赋值给只读数组，反过来不行
- **元组**长度固定、每位置类型确定，适合表达结构固定的多值组合
- 元组支持可选元素（`?`）、具名标签（4.0）、rest 元素和 `readonly` 修饰
- `as const` 将数组推导为只读元组，每个元素获得字面量类型
- **可变元组类型**（4.0+）支持泛型层面的元组展开、拼接和提取（`[...T, ...U]`）
- 元组常用于 React useState、API 错误/数据模式、CSV 行等固定结构场景
