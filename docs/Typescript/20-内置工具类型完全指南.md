# 第 20 章 内置工具类型

一个接口有 30 个字段，更新接口只想放开其中几个；从联合类型里排除 `null` 要写一串条件。内置工具类型覆盖了这些高频操作。这一章按用途分组讲 20 多个工具类型的行为与边界。

TypeScript 自带 20 多个[工具类型](https://www.typescriptlang.org/docs/handbook/utility-types.html)，覆盖属性修饰、属性选取、键值构造、联合筛选、函数提取、Promise 解包、字符串变换与 this 标记。下面按功能分组，每个给出用法、实现和边界。

## 属性修饰工具

这三个工具类型用映射类型控制属性的可选性和只读性。

### Partial\<T\>

把所有属性变为可选：

```typescript
interface Article {
  id: number;
  title: string;
  body: string;
  authorId: number;
}

type DraftArticle = Partial<Article>;
const draft: DraftArticle = { title: "初稿" };
// { id?: number; title?: string; body?: string; authorId?: number }
```

**实现**：

```typescript
type Partial<T> = {
  [K in keyof T]?: T[K];
};
```

Partial 是同态映射，原属性上的 `?` 和 `readonly` 会保留，只额外增加可选性。

### Required\<T\>

把所有属性变为必选：

```typescript
interface Options {
  url: string;
  method?: string;
  timeout?: number;
}

type FullOptions = Required<Options>;
// { url: string; method: string; timeout: number }
```

**实现**：

```typescript
type Required<T> = {
  [K in keyof T]-?: T[K];
};
```

`-?` 是映射修饰符，作用是把可选标记去掉。

### Readonly\<T\>

把所有属性变为只读：

```typescript
interface Endpoint {
  url: string;
  timeout: number;
}

const endpoint: Readonly<Endpoint> = { url: "/api", timeout: 5000 };
endpoint.url = "/other";  // error TS2540: Cannot assign to 'url' because it is a read-only property.
```

**实现**：

```typescript
type Readonly<T> = {
  readonly [K in keyof T]: T[K];
};
```

Readonly 只做浅层只读。属性值是对象时，对象内部仍然可写。

## 属性选取工具

### Pick\<T, K\>

从类型 `T` 中选一组属性：

```typescript
interface Article {
  id: number;
  title: string;
  body: string;
  authorId: number;
}

type ArticleSummary = Pick<Article, "id" | "title">;
// { id: number; title: string }
```

**实现**：

```typescript
type Pick<T, K extends keyof T> = {
  [P in K]: T[P];
};
```

`K` 受 `keyof T` 约束，键名拼错时直接报 TS2344。

### Omit\<T, K\>

从类型 `T` 中排除一组属性：

```typescript
type PublicArticle = Omit<Article, "authorId">;
// { id: number; title: string; body: string }
```

**实现**：

```typescript
type Omit<T, K extends keyof any> = Pick<T, Exclude<keyof T, K>>;
```

Omit 是 Pick 与 Exclude 的组合：先算出剩余的键，再按这些键取属性。

`K` 的约束是 `keyof any`，不是 `keyof T`。键名拼错不会报错，见后面的坑。

## 键值构造工具

### Record\<K, V\>

构造键类型为 `K`、值类型为 `V` 的对象类型：

```typescript
type PageMeta = Record<"home" | "about", { title: string }>;
// { home: { title: string }; about: { title: string } }

const meta: PageMeta = {
  home: { title: "首页" },
  about: { title: "关于" },
};
```

**实现**：

```typescript
type Record<K extends keyof any, T> = {
  [P in K]: T;
};
```

`K` 必须是 `string`、`number` 或 `symbol` 的子类型。用联合字面量作键时，每个键都要写出来，漏写会报缺少属性。

## 联合类型筛选工具

### Exclude\<T, U\>

从联合类型 `T` 中排除可赋值给 `U` 的成员：

```typescript
type AllEvents = "click" | "submit" | "change" | "keydown";
type PointerEvents = Exclude<AllEvents, "submit" | "change">;  // "click" | "keydown"

type Mixed = string | number | (() => void);
type NonFunc = Exclude<Mixed, Function>;  // string | number
```

**实现**：

```typescript
type Exclude<T, U> = T extends U ? never : T;
```

条件类型对裸类型参数逐成员判断，命中 `U` 的成员变成 `never`，`never` 在联合中消失。

### Extract\<T, U\>

从联合类型 `T` 中保留可赋值给 `U` 的成员：

```typescript
type Mixed = string | number | (() => void);
type Funcs = Extract<Mixed, Function>;  // () => void
```

**实现**：

```typescript
type Extract<T, U> = T extends U ? T : never;
```

### NonNullable\<T\>

去掉 `null` 和 `undefined`：

```typescript
type T0 = NonNullable<string | number | undefined>;  // string | number
type T1 = NonNullable<string[] | null | undefined>;   // string[]
```

**实现**：

```typescript
type NonNullable<T> = T & {};
```

从 [TypeScript 4.8](https://www.typescriptlang.org/docs/handbook/release-notes/typescript-4-8.html) 起，内置实现是 `T & {}`，也可以写成 `T extends null | undefined ? never : T`。

## 函数类型工具

这组工具类型用 `infer` 从函数类型中提取子类型。

### ReturnType\<T\>

提取函数返回值类型：

```typescript
declare function createArticle(): { id: number; title: string };
type Created = ReturnType<typeof createArticle>;  // { id: number; title: string }

type FetchResult = ReturnType<typeof fetch>;  // Promise<Response>
```

**实现**：

```typescript
type ReturnType<T extends (...args: any) => any> =
  T extends (...args: any) => infer R ? R : any;
```

类型参数是 `any` 时结果是 `any`，是 `never` 时结果是 `never`。遇到重载函数，取最后一个签名。

### Parameters\<T\>

提取参数列表，结果是元组：

```typescript
declare function createArticle(title: string, tags?: string[]): { id: number };

type Args = Parameters<typeof createArticle>;  // [title: string, tags?: string[]]

function createMany(...args: Args) {
  return createArticle(...args);
}
```

**实现**：

```typescript
type Parameters<T extends (...args: any) => any> =
  T extends (...args: infer P) => any ? P : never;
```

### ConstructorParameters\<T\>

提取构造函数的参数元组：

```typescript
class Article {
  constructor(public title: string, public authorId: number) {}
}

type CtorArgs = ConstructorParameters<typeof Article>;  // [title: string, authorId: number]
```

**实现**：

```typescript
type ConstructorParameters<T extends abstract new (...args: any) => any> =
  T extends abstract new (...args: infer P) => any ? P : never;
```

约束用 `abstract new` 才能同时接受抽象类和普通类。参数位置必须写 `any`，写 `unknown[]` 会让带参构造函数不满足约束。

### InstanceType\<T\>

提取构造函数对应的实例类型：

```typescript
type ArticleInstance = InstanceType<typeof Article>;  // Article
```

**实现**：

```typescript
type InstanceType<T extends abstract new (...args: any) => any> =
  T extends abstract new (...args: any) => infer R ? R : any;
```

### ThisParameterType\<T\>

提取函数 `this` 参数的类型：

```typescript
function greet(this: { name: string }, greeting: string): string {
  return `${greeting}, ${this.name}`;
}

type Context = ThisParameterType<typeof greet>;  // { name: string }
```

**实现**：

```typescript
type ThisParameterType<T> =
  T extends (this: infer U, ...args: never) => any ? U : unknown;
```

函数没有 `this` 参数时返回 `unknown`。

### OmitThisParameter\<T\>

去掉函数的 `this` 参数：

```typescript
type PlainGreet = OmitThisParameter<typeof greet>;
// (greeting: string) => string
```

**实现**：

```typescript
type OmitThisParameter<T> = unknown extends ThisParameterType<T>
  ? T
  : T extends (...args: infer A) => infer R
    ? (...args: A) => R
    : T;
```

先用 `unknown extends ThisParameterType<T>` 判断有没有 `this` 参数，有则拆出参数列表和返回值重新组装。

## Promise 工具

### Awaited\<T\>

递归解包 Promise，拿到最终值类型：

```typescript
type A = Awaited<Promise<string>>;            // string
type B = Awaited<Promise<Promise<number>>>;   // number
type C = Awaited<boolean | Promise<number>>;  // boolean | number
```

**实现**：

```typescript
type Awaited<T> = T extends null | undefined
  ? T
  : T extends object & { then(onfulfilled: infer F, ...args: infer _): any }
    ? F extends (value: infer V, ...args: infer _) => any
      ? Awaited<V>
      : never
    : T;
```

实现会识别任何带 `then` 方法的对象，所以 PromiseLike 和自定义 thenable 都能解包。`null` 和 `undefined` 原样返回。

## NoInfer\<T\>（TS 5.4+）

阻止某个位置参与泛型推导：

```typescript
function createMachine<T extends string>(config: {
  states: readonly T[];
  initial: NoInfer<T>;
}) {
  return config.initial;
}

createMachine({ states: ["idle", "running"] as const, initial: "running" });

createMachine({ states: ["idle", "running"] as const, initial: "paused" });  // error TS2322: Type '"paused"' is not assignable to type '"idle" | "running"'.
```

去掉 NoInfer 后，`initial` 也参与推导，`T` 被扩大成 `"idle" | "running" | "paused"`，拼错的状态混进类型也不报错。

NoInfer 在 lib 里是 `type NoInfer<T> = intrinsic`，只在类型检查阶段生效，没有运行时开销。

## 字符串操作工具

| 工具类型 | 效果 |
|---|---|
| `Uppercase<S>` | 全部大写 |
| `Lowercase<S>` | 全部小写 |
| `Capitalize<S>` | 首字母大写 |
| `Uncapitalize<S>` | 首字母小写 |

```typescript
type T1 = Uppercase<"hello">;      // "HELLO"
type T2 = Lowercase<"HELLO">;      // "hello"
type T3 = Capitalize<"hello">;     // "Hello"
type T4 = Uncapitalize<"Hello">;   // "hello"
```

这四个类型由编译器 intrinsic 实现，只接受字符串字面量，编译期展开，运行时没有对应代码。

## ThisType\<T\>

ThisType 不改变类型，只作为上下文标记，指定对象字面量里 `this` 的类型：

```typescript
type ObjectDescriptor<D, M> = {
  data?: D;
  methods?: M & ThisType<D & M>;
};

function makeObject<D, M>(desc: ObjectDescriptor<D, M>): D & M {
  return { ...(desc.data ?? {}), ...(desc.methods ?? {}) } as D & M;
}

const counter = makeObject({
  data: { count: 0 },
  methods: {
    increment() {
      this.count += 1;
    },
  },
});
```

需要在 `noImplicitThis` 开启时使用。

## 组合用法

工具类型很少单独使用。下面四种组合在业务代码里出现频率最高。

### 更新请求体

排除服务端生成的字段和敏感字段，其余全部可选：

```typescript
interface Article {
  id: number;
  title: string;
  body: string;
  authorId: number;
  publishedAt: Date;
  updatedAt: Date;
}

type UpdateArticleDTO = Partial<Omit<Article, "id" | "authorId" | "publishedAt" | "updatedAt">>;
// { title?: string; body?: string }
```

### 查询参数

只保留可筛选的字段，再拼上分页参数：

```typescript
type ArticleQuery = Partial<Pick<Article, "title" | "body">> & {
  page: number;
  pageSize: number;
};

const query: ArticleQuery = { page: 1, pageSize: 20 };
```

### 响应包装

给任意数据套统一外壳：

```typescript
type ApiResponse<T> = {
  code: number;
  message: string;
  data: T;
};

type ArticleListResponse = ApiResponse<Article[]>;
type ArticleDetailResponse = ApiResponse<Article>;
```

### 事件映射

用 Record 约束事件名与事件数据的对应关系：

```typescript
class TypedEmitter<Events extends Record<string, unknown>> {
  on<E extends keyof Events>(event: E, handler: (data: Events[E]) => void): void {}
  emit<E extends keyof Events>(event: E, data: Events[E]): void {}
}

type AppEvents = {
  userLogin: { userId: string };
  error: { message: string; code: number };
};

const emitter = new TypedEmitter<AppEvents>();
emitter.on("userLogin", (data) => data.userId);
emitter.emit("error", { message: "失败", code: 500 });
```

`AppEvents` 必须用 `type` 声明。`interface` 没有隐式索引签名，写成 `interface` 会报 TS2344。

## 三个常见坑

### Omit 拼错键不报错

```typescript
type Typo = Omit<Article, "tittle">;  // 没有报错

const t: Typo = { id: 1, title: "t", body: "b", authorId: 2 };
```

`Omit` 的 `K` 约束是 `keyof any`，拼错的键只是从 `keyof T` 里减不到任何东西，结果等于原类型。

`Pick` 的约束是 `keyof T`，拼错会当场报错：

```typescript
type Bad = Pick<Article, "tittle">;  // error TS2344: Type '"tittle"' does not satisfy the constraint 'keyof Article'.
```

需要键名安全时用 `Pick`，或者给 `Omit` 包一层约束。

### 联合类型进 keyof 会塌缩

```typescript
type A = { kind: "a"; x: number };
type B = { kind: "b"; y: string };

type Keys = keyof (A | B);          // "kind"
type Picked = Pick<A | B, "kind">;  // { kind: "a" | "b" }
type Omitted = Omit<A | B, "kind">; // {}
```

`keyof (A | B)` 是交集，只剩两个成员共有的键。`Omit` 不是分布式条件类型，它只对 `A | B` 整体做一次键运算，去掉 `kind` 后没有键可选，结果成了空对象。

需要按成员分别处理时，先写一个分布式外壳：

```typescript
type DistributiveOmit<T, K extends PropertyKey> = T extends any ? Omit<T, K> : never;

type Fixed = DistributiveOmit<A | B, "kind">;  // { x: number } | { y: string }

const f1: Fixed = { x: 1 };
const f2: Fixed = { y: "s" };
```

### Pick 与 Omit 对可选属性的处理

```typescript
interface Draft {
  id: number;
  title?: string;
  readonly slug: string;
}

type P1 = Pick<Draft, "title">;  // { title?: string }
type O1 = Omit<Draft, "id">;     // { title?: string; readonly slug: string }
```

两者都保留原属性的 `?` 和 `readonly`，因为都通过映射类型拷贝键。差别在约束：`Pick` 要求键必须存在，`Omit` 不要求。去掉一个可选属性时用 `Omit`，只要几个已知属性时用 `Pick`。

| 工具类型 | 输入 | 输出 | 实现方式 |

| `Partial<T>` | 对象类型 | 全部可选 | 映射类型 + `?` |
| `Required<T>` | 对象类型 | 全部必选 | 映射类型 + `-?` |
| `Readonly<T>` | 对象类型 | 全部只读 | 映射类型 + `readonly` |

| `ConstructorParameters<T>` | 构造函数类型 | 构造参数元组 | `infer P` |

## 检查器里发生了什么

工具类型没有特殊分支。`Partial<T>` 展开就是一个映射对象，`Exclude<T, U>` 展开就是一个条件类型，之后和手写的类型走同一条实例化与关系比较流程。`instantiateType`（checker.ts:20951）负责代入类型参数，`checkTypeRelatedTo`（22303）负责比较。

有一小撮例外由编译器直接标记。`Uppercase`、`Lowercase`、`Capitalize`、`Uncapitalize` 建成 `StringMappingType`，只折叠字面量。`NoInfer<T>` 建成替换类型，`getNoInferType`（17139）把 `T` 与 `unknown` 组成一个替换关系，推导时跳过这个位置。`ThisType` 只在对象字面量的 `this` 类型上起作用，本身不产生结构。

`Awaited`、`OmitThisParameter` 这类递归和重组，都是前面那些实现展开后的结果。内置实现没有隐藏版本，改实现就等于改展开结果。

正因为没有特殊分支，工具类型的边界都能从展开式推出来。`Partial` 只加 `?`，值类型不动；`Readonly` 只加 `readonly`，嵌套对象不跟着变；`Exclude` 依赖裸类型参数分布，传入的不是联合就没有分布效果。遇到反直觉的结果，先把工具类型手工展开一遍，多数疑问当场消失。

查询顺序也值得记一笔。`Partial<Omit<T, K>>` 是先去键再加可选，`Omit<Partial<T>, K>` 是先全部可选再删键。`K` 是具体键时结果相似，`K` 来自 `keyof` 计算时可能不同。

还有一处容易忽略：`Pick` 与 `Omit` 的键约束不同，`Pick` 要求键存在，`Omit` 不要求。这不是实现细节，而是展开式里 `K extends keyof T` 与 `K extends keyof any` 的直接结果。

挑工具类型时，先看输入是对象还是联合。对象类型适合映射类工具，联合类型适合条件类工具。把联合塞给 `Pick`、`Omit`，得到的是交集键，不是每个成员分别处理。需要逐成员时，先写分布式外壳，再在里面调用工具类型。

行号取自 TypeScript 5.9.3 的 src/compiler/checker.ts；7.0 换成 Go 实现，逻辑相同但没有逐行核对。

### 报错现场

```ts
type Article = { id: number; title: string };
type Meta = Record<"home" | "about", { title: string }>;
const meta: Meta = { home: { title: "首页" } };
const draft: Partial<Article> = { title: 1 };
```

`repro-20.ts(3,7): error TS2741: Property 'about' is missing in type '{ home: { title: string; }; }' but required in type 'Meta'.`。`Record` 生成的是必选键，漏一个就报错。改法：补齐 `about`，或改用 `Partial<Record<...>>`。

`repro-20.ts(4,35): error TS2322: Type 'number' is not assignable to type 'string'.`。`Partial` 只放松可选性，不改值类型。改法：`title` 传字符串。

### 一句话记住

工具类型像一批标准模具：模具本身只是普通类型表达式，用的时候现场冲压一次。`Uppercase` 这类不走模具，由编译器内置表直接换算。

比喻不成立的地方：模具冲压不会改变内部结构的语义，工具类型却能改变可选性、只读性和键集合。

```ts
type Post = { id: number; title: string; body: string };
type Draft = Partial<Omit<Post, "id">>;  // { title?: string; body?: string }
type Upper = Uppercase<"draft">;         // "DRAFT"
```

## 小结

- 工具类型按功能分八组：属性修饰、属性选取、键值构造、联合筛选、函数提取、Promise 解包、字符串变换、this 标记。
- 实现手段只有四种：映射类型、分布式条件类型、`infer`、编译器 intrinsic。
- `Omit` 的键约束宽松，拼错键会静默通过；`Pick` 的约束严格，拼错当场报 TS2344。
- 联合类型传进 `keyof` 会取交集，`Omit` 不会逐成员处理，需要分布式外壳。
- 组合用法比单个工具类型更常见：更新请求体、查询参数、响应包装、事件映射。

## 用不上的时候

### 嵌套结构

`Partial<T>`、`Required<T>` 只处理第一层。深层可选、深层只读都要手写递归类型。

### 宽松的键约束

`Omit<T, K>` 的 `K` 不要求是 `keyof T`，键拼错不会报错。需要严格校验时自己加 `K extends keyof T`。

### 联合类型上的工具

`keyof (A | B)` 取的是交集，`Omit` 不会逐成员处理。要逐成员得先分发。
