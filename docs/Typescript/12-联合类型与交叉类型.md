# 第12章 联合类型与交叉类型

在第 4 章中我们初步使用了联合类型（`|`）来组合字面量，第 6 章中我们用交叉类型（`&`）来合并对象类型。这两种类型操作符是 TypeScript 类型编程的基石——它们一个表示"或"，一个表示"且"。本章将深入讲解它们的语义、运作机制和实际应用模式。

## 联合类型深入

### 联合类型的语义

联合类型 `A | B` 表示**值可以是 A 类型，也可以是 B 类型**——满足其中一个即可：

```typescript
function format(value: string | number): string {
  // value 可能是 string，也可能是 number
  return String(value);
}

format("hello");  // ✅
format(42);       // ✅
// format(true);  // ❌ boolean 不在联合中
```

联合类型的关键心智模型是：**在使用一个联合类型的值时，你只能安全地访问对每个成员都存在的成员**。

```typescript
function process(value: string | number) {
  // value.toUpperCase();  // ❌ number 上没有 toUpperCase
  // value.toFixed();      // ❌ string 上没有 toFixed

  // ✅ 两者都有的成员（toString 在 string 和 number 上都存在）
  console.log(value.toString());
}
```

这看起来像是"取交集"，但这是合理的：对于 `string | number`，你唯一能确定每个值都有的属性，就是 `string` 和 `number` 共有的属性。

### 联合类型的自动展平

嵌套的联合类型会被 TypeScript 自动展平：

```typescript
type Flattened = 1 | (2 | (3 | 4));
// 等价于 1 | 2 | 3 | 4

type WithNever = string | number | never;
// 等价于 string | number（never 在联合中消失）
```

### 对象联合类型

当联合类型的成员是对象时，只有访问所有成员共有的属性才类型安全：

```typescript
interface Bird {
  fly(): void;
  layEggs(): void;
}

interface Fish {
  swim(): void;
  layEggs(): void;
}

type Pet = Bird | Fish;

function care(pet: Pet) {
  pet.layEggs();  // ✅ Bird 和 Fish 都有 layEggs()
  // pet.fly();   // ❌ Fish 没有 fly()
  // pet.swim();  // ❌ Bird 没有 swim()
}
```

通过类型守卫收窄之后，就可以安全访问特定类型的独有成员：

```typescript
function care(pet: Pet) {
  if ("fly" in pet) {
    pet.fly();   // ✅ 收窄为 Bird
  } else {
    pet.swim();  // ✅ 收窄为 Fish
  }
}
```

## 交叉类型深入

### 交叉类型的语义

交叉类型 `A & B` 表示**值同时具有 A 类型和 B 类型的所有成员**——必须同时满足两者：

```typescript
interface Named {
  name: string;
}

interface Aged {
  age: number;
}

type Person = Named & Aged;
// { name: string; age: number; }

const p: Person = { name: "Alice", age: 25 };
```

对于对象类型，交叉类型就是**属性的合并**。如果两个类型有同名属性，该属性的类型也会做交叉：

```typescript
interface A {
  x: string;
  y: number;
}

interface B {
  y: boolean;
  z: string;
}

type C = A & B;
// { x: string; y: number & boolean; z: string; }
// y 的类型是 number & boolean → never（没有值能同时是 number 和 boolean）
```

### 原始类型的交叉

两个原始类型的交叉是 `never`——因为没有任何值能同时是两个不兼容的原始类型：

```typescript
type Impossible = string & number;   // never
type AlsoImpossible = true & false;  // never
type Empty = boolean & string;       // never
```

但一些看似矛盾的类型交叉后可能不是 `never`：

```typescript
type T = string & { toString(): string };
// string 类型——string 自身就满足 toString(): string
```

### 交叉类型与联合类型的分配律

交叉类型对联合类型具有分配律，与乘法的分配律类似：

```typescript
type T = (A | B) & C;
// 等价于 (A & C) | (B & C)

// 实例
type Admin = { role: "admin"; permissions: string[] } & { name: string; age: number };
// { role: "admin"; permissions: string[]; name: string; age: number; }
```

## interface extends vs 交叉类型 &

两者在合并对象类型时大部分情况等价，但有重要区别：

### 属性冲突的处理

```typescript
interface A {
  x: string;
}

interface B {
  x: number;
}

// interface C extends A, B { }  // ❌ 编译报错：类型不兼容

type C = A & B;
// C = { x: never } — 不报错，但 x 的类型变为 never（不可用）
```

`interface extends` 在属性类型冲突时会**立即报错**，而 `&` 会静默地把冲突属性的类型变成 `never`。这使得 `extends` 在遇到错误时更容易发现和修复。

### 非对象类型的处理

```typescript
type Primitive = string;
type Union = string | number;

// type T1 = Primitive & Union;  // string — 交集是 string
// interface I1 extends Primitive { }  // ❌ interface 只能扩展对象类型
```

`type` 可以对任意类型做交叉，而 `interface` 只能扩展对象类型（或对象类型的交集）。

### 选择建议

- 如果你想要**声明合并**能力 → `interface`
- 如果你需要合并基本类型、联合类型 → 只能用 `type` 的 `&`
- 如果你希望属性冲突时**尽早暴露错误** → `interface extends` 更安全
- **大规模项目中优先用 `extends`** → TypeScript 对接口继承有内部缓存，编译速度优于交叉类型的展开计算；同时错误信息中 `interface` 始终显示原名，而 `&` 的结果可能被展开为难以阅读的匿名类型

关于可辨识联合类型的具体应用（如何通过 `kind` 字段精确收窄类型），详见第 9 章「类型断言与类型守卫」。

## 可辨识联合类型（Discriminated Union）

这是联合类型最强大的应用模式。在第 9 章中我们从"类型缩小"的角度介绍过，这里从类型设计的角度做更深入的分析。

### 三个要素

可辨识联合类型由三个要素组成：
1. **共同的辨识字段**：每个联合成员有一个**相同名称**的属性
2. **字面量类型的辨识值**：该属性的类型是**字面量类型的联合**（每个成员各取一个值）
3. **类型守卫**：对这个字段的检查能收窄到具体成员

```typescript
// 三个要素全部满足
type Shape =
  | { kind: "circle"; radius: number }
  | { kind: "square"; sideLength: number }
  | { kind: "rectangle"; width: number; height: number };

// 1. 共同的辨识字段: kind
// 2. 字面量类型: "circle" | "square" | "rectangle"
// 3. switch 对 kind 的检查构成类型守卫
```

### 为什么这个模式强大

它支持**对每个变体精确访问其独有属性**，而且通过穷尽检查能保证没有遗漏：

```typescript
function getArea(shape: Shape): number {
  switch (shape.kind) {
    case "circle":
      return Math.PI * shape.radius ** 2;     // shape: Circle
    case "square":
      return shape.sideLength ** 2;            // shape: Square
    case "rectangle":
      return shape.width * shape.height;       // shape: Rectangle
    default: {
      // 穷尽检查：如果有人新增了 Triangle 变体，编译报错
      const _exhaustive: never = shape;
      throw new Error(`Unknown shape`);
    }
  }
}
```

### 实战：API 请求状态

```typescript
type AsyncState<T> =
  | { status: "idle" }
  | { status: "loading" }
  | { status: "success"; data: T }
  | { status: "error"; error: Error };

function render<T>(state: AsyncState<T>) {
  switch (state.status) {
    case "idle":
      return "请点击加载";
    case "loading":
      return "加载中...";
    case "success":
      return `数据: ${JSON.stringify(state.data)}`;
    case "error":
      return `错误: ${state.error.message}`;
  }
}
```

### 实战：Redux Action 类型

```typescript
type Action =
  | { type: "ADD_TODO"; text: string }
  | { type: "TOGGLE_TODO"; index: number }
  | { type: "SET_VISIBILITY"; filter: "all" | "active" | "completed" };

function reducer(state: State, action: Action): State {
  switch (action.type) {
    case "ADD_TODO":
      return { ...state, todos: [...state.todos, action.text] };
    case "TOGGLE_TODO":
      return toggleTodo(state, action.index);
    case "SET_VISIBILITY":
      return { ...state, visibility: action.filter };
  }
}
```

## 联合与交叉的组合实战

### 模式：基础类型 + 交叉扩展

```typescript
// 所有事件共有的基础字段
type BaseEvent = {
  timestamp: number;
  source: string;
};

// 具体事件 = 基础字段 + 特有字段
type ClickEvent = BaseEvent & {
  type: "click";
  x: number;
  y: number;
};

type KeyEvent = BaseEvent & {
  type: "keydown" | "keyup";
  key: string;
};

// 联合所有事件
type AppEvent = ClickEvent | KeyEvent;

function handleEvent(event: AppEvent) {
  console.log(event.timestamp);  // ✅ 共有字段，不用收窄

  if (event.type === "click") {
    console.log(event.x, event.y);  // ✅ 收窄后可访问独有字段
  }
}
```

### 模式：Partial + Pick 组合

```typescript
interface User {
  id: number;
  name: string;
  email: string;
  avatar: string;
  bio: string;
}

// 用于列表展示（只需要 id + name + avatar）
type UserListItem = Pick<User, "id" | "name" | "avatar">;

// 用于详情展示（所有字段）
type UserDetail = User;

// 用于编辑表单（部分字段可选更新）
type UserUpdateForm = Partial<Pick<User, "name" | "email" | "avatar" | "bio">>;

// 联合：列表项或详情都可以传给渲染函数
type RenderableUser = UserListItem | UserDetail;
```

## 本章小结

- **联合类型** `A | B` 表示"满足其一"，只能安全访问各成员共有的属性
- **交叉类型** `A & B` 表示"同时满足"，用于合并对象类型
- 原始类型的交叉（如 `string & number`）得到 `never`
- `interface extends` 在属性冲突时直接报错，`&` 静默变为 `never`——`extends` 更安全
- **可辨识联合类型**结合了联合类型、字面量类型和类型守卫，是 TypeScript 最强大的模式之一
- 常用于 API 状态、Redux Action、事件系统等需要精确分支处理的场景
- `Base & Variant` 交叉后再联合是构建事件系统的经典模式
