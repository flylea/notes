# 第 37 章 迭代器、生成器与资源管理

接口一次返回几十万条记录，想边读边处理，不想先堆进数组。生成器把取值和消费分开，`using` 把资源释放绑在作用域上。这一章讲迭代器类型、辅助方法、委托和释放顺序。

`function*` 的返回类型是 `Generator<T, TReturn, TNext>`。三个类型参数对应三处信息：yield 出去的值、return 返回的值、`next()` 收到的实参。第三个参数只在双向通信时有用，平时写 `undefined` 就行。三个参数的位置固定，记不住时查一次 `lib.es2015.generator.d.ts` 里的声明。

一句话：`function*` 调用时不执行函数体，只返回一个能 `next()` 的对象，代码跑到第一个 `yield` 才停。`const it = counter()` 这一步没有副作用，`it.next()` 才有。失效处：普通函数调用立刻执行；生成器体里 `try/finally` 的清理也要等 `next()` 或 `return()` 才发生，忘了消费就不会执行。

```typescript
function* tally(limit: number): Generator<number, string, boolean> {
  let total = 0;
  for (let i = 0; i < limit; i++) {
    if (yield i) return `stopped at ${total}`;
    total += i;
  }
  return `done at ${total}`;
}

const it = tally(3);
const step = it.next();
if (step.done) {
  const label: string = step.value;
  console.log(label);
} else {
  const count: number = step.value;
  console.log(count);
}
```

`next()` 返回 `IteratorResult<number, string>`。`done` 为 false 时 `value` 是 `number`，为 true 时是 `string`。`if (step.done)` 能把两个分支分开，不写判断直接取 `value` 只能拿到联合类型。

`IteratorResult<T, TReturn>` 是两个类型的联合：`IteratorYieldResult<T>` 的 `done` 是 `false` 或省略，`IteratorReturnResult<TReturn>` 的 `done` 是 `true`。判断 `done` 之后，`value` 的类型从 `T | TReturn` 收窄成其中一个。

`yield` 表达式本身的值来自 `next()` 的实参，类型是第三个参数。上例中传入 `true` 会提前返回，因为 `if (yield i)` 读到的就是那个布尔值。

## 用到 next 实参就写注解

第三个类型参数只有显式标注时才可靠。若在生成器内部读取 `yield` 的值，但不写返回类型注解，TypeScript 7.0.2 会报 TS7057。

```bash
$ cat dialog.ts
function* dialog() {
  const answer = yield "hello";
  return answer.reply;
}

$ tsc --noEmit --strict --ignoreConfig --target esnext --lib esnext dialog.ts
dialog.ts(2,16): error TS7057: 'yield' expression implicitly results in an 'any' type because its containing generator lacks a return-type annotation.
```

补上第三个参数就不报错。`next()` 的实参类型与 `yield` 表达式类型同时被约束。

```typescript
function* dialog(): Generator<string, string, { reply: string }> {
  const answer = yield "hello";
  return answer.reply;
}

const session = dialog();
session.next({ reply: "hi" });
const finished: IteratorResult<string, string> = session.next({ reply: "bye" });
console.log(finished);
```

只用 yield 和 return 的生成器不需要注解。类型分别从 `yield` 后的表达式和 `return` 后的表达式推断。一旦要收 `next()` 的实参，就把三个参数写全。

不写注解时，`function* () { yield 1; return "x" }` 推断为 `Generator<number, string, unknown>`。第三个参数是 `unknown`，`next()` 收到任何实参都不报错，约束等于没有。把第三个参数写成 `undefined`，`next()` 就只能不带实参，多传值报 TS2345：`Argument of type '[1]' is not assignable to parameter of type '[] | [undefined]'`。

## 五种迭代器类型的区别

| 类型 | 提供什么 | 典型来源 |
|---|---|---|
| `Iterable<T>` | `[Symbol.iterator]()` | 数组、字符串、Map、Set |
| `Iterator<T, TReturn, TNext>` | `next()` | 生成器、手写迭代器 |
| `IterableIterator<T>` | 两者都有，没有辅助方法 | TypeScript 5.6 之前的旧接口 |
| `IteratorObject<T, TReturn, TNext>` | 两者都有，带 `map`、`take` 等 | 数组迭代器、`Iterator.from()` |
| `Generator<T, TReturn, TNext>` | `next`、`return`、`throw` 与辅助方法 | `function*` |

生成器满足以上全部类型，赋值不报错。

表中后三行都能被 `for...of` 使用，只有 `Iterator` 不行。`Iterator<number, any, any>` 上找不到 `[Symbol.iterator]`，直接遍历报 TS2488。生成器同时带 `next()` 与 `[Symbol.iterator]`，所以四种类型都能接。

```typescript
function* letters(): Generator<string, void, undefined> {
  yield "a";
  yield "b";
}

const gen = letters();
const iterablePart: Iterable<string> = gen;
const iteratorPart: Iterator<string, void, undefined> = gen;
const oldPart: IterableIterator<string> = gen;
const modernPart: IteratorObject<string, void, undefined> = gen;

console.log([iterablePart, iteratorPart, oldPart, modernPart].length);
```

反过来不成立。数组是 Iterable，也有辅助方法，但没有 `Generator` 的 `return` 与 `throw`。把 `number[]` 赋给 `Generator<number, any, any>` 报 TS2740，缺少 `next`、`return`、`throw`、`take` 等属性。

内置容器有具体的迭代器类型：`[1, 2][Symbol.iterator]()` 是 `ArrayIterator<number>`，`new Map<string, number>().keys()` 是 `MapIterator<string>`，`"ab"[Symbol.iterator]()` 是 `StringIterator<string>`。它们都扩展 `IteratorObject`，可以直接链式调用辅助方法。

`Generator` 还多出 `return()` 与 `throw()`，分别用于提前结束和向生成器内部抛错。这两个方法一般由运行时调用，手写的时候不多。

## for...of 只认 Iterable

`for...of` 编译时检查对象有没有 `[Symbol.iterator]`。只写 `next()` 的对象不能遍历，报 TS2488。可迭代协议与生成器的类型关系见 [迭代器与生成器](https://www.typescriptlang.org/docs/handbook/iterators-and-generators.html)。

```bash
$ cat counter.ts
const counter = {
  i: 0,
  next() {
    return { done: this.i >= 3, value: this.i++ };
  },
};
for (const n of counter) console.log(n);

$ tsc --noEmit --strict --ignoreConfig --target esnext --lib esnext counter.ts
counter.ts(7,17): error TS2488: Type '{ i: number; next(): { done: boolean; value: number; }; }' must have a '[Symbol.iterator]()' method that returns an iterator.
```

给对象补上 `[Symbol.iterator]` 就能遍历。返回生成器最省事，类型的对应关系由 `Generator` 保证。

```typescript
class Countdown {
  private readonly from: number;
  constructor(from: number) {
    this.from = from;
  }
  *[Symbol.iterator](): Generator<number, void, undefined> {
    for (let i = this.from; i > 0; i--) {
      yield i;
    }
  }
}

for (const n of new Countdown(3)) {
  console.log(n);
}
```

`Iterable` 签名要求 `[Symbol.iterator]()` 返回 `Iterator<T>`，不要求返回 `IterableIterator`。返回类型写成 `Iterator<number>` 也能通过，但会失去辅助方法。

异步版本把 `Symbol.iterator` 换成 `Symbol.asyncIterator`，方法写成 `async *[Symbol.asyncIterator]()`，返回 `AsyncGenerator<T>`。对象相应实现 `AsyncIterable<T>`，消费端用 `for await...of`。

`for...of` 编译后接近 `while (true) { const step = it.next(); if (step.done) break; ... }`。循环体里 `break`、`return` 或抛错时，运行时会调用迭代器的 `return()`。没有 `return()` 的对象照样能遍历，但生成器的 `finally` 依赖这个调用。

## yield* 委托另一个可迭代对象

`yield*` 把迭代工作交给另一个对象，同时取出被委托生成器的 return 值。

```typescript
function* inner(): Generator<string, number, undefined> {
  try {
    yield "a";
    yield "b";
    return 42;
  } finally {
    console.log("inner finally");
  }
}

function* outer(): Generator<string, number, undefined> {
  const total = yield* inner();
  return total;
}

const walk = outer();
console.log(walk.next());
console.log(walk.next());
console.log(walk.next());
```

```bash
$ node walk.ts
{ value: 'a', done: false }
{ value: 'b', done: false }
inner finally
{ value: 42, done: true }
```

被委托对象的 yield 类型必须能赋给外层生成器的类型。下面这行报 TS2322，因为外层只产出 `number`。

```bash
$ tsc --noEmit --strict --ignoreConfig --target esnext --lib esnext mixed.ts
mixed.ts(5,10): error TS2322: Type 'string' is not assignable to type 'number'.
```

委托对象不限于生成器。`yield* [1, 2, 3]` 委托数组，整个表达式没有返回值，类型是 `void`；`yield* "ab"` 委托字符串。遍历时外层 `next(v)` 的实参传给当前执行的内层生成器，外层 `return(v)` 也一路传到最内层的 `finally`。

`for...of` 里 `break` 或 `return` 会调用生成器的 `return()`。`finally` 块照常执行，这正是把清理逻辑放进生成器的基础。

## 迭代器辅助方法

TypeScript 5.6 起，`IteratorObject` 上有一组链式方法（来自 [TC39 的迭代器辅助方法提案](https://github.com/tc39/proposal-iterator-helpers)）：`map`、`filter`、`take`、`drop`、`flatMap`、`reduce`、`toArray`。生成器自带这些方法，`Symbol.iterator` 返回带类型的 `Generator` 时也能直接链式调用。

```typescript
function* naturals(): Generator<number, void, undefined> {
  for (let i = 0; ; i++) {
    yield i;
  }
}

const squares = naturals()
  .map((n) => n * n)
  .filter((n) => n % 2 === 0)
  .take(3)
  .toArray();

const total = naturals().drop(2).take(3).reduce((acc, n) => acc + n, 0);
const flat = naturals().take(3).flatMap((n) => [n, n * 10]).toArray();

console.log(squares, total, flat);
```

这段要 `lib` 含 `esnext.iterator`（写 `lib: ["esnext"]` 即可）。只给 `es2022` 会报 `TS2339: Property 'map' does not exist on type 'Generator<...>'`，参数也跟着报 `TS7006`。

```bash
$ node helpers.ts
[ 0, 4, 16 ] 9 [ 0, 0, 1, 10, 2, 20 ]
```

这些方法不立即执行。`take(2)` 只从源头取两个值，后面的元素不会计算。`Iterator.from()` 既接受可迭代对象，也接受已经是迭代器的对象，两种都能接上辅助方法。

```typescript
let visited = 0;

function* track(): Generator<number, void, undefined> {
  for (const n of [1, 2, 3, 4, 5]) {
    visited++;
    yield n;
  }
}

const firstTwo = track().take(2).toArray();
console.log(firstTwo, visited);
```

```bash
$ node lazy.ts
[ 1, 2 ] 2
```

`toArray()` 与 `Array.from()` 结果相同，区别是 `toArray()` 只挂在 `IteratorObject` 上，`Array.from()` 接受任意 `Iterable` 或类数组。迭代器只能消费一次，`toArray()` 之后再调用一次，拿到的是空数组。

这些方法需要 `lib` 含 `esnext.iterator`。`--lib es2024` 下 `Generator<number, void, undefined>` 上找不到 `map`，报 TS2339，换成 `esnext` 才有。项目锁死旧 lib 时，先用 `Iterator.from()` 转一层，再链式调用。

生成器函数体在第一次 `next()` 之前不执行。代码里写了 `console.log` 却没有任何输出，先确认有没有调用 `next()` 或进入 `for...of`。

辅助方法只挂在 `IteratorObject` 上。旧的 `IterableIterator` 不继承它，异步的 `AsyncIteratorObject` 也没有对应方法，`reduce` 同样不检查空迭代器。

```bash
$ cat old-interface.ts
declare const old: IterableIterator<number>;
old.map((n) => n);
# TS2339: Property 'map' does not exist on type 'IterableIterator<number>'.

$ cat async-iterator.ts
declare const asyncIt: AsyncIteratorObject<number, void, unknown>;
asyncIt.map((n) => n);
# TS2339: Property 'map' does not exist on type 'AsyncIteratorObject<number, void, unknown>'.

$ cat empty-reduce.ts
function* empty(): Generator<number, void, undefined> {}
console.log(empty().reduce((acc, n) => acc + n));

$ node empty-reduce.ts
true Reduce of a done iterator with no initial value
```

需要把任意可迭代对象转成带辅助方法的迭代器，用 `Iterator.from()`。数组迭代器和自定义 `Iterable` 都能转。

```typescript
class Range implements Iterable<number> {
  private readonly stop: number;
  constructor(stop: number) {
    this.stop = stop;
  }
  *[Symbol.iterator](): Generator<number, void, undefined> {
    for (let i = 0; i < this.stop; i++) yield i;
  }
}

const doubled = Iterator.from(new Range(6))
  .filter((n) => n % 2 === 0)
  .map((n) => n * 2)
  .toArray();

console.log(doubled);
```

这块要 `lib` 含 `esnext`，`Iterator` 才是运行时值；只给 `es2022` 会报 `TS2693: 'Iterator' only refers to a type, but is being used as a value here.` 与 `TS7006`。`lib` 里带 `dom` 时 `Range` 与 DOM 的同名类型冲突，报 `TS2300` 和 `TS2345`；按 `--module nodenext --lib esnext` 编译通过。

```bash
$ node from.ts
[ 0, 4, 8 ]
```

## using：作用域结束时自动释放

`using` 声明的变量在离开当前块时调用 `[Symbol.dispose]()`。存放顺序与声明顺序相反。这两个关键字来自 [TC39 的显式资源管理提案](https://github.com/tc39/proposal-explicit-resource-management)。

下面这些 `using` 示例要 `lib` 含 `esnext`（或 `esnext.disposable`）。只给 `es2022` 会报 `TS2318: Cannot find global type 'Disposable'`、`TS2304` 和 `TS2550`。

```typescript
class Track implements Disposable {
  private readonly name: string;
  constructor(name: string) {
    this.name = name;
  }
  [Symbol.dispose]() {
    console.log("dispose", this.name);
  }
}

function run() {
  using first = new Track("first");
  using second = new Track("second");
  console.log("body", first, second);
}

run();
```

```bash
$ node dispose.ts
body Track { name: 'first' } Track { name: 'second' }
dispose second
dispose first
```

初始值必须是有 `[Symbol.dispose]()`（[MDN 说明](https://developer.mozilla.org/en-US/docs/Web/JavaScript/Reference/Global_Objects/Symbol/dispose)）的对象，或者 `null`、`undefined`。`using` 声明的变量不能被重新赋值。`Symbol.dispose` 的返回值是 `void`，`Symbol.asyncDispose` 要求返回 `PromiseLike<void>`，两者抛出的错误都由运行时接管。

```bash
$ tsc --noEmit --strict --ignoreConfig --target esnext --lib esnext rules.ts
rules.ts(1,11): error TS2850: The initializer of a 'using' declaration must be either an object with a '[Symbol.dispose]()' method, or be 'null' or 'undefined'.
rules.ts(5,1): error TS2588: Cannot assign to 'r' because it is a constant.
```

多个清理函数可以用 `DisposableStack` 集中登记：`stack.use(obj)` 收实现 `Disposable` 的对象，`stack.adopt(value, disposer)` 收值加清理函数，`stack.defer(fn)` 收普通函数。释放顺序与登记顺序相反，实测依次输出 use、adopt、defer。把 stack 声明成 `using`，块结束时统一执行。

需要异步释放时用 `await using`。对象实现 `[Symbol.asyncDispose]()`，返回 `Promise`。同一个块里混用两种声明，同步的立即释放，异步的要等 `await`。

```typescript
class Fast implements Disposable {
  private readonly name: string;
  constructor(name: string) {
    this.name = name;
  }
  [Symbol.dispose]() {
    console.log("dispose", this.name);
  }
}

class Slow implements AsyncDisposable {
  private readonly name: string;
  constructor(name: string) {
    this.name = name;
  }
  async [Symbol.asyncDispose]() {
    await new Promise((resolve) => setTimeout(resolve, 10));
    console.log("async dispose", this.name);
  }
}

async function runAsync() {
  await using slow = new Slow("slow");
  using fast = new Fast("fast");
  console.log("body");
}

runAsync();
```

这段同样要 `lib` 含 `esnext`。`AsyncDisposable` 在 `es2022` 下不存在，报 `TS2304`、`TS2318` 与 `TS2550`。

```bash
$ node mixed.ts
body
dispose fast
async dispose slow
```

`await using` 也接受只实现 `Disposable` 的对象，同步释放会被包成 Promise。不必为了配合 `await using` 强行写 async 方法。

## 异常路径

块内抛异常时，`using` 声明的对象照样释放。释放过程再抛错，两个错误会包成 `SuppressedError`。

```typescript
export {};

class Leak implements Disposable {
  [Symbol.dispose]() {
    throw new Error("cleanup failed");
  }
}

function bodyThrows() {
  using leak = new Leak();
  throw new Error("work failed");
}

try {
  bodyThrows();
} catch (err) {
  if (err instanceof SuppressedError) {
    console.log("suppressed:", (err.suppressed as Error).message);
    console.log("error:", (err.error as Error).message);
  }
}
```

同上，`using` 与 `SuppressedError` 需要 `lib` 含 `esnext`。`es2022` 下报 `TS2318`、`TS2304` 与 `TS2550`。

```bash
$ node suppressed.ts
suppressed: work failed
error: cleanup failed
```

`error` 是释放时抛的错误，`suppressed` 是块内原本的错误。日志与上报要两个字段都读，只读 `message` 会丢掉原始错误。

两个错误只抛一次，外面一个 `catch` 就够。没有 `try/catch` 时，`SuppressedError` 直接冒泡到调用方，进程按未捕获异常退出。`SuppressedError` 在 Node 26.13.1 里是全局构造器，用 `instanceof` 就能判断。`message` 只说明发生了抑制，具体错误在另外两个字段里。

`using` 在生成器里同样生效。外部提前结束迭代时，生成器的 `finally` 和 `using` 的释放都会执行。

```typescript
class Temp implements Disposable {
  [Symbol.dispose]() {
    console.log("temp released");
  }
}

function* visits(): Generator<number, void, undefined> {
  using temp = new Temp();
  try {
    yield 1;
    yield 2;
  } finally {
    console.log("generator finally");
  }
}

const trip = visits();
console.log(trip.next());
trip.return();
console.log("after return");
```

同上，生成器里的 `using` 也要 `lib` 含 `esnext`。`es2022` 下报 `TS2318`、`TS2304` 与 `TS2550`。

```bash
$ node generator-using.ts
{ value: 1, done: false }
generator finally
temp released
after return
```

`using` 是声明语句，只能出现在语句位置，不能当表达式或回调参数。

顺序固定：`finally` 先跑，`using` 最后释放。释放函数里抛错，`return()` 会把错误抛给调用方。

## using 与 try/finally 的取舍

`try/finally` 能做同样的事，`using` 少写一层缩进，也少一个忘记调用的机会。

```typescript
interface Handle {
  close(): void;
}

function open(): Handle {
  let closed = false;
  return {
    close() {
      if (closed) return;
      closed = true;
      console.log("close");
    },
  };
}

function work(handle: Handle): void {
  console.log("work");
}

function withFinally() {
  const handle = open();
  try {
    work(handle);
  } finally {
    handle.close();
  }
}

class Managed implements Disposable {
  close() {
    console.log("close");
  }
  [Symbol.dispose]() {
    this.close();
  }
}

function withUsing() {
  using handle = new Managed();
  work(handle);
}

withFinally();
withUsing();
```

两次调用的输出一样：`work`、`close`、`work`、`close`。

`try/finally` 能做的事更多：可以在 finally 里读局部变量、写异步流程、按条件释放。`using` 适合“拿到就忘、结束必放”的资源，文件句柄、锁、临时目录都属于这一类。已有对象没有 `[Symbol.dispose]` 时，用 `try/finally` 包一层，不必为了语法改类。

## 低 target 会注入释放辅助代码

`using` 的作用域是最近的 `{}`，函数体、`if` 分支、循环体都算。

`using` 是 JavaScript 语法，TypeScript 只在目标版本不支持时降级。`target` 设为 `es2022` 会注入 `__addDisposableResource` 与 `__disposeResources` 两个 helper，包体积会变大。

两个 helper 把资源收集进数组，退出块时逆序调用释放方法。目标环境越老，注入的代码越多。

`target` 设为 `esnext` 时原样保留 `using`，交给运行时处理，Node 26.13.1 的 V8 已经支持这段语法。lib 里没有 `Disposable` 时连类型都找不到，`es2022` 需要额外加 `esnext.disposable`，`esnext` 已包含它。

```bash
$ tsc --target es2022 --lib es2022,esnext.disposable --module esnext probe.ts
$ grep -c '__addDisposableResource' probe.js
1

$ tsc --noEmit --strict --ignoreConfig --target es2022 --lib es2022 nolib.ts
nolib.ts(1,20): error TS2304: Cannot find name 'Disposable'.
nolib.ts(2,11): error TS2550: Property 'dispose' does not exist on type 'SymbolConstructor'. Do you need to change your target library? Try changing the 'lib' compiler option to 'esnext' or later.
```

### 释放顺序在编译产物里的样子

把 `using` 降级到 `es2022`，产物多出一个环境对象和一层 try/catch/finally。声明处调 `__addDisposableResource(env_1, new Track("first"), false)`，它把对象压进 `env_1.stack`，再把对象返回给变量；块结束时 `finally` 调 `__disposeResources(env_1)`，里面是 `while (r = env.stack.pop())`，逐个取出并调用 `[Symbol.dispose]()`。取出的顺序与压入相反，所以释放顺序与声明顺序相反。

为什么用栈，而不是给每条声明包一层 try/finally：栈让 N 条声明共享一层 try/finally，产物体积随声明数线性增长；嵌套写法是平方级，也会让 `break`、`return`、异常三条出口难以合并。逆序还符合资源的常见依赖关系，后申请的先释放。

为什么只有低 target 才注入：`using` 本身是 JavaScript 语法，目标环境认它就原样保留。helper 内部还有运行时检查，`typeof value !== "object"` 或者找不到 `Symbol.dispose` 时直接抛 `TypeError`。这说明编译期只验证类型上有没有 dispose 方法，对象到底能不能释放要等运行时。

`using` 的降级产物来自 [TS 5.2 的 Explicit Resource Management](https://www.typescriptlang.org/docs/handbook/release-notes/typescript-5-2.html) 一节；产物为 tsc 7.0.2 `--target es2022` 实测。

### 两条语法边界上的报错

```ts
class Handle {
  async [Symbol.asyncDispose]() {}
}

function load() {
  await using handle = new Handle();
  return handle;
}

function take() {
  const value = yield 1;
  return value;
}
```

tsc 7.0.2 的输出（`--lib esnext`）：

```text
scope.ts(6,3): error TS2852: 'await using' statements are only allowed within async functions and at the top levels of modules.
scope.ts(11,17): error TS1163: A 'yield' expression is only allowed in a generator body.
```

TS2852 是位置错了，不是类型错了：`await using` 只能写在 async 函数里或模块顶层，改法是把 `load` 声明成 `async`，或改用同步的 `using`。TS1163 同样是语法层面的限制，`yield` 只能出现在 `function*` 体内，改法是把函数改成生成器，或用普通返回值。

两条报错放在一起看，说明生成器与资源管理改的是函数体的执行方式，不是值的类型。检查器先拦语法，再谈类型。

## 哪些语法能被 Node 直接执行

Node 26 剥离类型时只删类型，不生成运行时代码。带运行时语义的 TypeScript 语法会直接报错。

| 语法 | `node file.ts` | 原因 |
|---|---|---|
| 类型注解、`interface`、`as`、`satisfies`、`!` | 可以 | 纯类型，整体删除 |
| `function*`、`yield` | 可以 | JavaScript 语法，原样执行 |
| `using`、`await using` | 可以 | JavaScript 语法，原样执行 |
| `enum`、`const enum` | 报错 | 需要生成对象与反向映射 |
| 构造函数参数属性 | 报错 | 需要生成赋值语句 |
| 带运行时代码的 `namespace` | 报错 | 需要生成函数作用域 |
| `import x = require("y")` | 报错 | 需要改写成 import 语句 |
| 装饰器 | 报错 | 需要生成包装代码 |

```bash
$ node mode.ts
file:///private/tmp/abasic/mode.ts:1
enum Mode { A, B }
^^^^^^^^^^^^^^^^^^

SyntaxError [ERR_UNSUPPORTED_TYPESCRIPT_SYNTAX]: TypeScript enum is not supported in strip-only mode

$ tsc --noEmit --strict --ignoreConfig --target esnext --lib esnext --erasableSyntaxOnly enum.ts
enum.ts(1,6): error TS1294: This syntax is not allowed when 'erasableSyntaxOnly' is enabled.

$ tsc --noEmit --strict --ignoreConfig --target esnext --lib esnext --erasableSyntaxOnly using.ts
# 无输出，退出码 0
```

Node 26 默认开启剥离，关闭用 `--no-strip-types`。`.tsx` 不在剥离范围内，Node 直接拒绝，React 项目交给 Vite 这类构建工具处理。`--experimental-strip-types` 还能用，加不加效果一样。导入本地模块要写 `.ts` 扩展名，`import { add } from "./add.ts"` 合法，省略扩展名运行时报模块找不到。

判断标准只有一条：这段代码在 JavaScript 里有没有对应语义。需要编译器生成代码的语法，剥离模式都不接受。`tsc --erasableSyntaxOnly` 在编译期就能拦住同类问题，`using` 因为它本身就是 JavaScript 语法而不受影响。

打算只用 Node 运行、不经过 bundler 的项目，把 `erasableSyntaxOnly` 打开。这样写下的每一行都能被 `node` 直接执行，也能被任意转译器处理。设置写在 `tsconfig.json` 的 `compilerOptions` 里，只有一行：`"erasableSyntaxOnly": true`。同时打开 `verbatimModuleSyntax`，类型导入必须写成 `import type`，转译器删除时不会误删有副作用的导入。

## 一个完整的例子

临时目录、文件读写、行迭代放在一起。目录用 `using` 管理，异常时也会删除。生成器负责分行，消费方只写 `for...of`。

```typescript
import { mkdtempSync, readFileSync, rmSync, writeFileSync } from "node:fs";
import { tmpdir } from "node:os";
import { join } from "node:path";

function* lines(text: string): Generator<string, void, undefined> {
  for (const line of text.split("\n")) {
    yield line;
  }
}

function withScratchDir<T>(fn: (dir: string) => T): T {
  using dir = {
    path: mkdtempSync(join(tmpdir(), "iter-")),
    [Symbol.dispose]() {
      rmSync(this.path, { recursive: true, force: true });
    },
  };
  return fn(dir.path);
}

const total = withScratchDir((dir) => {
  const file = join(dir, "notes.txt");
  writeFileSync(file, "alpha\nbeta\ngamma\n");
  let chars = 0;
  for (const line of lines(readFileSync(file, "utf8").trim())) {
    chars += line.length;
  }
  return chars;
});

console.log(total);
```

这块按下面的命令编译（`--lib esnext --types node`）。缺 `lib` 报 `TS2318`、`TS2550`，缺 Node 类型报 `TS2591`。

```bash
$ tsc --noEmit --strict --target esnext --lib esnext --types node example.ts
$ node example.ts
14
```

这段代码能在 `node example.ts` 下直接运行。`using` 的对象用对象字面量加方法，没有用构造函数参数属性，参数属性属于需要生成的语法，剥离模式会报 ERR_UNSUPPORTED_TYPESCRIPT_SYNTAX。`withScratchDir` 里抛错时 `using` 照样执行 `rmSync`，临时目录不会留下。`lines` 没有 `return`，返回类型的第二个参数写 `void`；文件末尾的换行先 `trim()` 掉，否则会多出一行空字符串。

简单遍历不要用生成器。数组已经能 `for...of`，外面再包一层生成器，多一次调用与一个对象，收益是零。CPU 密集的循环直接写 `for`。生成器的价值在惰性、无限序列、把清理逻辑和迭代绑在一起。

异步场景用 `async function*`，返回 `AsyncGenerator<T, TReturn, TNext>`，消费端写 `for await...of`。异步迭代器目前没有 `map`、`toArray` 这些方法，链式处理要自己写循环。

## 选型表

| 需求 | 写法 |
|---|---|
| 只要能被 `for...of` 遍历 | 实现 `Iterable<T>` |
| 要链式 `map`、`take` | 返回 `Generator`，或用 `Iterator.from()` |
| 要收 `next()` 的实参 | 显式标注 `Generator<T, TReturn, TNext>` |
| 要惰性处理无限序列 | 生成器加 `take`，不要先 `toArray` |
| 同步资源随作用域释放 | `using` 加 `Disposable` |
| 异步资源随作用域释放 | `await using` 加 `AsyncDisposable` |
| 已存在的对象没有释放接口 | `try/finally` 包一层 |
| 代码要能被 `node` 直接执行 | 避开 `enum`、参数属性、`namespace` 等需要生成的语法 |

## 用不上的时候

### 数据量小且一次算完

几百条记录、算完就返回的场景，数组加 `map` 更直接。生成器多一层 `next()` 调用，返回类型还要标 `Generator<T, TReturn, TNext>`，收益抵不过阅读成本。惰性只在数据量大或序列无限时才有意义。

### 不需要双向通信

`next(实参)` 的返回值只有生成器内部用得上，平时第三个类型参数写 `undefined`。没有这个需求时，普通函数返回数组或 `Iterable` 就够，注解也短。`Generator` 的第三个参数容易写错，不用的地方不要引入。

### 已有对象没有释放接口

`using` 要求初始值实现 `[Symbol.dispose]()`，否则报 `TS2850`。为了用它给类补一个 dispose 方法，可能改到不相关的代码。这种情况 `try/finally` 包一层更直接，还能在 `finally` 里按条件释放。
