# 第 19 章 协变与逆变

把 `(dog: Dog) => void` 赋给 `(animal: Animal) => void` 会报错，反过来却通过。函数参数的子类型方向与直觉相反。这一章讲协变、逆变、双变的判定，以及 `strictFunctionTypes` 的作用范围。


一句话：变型是属性比较的方向。读位置顺着子类型走，写位置逆着走，方法参数两边都试。这个说法在方法简写上失效：方法永远双变，开了 `strictFunctionTypes` 也一样。

`Array<Dog>` 能赋给 `Array<Animal>`，反过来不行；`Setter<Dog>` 却能赋给 `Setter<Animal>`，不安全的写被放过了。

协变（Covariance）与逆变（Contravariance）是类型系统中判断**子类型关系如何随类型构造器传递**的核心概念。理解它们对于正确使用函数类型、泛型和回调参数至关重要：许多看似违反直觉的类型报错，根源都在这里。

## 什么是协变与逆变

有两种类型 `A` 和 `B`，`B` 是 `A` 的子类型（`B extends A`）。用一个类型构造器 `F<T>` 包住它们（`F` 可以是数组、Promise、函数等）。`F<B>` 和 `F<A>` 的关系由变型决定。

- **协变（Covariance）**：`F<B>` 是 `F<A>` 的子类型，**子类型关系保持不变**
- **逆变（Contravariance）**：`F<A>` 是 `F<B>` 的子类型，**子类型关系反转了**
- **不变（Invariance）**：`F<A>` 和 `F<B>` 之间没有子类型关系，**无法自动转换**
- **双变（Bivariance）**：既是协变又是逆变，**两者可以互相赋值**

## 各种类型构造器的变型

### 数组：协变

```typescript
class Animal {
  name: string = "";
}

class Dog extends Animal {
  breed: string = "";
}

// 数组是协变的：Dog[] 是 Animal[] 的子类型
const dogs: Dog[] = [new Dog()];
const animals: Animal[] = dogs;  // 正确
```

大多数主流语言的数组都是协变的。TypeScript 遵循了 JavaScript 的惯例。

### 函数返回值：协变

函数的返回值类型是协变的：

```typescript
type AnimalFactory = () => Animal;
type DogFactory = () => Dog;

let f1: AnimalFactory = () => new Animal();
let f2: DogFactory = () => new Dog();

f1 = f2;  // 正确 DogFactory 可以赋值给 AnimalFactory
// f2 = f1;  // error TS2322: Type 'AnimalFactory' is not assignable to type 'DogFactory'.
```

`DogFactory` 返回 `Dog`，而 `Dog` 是 `Animal` 的子类型，所以期望返回 `Animal` 的函数可以接受返回 `Dog` 的函数，这就是协变，子类型关系不变。

### 函数参数：逆变

**这是最关键的、也是最常让人困惑的部分**。函数的参数类型是**逆变**的：

```typescript
type AnimalHandler = (a: Animal) => void;
type DogHandler = (d: Dog) => void;

let h1: AnimalHandler = (a: Animal) => {};
let h2: DogHandler = (d: Dog) => {};

// h1 = h2;  // error TS2322: Type 'DogHandler' is not assignable to type 'AnimalHandler'.
h2 = h1;     // 正确 AnimalHandler 可以赋值给 DogHandler！
```

`AnimalHandler` 可以赋值给 `DogHandler`，原因在参数位置：

- `h2` 是 `DogHandler`，它期望接收 `Dog` 类型的参数
- 如果把 `h1`（接受任意 `Animal`）赋值给 `h2`，调用 `h2(new Dog())` 时传入的是 `AnimalHandler`，它当然能处理 `Dog`（因为 `Dog` 是 `Animal`）
- 反之，如果把 `h2`（只接受 `Dog`）赋值给 `h1`，然后 `h1(new Animal())` 传入普通 `Animal`，`h2` 函数体可能访问 `Dog` 独有的属性，运行时爆炸

因此，**函数参数是逆变的**：被赋值的一方参数类型必须更宽泛（父类型），赋值的一方参数类型可以更具体（子类型）。

### 回调参数与 strictFunctionTypes

TypeScript 默认情况下，**方法风格的函数参数是双变的**（既协变又逆变），但可以通过 `strictFunctionTypes`（包含在 `strict` 中）将其改为正确的逆变检查：

```typescript
// 开启 strictFunctionTypes 后：
type AnimalHandler = (x: Animal) => void;
type DogHandler = (x: Dog) => void;

declare let f1: AnimalHandler;
declare let f2: DogHandler;

// f1 = f2;  // error TS2322: Type 'DogHandler' is not assignable to type 'AnimalHandler'.
f2 = f1;     // 正确，逆变，AnimalHandler 可以赋给 DogHandler
```

为什么要默认双变？因为 JavaScript 生态中存在大量回调函数，参数类型写得更宽（例如 `Array.forEach((element, index, array) => ...)`）但仍然被赋值给期望更窄参数的类型，双变保证了这些代码不报错。

### 对象属性：协变（但不安全）

```typescript
interface Box<T> {
  value: T;
}

let boxAnimal: Box<Animal> = { value: new Animal() };
let boxDog: Box<Dog> = { value: new Dog() };

// boxAnimal = boxDog;  // 正确，编译通过，可变属性在 TS 里按协变检查
// boxDog = boxAnimal;  // error TS2322: Type 'Box<Animal>' is not assignable to type 'Box<Dog>'.
```

为什么会这样？因为 `T` 同时用于读写（你可以 `box.value = new Animal()`，也可以 `const a = box.value`）。TypeScript 对**可变属性**选择了"按协变检查"，它知道这不安全：把 `Box<Dog>` 赋给 `Box<Animal>` 之后，就能往里面塞一只普通 `Animal`，破坏原来 `Box<Dog>` 的类型保证。这是编译器在"实用性"和"可靠性"之间的取舍，不是保证。

想要真正安全的协变，请用 `readonly value: T` / `Readonly<T>`（只读时不变量变成协变），或者用 `in`/`out` 显式标注；需要可变又需要类型安全，就保持不变、老老实实做双向检查。

### 检查器只比一次方向

比较两个泛型实例时，检查器逐属性比。属性 `value` 只做一件事：看源属性的类型能否赋给目标属性的类型。它不区分这个属性将来被读还是被写。

写方向不参与比较，结论就是协变。`Box<Dog>` 能赋给 `Box<Animal>`，实测通过。代价是一个洞：拿到 `Box<Animal>` 后写 `new Animal()`，原来 `Box<Dog>` 里的 `value` 成了 `Animal`，编译期不拦。

为什么不按读写分开比？要证明可变位置安全，得跟踪每个引用的读写方向，还要处理别名、闭包和 `JSON.parse` 这类边界。这需要流分析，每次赋值都要重算，增量编译也会变慢。官方把系统可靠性列为非目标，见 [Design Goals](https://github.com/microsoft/TypeScript/wiki/TypeScript-Design-Goals) 里的 non-goal。

`strictFunctionTypes` 只改一类位置：属性风格的函数类型。这类签名比参数时按逆变，`(d: Dog) => void` 不能赋给 `(a: Animal) => void`。方法简写不受影响，参数仍按双变比，两个方向都试。所以 `Setter<Dog>` 能赋给 `Setter<Animal>`，开了 `strict` 也拦不住。

数组同样。`Animal[] = dogs` 通过，之后 `animals.push(new Animal())` 也通过，数组里混进非 `Dog`。`readonly Animal[]` 才拦得住，往只读数组 `push` 报 `TS2339`。

关系和缓存解释了报错位置。检查器在赋值时一次走完属性与签名比较，之后把结论写进缓存；同一个类型的后续比较直接取缓存，不再展开。所以错误总落在赋值行，而不是属性访问行。

方法标志来自声明形式。接口里的 `set(value: T): void` 与对象字面量的方法简写都算方法；`set: (value: T) => void` 算属性。写 `interface` 时用哪种写法，直接决定这个类型受不受 `strictFunctionTypes` 约束。

依据：`compareSignaturesRelated` 里参数比较分支，函数名来自 5.x 源码，行号未核对；方法排除见 [TS 2.6 发布说明](https://www.typescriptlang.org/docs/handbook/release-notes/typescript-2-6.html)；Design Goals 见前文

## 协变与逆变速查表

| 位置 | 变型 | 说明 |
|------|------|------|
| 数组 `T[]` | 协变 | `Dog[]` → `Animal[]` |
| Promise `Promise<T>` | 协变 | `Promise<Dog>` → `Promise<Animal>` |
| 函数返回值 | 协变 | `() => Dog` → `() => Animal` |
| 函数参数 | 逆变 | `(a: Animal) => void` → `(d: Dog) => void` |
| 对象属性（读写） | 协变（不安全） | `{value: Dog}` → `{value: Animal}` 能过，反向报错 |
| 只读属性/集合 | 协变 | 只读的属性不需要逆变保护 |

## TypeScript 4.7+ 的变型标注

从 [TypeScript 4.7](https://www.typescriptlang.org/docs/handbook/release-notes/typescript-4-7.html) 开始，泛型类型参数支持显式的变型标注（Variance Annotations），这让你可以在定义泛型类/接口时就明确指定变型方向：

```typescript
// 只读数据：协变（out）
interface ReadonlyBox<out T> {
  readonly value: T;
}

// 只写数据：逆变（in）
interface WriteOnlyBox<in T> {
  set(value: T): void;
}

// 可读写数据：不变（in out / 不标注）
interface Box<in out T> {
  value: T;
}
```

标注了 `out` 的类型参数只能出现在**输出位置**（返回值、只读属性），标注了 `in` 的只能出现在**输入位置**（参数、写属性），标注了 `in out` 或无标注的可以出现在任何位置。如果标注与实际使用冲突，TypeScript 会报错。

```typescript
interface EventEmitter<out T> {
  on(handler: (event: T) => void): void;
  // emit: (event: T) => void;  // error TS2636: Type 'EventEmitter<sub-T>' is not assignable to type 'EventEmitter<super-T>' as implied by variance annotation.
}
```

方法简写会按双变检查，不触发这条校验；改成属性写法才会报 TS2636。

大多数情况下不需要手动标变型，TypeScript 会自动从参数的结构中推导。显式标注主要用于：
- 编译器检查：防止你意外在协变位置使用逆变参数
- 文档价值：让阅读者一眼就知道泛型参数的读写角色
- 更精确的类型兼容：标注后编译器可以放宽一些类型检查

## 函数参数的双变历史

在 `strictFunctionTypes` 开启之前（或未开启时），TypeScript 的函数参数是**双变**的。这意味着以下两种赋值都通过：

```typescript
// strictFunctionTypes 关闭时，以下都通过：
declare let f1: (a: Animal) => void;
declare let f2: (d: Dog) => void;

f1 = f2;  // 正确 协变方向
f2 = f1;  // 正确 逆变方向
```

双变是 TypeScript 为了与大量非类型安全的 JavaScript 代码兼容所做的妥协。开启 `strictFunctionTypes`（推荐）会让**属性风格**的函数类型（`handler: (x: Dog) => void`）按正确逆变检查，但**方法简写**（`method() {}`）不受影响，始终保持双变：

```typescript
interface T {
  // 属性风格：受 strictFunctionTypes 影响，参数逆变
  handler: (x: Dog) => void;

  // 方法简写：不受 strictFunctionTypes 影响，始终双变
  handle(x: Dog): void;
}
```

## 实际开发中的影响

### 回调参数类型

```typescript
// forEach 的类型大致是：
// forEach(callbackfn: (value: T, index: number, array: T[]) => void): void;

const animals: Animal[] = [];
const callback = (a: Animal) => {};  // 参数更宽

// 由于参数逆变，这应该是安全的
// 实际上 TypeScript 默认允许，因为 callback 能处理任何 Animal（包括 Dog）
```

### React 事件处理

```typescript
// 逆变保证：你可以传入接受更宽泛事件的处理器
const handleEvent = (e: Event) => {
  console.log(e.target);
};

// 正确，逆变使得这个赋值安全，handleEvent 能处理任何 Event
const btn = document.querySelector("button")!;
btn.addEventListener("click", handleEvent);
```

## 常见报错

两处报错来自同一个文件，用 tsc 7.0.2 实跑：

```ts
class Animal { name = ""; }
class Dog extends Animal { breed = ""; }

declare let animalHandler: (a: Animal) => void;
declare let dogHandler: (d: Dog) => void;
animalHandler = dogHandler;

declare function useHandler(handler: (a: Animal) => void): void;
useHandler((d: Dog) => {});
```

```text
variance.ts(6,1): error TS2322: Type '(d: Dog) => void' is not assignable to type '(a: Animal) => void'.
  Types of parameters 'd' and 'a' are incompatible.
    Property 'breed' is missing in type 'Animal' but required in type 'Dog'.
variance.ts(9,12): error TS2345: Argument of type '(d: Dog) => void' is not assignable to parameter of type '(a: Animal) => void'.
  Types of parameters 'd' and 'a' are incompatible.
    Property 'breed' is missing in type 'Animal' but required in type 'Dog'.
```

第一处 `TS2322`：属性风格函数类型的参数逆变，只接受 `Dog` 的函数接不住任意 `Animal`。改法是把参数放宽成 `Animal`。

第二处 `TS2345`：回调位置的规则相同，传进去的函数参数比目标窄。改法是让回调参数用目标类型，或改成泛型让调用处决定。

两处报错都不是“类型名不同”，而是参数位置不兼容。看附加行里缺了哪个成员，就知道方向反在了哪里。

## 小结

- **协变**：子类型关系保持不变（`Dog[] → Animal[]`，函数返回值）
- **逆变**：子类型关系反转（函数参数，`(Animal => void) → (Dog => void)`）
- **协变（不安全）**：可变属性在 TS 里按协变检查，`{value: Dog}` 能赋给 `{value: Animal}`，反向报错；要安全就用 `readonly`
- TypeScript 4.7+ 支持显式变型标注（`out`/`in`/`in out`）
- 开启 `strictFunctionTypes` 获得正确的参数逆变检查
- 方法简写是双变的（历史兼容），属性风格的函数类型是逆变的

## 用不上的时候

### 纯数据结构

只读、不可变的数据按协变理解就够，不需要关心逆变。

### 可变属性

把 `{ value: Dog }` 赋给 `{ value: Animal }` 后写入 `Animal`，读出来是错的。要么加 `readonly`，要么接受这个洞。

### 方法简写

`strictFunctionTypes` 不检查方法简写，方法参数仍是双变。要严格检查就写成属性风格的函数类型。
