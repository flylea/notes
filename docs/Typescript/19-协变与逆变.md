# 第19章 协变与逆变

协变（Covariance）与逆变（Contravariance）是类型系统中判断**子类型关系如何随类型构造器传递**的核心概念。理解它们对于正确使用函数类型、泛型和回调参数至关重要——许多看似违反直觉的类型报错，根源都在这里。

## 什么是协变与逆变

假设我们有两种类型 `A` 和 `B`，且 `B` 是 `A` 的子类型（`B extends A`）。现在用一个类型构造器 `F<T>` 包住它们（`F` 可以是数组、Promise、函数等）。问题是：`F<B>` 和 `F<A>` 的关系是什么？

- **协变（Covariance）**：`F<B>` 是 `F<A>` 的子类型——**子类型关系保持不变**
- **逆变（Contravariance）**：`F<A>` 是 `F<B>` 的子类型——**子类型关系反转了**
- **不变（Invariance）**：`F<A>` 和 `F<B>` 之间没有子类型关系——**无法自动转换**
- **双变（Bivariance）**：既是协变又是逆变——**两者可以互相赋值**

## 各种类型构造器的变型

### 数组——协变

```typescript
class Animal {
  name: string = "";
}

class Dog extends Animal {
  breed: string = "";
}

// 数组是协变的：Dog[] 是 Animal[] 的子类型
const dogs: Dog[] = [new Dog()];
const animals: Animal[] = dogs;  // ✅
```

大多数主流语言的数组都是协变的。TypeScript 遵循了 JavaScript 的惯例。

### 函数返回值——协变

函数的返回值类型是协变的：

```typescript
type AnimalFactory = () => Animal;
type DogFactory = () => Dog;

let f1: AnimalFactory = () => new Animal();
let f2: DogFactory = () => new Dog();

f1 = f2;  // ✅ DogFactory 可以赋值给 AnimalFactory
// f2 = f1;  // ❌ AnimalFactory 不能赋值给 DogFactory
```

`DogFactory` 返回 `Dog`，而 `Dog` 是 `Animal` 的子类型，所以期望返回 `Animal` 的函数可以接受返回 `Dog` 的函数——协变，子类型关系不变。

### 函数参数——逆变

**这是最关键的、也是最常让人困惑的部分**。函数的参数类型是**逆变**的：

```typescript
type AnimalHandler = (a: Animal) => void;
type DogHandler = (d: Dog) => void;

let h1: AnimalHandler = (a: Animal) => {};
let h2: DogHandler = (d: Dog) => {};

// h1 = h2;  // ❌ DogHandler 不能赋值给 AnimalHandler
h2 = h1;     // ✅ AnimalHandler 可以赋值给 DogHandler！
```

什么？`AnimalHandler` 可以赋值给 `DogHandler`？让我们分析一下：

- `h2` 是 `DogHandler`，它期望接收 `Dog` 类型的参数
- 如果把 `h1`（接受任意 `Animal`）赋值给 `h2`，调用 `h2(new Dog())` 时传入的是 `AnimalHandler`，它当然能处理 `Dog`（因为 `Dog` 是 `Animal`）
- 反之，如果把 `h2`（只接受 `Dog`）赋值给 `h1`，然后 `h1(new Animal())` 传入普通 `Animal`，`h2` 函数体可能访问 `Dog` 独有的属性——运行时爆炸

因此，**函数参数是逆变的**：被赋值的一方参数类型必须更宽泛（父类型），赋值的一方参数类型可以更具体（子类型）。

### 回调参数与 strictFunctionTypes

TypeScript 默认情况下，**方法风格的函数参数是双变的**（既协变又逆变），但可以通过 `strictFunctionTypes`（包含在 `strict` 中）将其改为正确的逆变检查：

```typescript
// 开启 strictFunctionTypes 后：
declare function f1(x: Animal): void;
declare function f2(x: Dog): void;

// f1 = f2;  // ❌ strictFunctionTypes 下报错
f2 = f1;     // ✅ 逆变——AnimalHandler 可以赋给 DogHandler
```

为什么要默认双变？因为 JavaScript 生态中存在大量回调函数，参数类型写得更宽（例如 `Array.forEach((element, index, array) => ...)`）但仍然被赋值给期望更窄参数的类型——双变保证了这些代码不报错。

### 对象属性——不变

```typescript
interface Box<T> {
  value: T;
}

let boxAnimal: Box<Animal> = { value: new Animal() };
let boxDog: Box<Dog> = { value: new Dog() };

// boxAnimal = boxDog;  // ❌ 不能互相赋值（不变）
// boxDog = boxAnimal;  // ❌
```

为什么是不变？因为 `T` 同时用于读写（你可以 `box.value = new Animal()`，也可以 `const a = box.value`）。如果协变，你就能把 `Box<Dog>` 赋值给 `Box<Animal>`，然后往里面放普通 `Animal`——破坏了 `Box<Dog>` 的类型保证。

## 协变与逆变速查表

| 位置 | 变型 | 说明 |
|------|------|------|
| 数组 `T[]` | 协变 | `Dog[]` → `Animal[]` |
| Promise `Promise<T>` | 协变 | `Promise<Dog>` → `Promise<Animal>` |
| 函数返回值 | 协变 | `() => Dog` → `() => Animal` |
| 函数参数 | 逆变 | `(a: Animal) => void` → `(d: Dog) => void` |
| 对象属性（读写） | 不变 | `{value: Dog}` 和 `{value: Animal}` 不能互转 |
| 只读属性/集合 | 协变 | 只读的属性不需要逆变保护 |

## TypeScript 4.7+ 的变型标注

从 TypeScript 4.7 开始，泛型类型参数支持显式的变型标注（Variance Annotations），这让你可以在定义泛型类/接口时就明确指定变型方向：

```typescript
// 只读数据——协变（out）
interface ReadonlyBox<out T> {
  readonly value: T;
}

// 只写数据——逆变（in）
interface WriteOnlyBox<in T> {
  set(value: T): void;
}

// 可读写数据——不变（in out / 不标注）
interface Box<in out T> {
  value: T;
}
```

标注了 `out` 的类型参数只能出现在**输出位置**（返回值、只读属性），标注了 `in` 的只能出现在**输入位置**（参数、写属性），标注了 `in out` 或无标注的可以出现在任何位置。如果标注与实际使用冲突，TypeScript 会报错。

```typescript
interface EventEmitter<out T> {
  on(handler: (event: T) => void): void;
  // emit(event: T): void;  // ❌ T 在 out 位置，不能作为参数
}
```

大多数情况下不需要手动标变型——TypeScript 会自动从参数的结构中推导。显式标注主要用于：
- 编译器检查——防止你意外在协变位置使用逆变参数
- 文档价值——让阅读者一眼就知道泛型参数的读写角色
- 更精确的类型兼容——标注后编译器可以放宽一些类型检查

## 函数参数的双变历史

在 `strictFunctionTypes` 开启之前（或未开启时），TypeScript 的函数参数是**双变**的。这意味着以下两种赋值都通过：

```typescript
// strictFunctionTypes 关闭时，以下都通过：
declare let f1: (a: Animal) => void;
declare let f2: (d: Dog) => void;

f1 = f2;  // ✅ 协变方向
f2 = f1;  // ✅ 逆变方向
```

双变是 TypeScript 为了与大量非类型安全的 JavaScript 代码兼容所做的妥协。开启 `strictFunctionTypes`（推荐）会将方法签名的参数改为正确的逆变，但**方法简写**（`method() {}`）不受影响，保持双变：

```typescript
interface T {
  // 属性风格——受 strictFunctionTypes 影响，参数逆变
  handler: (x: Dog) => void;

  // 方法简写——不受 strictFunctionTypes 影响，始终双变
  handle(x: Dog): void;
}
```

## 实际开发中的影响

### 回调参数类型

```typescript
// forEach 的类型大致是：
// forEach(callbackfn: (value: T, index: number, array: T[]) => void): void;

const animals: Animal[] = [];
const callback = (a: Animal) => {};  // 参数更宽

// 由于参数逆变，这应该是安全的
// 实际上 TypeScript 默认允许，因为 callback 能处理任何 Animal（包括 Dog）
```

### React 事件处理

```typescript
// 逆变保证：你可以传入接受更宽泛事件的处理器
const handleEvent = (e: Event) => {
  console.log(e.target);
};

// ✅ 逆变使得这个赋值安全——handleEvent 能处理任何 Event
const btn = document.querySelector("button")!;
btn.addEventListener("click", handleEvent);
```

## 本章小结

- **协变**：子类型关系保持不变（`Dog[] → Animal[]`，函数返回值）
- **逆变**：子类型关系反转（函数参数，`(Animal => void) → (Dog => void)`）
- **不变**：无子类型关系（可读写属性）
- TypeScript 4.7+ 支持显式变型标注（`out`/`in`/`in out`）
- 开启 `strictFunctionTypes` 获得正确的参数逆变检查
- 方法简写是双变的（历史兼容），属性风格的函数类型是逆变的
