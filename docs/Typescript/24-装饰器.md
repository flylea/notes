# 第24章 装饰器

装饰器（Decorator）是一种特殊的声明式语法，使用 `@expression` 的形式附加在类、方法、属性或参数上，能够在**编译时或运行时**修改类的行为。它是 TypeScript 中实现**元编程**的核心机制，在 Angular、NestJS、type-graphql 等框架中被大量使用。

## 装饰器概述

装饰器的本质就是一个**函数**，只不过它的参数是框架提前确定好的——被装饰的类、方法或属性等信息。基本形式：

```typescript
// 简单装饰器
function Sealed(constructor: Function) {
  Object.seal(constructor);
  Object.seal(constructor.prototype);
}

@Sealed
class BugReport {
  type = "report";
  title: string;
  constructor(t: string) {
    this.title = t;
  }
}
```

### 装饰器工厂

更常用的是**装饰器工厂（Decorator Factory）**——一个返回装饰器函数的函数，通过外层参数来灵活配置装饰器的行为：

```typescript
function Log(prefix: string) {
  return function (target: Function) {
    // 真正的装饰逻辑，可以访问 prefix
  };
}

@Log("MyClass")
class Foo {}
```

### 两个版本的历史

目前存在**两套装饰器语法**：

| 版本 | 语法 | 状态 | 启用方式 |
|------|------|------|---------|
| 旧版（实验性） | `@decorator` | TypeScript 一直支持 | `experimentalDecorators: true` |
| 新版（TC39 标准） | `@decorator` | TS 5.0+，Stage 3 | 默认支持（不开启 experimentalDecorators） |

两者的核心差异：新版装饰器完全遵循 TC39 提案设计，基于 `context` 对象提供统一的能力，且原生支持 `accessor` 关键字。旧版则更 "TypeScript 化"，提供了 `descriptor` 等能力。

大多数现有框架（NestJS、Angular 等）仍使用旧版装饰器，因此本章**先介绍旧版**（实际项目中最常见），**再介绍新版**（未来发展方向）。

## 旧版装饰器（Experimental）

需要开启配置：

```json
{
  "compilerOptions": {
    "experimentalDecorators": true,
    "emitDecoratorMetadata": true
  }
}
```

旧版装饰器有五种类型：**类装饰器**、**方法装饰器**、**访问符装饰器**、**属性装饰器**、**参数装饰器**。

### 类装饰器

类装饰器的唯一参数是**类的构造函数**本身：

```typescript
type ClassDecorator = <TFunction extends Function>(
  target: TFunction
) => TFunction | void;

// 使用
function AddProperty(value: string): ClassDecorator {
  return (target: any) => {
    // target 是构造函数本身
    target.prototype.newProp = value;
    target.newStaticProp = `static ${value}`;
  };
}

@AddProperty("hello")
class Foo {
  a = 1;
}

const foo: any = new Foo();
console.log(foo.newProp);           // "hello"
console.log((Foo as any).newStaticProp); // "static hello"
```

类装饰器可以返回一个新的构造函数来**完全替换原来的类**：

```typescript
const OverrideBar = (target: any) => {
  return class extends target {
    print() {
      console.log("This is Overridden Bar!");
    }
  };
};

@OverrideBar
class Bar {
  print() {
    console.log("This is Bar!");
  }
}

new Bar().print(); // "This is Overridden Bar!"
```

### 方法装饰器

方法装饰器接受三个参数：**类的原型（实例方法）或构造函数（静态方法）**、**方法名**、**属性描述符**：

```typescript
type MethodDecorator = <T>(
  target: Object,
  propertyKey: string | symbol,
  descriptor: TypedPropertyDescriptor<T>
) => TypedPropertyDescriptor<T> | void;
```

最经典的用法是**包装原方法**，在不修改原逻辑的情况下添加新行为：

```typescript
function ComputeProfiler(): MethodDecorator {
  const start = new Date();
  return (_target, methodIdentifier, descriptor: any) => {
    const original = descriptor.value;
    descriptor.value = async function (...args: unknown[]) {
      const res = await original.apply(this, args);
      const end = new Date();
      console.log(
        `${String(methodIdentifier)} 耗时: ${end.getTime() - start.getTime()}ms`
      );
      return res;
    };
  };
}

class ApiService {
  @ComputeProfiler()
  async fetchData() {
    return new Promise((resolve) => {
      setTimeout(() => resolve("data"), 2000);
    });
  }
}
// fetchData 耗时: 2003ms
```

另一个常用模式是**方法参数日志**：

```typescript
function Log(target: any, propertyKey: string, descriptor: PropertyDescriptor) {
  const original = descriptor.value;
  descriptor.value = function (...args: any[]) {
    console.log(`调用 ${propertyKey}，参数:`, args);
    const result = original.call(this, ...args);
    console.log(`${propertyKey} 返回:`, result);
    return result;
  };
}

class Calculator {
  @Log
  add(x: number, y: number) {
    return x + y;
  }
}

new Calculator().add(3, 5);
// 调用 add，参数: [3, 5]
// add 返回: 8
```

### 访问符装饰器

访问符装饰器作用于 getter 或 setter，入参与方法装饰器完全一致。**重要**：只能装饰一对 getter/setter 中的**其中一个**（装饰谁都能拿到完整的 get/set）：

```typescript
function HijackSetter(val: string): MethodDecorator {
  return (target, methodIdentifier, descriptor: any) => {
    const originalSetter = descriptor.set;
    descriptor.set = function (newValue: string) {
      const composed = `${val}-${newValue}`;
      originalSetter.call(this, composed);
    };
  };
}

class Foo {
  _value!: string;

  get value() {
    return this._value;
  }

  @HijackSetter("PREFIX")
  set value(input: string) {
    this._value = input;
  }
}

const f = new Foo();
f.value = "hello";
console.log(f.value); // "PREFIX-hello"
```

### 属性装饰器

属性装饰器的入参只有两个：**类的原型（实例属性）或构造函数（静态属性）**、**属性名**。它**拿不到属性值**（因为装饰器在实例化之前执行），返回值也会被忽略：

```typescript
type PropertyDecorator = (
  target: Object,
  propertyKey: string | symbol
) => void;
```

单独使用时能力有限，但可以通过在原型上定义属性来做一些 hack：

```typescript
function DefaultValue(value: string): PropertyDecorator {
  return (target: any, propertyKey) => {
    target[propertyKey] = value;
  };
}

class User {
  @DefaultValue("Guest")
  name!: string;
}

console.log(new User().name); // "Guest"
```

属性装饰器的真正威力在于**配合反射元数据（reflect-metadata）**来注册元数据信息，留待后续消费。

### 参数装饰器

参数装饰器接受三个参数：**类的原型**、**方法名**、**参数在参数列表中的索引**。返回值被忽略：

```typescript
type ParameterDecorator = (
  target: Object,
  propertyKey: string | symbol,
  parameterIndex: number
) => void;
```

```typescript
function Required(): ParameterDecorator {
  return (target, propertyKey, parameterIndex) => {
    console.log(`${String(propertyKey)} 的第 ${parameterIndex} 个参数被标记为必填`);
  };
}

class Service {
  greet(@Required() name: string) {
    console.log(`Hello, ${name}`);
  }
}
```

参数装饰器本身也无法直接修改类的行为，主要用于**注册元数据**。

### 旧版装饰器的执行顺序

**执行时机**：装饰器在**类定义时**执行，而不是在类实例化时。即使从未 `new` 过这个类，装饰器逻辑也已经执行完毕。

**执行顺序**（官方定义）：

1. 实例成员的参数装饰器 → 方法/访问符/属性装饰器
2. 静态成员的参数装饰器 → 方法/访问符/属性装饰器
3. 构造函数的参数装饰器
4. 类装饰器

同类装饰器按**从下往上**的顺序应用（洋葱模型）：

```typescript
function A(): MethodDecorator {
  console.log("A in");
  return () => console.log("A out");
}

function B(): MethodDecorator {
  console.log("B in");
  return () => console.log("B out");
}

class Foo {
  @A()
  @B()
  method() {}
}
// A in
// B in
// B out
// A out
```

## 反射元数据（reflect-metadata）

`reflect-metadata` 是一个独立的 polyfill 包，为 `Reflect` 全局对象增添了元数据读写 API。它是实现"装饰器只负责注册，由外部统一消费"这一模式的关键：

```bash
npm install reflect-metadata
```

```typescript
import "reflect-metadata";

// 注册元数据
Reflect.defineMetadata("role", "admin", User.prototype, "delete");

// 读取元数据
Reflect.getMetadata("role", User.prototype, "delete"); // "admin"
```

启动 `emitDecoratorMetadata` 后，TypeScript 会自动为装饰的类成员添加三条内置元数据：

- `design:type`：属性的类型
- `design:paramtypes`：方法的参数类型
- `design:returntype`：方法的返回值类型

这是实现依赖注入（DI）的基础——框架通过这些元数据就能知道"这个构造函数需要什么参数"、"这个属性是什么类型"，从而自动完成注入。

### 实战：基于装饰器 + 元数据的属性校验

```typescript
import "reflect-metadata";

const requiredKey = Symbol("required");
const typeKey = Symbol("type");

// 必填标记
function Required(): PropertyDecorator {
  return (target, prop) => {
    const existing: string[] =
      Reflect.getMetadata(requiredKey, target) ?? [];
    Reflect.defineMetadata(requiredKey, [...existing, prop], target);
  };
}

// 类型标记
function TypeCheck(expectedType: string): PropertyDecorator {
  return (target, prop) => {
    Reflect.defineMetadata(typeKey, expectedType, target, prop);
  };
}

// 校验函数
function validate(entity: any): string[] {
  const errors: string[] = [];
  const clsName = entity.constructor.name;

  // 必填检查
  const required: string[] =
    Reflect.getMetadata(requiredKey, entity) ?? [];
  const existing = Reflect.ownKeys(entity);
  for (const key of required) {
    if (!existing.includes(key)) {
      errors.push(`${clsName}.${String(key)} 为必填属性`);
    }
  }

  // 类型检查
  for (const key of existing) {
    const expected = Reflect.getMetadata(typeKey, entity, key);
    if (expected && typeof entity[key] !== expected) {
      errors.push(
        `${clsName}.${String(key)} 应为 ${expected}，实际为 ${typeof entity[key]}`
      );
    }
  }

  return errors;
}

// 使用
class User {
  @Required()
  name!: string;

  @TypeCheck("number")
  age!: number;
}

const user = new User();
(user as any).age = "十八";
console.log(validate(user));
// ["User.name 为必填属性", "User.age 应为 number，实际为 string"]
```

## 新版 TC39 装饰器（TypeScript 5.0+）

TC39 装饰器提案于 2022 年 3 月进入 Stage 3，TypeScript 5.0 开始原生支持。**不开启 `experimentalDecorators` 时即为新版语法**。

核心变化：
- 统一的 `context` 参数替代了旧版不同装饰器的不同参数
- 引入了 `accessor` 关键字用于自动生成 getter/setter
- 移除了 parameter decorator（参数装饰器不再单独存在）
- `addInitializer` 钩子替代了构造函数中的初始化代码

### 新版装饰器类型定义

```typescript
type Decorator = (
  value: DecoratedValue,
  context: {
    kind: string;         // 'class' | 'method' | 'getter' | 'setter' | 'field' | 'accessor'
    name: string | symbol;
    addInitializer?(initializer: () => void): void;
    static?: boolean;
    private?: boolean;
    access: {
      get?(): unknown;
      set?(value: unknown): void;
    };
  }
) => void | ReplacementValue;
```

`kind` 字段决定了装饰器的种类，总共六种：`class`、`method`、`getter`、`setter`、`field`、`accessor`。

### 新版类装饰器

第一个参数是类本身，`context.kind` 固定为 `"class"`：

```typescript
function logged(value: Function, context: ClassDecoratorContext) {
  console.log(`类 ${context.name} 被装饰`);
}

@logged
class MyClass {}
// 类 MyClass 被装饰
```

可以通过 `addInitializer` 在类完全定义后执行初始化逻辑：

```typescript
function customElement(name: string) {
  return (value: Function, context: ClassDecoratorContext) => {
    context.addInitializer(() => {
      customElements.define(name, value as any);
    });
  };
}

@customElement("hello-world")
class MyComponent extends HTMLElement {}
```

### 新版方法装饰器

`context.kind` 为 `"method"`：

```typescript
function logged(
  originalMethod: Function,
  context: ClassMethodDecoratorContext
) {
  const methodName = String(context.name);

  return function (this: any, ...args: any[]) {
    console.log(`进入 ${methodName}`);
    const result = originalMethod.call(this, ...args);
    console.log(`离开 ${methodName}`);
    return result;
  };
}

class Person {
  name: string;
  constructor(name: string) {
    this.name = name;
  }

  @logged
  greet() {
    console.log(`Hello, ${this.name}`);
  }
}

new Person("Alice").greet();
// 进入 greet
// Hello, Alice
// 离开 greet
```

### 新版属性装饰器（field）

第一个参数恒为 `undefined`，装饰器可返回一个**初始化函数**来修改初始值：

```typescript
function double() {
  return (initialValue: number) => initialValue * 2;
}

class Math {
  @double
  value = 3;
}

new Math().value; // 6
```

### 新版 accessor 装饰器

`accessor` 是装饰器提案引入的新关键字，自动为公开属性生成私有的 getter 和 setter：

```typescript
class C {
  accessor x = 1;
}

// 等价于
class C {
  #x = 1;
  get x() { return this.#x; }
  set x(val) { this.#x = val; }
}
```

accessor 装饰器的 `value` 参数包含 `get` 和 `set`，可返回新对象替换：

```typescript
function logged(
  value: { get: () => unknown; set: (v: unknown) => void },
  context: ClassAccessorDecoratorContext
) {
  const { get, set } = value;

  return {
    get() {
      console.log(`读取 ${String(context.name)}`);
      return get.call(this);
    },
    set(val) {
      console.log(`设置 ${String(context.name)} = ${val}`);
      return set.call(this, val);
    },
    init(initialValue: unknown) {
      console.log(`初始化 ${String(context.name)} = ${initialValue}`);
      return initialValue;
    },
  };
}

class Person {
  @logged
  accessor name = "Alice";
}

const p = new Person();
// 初始化 name = Alice
p.name;
// 读取 name
p.name = "Bob";
// 设置 name = Bob
```

## 新旧装饰器对比

| 特性 | 旧版（实验性） | 新版（TC39） |
|------|---------------|-------------|
| 启用方式 | `experimentalDecorators: true` | 默认（TS 5.0+） |
| 参数装饰器 | 支持 | 不支持 |
| 属性装饰器可拿 value | 否（通过 prototype 变通） | 可返回初始化函数 |
| accessor 关键字 | 无 | 有 |
| context 统一 | 否（不同装饰器不同参数） | 是（统一的 context 对象） |
| `addInitializer` | 无 | 有 |
| `Reflect.metadata` 内置 | 是（通过 `emitDecoratorMetadata`） | 否（需要手动注册） |
| 生态现状 | NestJS、Angular 等大量使用 | 尚在迁移中 |

## 本章小结

- **装饰器的本质**是一个函数，通过 `@` 语法在编译/运行时修改类的行为
- **旧版装饰器**分为五类：类、方法、访问符、属性、参数，执行顺序为实例成员 → 静态成员 → 构造函数参数 → 类
- **反射元数据**通过 `reflect-metadata` 实现，让装饰器注册信息 + 外部统一消费，是依赖注入的基础
- **新版 TC39 装饰器**使用统一的 `context` 参数，引入 `accessor` 关键字，移除参数装饰器，用 `addInitializer` 替代构造函数中的初始化
- 目前生产环境仍以旧版为主（NestJS、Angular 等），但新版是未来方向
