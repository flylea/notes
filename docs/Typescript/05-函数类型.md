# 第5章 函数类型

函数是 JavaScript 中传递数据的主要手段——处理 HTTP 请求、响应 UI 事件、转换数组数据，一切都围绕着函数。TypeScript 为函数提供了完整的类型标注能力，从简单的参数/返回值标注，到精确描述"不同输入对应不同输出"的函数重载。

本章将系统讲解 TypeScript 中与函数类型相关的全部知识。

## 函数的类型签名

函数的类型由两部分组成：**参数类型**和**返回值类型**。

```typescript
function greet(name: string): string {
  return `Hello, ${name}!`;
}
```

在这个例子中：
- `name: string` — 参数类型标注，必须在参数名之后
- `): string` — 返回值类型标注，在参数列表的括号之后

TypeScript 的类型标注始终在"被标注的东西"的**右边**（不是 C/Java 的 `int x = 0` 风格），这与整个类型系统的设计保持一致。

### 返回值类型的推导

大多数情况下，TypeScript 可以自动推导返回值类型：

```typescript
function add(x: number, y: number) {
  return x + y;  // 推导返回 number
}

function log(msg: string) {
  console.log(msg);  // 推导返回 void
}
```

但**显式标注返回值类型**仍然是一个好习惯，原因有二：
1. **文档价值**：阅读函数签名的人不需要看函数体就能知道返回什么
2. **防止意外**：如果函数体中的 return 语句类型不一致，你会第一时间在函数签名这里看到报错，而非在调用处才发现

### 函数表达式的类型标注

函数表达式（`const foo = function(){}`）有两种标注方式：

**方式一：在函数身上标注（推荐）**

```typescript
const add = function (x: number, y: number): number {
  return x + y;
};

const multiply = (x: number, y: number): number => x * y;
```

**方式二：标注变量的类型（函数类型签名）**

```typescript
const add: (x: number, y: number) => number = function (x, y) {
  return x + y;
};

const multiply: (x: number, y: number) => number = (x, y) => x * y;
```

方式二中 `(x: number, y: number) => number` 就是 TypeScript 的**函数类型签名**语法。注意以下几个细节：

- **参数名不可省略**：`(string, number) => void` 中的 `string` 和 `number` 会被当作参数**名称**（而非类型），且类型被推导为 `any`。必须写成 `(name: string, age: number) => void`
- **类型签名中的参数名与实际参数名可以不一致**：`let f: (x: number) => number = function(y: number) { return y; }` 是合法的
- 方式二混合箭头函数声明时可读性很差，在实际项目中通常是直接标注函数参数和返回值，或用**类型别名**抽离签名

### 使用类型别名抽离函数签名

当函数签名较长，或多个函数共享同一签名时，应该提取为类型别名：

```typescript
type FetchCallback = (url: string, options?: RequestInit) => Promise<Response>;

const get: FetchCallback = async (url, options) => {
  const res = await fetch(url, options);
  return res;
};

const post: FetchCallback = async (url, options) => {
  const res = await fetch(url, { ...options, method: "POST" });
  return res;
};
```

`interface` 也可以描述函数类型（称为 **Callable Interface**），不过在实际项目中几乎只见于特殊情况：

```typescript
interface FetchCallback {
  (url: string, options?: RequestInit): Promise<Response>;
}
```

### 参数较少与参数较多的兼容性

TypeScript 允许将**参数较少**的函数赋值给参数较多的函数类型（反之不行）：

```typescript
let x = (a: number) => 0;                 // 1 个参数
let y = (a: number, b: string) => 0;      // 2 个参数

y = x;  // ✅ 参数少的赋给参数多的——允许
x = y;  // ❌ 参数多的赋给参数少的——不允许
```

这是刻意设计的：在 JavaScript 中，回调函数接收的参数通常比它实际需要的多（比如 `Array.forEach(callback)` 会传递 `(element, index, array)` 三个参数，但回调往往只使用 `element`）。TypeScript 的这个规则确保了这种常见模式的类型安全。

## 参数类型

### 可选参数

在参数名后加 `?` 表示可选：

```typescript
function buildName(first: string, last?: string): string {
  if (last) {
    return `${first} ${last}`;
  }
  return first;
}

buildName("Alice");            // ✅
buildName("Alice", "Smith");   // ✅
```

**可选参数必须放在必选参数之后**——因为 JavaScript 是按位置（而非按名称）传参的。

可选参数的类型自动包含 `undefined`：

```typescript
function log(msg: string, timestamp?: number) {
  // timestamp 的类型是 number | undefined
  if (timestamp !== undefined) {
    console.log(`[${timestamp}] ${msg}`);
  } else {
    console.log(msg);
  }
}
```

### 参数默认值

有默认值的参数自动成为可选的，且类型可以从默认值推导：

```typescript
function createUser(name: string, age: number = 18) {
  // age 被推导为 number，且是可选参数
}

createUser("Alice");           // ✅ age 默认 18
createUser("Alice", undefined); // ✅ 显式传 undefined 也用默认值
createUser("Alice", 25);       // ✅
```

注意：当你有默认值又想显式标注类型时，类型必须兼容默认值。而且有默认值的参数不需要再写 `?`——有默认值本身就意味着可选。

### rest 参数

rest 参数用数组类型（或元组类型）标注：

```typescript
// 任意数量的数值
function sum(...nums: number[]): number {
  return nums.reduce((acc, n) => acc + n, 0);
}

sum(1, 2);
sum(1, 2, 3, 4, 5);

// 元组 rest：限定前几个参数的类型
function greetAll(greeting: string, ...names: string[]): string[] {
  return names.map(name => `${greeting}, ${name}!`);
}
```

对于更复杂的 rest 场景，可以使用元组标注：

```typescript
function pair(greeting: string, ...rest: [number, boolean]): void {}

pair("hello", 1, true);   // ✅
// pair("hello", 1);      // ❌ 少了一个
// pair("hello", 1, true, 2); // ❌ 多了一个
```

### 参数解构

```typescript
function draw({ x, y }: { x: number; y: number }): void {
  console.log(`Point(${x}, ${y})`);
}

// 解构参数的类型较长时应提取：
interface Point {
  x: number;
  y: number;
}
function draw2({ x, y }: Point): void {}
```

## 函数重载

函数重载是 TypeScript 中最容易被误解但也非常强大的特性。它让你可以声明同一个函数的**多组不同参数和返回值类型**，每种组合对应不同的调用方式。

### 为什么需要重载

考虑一个场景：根据参数的不同，返回值类型也不同：

```typescript
// ❌ 只用联合类型，丢失了输入输出之间的关联
function getItems(key: string | number): string | string[] {
  if (key === "all") return ["a", "b", "c"];
  if (typeof key === "number") return "default";
  return "unknown";
}

const all = getItems("all");  // 类型是 string | string[]
// 你明知 "all" 返回 string[]，但 TS 不知道——还得手动断言
```

重载解决了这个问题——明确声明"哪种输入对应哪种输出"：

```typescript
// 重载签名 1：传入 "all" 时返回 string[]
function getItems(key: "all"): string[];
// 重载签名 2：传入 number 时返回 string
function getItems(key: number): string;
// 重载签名 3：传入其他 string 时返回 string | undefined
function getItems(key: string): string | undefined;
// 实现签名——包含所有可能的情况
function getItems(key: string | number): string | string[] | undefined {
  if (key === "all") return ["a", "b", "c"];
  if (typeof key === "number") return "default";
  return undefined;
}

// 现在每个调用都有精确的类型
const all = getItems("all");     // string[]
const one = getItems(1);         // string
const val = getItems("key");     // string | undefined
```

### 重载的结构

```
前两行 → 重载签名（Overload Signatures）——对外暴露的"菜单"
第三行 → 实现签名（Implementation Signature）——实际逻辑
```

关键规则：
1. **重载签名之间必须与实现签名兼容**——实现签名的参数和返回类型需要覆盖所有重载签名的可能性
2. **实现签名对外不可见**——调用方只能看到重载签名，不能直接以实现签名的参数调用
3. **重载签名的顺序很重要**——TypeScript 从第一个重载签名开始尝试匹配

### 重载匹配顺序

```typescript
function getDate(timestamp: number): Date;     // 重载 1
function getDate(year: number, month: number, day: number): Date; // 重载 2
function getDate(a: number, b?: number, c?: number): Date {
  if (b !== undefined && c !== undefined) {
    return new Date(a, b, c);
  }
  return new Date(a);
}

getDate(1700000000000);         // 匹配重载 1
getDate(2024, 1, 15);          // 匹配重载 2
```

更具体的签名应该排在更前面——如果第一个签名就能匹配所有情况，后面的签名永远不会被使用。

### 重载与联合类型的选择

很多时候，联合类型 + 泛型比重载更简洁：

```typescript
// 如果入参和返回之间只是简单的"相同类型"关系，直接用泛型
function identity<T>(value: T): T {
  return value;
}

// 入参和返回类型的关联比较复杂时，用重载
function fetchData(key: "user"): Promise<User>;
function fetchData(key: "config"): Promise<Config>;
function fetchData(key: string): Promise<User | Config> {
  // ...
}
```

## this 类型

JavaScript 中 `this` 的值取决于函数的调用方式，而非定义位置。TypeScript 允许你声明函数期待的 `this` 类型，在编译时捕获 `this` 使用错误。

### 声明 this 类型

`this` 作为函数的**第一个假参数**——它不产生实际的运行时代码，只用于类型检查：

```typescript
interface Card {
  suit: string;
  rank: number;
}

// this: Card 表示这个函数应该在 Card 对象的上下文中调用
function describe(this: Card): string {
  return `${this.rank} of ${this.suit}`;
}

const card: Card = { suit: "hearts", rank: 7 };
card.describe = describe;
card.describe();   // ✅ this 是 Card

// describe();     // ❌ void 类型的 this 不能用于 Card 类型的上下文
```

### 在类中声明 this

类的方法中，`this` 类型会被自动推导为类的实例类型。但对于回调方法（会脱离类上下文的），显式标注能避免错误：

```typescript
class Button {
  constructor(public label: string) {}

  // 显式声明 this，防止在回调中丢失上下文时报错
  handleClick(this: Button, event: Event): void {
    console.log(`Clicked: ${this.label}`);
  }
}

const btn = new Button("Submit");
btn.handleClick(new Event("click"));  // ✅

// const handler = btn.handleClick;
// handler(new Event("click"));  // ❌ this 上下文丢失
```

### 禁止 this

如果函数不应该使用 `this`，可以声明 `this: void`：

```typescript
function pureFunction(this: void, x: number): number {
  // this 不能被访问
  return x * 2;
}
```

这在编写纯工具函数或传递给第三方库的回调时非常有用。

## 异步函数

async 函数的返回值类型始终是 `Promise<T>`，其中 `T` 是 `return` 语句返回值的类型：

```typescript
async function fetchUser(id: number): Promise<User> {
  const res = await fetch(`/api/users/${id}`);
  return res.json();  // res.json() 返回 Promise<any>，整体返回 Promise<User>
}
```

即使标注为 `Promise<void>`，在 `await` 表达式中的结果类型也会被自动解包：

```typescript
async function logAsync(): Promise<void> {
  console.log("done");
}

async function main() {
  await logAsync();  // void
}
```

Generator 和 Async Generator 也有对应的类型标注（`Generator`、`AsyncGenerator`），但在日常业务代码中使用较少，感兴趣可参考官方文档的 Iterators 章节。

## 本章小结

- 函数类型标注包括参数类型和返回值类型，类型标注始终在被标注者的**右边**
- 可选参数用 `?`，必须放在必选参数之后；有默认值的参数自动变为可选
- rest 参数用 `T[]` 或元组类型标注
- **函数重载**精确描述"不同输入对应不同输出"，重载签名按顺序从上到下匹配
- `this` 作为首个假参数声明，用于验证函数的调用上下文
- async 函数始终返回 `Promise<T>`
- 对回调函数，TypeScript 的**上下文类型推导（Contextual Typing）**可以自动推导参数类型，无需手动标注
