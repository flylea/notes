# 第 17 章 模板字符串类型

路由参数 `:id`、事件名 `onClick`、CSS 属性名，都需要把字符串拼成有限集合。模板字符串类型把拼接和匹配搬到类型层。这一章讲拼接、`infer` 提取和键名重映射中的用法。

[TypeScript 4.1](https://www.typescriptlang.org/docs/handbook/release-notes/typescript-4-1.html) 引入了**模板字符串类型（Template Literal Types）**，将 JavaScript 的模板字符串语法提升到了类型层面。它与联合类型结合时会产生类似"字符串拼接的笛卡尔积"效果，配合 `infer` 还可以在类型层面进行字符串的模式匹配和提取。这是 TypeScript 从"结构类型系统"迈向"字符串级别的类型计算"的关键一步。

## 基本语法

模板字符串类型的语法与 JavaScript 的模板字符串一致，反引号包裹，`${}` 内插值。但它接受的是**类型**而非值：

```typescript
type World = "world";
type Greeting = `hello ${World}`;
// "hello world"
```

`${}` 内可以放任何能转换为字符串的类型：

```typescript
// 模板字符串类型里 ${} 内插的是"类型"，不是函数参数，类型不能像函数那样调用
type Greet<Name extends string> = `Hello, ${Name}!`;

type T1 = Greet<"Alice">;  // "Hello, Alice!"，类型层面的计算
const t1: T1 = "Hello, Alice!";

// 错误写法：type Greet = (name: string) => `Hello, ${name}!`;  // error TS2749: 'name' refers to a value, but is being used as a type here. Did you mean 'typeof name'?
//    type T1 = Greet("Alice");  // error TS1005: ';' expected.
```

注释里的两行分别说明：类型位置不能引用值，类型别名不能当函数调用。

想把它写成一个可以"传参"的类型，正确做法是把参数声明成泛型参数（如上面的 `Name`），用 `Greet<"Alice">` 这样的类型实参来调用。

## 与联合类型的自动分布

这是[模板字符串类型](https://www.typescriptlang.org/docs/handbook/2/template-literal-types.html)**最核心也最强大的特性**。当 `${}` 内的类型是联合类型时，模板字符串类型会**自动分布到联合的每个成员**上，产生类似"笛卡尔积"的效果：

```typescript
type EmailLocaleID = "welcome_email" | "email_heading";
type FooterLocaleID = "footer_title" | "footer_sendoff";

// 联合类型的笛卡尔积
type AllLocaleIDs = `${EmailLocaleID | FooterLocaleID}_id`;
// "welcome_email_id" | "email_heading_id" | "footer_title_id" | "footer_sendoff_id"
```

如果多个插值位置都是联合类型，会产生全量的排列组合：

```typescript
type Color = "red" | "green" | "blue";
type Shade = "light" | "dark";

type Theme = `${Color}-${Shade}`;
// "red-light" | "red-dark" |
// "green-light" | "green-dark" |
// "blue-light" | "blue-dark"
```

**注意**：联合类型较大时排列组合会爆炸。比如 4 个 Color × 5 个 Shade = 20 种组合。TypeScript 对过大的联合类型（约 10 万成员以上）会报错或性能下降。

## 内置字符串工具类型

TypeScript 内置了四个字符串操作的工具类型，它们通过编译器内部（`intrinsic`）实现，映射到 JavaScript 的运行时字符串方法：

```typescript
type U = Uppercase<"hello">;        // "HELLO"
type L = Lowercase<"HELLO">;        // "hello"
type C = Capitalize<"hello world">; // "Hello world"
type UC = Uncapitalize<"Hello World">; // "hello World"
```

它们不是普通的映射类型：在编译器内部直接调用 JavaScript 字符串方法进行计算：

```typescript
// 实际处理规则
// Uppercase<StringType>       → String.prototype.toUpperCase()
// Lowercase<StringType>       → String.prototype.toLowerCase()
// Capitalize<StringType>     → 首字符大写（其他不变）
// Uncapitalize<StringType>   → 首字符小写（其他不变）
```

### 与联合类型结合

这四个工具类型保留了与联合类型的分布特性：

```typescript
type Status = "loading" | "success" | "error";
type UpperStatus = Uppercase<Status>;  
// "LOADING" | "SUCCESS" | "ERROR"
```

## 键名重映射中的模板字符串

在第 15 章的键名重映射中我们已经见过这种用法，模板字符串类型 + `as` 子句是给属性改名的主要方式：

```typescript
interface User {
  name: string;
  age: number;
  email: string;
}

// 给每个属性加 "get" 前缀，首字母大写
type Getters<T> = {
  [K in keyof T as `get${Capitalize<string & K>}`]: () => T[K];
};

type UserGetters = Getters<User>;
// {
//   getName: () => string;
//   getAge: () => number;
//   getEmail: () => string;
// }
```

为什么需要 `string & K`？
- `keyof T` 可能返回 `string | number | symbol`
- `Capitalize` 只接受 `string` 作为类型参数
- `string & K` 做了交叉过滤：只保留 `K` 中是 `string` 的部分

## 模板字符串类型的模式匹配（infer）

这是模板字符串类型的第二大核心能力：在条件类型中通过 `infer` 从字符串模式中提取子串：

```typescript
// 提取第一个空格前的部分
type FirstWord<S extends string> = 
  S extends `${infer Word} ${infer _Rest}` ? Word : S;

type W1 = FirstWord<"hello world">;  // "hello"
type W2 = FirstWord<"TypeScript">;   // "TypeScript"（没有空格，返回整个字符串）
```

这个模式可用于构建各种字符串处理工具：

```typescript
// 移除前导空格
type TrimLeft<S extends string> = 
  S extends ` ${infer Rest}` ? TrimLeft<Rest> : S;

// 移除尾部空格
type TrimRight<S extends string> = 
  S extends `${infer Rest} ` ? TrimRight<Rest> : S;

// 移除前后空格
type Trim<S extends string> = TrimLeft<TrimRight<S>>;

type T0 = TrimLeft<"   hello">;   // "hello"
type T1 = TrimRight<"hello   ">;  // "hello"
type T2 = Trim<"  hello  ">;      // "hello"
```

```typescript
// 替换子串
type Replace<
  S extends string,
  From extends string,
  To extends string
> = From extends ""
  ? S
  : S extends `${infer Before}${From}${infer After}`
    ? `${Before}${To}${After}`
    : S;

type T3 = Replace<"hello world", "world", "TypeScript">;  
// "hello TypeScript"

// 替换所有（递归）
type ReplaceAll<
  S extends string,
  From extends string,
  To extends string
> = From extends ""
  ? S
  : S extends `${infer Before}${From}${infer After}`
    ? `${Before}${To}${ReplaceAll<After, From, To>}`
    : S;
```

```typescript
// 字符串分割为元组
type Split<
  S extends string,
  Delimiter extends string
> = S extends `${infer Head}${Delimiter}${infer Tail}`
  ? [Head, ...Split<Tail, Delimiter>]
  : S extends ""
    ? []
    : [S];

type Parts = Split<"a,b,c", ",">;  // ["a", "b", "c"]
```

## 实际应用模式

### 模式一：类型安全的事件名称

利用模板字符串类型限制合法的事件名：

```typescript
type EventName = "click" | "doubleClick" | "mouseDown";

// 类型安全的 on 方法
function on(event: `on${Capitalize<EventName>}`, handler: () => void) {
  // ...
}

on("onClick", () => {});       // 正确
on("onDoubleClick", () => {}); // 正确
// on("onDrag", () => {});  // error TS2345: Argument of type '"onDrag"' is not assignable to parameter of type '"onClick" | "onDoubleClick" | "onMouseDown"'.
```

### 模式二：CSS 属性名类型

```typescript
type CSSProperty = "margin" | "padding" | "border";
type CSSDirection = "Top" | "Right" | "Bottom" | "Left";

type CSSSpacing = `${CSSProperty}${CSSDirection}`;
// "marginTop" | "marginRight" | "marginBottom" | "marginLeft" |
// "paddingTop" | "paddingRight" | "paddingBottom" | "paddingLeft" |
// "borderTop" | "borderRight" | "borderBottom" | "borderLeft"
```

### 模式三：下划线转驼峰（Snake Case → Camel Case）

```typescript
type SnakeToCamel<S extends string> = 
  S extends `${infer Head}_${infer Tail}`
    ? `${Head}${Capitalize<SnakeToCamel<Tail>>}`
    : S;

type CamelCase1 = SnakeToCamel<"user_id">;         // "userId"
type CamelCase2 = SnakeToCamel<"first_name_last">;  // "firstNameLast"
```

### 模式四：对象键名的批量转换

```typescript
// 将所有键名从下划线转为驼峰
type CamelCasedProperties<T> = {
  [K in keyof T as SnakeToCamel<string & K>]: T[K];
};

interface ApiResponse {
  user_id: number;
  first_name: string;
  created_at: string;
}

type CamelCased = CamelCasedProperties<ApiResponse>;
// {
//   userId: number;
//   firstName: string;
//   createdAt: string;
// }
```

### 模式五：格式化字符串类型约束

```typescript
// 限制为 ISO 日期格式 YYYY-MM-DD
type ISODate = `${number}-${number}-${number}`;

function setDate(date: ISODate) {
  // ...
}

setDate("2024-01-15");  // 正确
// setDate("01/15/2024");  // error TS2345: Argument of type '"01/15/2024"' is not assignable to parameter of type '`${number}-${number}-${number}`'.
```

## 注意事项与限制

1. **性能**：复杂的递归模板字符串类型（如深层的 `SnakeToCamel`）在大型联合类型（> 50 成员）上可能导致编译变慢甚至报错。"够用就好"，不需要追求完美的类型体操
2. **`${number}` 的行为**：`${number}` 匹配**任意数字字符串**，不是"一个数字字符"，也不是精确的数字范围
3. **插值类型限制**：`${}` 中可用的类型为 `string | number | boolean | bigint | null | undefined`。`null` 和 `undefined` 会被转换为字符串 `"null"` 和 `"undefined"`
4. **大写类型的限制**：`Uppercase<T>` 在 `T` 是具体字面量时才会被计算（`Uppercase<"abc">` 就是 `"ABC"`）；传入宽泛的 `string` 时得到的是编译器保留的 `Uppercase<string>`，**它不会退化为 `string`**，`string` 反而不能赋给它（`Type 'string' is not assignable to type 'Uppercase<string>'`），只有具体的字符串字面量可以。它是"尚未展开"的 intrinsic 类型，别把它当成 `string` 用

## 检查器里发生了什么

模板字符串类型不是字符串拼接，是独立类型。`getTemplateLiteralType`（checker.ts:18983）先找插值位置的 `never` 或联合类型；命中联合就用 `mapType` 展开，逐个成员再拼，这就是笛卡尔积。展开前过 `checkCrossProductUnion`（18726），成员数到 10 万报 TS2590。

字面量插值直接折进文本，联合的每个成员都变成具体字符串字面量。`${string}` 这种宽类型不折，留在类型的 `types` 列表里当模式占位符。

模式匹配发生在条件类型比较阶段。目标模板拆成文本段和占位符，源字符串按占位符能匹配的宽度切分，`infer` 拿到的就是每一段。

`Uppercase` 这类不是普通工具类型。检查器把它们建成 `StringMappingType`，`getStringMappingType`（19059）只在参数是字面量时折叠；参数是宽 `string` 时保留未展开的类型，所以 `Uppercase<string>` 不等于 `string`。

联合插值之所以是笛卡尔积，是因为每个插值位置独立展开：先找到第一个联合，逐成员替换，替换后的类型还有联合就继续展开。两个联合位置就是两重循环，结果是两份成员的组合。成员数乘到 10 万，编译器放弃，报 TS2590。

这也是模板字面量与字符串方法的差别。运行时 `"a" + b` 的结果永远是 `string`；类型层 `` `a${B}` `` 在 B 是字面量联合时能算出一个有限集合，在 B 是宽 `string` 时只能退回模式类型。

递归模板字符串还有一层代价：每次匹配都要拆前缀，长字符串会生成很多中间字面量类型。几百个字符以内问题不大，上千字符的模板匹配容易触发深度上限，报的还是 TS2589。

行号取自 TypeScript 5.9.3 的 src/compiler/checker.ts；7.0 换成 Go 实现，逻辑相同但没有逐行核对。

### 报错现场

```ts
type BadKey = Capitalize<string | number>;

type Upper = Uppercase<string>;
function takeUpper(u: Upper) {}
function passRaw(s: string) { takeUpper(s); }

function on(event: "onClick", handler: () => void) {}
on("onDrag", () => {});
```

`repro-17.ts(1,26): error TS2344: Type 'string | number' does not satisfy the constraint 'string'.`，下一行 `Type 'number' is not assignable to type 'string'.`。`Capitalize` 只收字符串。改法：先 `Extract<K, string>` 再传进去。

`repro-17.ts(5,41): error TS2345: Argument of type 'string' is not assignable to parameter of type 'Uppercase<string>'.`。宽 `string` 不满足未展开的 intrinsic 类型。改法：传字面量，或在函数内部收窄后再用。

`repro-17.ts(8,4): error TS2345: Argument of type '"onDrag"' is not assignable to parameter of type '"onClick"'.`。模板只允许 `"onClick"` 这一个成员。改法：把允许的事件名写成联合，例如 `` `on${"Click" | "Drag"}` ``。

### 一句话记住

模板字符串类型像盖章机：固定文字印死，`${}` 是活字槽；槽里塞联合类型，机器逐张换字盖一遍。运行时的字符串拼接不经过这台机器，拼出来的 `string` 不会自动收窄。

比喻不成立的地方：盖章机只处理有限字面量，运行时的值不在它的视野里。

```ts
type Side = "left" | "right";
type ClassName = `is-${Side}`;    // "is-left" | "is-right"
const ok: ClassName = "is-left";

const side = "left" as string;
const raw = `is-${side}`;         // string，不是 ClassName
```

## 小结

- **模板字符串类型** 将 JavaScript 模板字符串语法提升至类型层面，`${}` 内接受类型
- 与**联合类型结合**时产生类似笛卡尔积的自动分布，这是模板字符串类型最强大的特性
- **内置字符串工具**：`Uppercase`、`Lowercase`、`Capitalize`、`Uncapitalize`，通过编译器 intrinsic 实现
- **infer 模式匹配**：在条件类型中从字符串字面量类型提取子串，实现 `Trim`、`Replace`、`Split` 等经典操作
- **键名重映射** 中配合 `as` 子句批量转换对象属性名
- 注意性能：深度递归 + 大联合类型可能触发编译器限制

## 用不上的时候

### 联合规模膨胀

两个各含十几个成员的联合做模板拼接，结果是上百个成员，补全和编译都变慢。

### 运行时解析字符串

模板字符串类型只在类型层匹配，运行时拆路由参数、解析路径仍然要正则或 parser。

### 文案本身不固定

带用户输入、翻译文案的字符串无法穷举，只适合稳定的标识符与键名。
