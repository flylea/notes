# 第17章 模板字符串类型

TypeScript 4.1 引入了**模板字符串类型（Template Literal Types）**——将 JavaScript 的模板字符串语法提升到了类型层面。它与联合类型结合时会产生类似"字符串拼接的笛卡尔积"效果，配合 `infer` 还可以在类型层面进行字符串的模式匹配和提取。这是 TypeScript 从"结构类型系统"迈向"字符串级别的类型计算"的关键一步。

## 基本语法

模板字符串类型的语法与 JavaScript 的模板字符串一致——反引号包裹，`${}` 内插值。但它接受的是**类型**而非值：

```typescript
type World = "world";
type Greeting = `hello ${World}`;
// "hello world"
```

`${}` 内可以放任何能转换为字符串的类型：

```typescript
type Greet = (name: string) => `Hello, ${name}!`;

type T1 = Greet("Alice");  // `Hello, Alice!` — 类型层面的计算
```

## 与联合类型的自动分布

这是模板字符串类型**最核心也最强大的特性**。当 `${}` 内的类型是联合类型时，模板字符串类型会**自动分布到联合的每个成员**上，产生类似"笛卡尔积"的效果：

```typescript
type EmailLocaleID = "welcome_email" | "email_heading";
type FooterLocaleID = "footer_title" | "footer_sendoff";

// 联合类型的笛卡尔积
type AllLocaleIDs = `${EmailLocaleID | FooterLocaleID}_id`;
// "welcome_email_id" | "email_heading_id" | "footer_title_id" | "footer_sendoff_id"
```

如果多个插值位置都是联合类型，会产生全量的排列组合：

```typescript
type Color = "red" | "green" | "blue";
type Shade = "light" | "dark";

type Theme = `${Color}-${Shade}`;
// "red-light" | "red-dark" |
// "green-light" | "green-dark" |
// "blue-light" | "blue-dark"
```

**注意**：联合类型较大时排列组合会爆炸。比如 4 个 Color × 5 个 Shade = 20 种组合。TypeScript 对过大的联合类型（约 10 万成员以上）会报错或性能下降。

## 内置字符串工具类型

TypeScript 内置了四个字符串操作的工具类型，它们通过编译器内部（`intrinsic`）实现，映射到 JavaScript 的运行时字符串方法：

```typescript
type U = Uppercase<"hello">;        // "HELLO"
type L = Lowercase<"HELLO">;        // "hello"
type C = Capitalize<"hello world">; // "Hello world"
type UC = Uncapitalize<"Hello World">; // "hello World"
```

它们不是普通的映射类型——在编译器内部直接调用 JavaScript 字符串方法进行计算：

```typescript
// 实际处理规则
// Uppercase<StringType>       → String.prototype.toUpperCase()
// Lowercase<StringType>       → String.prototype.toLowerCase()
// Capitalize<StringType>     → 首字符大写（其他不变）
// Uncapitalize<StringType>   → 首字符小写（其他不变）
```

### 与联合类型结合

这四个工具类型保留了与联合类型的分布特性：

```typescript
type Status = "loading" | "success" | "error";
type UpperStatus = Uppercase<Status>;  
// "LOADING" | "SUCCESS" | "ERROR"
```

## 键名重映射中的模板字符串

在第 15 章的键名重映射中我们已经见过这种用法——模板字符串类型 + `as` 子句是给属性改名的主要方式：

```typescript
interface User {
  name: string;
  age: number;
  email: string;
}

// 给每个属性加 "get" 前缀，首字母大写
type Getters<T> = {
  [K in keyof T as `get${Capitalize<string & K>}`]: () => T[K];
};

type UserGetters = Getters<User>;
// {
//   getName: () => string;
//   getAge: () => number;
//   getEmail: () => string;
// }
```

为什么需要 `string & K`？
- `keyof T` 可能返回 `string | number | symbol`
- `Capitalize` 只接受 `string` 作为类型参数
- `string & K` 做了交叉过滤——只保留 `K` 中是 `string` 的部分

## 模板字符串类型的模式匹配（infer）

这是模板字符串类型的第二大核心能力——在条件类型中通过 `infer` 从字符串模式中提取子串：

```typescript
// 提取第一个空格前的部分
type FirstWord<S extends string> = 
  S extends `${infer Word} ${infer _Rest}` ? Word : S;

type W1 = FirstWord<"hello world">;  // "hello"
type W2 = FirstWord<"TypeScript">;   // "TypeScript"（没有空格，返回整个字符串）
```

这个模式可用于构建各种字符串处理工具：

```typescript
// 移除前导空格
type TrimLeft<S extends string> = 
  S extends ` ${infer Rest}` ? TrimLeft<Rest> : S;

// 移除尾部空格
type TrimRight<S extends string> = 
  S extends `${infer Rest} ` ? TrimRight<Rest> : S;

// 移除前后空格
type Trim<S extends string> = TrimLeft<TrimRight<S>>;

type T0 = TrimLeft<"   hello">;   // "hello"
type T1 = TrimRight<"hello   ">;  // "hello"
type T2 = Trim<"  hello  ">;      // "hello"
```

```typescript
// 替换子串
type Replace<
  S extends string,
  From extends string,
  To extends string
> = From extends ""
  ? S
  : S extends `${infer Before}${From}${infer After}`
    ? `${Before}${To}${After}`
    : S;

type T3 = Replace<"hello world", "world", "TypeScript">;  
// "hello TypeScript"

// 替换所有（递归）
type ReplaceAll<
  S extends string,
  From extends string,
  To extends string
> = From extends ""
  ? S
  : S extends `${infer Before}${From}${infer After}`
    ? `${Before}${To}${ReplaceAll<After, From, To>}`
    : S;
```

```typescript
// 字符串分割为元组
type Split<
  S extends string,
  Delimiter extends string
> = S extends `${infer Head}${Delimiter}${infer Tail}`
  ? [Head, ...Split<Tail, Delimiter>]
  : S extends ""
    ? []
    : [S];

type Parts = Split<"a,b,c", ",">;  // ["a", "b", "c"]
```

## 实际应用模式

### 模式一：类型安全的事件名称

利用模板字符串类型限制合法的事件名：

```typescript
type EventName = "click" | "doubleClick" | "mouseDown";

// 类型安全的 on 方法
function on(event: `on${Capitalize<EventName>}`, handler: () => void) {
  // ...
}

on("onClick", () => {});       // ✅
on("onDoubleClick", () => {}); // ✅
// on("onDrag", () => {});     // ❌ 不是合法的事件名
```

### 模式二：CSS 属性名类型

```typescript
type CSSProperty = "margin" | "padding" | "border";
type CSSDirection = "Top" | "Right" | "Bottom" | "Left";

type CSSSpacing = `${CSSProperty}${CSSDirection}`;
// "marginTop" | "marginRight" | "marginBottom" | "marginLeft" |
// "paddingTop" | "paddingRight" | "paddingBottom" | "paddingLeft" |
// "borderTop" | "borderRight" | "borderBottom" | "borderLeft"
```

### 模式三：下划线转驼峰（Snake Case → Camel Case）

```typescript
type SnakeToCamel<S extends string> = 
  S extends `${infer Head}_${infer Tail}`
    ? `${Head}${Capitalize<SnakeToCamel<Tail>>}`
    : S;

type CamelCase1 = SnakeToCamel<"user_id">;         // "userId"
type CamelCase2 = SnakeToCamel<"first_name_last">;  // "firstNameLast"
```

### 模式四：对象键名的批量转换

```typescript
// 将所有键名从下划线转为驼峰
type CamelCasedProperties<T> = {
  [K in keyof T as SnakeToCamel<string & K>]: T[K];
};

interface ApiResponse {
  user_id: number;
  first_name: string;
  created_at: string;
}

type CamelCased = CamelCasedProperties<ApiResponse>;
// {
//   userId: number;
//   firstName: string;
//   createdAt: string;
// }
```

### 模式五：格式化字符串类型约束

```typescript
// 限制为 ISO 日期格式 YYYY-MM-DD
type ISODate = `${number}-${number}-${number}`;

function setDate(date: ISODate) {
  // ...
}

setDate("2024-01-15");  // ✅
// setDate("01/15/2024"); // ❌
```

## 注意事项与限制

1. **性能**：复杂的递归模板字符串类型（如深层的 `SnakeToCamel`）在大型联合类型（> 50 成员）上可能导致编译变慢甚至报错。"够用就好"，不需要追求完美的类型体操
2. **`${number}` 的行为**：`${number}` 匹配**任意数字字符串**，不是"一个数字字符"，也不是精确的数字范围
3. **插值类型限制**：`${}` 中可用的类型为 `string | number | boolean | bigint | null | undefined`。`null` 和 `undefined` 会被转换为字符串 `"null"` 和 `"undefined"`
4. **大写类型**：`Uppercase<string>` 的结果仍然是 `string` 而非 `Uppercase<string>`——当不传入具体字面量时，输出退化为宽泛的 `string`

## 本章小结

- **模板字符串类型** 将 JavaScript 模板字符串语法提升至类型层面，`${}` 内接受类型
- 与**联合类型结合**时产生类似笛卡尔积的自动分布——这是模板字符串类型最强大的特性
- **内置字符串工具**：`Uppercase`、`Lowercase`、`Capitalize`、`Uncapitalize`——通过编译器 intrinsic 实现
- **infer 模式匹配**：在条件类型中从字符串字面量类型提取子串，实现 `Trim`、`Replace`、`Split` 等经典操作
- **键名重映射** 中配合 `as` 子句批量转换对象属性名
- 注意性能——深度递归 + 大联合类型可能触发编译器限制
