# 第3章 基础类型

TypeScript 作为 JavaScript 的类型超集，为 JS 中每一种值都提供了对应的类型标注。本章从 JavaScript 的既有概念出发，系统学习 TypeScript 中与 JS 概念最为接近的部分：原始类型、数组、元组与对象类型的基础标注。这些是后续所有类型能力的基础。

> 本章代码的完整示例见 [TypeScript 官方 Playground](https://www.typescriptlang.org/play/)，你可以边看边动手实验。

## 原始类型的类型标注

JavaScript 的内置原始类型包括 `string`、`number`、`boolean`、`null`、`undefined`、`symbol`（ES2015）和 `bigint`（ES2020）。TypeScript 为它们全部提供了同名的类型标注：

```typescript
const name: string   = "linbudu";
const age: number    = 24;
const male: boolean  = false;
const undef: undefined = undefined;
const nul: null      = null;
const obj: object    = { name, age, male };
const bigintVar1: bigint = 9007199254740991n;
const bigintVar2: bigint = BigInt(9007199254740991);
const symbolVar: symbol = Symbol("unique");
```

其中 `string`、`number`、`boolean` 是最常用的三种。它们的类型名与 JavaScript 中 `typeof` 操作符返回的结果完全对应——当你在 JS 中用 `typeof` 检查一个字符串值时，得到的就是 `"string"`，这也正是 TS 中字符串类型的名称。这个设计极大降低了从 JS 过渡到 TS 的心智负担。

需要注意的是，`string`、`number`、`boolean` 这三个类型名称都是**小写**的。在 TypeScript 中也存在大写开头的 `String`、`Number`、`Boolean`，它们指的是 JavaScript 的**装箱类型（Boxed Types）**，几乎不应该被使用：

```typescript
// ✅ 正确：小写
function reverse(s: string): string {
  return s.split("").reverse().join("");
}

// ❌ 错误：大写（装箱类型，行为不一致）
function reverseBad(s: String): String {
  return s.split("").reverse().join("");
}
```

关于装箱类型与拆箱类型的更多细节，我们会在"object、Object 与 {}"一节进一步讲解。

### null 与 undefined

在 JavaScript 中，`null` 与 `undefined` 分别表示"**这里有值，但是个空值**"和"**这里没有值**"。TypeScript 中，这两者都是具有实际意义的独立类型——也就是说，`null` 类型只接受值 `null`，`undefined` 类型只接受值 `undefined`。

它们与其他类型的关系，取决于你是否开启了 `strictNullChecks` 编译选项（这可以说是 TypeScript 中最重要的一个配置项）。

**当 strictNullChecks 关闭时（不推荐）**，`null` 和 `undefined` 会被视为所有类型的子类型，也就是说它们可以被赋值给任意类型的变量：

```typescript
// ⚠️ 仅在 strictNullChecks: false 时成立
const tmp1: null = null;
const tmp2: undefined = undefined;

const tmp3: string = null;       // 不报错
const tmp4: string = undefined;  // 不报错
const tmp5: number = null;       // 不报错
```

这是最大的"历史遗留问题"来源之一——在很多传统语言（Java、C#）中 null 就是可以赋值给任意引用类型的。但在 JavaScript 中，这种宽松带来了著名的 `Cannot read property 'xxx' of null/undefined` 运行时错误。

**当 strictNullChecks 开启时（强烈推荐）**，`null` 和 `undefined` 只能赋值给自身、`any`、`unknown` 和 `void` 类型（有一个特例：`undefined` 也能赋值给 `void`）：

```typescript
// ✅ strictNullChecks: true 下的行为
const tmp1: null = null;
const tmp2: undefined = undefined;

const tmp3: string = null;       // ❌ 类型错误
const tmp4: string = undefined;  // ❌ 类型错误

// 如果确实需要允许 null/undefined，请显式使用联合类型
const tmp5: string | null = null;  // ✅
```

我们强烈建议在所有新项目中开启 `strictNullChecks`（它是 `strict: true` 的一部分）。这会在编译时帮你揪出大量潜在的"可能为空"的问题。

### void

`void` 是 TypeScript 中的一个特殊类型，用于描述函数没有有意义的返回值。注意它和 JavaScript 中的 `void` 操作符（如 `void(0)`）不是一回事：

```typescript
// 没有 return 语句
function func1(): void {}

// 有 return，但后面没有值
function func2(): void {
  return;
}

// 显式返回 undefined（这种场景也可以用 void）
function func3(): void {
  return undefined;
}
```

`func1` 和 `func2` 的返回值会被类型系统自动推导为 `void`。而 `func3` 显式返回了 `undefined`，它的返回值可以被推导为 `undefined`，但你仍然可以用 `void` 来标注，因为在类型层面这三者都表示"没有返回一个有意义的值"。

这里有一个细微但重要的认知：**`void` 表示"函数没有进行有意义的返回操作"，而 `undefined` 表示"函数主动返回了一个 undefined 值"**。可以这样理解：`void` 是"我根本就没考虑返回值这回事"，`undefined` 是"我想好了，我要返回的就是 undefined"。

```typescript
// void 类型变量只能接受 undefined（strictNullChecks 下）
const voidVar1: void = undefined;  // ✅
// const voidVar2: void = null;    // ❌ strictNullChecks 下不允许

// 但反过来可以：undefined 类型可以接受 void
const undefVar: undefined = voidVar1;  // ✅
```

在实际开发中，你几乎只需要在函数的返回值类型上使用 `void`，声明 `void` 类型的变量没有什么实际用途。

### symbol

`symbol` 是 ES2015 引入的原始类型，每一个通过 `Symbol()` 创建的值都是独一无二的：

```typescript
const sym1: symbol = Symbol("key");
const sym2: symbol = Symbol("key");

// 即使描述字符串相同，两个 symbol 也不相等——这是运行时行为
// sym1 !== sym2
```

`symbol` 作为类型时，所有 symbol 值都符合这个类型。但如果你需要表达"某一个具体的、唯一的 symbol 值"（而非任意 symbol），可以使用 `unique symbol` 子类型：

```typescript
const uniqueSym: unique symbol = Symbol("unique");

// unique symbol 的主要用途：作为对象的属性名，防止属性冲突
const FOO: unique symbol = Symbol("FOO");

interface Foo {
  [FOO]: string;
}

// 只能通过该 symbol 访问
const foo: Foo = { [FOO]: "hello" };
foo[FOO];  // string
```

`unique symbol` 的几个硬性规则：
- 只能用 `const` 声明，不能用 `let` 或 `var`
- 它的类型会被自动推导为 `unique symbol`（不需要也不能显式写出）
- 若要引用一个已声明的 `unique symbol` 的类型，必须使用 `typeof` 操作符：

```typescript
declare const uniqueSymbolFoo: unique symbol;
const uniqueSymbolBaz: typeof uniqueSymbolFoo = uniqueSymbolFoo;
```

日常开发中 `unique symbol` 的使用场景较少，了解即可。

### bigint

`bigint` 是 ES2020 引入的类型，用于表示超出 `number` 安全范围的任意精度整数：

```typescript
const big1: bigint = 9007199254740991n;     // 字面量语法
const big2: bigint = BigInt(9007199254740991); // 函数语法
const big3: bigint = BigInt("9007199254740991"); // 从字符串转换
```

`bigint` 和 `number` 是两种完全不同的类型，不能互相赋值，也不能直接在一起进行算术运算：

```typescript
const a: bigint = 100n;
const b: number = 100;

// const c: bigint = a + b;  // ❌ bigint 和 number 不能混合运算
// const d: number = a;       // ❌ bigint 不能赋值给 number
```

## 数组的类型标注

数组在 TypeScript 中有两种等价的标注方式：

```typescript
// 写法一：T[]（推荐，更简洁）
const arr1: string[] = ["a", "b", "c"];
const arr2: number[] = [1, 2, 3];

// 写法二：Array<T>（泛型写法）
const arr3: Array<string> = ["a", "b", "c"];
const arr4: Array<number> = [1, 2, 3];
```

两种写法完全等价——将鼠标悬停在 `Array<string>` 上，编辑器会显示它为 `string[]`。实际开发中 `T[]` 是绝对的主流写法。

对于包含多种类型的数组，使用联合类型：

```typescript
const mixed: (string | number)[] = ["a", 1, "b", 2];

// 注意括号是必需的！下面的写法含义完全不同：
// const bad: string | number[]   ← 表示 string 或 number[]
```

数组类型的推导规则：

```typescript
const arr1 = [1, 2, 3];          // 推导为 number[]
const arr2 = ["a", "b", "c"];    // 推导为 string[]
const arr3 = [1, "a", true];     // 推导为 (string | number | boolean)[]

// 空数组在没有 noImplicitAny 时被推导为 any[]
// 其类型会在后续 push 操作中动态"进化"
const arr4 = [];                  // any[]
arr4.push(1);                     // 现在视为 number[]
arr4.push("hello");               // 现在视为 (string | number)[]

// 开启 noImplicitAny 后，TS 无法推导空数组的具体类型，会报错
// const arr5 = [];  // ❌ 需要显式标注类型
```

## 元组类型

普通的数组类型只关心"里面存了什么类型"，而不关心"长度"和"每个位置的具体类型"。但实际开发中有大量场景需要这种精确描述——比如 React 的 `useState` 返回值 `[value, setter]`，或者一个坐标 `[x, y]`。

**元组（Tuple）** 就是为此设计的。它描述一个定长的、每个位置类型确定的数组：

```typescript
// 基本元组
const point: [number, number] = [3, 4];

// 混合类型的元组
const user: [string, number, boolean] = ["Alice", 25, true];

// 每个位置的类型被精确记住
const name: string = user[0];   // ✅ string
const age: number = user[1];    // ✅ number
const active: boolean = user[2]; // ✅ boolean
```

元组最核心的价值在于**越界访问的类型报错**。对于普通数组，越界访问在类型层面完全无法检查：

```typescript
const arr: string[] = ["a", "b", "c"];
console.log(arr[599]);  // 类型检查通过！但运行时得到 undefined
```

换成元组，越界访问直接报错：

```typescript
const tuple: [string, string, string] = ["a", "b", "c"];
// tuple[599];  // ❌ 类型错误：长度为"3"的元组在索引"599"处没有元素
```

甚至**隐式越界**（解构时取的比元组长度多）也能被检测到：

```typescript
const tuple: [string, number, boolean] = ["Alice", 25, true];

// ❌ 类型错误：元组长度为 3，但解构了 4 个元素
// const [a, b, c, d] = tuple;
```

### 元组的可选元素

在元组中，某位置上的成员可以用 `?` 标记为可选。注意可选元素必须在必选元素之后：

```typescript
// 第二个位置可选
const tuple1: [string, number?] = ["hello"];     // ✅
const tuple2: [string, number?] = ["hello", 42]; // ✅

// 在 strictNullChecks 下，可选元素的类型自动包含 undefined
// 同时会影响 length 属性的类型：
type T1 = typeof tuple1.length; // 1 | 2
type T2 = [string, number?, boolean?]["length"]; // 1 | 2 | 3
```

### 具名元组（Labeled Tuple）

TypeScript 4.0 引入了具名元组，为每个位置添加标签提升可读性——标签不影响类型行为，但会在 IDE 提示中显示：

```typescript
// 不使用标签：可读性差，不知道每个位置表示什么
type ApiResult1 = [number, string];

// 使用标签：一目了然
type ApiResult2 = [code: number, message: string];

const result: ApiResult2 = [200, "OK"];

// 标签不影响类型检查——依然按位置匹配
// result[0] 仍是 number，result[1] 仍是 string
```

这使得元素在某些场景下可以替代"为了传两个值而临时拼一个对象"的做法，代码更简洁。

### 只读数组与只读元组

数组和元组都可以标记为只读（readonly），禁止修改操作：

```typescript
// 只读数组：三种等价写法
const roArr1: readonly number[] = [1, 2, 3];
const roArr2: ReadonlyArray<number> = [1, 2, 3];
const roArr3 = [1, 2, 3] as const;

// roArr1[0] = 5;  // ❌ 只读
// roArr1.push(4);  // ❌ push 方法不可用

// 只读元组
const roTuple: readonly [number, string] = [1, "hello"];
// roTuple[0] = 2;  // ❌ 只读
```

这里有一个容易被忽视的重要行为：只读数组/元组一旦被标记为只读，其类型就不再是 `Array`，而是 `ReadonlyArray`（`lib.es5.d.ts` 中的一个内置类型）。这就是为什么 `push`、`pop`、`sort` 等方法全部不可用了——`ReadonlyArray` 上没有这些方法。

只读数组不能赋值给可变数组（因为只读类型缺少可变方法），但反过来可以：

```typescript
const ro: readonly number[] = [1, 2, 3];
// const mut: number[] = ro;  // ❌
const mut: number[] = [1, 2, 3];
const ro2: readonly number[] = mut;  // ✅ 放宽总是安全的
```

## 对象的类型标注

对象是 JavaScript 中使用最频繁的数据结构。TypeScript 通过 **interface** 和 **type** 来描述对象的结构（即这个对象应该具有哪些属性及各自的类型）。

### interface 声明

使用 `interface` 关键字声明一个对象类型，然后用它标注变量：

```typescript
interface User {
  name: string;
  age: number;
  active: boolean;
}

const user: User = {
  name: "Alice",
  age: 25,
  active: true,
};
```

TypeScript 对对象类型的检查遵循**结构化类型（Structural Typing）**原则：只要一个对象具有所需的结构，它就符合该类型。但同时有几个硬性约束：

1. **属性不能少**——缺少必选属性会报错
2. **属性不能多**——对象字面量直接赋值时，多余的属性会触发**额外属性检查（Excess Property Checking）**
3. **属性类型必须匹配**

```typescript
const u1: User = { name: "Bob" };
// ❌ 缺少 age 和 active

const u2: User = { name: "Bob", age: 30, active: true, height: 180 };
// ❌ height 是额外属性

const u3: User = { name: "Bob", age: "30", active: true };
// ❌ age 类型不匹配
```

关于额外属性检查有一个重要的例外：如果先将对象赋值给一个中间变量，再赋值给目标类型，就不会触发额外属性检查：

```typescript
const temp = { name: "Bob", age: 30, active: true, height: 180 };
const u: User = temp;  // ✅ 不报错

// 这是刻意的设计。对象字面量直接赋值时的额外属性检查是为了
// 防止拼写错误（比如将 active 误写为 activ），而中间变量的场景
// 说明这个对象有自己独立的用途，多余属性可能是有意为之
```

### 可选属性

在属性名后加 `?` 表示该属性可选。可选属性的类型会自动包含 `undefined`：

```typescript
interface Config {
  url: string;
  method?: string;    // 可选，可以不提供
  timeout?: number;   // 可选，可以不提供
}

const config: Config = { url: "/api/users" };  // ✅

// 读取可选属性时必须处理 undefined 的情况
function printConfig(c: Config) {
  // console.log(c.method.toUpperCase()); // ❌ c.method 可能是 undefined

  // 方案一：可选链
  console.log(c.method?.toUpperCase());

  // 方案二：判空
  if (c.method !== undefined) {
    console.log(c.method.toUpperCase());
  }

  // 方案三：空值合并
  const method = c.method ?? "GET";
}
```

### 只读属性

`readonly` 修饰符防止属性在初始化后被重新赋值：

```typescript
interface Point {
  readonly x: number;
  readonly y: number;
}

const p: Point = { x: 10, y: 20 };
// p.x = 5;  // ❌ 无法分配到 "x"，因为它是只读属性
```

这个机制只在编译时有效——编译成 JavaScript 后 `readonly` 完全被移除，运行时没有任何保护。但这个编译时约束在实际工程中非常有价值：它可以防止意外的属性修改，让代码的意图更加清晰。

### type 与 interface

除了 `interface`，你还可以用 `type`（类型别名）来描述对象结构：

```typescript
type User = {
  name: string;
  age: number;
  active: boolean;
};
```

在这个场景（描述简单的对象结构）中，两者功能几乎完全重叠，可以选择你喜欢的风格。但它们有各自独有的特性：

| 特性 | interface | type |
|------|-----------|------|
| 描述对象结构 | ✅ | ✅ |
| 继承/扩展 | `extends` | `&`（交叉类型） |
| 声明合并 | ✅ 同名自动合并 | ❌ 不允许重复 |
| 定义联合类型 | ❌ | ✅ |
| 定义基本类型别名 | ❌ | ✅ `type ID = string` |
| 映射类型/条件类型 | ❌ | ✅ |

在实际项目中，一个常见的分工模式是：**用 interface 描述对象和类的结构，用 type 做类型计算（联合类型、映射类型、工具类型等）**。第 6 章将进一步对比这两种方式。

### object、Object 与 {}

这是 TypeScript 中三个容易混淆的类型，需要彻底理清。

**`Object`**（大写开头）是 JavaScript 原型链顶端的类型。在 TypeScript 中，它几乎包含了所有类型的值（除了 `null` 和 `undefined`，需要在关闭 `strictNullChecks` 时）。**永远不要使用 `Object` 作为类型标注**——它过于宽泛，和你想要的"对象类型"完全不同：

```typescript
// ❌ 永远不要这样做
const a: Object = "hello";   // 通过
const b: Object = 42;        // 通过
const c: Object = () => {};  // 通过
const d: Object = [];        // 通过
```

类似的还有 `String`、`Number`、`Boolean`、`Symbol` 这些大写开头的**装箱类型（Boxed Types）**，它们同样包含了不应该有的类型（如 `String` 类型接受 `undefined`、`null`），不应该被使用。

**`object`**（小写开头）是 TypeScript 专门引入来纠正上述问题的。它代表**所有非原始类型的值**——即除了 `string`、`number`、`boolean`、`bigint`、`symbol`、`null`、`undefined` 之外的一切：

```typescript
let a: object = { name: "foo" };  // ✅
a = [1, 2, 3];                     // ✅
a = () => {};                      // ✅
// a = "hello";                    // ❌ string 是原始类型
// a = 42;                         // ❌ number 是原始类型
```

`object` 本身过于宽泛，实际开发中很少直接使用。更好的做法是：
- 对象用 `Record<string, unknown>` 或 `Record<string, any>`
- 数组用 `unknown[]` 或 `any[]`
- 函数用 `(...args: any[]) => any`

**`{}`**（空对象字面量类型）表示"除了 `null`/`undefined` 之外的任何值"。从这个角度看，它和 `Object` 一样糟糕：

```typescript
let e: {} = "hello";   // ✅
e = 42;                 // ✅
e = { name: "foo" };   // ✅
// e.name = "bar";      // ❌ 类型"{}"上不存在属性"name"
```

你会发现 `{}` 可以接受几乎任何值，但之后你**无法对它做任何有意义的属性操作**。

**总结**：这三个类型都不应该在生产代码中作为类型标注出现。如果需要描述"一个键值对对象"，请用 `Record<string, unknown>`；如果需要描述"任意对象"，请用具体的 interface/type。

## 类型推导

TypeScript 有强大的类型推导能力。在变量声明时，如果你同时给出了初始值，大多数情况下不需要显式写出类型标注：

```typescript
let name = "TypeScript";  // 推导为 string
let count = 0;            // 推导为 number
let items = [1, 2, 3];    // 推导为 number[]
let flag = true;          // 推导为 boolean
```

但在以下情况下，建议**显式标注类型**：

1. **函数参数**——没有初始值，TS 无法推导：

```typescript
function greet(name: string) { /* ... */ }
```

2. **没有初始值的变量**：

```typescript
let timeout: number;  // 如果不标注，会是 any（取决于 noImplicitAny 设置）
```

3. **推导的精度不够时**——比如你想让类型更严格：

```typescript
// TS 推导为 string，但你想限制它只能是某几个值之一
let status: "success" | "error" = "success";
```

### const 声明的字面量类型推导

`const` 和 `let` 声明的类型推导行为有显著区别：

```typescript
let name1 = "TypeScript";  // 类型: string
const name2 = "TypeScript"; // 类型: "TypeScript"

let age1 = 10;             // 类型: number
const age2 = 10;           // 类型: 10
```

`const` 声明的变量不可重新赋值，TypeScript 可以直接将类型精确到具体的值——即**字面量类型（Literal Type）**。而 `let` 变量可能被修改，推导为宽泛的原始类型即可。

但对象类型不同——即使 `const` 声明，对象的属性仍可修改，所以不会自动推导为字面量类型：

```typescript
const user = {
  name: "Alice",
  age: 25,
};
// 类型: { name: string; age: number; }
// 而非 { name: "Alice"; age: 25; }
```

如果需要对象属性也推导为字面量类型（且变为只读），可以使用 `as const` 断言。关于字面量类型和 `as const` 的完整内容，将在第 4 章详细展开。

## 本章小结

- TypeScript 为 JavaScript 的七种原始类型全部提供同名类型标注：`string`、`number`、`boolean`、`null`、`undefined`、`symbol`、`bigint`
- `null` 和 `undefined` 在 `strictNullChecks` 开启后不再是所有类型的子类型，这能防止大量的运行时错误
- `void` 用于描述函数没有有意义的返回值，与 `undefined` 的语义略有区别
- 数组用 `T[]` 或 `Array<T>` 标注，前者是主流
- 元组是定长、每位置类型确定的数组，支持可选元素、具名标签、只读修饰
- 对象类型用 `interface` 或 `type` 描述，属性可以标记为可选（`?`）或只读（`readonly`）
- 永远不要使用 `Object`、`String`、`Number` 等装箱类型，也避免使用 `object` 和 `{}`
- TypeScript 的自动类型推导可以省去大部分变量类型标注，但函数参数和无初始值的变量需要显式标注

在掌握了原始类型和对象类型的基础标注后，下一章我们将学习如何让类型更加精确——通过字面量类型、联合类型和枚举，将"可能是任何 string"收窄到"只能是这三个 string"。
