# 第 4 章 字面量类型与枚举

`string`、`number` 这样的类型过于宽泛。接口返回的状态码往往只能是 `200 | 404 | 500` 之一，HTTP 方法只能是 `"GET" | "POST" | "PUT"`。这一章用字面量类型、联合类型和枚举表达这种精确约束。

## 一句话说清

枚举不是纯类型，它在编译产物里留下一个对象；`as const` 对象本来就是普通对象。判断标准只有一条：这段代码有没有运行时语义。可以把枚举想成“自带一张查表”，但它在 `const enum` 上不成立，那种枚举连表都不生成。

```ts
enum Level { Info, Error }
```

上面这段编译后是一段立即执行函数，不是一个类型。

## 字面量类型

**字面量类型（Literal Types）** 是 TypeScript 中最实用也最常被忽视的特性之一。它让你可以用具体的值作为类型，表达比原始类型更精确的约束。

### 字面量类型的三种形式

```typescript
// 字符串字面量类型
const greeting: "hello" = "hello";   // 正确
// const greeting2: "hello" = "hi";  // error TS2322: Type '"hi"' is not assignable to type '"hello"'.

// 数字字面量类型
const answer: 42 = 42;               // 正确
// const answer2: 42 = 43;  // error TS2322: Type '43' is not assignable to type '42'.

// 布尔字面量类型
const yes: true = true;              // 正确
// const yes2: true = false;  // error TS2322: Type 'false' is not assignable to type 'true'.
```

字面量类型是原始类型的**子类型**。这一点会如何影响类型兼容性，将在第 18 章的类型层级中详细讲解。目前你只需要理解：`"hello"` 类型是 `string` 类型的子类型，`42` 是 `number` 的子类型，也就是说，一个字面量类型可以赋值给对应的原始类型变量，但反过来不行：

```typescript
const literal: "hello" = "hello";
const str: string = literal;  // 正确：字面量可以赋值给更宽泛的 string

const str2: string = "world";
// const literal2: "hello" = str2;  // error TS2322: Type 'string' is not assignable to type '"hello"'.
```

单独的"一个值是类型"听起来很抽象，但在实践中几乎总是和**[联合类型](https://www.typescriptlang.org/docs/handbook/2/everyday-types.html)**搭配使用。

### 字面量类型 + 联合类型

联合类型 `|` 将多个类型组合在一起，表示"满足其中一个即可"。把字面量类型和联合类型结合，就能表达一组确定值的集合：

```typescript
// 描述 API 接口返回的响应结构
interface ApiResponse {
  code: 200 | 404 | 500;                     // code 只能是这三个数字之一
  status: "success" | "failure" | "pending"; // status 只能是这三个字符串之一
  data: unknown;
}

declare const res: ApiResponse;

// 现在访问这些属性时会获得精确的类型提示
if (res.status === "success") {
  // status 在此分支被缩小为 "success"
  console.log(res.data);
}

// const bad: ApiResponse = { code: 500, status: "error", data: null };
// error TS2322: Type '"error"' is not assignable to type '"failure" | "success" | "pending"'.
```

这就是字面量联合类型的典型使用场景：将类型从宽泛的 `string` 精确收窄到一组具体值。在 IDE 中输入 `res.status` 时，会自动补全 `"success"`、`"failure"`、`"pending"`。

对于常用的联合类型，可以抽取为类型别名来复用：

```typescript
type StatusCode = 200 | 301 | 302 | 404 | 500;
type HttpMethod = "GET" | "POST" | "PUT" | "DELETE";

function request(url: string, method: HttpMethod): Promise<unknown> {
  throw new Error("未实现");
}
```

### 联合类型不仅仅是字面量

联合类型不限于字面量：成员可以是任意类型：

```typescript
type Mixed =
  | string        // 原始类型
  | 42            // 数字字面量
  | true          // 布尔字面量
  | { name: string }  // 对象类型
  | (() => void); // 函数类型（需要用括号包裹）

// 嵌套的联合会被自动展平
type Nested = 1 | (2 | (3 | 4));
// 等价于 1 | 2 | 3 | 4
```

几点注意事项：
- 函数类型在联合中必须用 `()` 包裹，否则语法歧义
- 嵌套的联合类型会被 TypeScript 自动**展平**到第一级

### 联合类型的实际运作方式

理解联合类型有一个关键心智模型：**当你要使用一个联合类型的值时，TypeScript 只允许你进行对每个成员都安全的操作**。这听起来有点抽象，来看例子：

```typescript
function format(value: string | number): string {
  // value.toUpperCase();  // error TS2339: Property 'toUpperCase' does not exist on type 'string | number'.

  // 只能访问两者共有的成员
  return String(value);  // 正确：String() 接受 string 和 number
}
```

只有通过类型缩小（Narrowing）之后，才能安全地使用成员特有的方法：

```typescript
function format(value: string | number): string {
  if (typeof value === "string") {
    // 此分支中 value 被缩小为 string
    return value.toUpperCase();
  }
  // 此分支中 value 被缩小为 number
  return value.toFixed(2);
}
```

这看起来很符合直觉，就像你在 JavaScript 中做的那样，只是 TypeScript 能在编译时帮你验证逻辑的正确性。类型缩小的完整内容将在第 9 章展开。

### 对象字面量类型

对象也可以有字面量类型，即特定结构的精确匹配：

```typescript
interface Tmp {
  obj: {
    name: "Alice";
    age: 18;
  };
}

// 必须精确匹配每个值的字面量类型
const tmp: Tmp = {
  obj: {
    name: "Alice",   // 正确：只能是 "Alice"
    age: 18,          // 正确：只能是 18
  },
};
```

对象字面量类型要求完全实现每一个属性的每一个具体值，在实际开发中使用较少，了解即可。

## const 声明与 as const 断言

第 3 章已经提到 `const` 和 `let` 在类型推导上的差异，这里从字面量类型的角度再做深入理解。

### const 声明的推导规则

```typescript
let name1 = "TypeScript";   // 推导为 string
const name2 = "TypeScript"; // 推导为 "TypeScript"

let age1 = 10;              // 推导为 number
const age2 = 10;            // 推导为 10
```

设计逻辑是：`let` 声明的变量可以被重新赋值，所以推导为宽泛的原始类型即可（保证后续赋值都符合类型）；`const` 声明的**原始类型变量**不可变，类型可以直接精确到值本身。

但对象类型的 `const` 声明又不一样：对象本身是 const，但其属性仍可修改，所以属性类型推导为普通类型而非字面量：

```typescript
const user = {
  name: "Alice",
  age: 25,
};
// 推导为 { name: string; age: number }
// 而非 { name: "Alice"; age: 25 }
```

### as const 断言

当你需要 `let` 变量或对象属性也获得字面量类型时，可以使用 `as const` 断言。它的效果是三重的：

```typescript
// 1. 对基本值：类型收窄为字面量类型
let greeting = "hello" as const;
// greeting 的类型是 "hello" 而非 string
// greeting = "world";  // error TS2322: Type '"world"' is not assignable to type '"hello"'.

// 2. 对数组：变为 readonly 元组，每个元素获得字面量类型
const nums = [1, 2, 3] as const;
// 类型: readonly [1, 2, 3]

// 3. 对对象：所有属性变为 readonly 字面量类型（递归生效）
const config = {
  method: "GET",
  url: "/api/users",
} as const;
// 类型: { readonly method: "GET"; readonly url: "/api/users"; }
```

`as const` 在日常开发中有几个非常实用的场景：

**场景一：配合函数调用需要固定长度的元组**

```typescript
function add(x: number, y: number): number {
  return x + y;
}

const nums = [1, 2];
// add(...nums);  // error TS2556: A spread argument must either have a tuple type or be passed to a rest parameter.

const numsAsConst = [1, 2] as const;
add(...numsAsConst);  // 正确：readonly [1, 2] 确定是 2 个参数
```

**场景二：定义不会被修改的常量配置**

```typescript
const COLORS = ["red", "green", "blue"] as const;
type Color = (typeof COLORS)[number];
// Color = "red" | "green" | "blue"
```

**场景三：需要对象属性为具体字面量的场景**

```typescript
declare function handleRequest(url: string, method: "GET" | "POST"): void;

const req1 = { url: "/api", method: "GET" };
// handleRequest(req1.url, req1.method);  // error TS2345: Argument of type 'string' is not assignable to parameter of type '"GET" | "POST"'.

// 正确：方案1 使用 as const
const req2 = { url: "/api", method: "GET" } as const;
handleRequest(req2.url, req2.method);

// 正确：方案2 对单个属性断言
const req3 = { url: "/api", method: "GET" as "GET" };
handleRequest(req3.url, req3.method);
```

## 枚举

[枚举](https://www.typescriptlang.org/docs/handbook/enums.html)是 TypeScript 中少数不是"纯类型层面"的特性之一：它会同时产生类型定义和运行时代码。枚举用于将一组相关的命名常量组织在一个命名空间下。

### 为什么枚举擦不掉

普通枚举编译成一段立即执行函数加一个对象，对象上有成员名到值的映射，数字枚举还多一层值到名的反向映射。这段产物是运行时代码，不是类型。

逐文件剥离只做一件事：把类型语法替换成空白。它不能新增语句，也不知道别的文件怎么用这个枚举，碰上 `enum` 只能报错。`tsc` 能处理，因为它为每个文件重新生成整份 JavaScript。[`erasableSyntaxOnly`](https://devblogs.microsoft.com/typescript/announcing-typescript-5-8/) 把这条限制提前到编译期，报 TS1294，让你在本地就发现，而不是等到 `node` 启动时才炸。

`const enum` 看着像纯类型，代价在别处：它的值在使用处内联。内联要求编译器看到常量定义，而逐文件转译器（esbuild、tsx、Node）只看得到当前文件。对手写 `.d.ts` 里的 `declare const enum`，它拿不到值，只能报 TS2748。

内联还有一个工程代价：值是编译时的快照，上游改了值，下游不重新编译就还跑旧值。[`preserveConstEnums`](https://www.typescriptlang.org/tsconfig) 能让产物保留这个对象，方便调试，但运行时开销也回来了。

依据：[Node 文档 Type stripping 一节](https://nodejs.org/api/typescript.html)；`erasableSyntaxOnly` 见 TypeScript 5.8 发布说明。

逐文件转译器的处理方式不同：esbuild、tsx 在转译阶段补出那个对象，代价是放弃“只删除、不新增”的前提，所以它们与 `erasableSyntaxOnly` 冲突。要用枚举又要求可擦除，只能选运行时替代品。

如果你写过 JavaScript 中的常量定义文件：

```javascript
// 传统 JS 中定义一组相关常量
export const PageUrl = {
  Home: "url1",
  Settings: "url2",
  Profile: "url3",
};
```

用枚举改写后，获得了类型安全和命名空间约束：

```typescript
enum PageUrl {
  Home = "url1",
  Settings = "url2",
  Profile = "url3",
}

const home = PageUrl.Home;  // 类型推断为 PageUrl
```

### 数字枚举

如果不显式赋值，第一个成员从 `0` 开始，后续依次自增 1：

```typescript
enum Direction {
  Up,      // 0
  Down,    // 1
  Left,    // 2
  Right,   // 3
}
```

可以手动指定起始值：

```typescript
enum Direction {
  Up = 1,
  Down,    // 2
  Left,    // 3
  Right,   // 4
}
```

如果某中间的成员被赋值，后面的成员会在该值基础上继续递增：

```typescript
enum Items {
  Foo,         // 0
  Bar = 599,   // 599
  Baz,         // 600
}
```

枚举成员的值可以是**常量表达式**或**计算表达式**。常量表达式是可以在编译时求值的表达式子集（包括字面量、对已有常量枚举成员的引用、一元/二元运算符等）：

```typescript
enum FileAccess {
  None,
  Read    = 1 << 1,   // 2：位运算常量表达式
  Write   = 1 << 2,   // 4
  ReadWrite = Read | Write, // 6：引用已有成员
  // G = "123".length, // 计算成员，会中断赋值递增
}
```

一旦使用了计算表达式，后续没有显式赋值的成员必须提供初始值：编译器无法在编译时计算出应该递增为多少。此外，计算成员之后不能再有常量递增成员（即必须全部显式赋值）。

### 字符串枚举

字符串枚举的每个成员都必须用字符串字面量或另一个字符串枚举成员来初始化：

```typescript
enum Direction {
  Up    = "UP",
  Down  = "DOWN",
  Left  = "LEFT",
  Right = "RIGHT",
}
```

字符串枚举没有自增行为，但有一个重要的优势：运行时的值直接就是人类可读的字符串。这在调试时非常有帮助，你看到的不是不知所云的数字，而是有意义的文本。

```typescript
// 数字枚举在运行时：console.log(Direction.Up) 输出 0，含义不明
// 字符串枚举在运行时：console.log(Direction.Up) 输出 "UP"，一目了然
```

在实际开发中，字符串枚举非常适用于前端与后端的 API 约定：

```typescript
const enum MediaTypes {
  JSON = "application/json",
  XML  = "application/xml",
  Form = "application/x-www-form-urlencoded",
}

fetch(url, {
  headers: {
    Accept: MediaTypes.JSON,
  },
});
```

数字枚举和字符串枚举尽量不要混用（这被称为异构枚举 Heterogeneous Enum），虽然在技术上合法：

```typescript
// ⚠️ 技术上合法但不推荐
enum Mixed {
  No = 0,
  Yes = "YES",
}
```

### 枚举的双向映射

数字枚举在编译后的运行时对象中是**双向映射**的：既可以通过成员名找到值，也可以通过值找到成员名：

```typescript
enum Status {
  Pending,   // 0
  Approved,  // 1
  Rejected,  // 2
}

console.log(Status.Approved);  // 1（键 → 值）
console.log(Status[1]);        // "Approved"（值 → 键）
```

这是因为编译产物中构建了双向映射对象：

```javascript
"use strict";
var Status;
(function (Status) {
    Status[Status["Pending"] = 0] = "Pending";
    Status[Status["Approved"] = 1] = "Approved";
    Status[Status["Rejected"] = 2] = "Rejected";
})(Status || (Status = {}));
```

`Status["Pending"] = 0` 的返回值是 `0`，所以 `Status[Status["Pending"] = 0] = "Pending"` 等价于同时执行了 `Status["Pending"] = 0` 和 `Status[0] = "Pending"`。

**字符串枚举没有双向映射**，编译后只有单向映射：

```javascript
// 字符串枚举编译产物
var Direction;
(function (Direction) {
    Direction["Up"] = "UP";
    Direction["Down"] = "DOWN";
})(Direction || (Direction = {}));
```

### 常量枚举（const enum）

在 `enum` 前加 `const`，编译产物将完全不一样，枚举值会被直接**内联**到使用处，不产生运行时代码：

```typescript
const enum Color {
  Red,
  Green,
  Blue,
}

const c = Color.Red;

// 编译后：
// const c = 0 /* Color.Red */;
```

常量枚举的特点：
- **只能成员名 → 值**，没有反向映射
- **零运行时开销**：编译后完全消失
- 对于字符串常量枚举同样生效

是否产生运行时代码还与 `preserveConstEnums` 编译选项有关，将来在第 23 章详细讲解。

### 枚举相关的三个报错

```ts
// e02enum.ts
enum Level { Info, Error }
// iso2.ts
import { Shade } from "./shade";
console.log(Shade.Light);
```

第二个导入针对的是 `.d.ts` 里的 `declare const enum Shade`。三条原文：

- `e02enum.ts(1,6): error TS1294: This syntax is not allowed when 'erasableSyntaxOnly' is enabled.` 配置要求可擦除语法。改法：字符串联合或 `as const` 对象。
- `iso2.ts(2,13): error TS2748: Cannot access ambient const enums when 'isolatedModules' is enabled.` 当前文件只看得到声明，拿不到常量值，无法内联，报错落在使用 `Shade.Light` 的地方。改法：改用普通对象常量，或让上游提供运行时的值。
- `SyntaxError [ERR_UNSUPPORTED_TYPESCRIPT_SYNTAX]: TypeScript enum is not supported in strip-only mode` Node 直接执行时的错误，没有 TS 编号。改法：换 `tsx`，或先 `tsc` 再跑产物。

第一条和第三条是同一个原因的两个阶段：编译期开关拦一次，运行时加载再拦一次。

### 枚举合并

多个同名的 `enum` 声明会自动合并，这在扩展第三方枚举时非常有用：

```typescript
enum Foo {
  A,
}

enum Foo {
  B = 1,
}

// 等价于：
// enum Foo { A = 0, B = 1 }
```

合并规则：
- 只允许第一个声明的第一个成员省略初始值
- 不能有同名成员
- 所有声明必须同为 `const enum` 或同为非 `const`

### 枚举成员作为类型

当枚举的所有成员都是字面量枚举成员（即被初始化为字面量值）时，每个枚举成员也变成了一个独立的类型：

```typescript
enum ShapeKind {
  Circle,
  Square,
}

// Circle 和 Square 也作为类型存在
interface Circle {
  kind: ShapeKind.Circle;
  radius: number;
}

// 此时 kind 只能是 ShapeKind.Circle
const c: Circle = { kind: ShapeKind.Circle, radius: 5 };
// const c2: Circle = { kind: ShapeKind.Square, radius: 5 };  // error TS2322: Type 'ShapeKind.Square' is not assignable to type 'ShapeKind.Circle'.
```

这种"[枚举成员即类型](https://www.typescriptlang.org/docs/handbook/release-notes/typescript-5-0.html)"的特性在需要区分不同变体的场景（如可辨识联合类型）中非常有用。

### 枚举 vs as const 对象

由于普通枚举会在编译后产生 JavaScript 对象，Handbook 的 Enums 页在 Objects vs Enums 一节里建议谨慎使用枚举。`as const` 对象可以作为枚举的纯 JavaScript 替代方案：

```typescript
// 枚举方案
enum Color {
  Red,
  Green,
  Blue,
}

// as const 对象方案
const ColorConst = {
  Red: 0,
  Green: 1,
  Blue: 2,
} as const;

type ColorValue = (typeof ColorConst)[keyof typeof ColorConst];
// 0 | 1 | 2
```

对比：

| | enum（非 const） | const enum | as const 对象 |
|------|------|------|------|
| 编译产物 | 生成 IIFE + 对象 | 完全擦除，内联值 | 普通 JS 对象 |
| 反向映射 | 数字枚举支持 | 无 | 无 |
| 作为类型使用 | 直接用枚举名 | 直接用枚举名 | 需额外 `typeof` 提取 |
| 运行时可迭代 | ✅ | ❌ 已消失 | ✅ |

**选择建议**：如果只是需要一组常量值且不需要反向映射，优先用 `as const` 对象配合类型提取。如果需要一个有名字的类型且接受运行时对象的存在，枚举依然是好选择。常量枚举则适合追求零运行时开销的场景。团队内部应统一约定一种风格。

按决策优先级排列：

1. **只用于类型标注**（不需要运行时值） → **字符串字面量联合类型**（`type Status = "a" | "b"`）：零运行时开销，最简洁
2. **需要运行时值 + 需要遍历/反向映射** → **数字枚举**
3. **需要运行时值 + 希望值是人类可读的** → **字符串枚举** 或 **`as const` 对象**
4. **需要运行时值 + 追求零打包体积** → **`const enum`**（但注意跨模块引用兼容性）

## 小结

- **字面量类型**将值本身作为类型，是原始类型的子类型
- **联合类型** `A | B` 表示"满足 A 或 B 之一"，与字面量组合实现精确约束
- **`as const`** 将推导收窄为最精确的字面量类型，同时施加 `readonly`
- **枚举**是 TypeScript 特有的"类型+值"双重构造，用于组织命名常量
- 数字枚举有自动递增和双向映射特性；字符串枚举更可读但没有双向映射
- 常量枚举（`const enum`）编译后完全擦除，零运行时开销
- 在合适场景下可以用 `as const` 对象替代枚举

## 用不上的时候

### 集合由外部决定且会变

取值由第三方接口决定、随时新增时，写死的联合类型会拦下合法值，需要放宽成 `string` 并做运行时校验。

### 需要遍历成员

`as const` 对象配合 `Object.keys` 可以遍历。枚举的反向映射只对数字成员存在，字符串枚举没有。

### 跨进程传输

enum 是运行时对象，序列化到另一端只剩值。两端必须用同一份定义，否则字面量能过、类型对不上。
