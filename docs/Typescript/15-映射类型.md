# 第15章 映射类型

映射类型（Mapped Types）让你可以**基于已有类型的属性，逐一映射生成新类型**。如果说上一章的 `keyof` 和索引访问类型是基础构造块，映射类型就是它们的组合应用——把"遍历属性 → 变换每个属性的类型"这一模式抽象为通用的泛型工具。TypeScript 内置的 `Partial`、`Readonly`、`Required`、`Pick`、`Omit` 等工具类型全部是用映射类型实现的。

## 映射类型的基本语法

```typescript
type MappedType<T> = {
  [K in keyof T]: 新的类型表达式;
};
```

结构的含义是：
- `keyof T` — 获取 `T` 所有键名构成的联合类型
- `K in keyof T` — 逐一迭代联合中的每个键（与 `for...in` 遍历对象属性类似）
- `: 新的类型表达式` — 对每个属性重新定义其值类型

最基本的映射：原样复制一个对象类型：

```typescript
type Clone<T> = {
  [K in keyof T]: T[K];
};

interface User {
  name: string;
  age: number;
}

type UserClone = Clone<User>;
// { name: string; age: number; }
```

## 映射修饰符

映射时可以在 `readonly` 和 `?` 前面加 `+` 或 `-` 控制修饰符的增减。

### 属性可选性的控制

```typescript
// 将所有属性变为可选（+?）
type Partial<T> = {
  [K in keyof T]?: T[K];
};

// 将所有属性变为必选（-?）
type Required<T> = {
  [K in keyof T]-?: T[K];
};

// 演示
interface Config {
  url: string;
  method?: string;
  readonly timeout?: number;
}

type RequiredConfig = Required<Config>;
// { url: string; method: string; timeout: number; }
// method 和 timeout 失去了可选性
```

### readonly 的控制

```typescript
// 全部变为只读（+readonly）
type Readonly<T> = {
  readonly [K in keyof T]: T[K];
};

// 全部移除只读（-readonly）
type Mutable<T> = {
  -readonly [K in keyof T]: T[K];
};
```

`+` 可以省略不写——`+readonly` 和 `readonly` 等价，`+?` 和 `?` 等价。但 `-` 必须显式写出。

### 修饰符实际影响

```typescript
interface Todo {
  title: string;
  description?: string;
  readonly id: number;
}

// Partial — 全部可选
type PartialTodo = Partial<Todo>;
// { title?: string; description?: string; readonly id?: number; }

// Required — 全部必选，readonly 保留
type RequiredTodo = Required<Todo>;
// { title: string; description: string; readonly id: number; }

// Readonly — 全部只读，可选性保留
type ReadonlyTodo = Readonly<Todo>;
// { readonly title: string; readonly description?: string; readonly id: number; }
```

## 键名重映射（Key Remapping）

TypeScript 4.1 引入了 `as` 子句，允许在映射过程中**重新构造键名**：

```typescript
// 基本语法
type Mapped<T> = {
  [K in keyof T as 新键名]: T[K];
};
```

### 基本用法：为每个键加前缀

```typescript
interface User {
  name: string;
  age: number;
}

// 每个属性名前加 "get"
type Getters<T> = {
  [K in keyof T as `get${Capitalize<string & K>}`]: () => T[K];
};

type UserGetters = Getters<User>;
// {
//   getName: () => string;
//   getAge: () => number;
// }
```

等几个注意点：
- `string & K` — 因为 `keyof` 返回的可能是 `string | number | symbol`，而 `Capitalize` 只接受 `string`，所以用交叉类型把 `K` 约束为 `string`
- `Capitalize` 是 TypeScript 内置的工具类型，将字符串首字母大写
- 模板字符串类型 `${...}` 在这里用作键名

### 条件类型过滤属性

在 `as` 子句中使用条件类型，达到**过滤属性**的效果——`never` 会导致对应键被排除：

```typescript
// 只保留值类型为 string 的属性
type StringKeys<T> = {
  [K in keyof T as T[K] extends string ? K : never]: T[K];
};

interface User {
  name: string;
  age: number;
  email: string;
  active: boolean;
}

type StringUser = StringKeys<User>;
// { name: string; email: string; }
// age 和 active 被过滤掉了
```

因为 `never` 在联合类型中会被消除，所以条件类型返回 `never` 的键不会出现在结果类型中。

### 过滤掉函数类型属性

```typescript
// 只保留非函数类型的属性
type NonFunctionKeys<T> = {
  [K in keyof T as T[K] extends (...args: unknown[]) => unknown ? never : K]: T[K];
};
```

## 任意联合类型的映射

映射类型不限于 `keyof T`——可以迭代任意联合类型：

```typescript
type MyMapped = {
  [K in "x" | "y" | "z"]: number;
};
// { x: number; y: number; z: number; }

// 等价于 Record<"x" | "y" | "z", number>
```

甚至可以迭代对象联合类型，将每个对象通过其辨识字段映射为键：

```typescript
type Square = { kind: "square"; sideLength: number };
type Circle = { kind: "circle"; radius: number };
type Shape = Square | Circle;

// 以 kind 字段为键，值为对应的处理函数
type ShapeHandlers = {
  [S in Shape as S["kind"]]: (shape: S) => void;
};
// {
//   square: (shape: Square) => void;
//   circle: (shape: Circle) => void;
// }
```

## 内置映射类型实现一览

理解了映射类型之后，TypeScript 内置的工具类型就一目了然了：

```typescript
// 所有属性变为可选
type Partial<T> = {
  [K in keyof T]?: T[K];
};

// 所有属性变为必选
type Required<T> = {
  [K in keyof T]-?: T[K];
};

// 所有属性变为只读
type Readonly<T> = {
  readonly [K in keyof T]: T[K];
};

// 选取指定属性
type Pick<T, K extends keyof T> = {
  [P in K]: T[P];
};

// Record 也是映射类型的特例
type Record<K extends string | number | symbol, V> = {
  [P in K]: V;
};
```

`Omit` 的实现则是组合了 `Pick` 和 `Exclude`：

```typescript
type Omit<T, K extends keyof T> = Pick<T, Exclude<keyof T, K>>;
```

## 实际应用模式

### 模式一：条件属性转换

```typescript
// 将所有函数类型的属性变为可选（适合 API 接口的 mock 数据）
type MakeFunctionsOptional<T> = {
  [K in keyof T]: T[K] extends (...args: unknown[]) => unknown
    ? T[K] | undefined
    : T[K];
};
```

### 模式二：深层映射

映射类型本身是**浅层**的——`Partial<User>` 只让 `User` 的第一层属性可选，嵌套对象不受影响。要实现深层映射，需要用递归：

```typescript
// 深层 Partial
type DeepPartial<T> = {
  [K in keyof T]?: T[K] extends object
    ? DeepPartial<T[K]>
    : T[K];
};

interface Config {
  server: {
    host: string;
    port: number;
    ssl: {
      enabled: boolean;
      cert: string;
    };
  };
  plugins: string[];
}

type PartialConfig = DeepPartial<Config>;
// 现在 server.ssl 也会变为可选
```

### 模式三：可辨识联合类型的映射

```typescript
// 为可辨识联合类型的每种变体生成处理函数
type ActionMap<Actions extends { type: string }> = {
  [A in Actions as A["type"]]: (action: A) => void;
};

type AddTodo = { type: "ADD_TODO"; text: string };
type ToggleTodo = { type: "TOGGLE_TODO"; index: number };
type TodoAction = AddTodo | ToggleTodo;

type Handlers = ActionMap<TodoAction>;
// {
//   ADD_TODO: (action: AddTodo) => void;
//   TOGGLE_TODO: (action: ToggleTodo) => void;
// }
```

## 本章小结

- **映射类型** `[K in keyof T]: ...` 是基于已有类型的属性逐一映射
- **修饰符** `+?`/`-?` 控制可选性，`+readonly`/`-readonly` 控制只读性
- **键名重映射** `as` 子句（4.1+）可以在映射的同时变换键名或过滤属性
- 映射类型可以迭代任意联合类型，不仅限于 `keyof T`
- `Partial`、`Readonly`、`Required`、`Pick`、`Record` 等内置工具类型都是映射类型的实例
- 映射类型是浅层的，深层映射需要递归

下一章将介绍条件类型与 `infer`——这是类型编程中最强大的工具，让你可以在类型层面实现 `if/else` 分支逻辑和模式匹配。
