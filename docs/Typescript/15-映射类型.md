# 第 15 章 映射类型

映射类型（Mapped Types）让你可以**基于已有类型的属性，逐一映射生成新类型**。`keyof` 和索引访问类型是基础构造块，映射类型就是它们的组合应用：把"遍历属性 → 变换每个属性的类型"这一模式抽象为通用的泛型工具。TypeScript 内置的 `Partial`、`Readonly`、`Required`、`Pick`、`Omit` 等工具类型全部是用映射类型实现的（[TypeScript Handbook：Mapped Types](https://www.typescriptlang.org/docs/handbook/2/mapped-types.html)）。

## 映射类型的基本语法

```typescript
type MappedType<T> = {
  [K in keyof T]: 新的类型表达式;
};
```

结构的含义是：
- `keyof T`：获取 `T` 所有键名构成的联合类型
- `K in keyof T`：逐一迭代联合中的每个键（与 `for...in` 遍历对象属性类似）
- `: 新的类型表达式`：对每个属性重新定义其值类型

最基本的映射：原样复制一个对象类型：

```typescript
type Clone<T> = {
  [K in keyof T]: T[K];
};

// User 沿用第 6 章的定义
type UserClone = Clone<User>;
// { id: string; name: string; email: string; }
```

## 映射修饰符

映射时可以在 `readonly` 和 `?` 前面加 `+` 或 `-` 控制修饰符的增减。

### 属性可选性的控制

```typescript
// 将所有属性变为可选（+?）
type Partial<T> = {
  [K in keyof T]?: T[K];
};

// 将所有属性变为必选（-?）
type Required<T> = {
  [K in keyof T]-?: T[K];
};

// 演示
interface Config {
  url: string;
  method?: string;
  readonly timeout?: number;
}

type RequiredConfig = Required<Config>;
// { url: string; method: string; timeout: number; }
// method 和 timeout 失去了可选性
```

### readonly 的控制

```typescript
// 全部变为只读（+readonly）
type Readonly<T> = {
  readonly [K in keyof T]: T[K];
};

// 全部移除只读（-readonly）
type Mutable<T> = {
  -readonly [K in keyof T]: T[K];
};
```

`+` 可以省略不写，`+readonly` 和 `readonly` 等价，`+?` 和 `?` 等价。但 `-` 必须显式写出。

### 修饰符实际影响

```typescript
interface Todo {
  title: string;
  description?: string;
  readonly id: number;
}

// Partial：全部可选
type PartialTodo = Partial<Todo>;
// { title?: string; description?: string; readonly id?: number; }

// Required：全部必选，readonly 保留
type RequiredTodo = Required<Todo>;
// { title: string; description: string; readonly id: number; }

// Readonly：全部只读，可选性保留
type ReadonlyTodo = Readonly<Todo>;
// { readonly title: string; readonly description?: string; readonly id: number; }
```

## 键名重映射（Key Remapping）

TypeScript 4.1 引入了 `as` 子句（[TypeScript 4.1 发布说明](https://www.typescriptlang.org/docs/handbook/release-notes/typescript-4-1.html) 的 Key Remapping in Mapped Types），允许在映射过程中**重新构造键名**：

```typescript
// 基本语法
type Mapped<T> = {
  [K in keyof T as 新键名]: T[K];
};
```

### 基本用法：为每个键加前缀

```typescript
// User 沿用第 6 章的定义
// 每个属性名前加 "get"
type Getters<T> = {
  [K in keyof T as `get${Capitalize<string & K>}`]: () => T[K];
};

type UserGetters = Getters<User>;
// {
//   getId: () => string;
//   getName: () => string;
//   getEmail: () => string;
// }
```

等几个注意点：
- `string & K`：因为 `keyof` 返回的可能是 `string | number | symbol`，而 `Capitalize` 只接受 `string`，所以用交叉类型把 `K` 约束为 `string`
- `Capitalize` 是 TypeScript 内置的工具类型，将字符串首字母大写
- 模板字符串类型 `${...}` 在这里用作键名

### 条件类型过滤属性

在 `as` 子句中使用条件类型，达到**过滤属性**的效果，`never` 会导致对应键被排除：

```typescript
// 只保留值类型为 string 的属性
type StringKeys<T> = {
  [K in keyof T as T[K] extends string ? K : never]: T[K];
};

type Profile = {
  id: string;
  age: number;
  email: string;
  active: boolean;
};

type StringProfile = StringKeys<Profile>;
// { id: string; email: string; }
// age 和 active 被过滤掉了
```

因为 `never` 在联合类型中会被消除，所以条件类型返回 `never` 的键不会出现在结果类型中。

### 过滤掉函数类型属性

```typescript
// 只保留非函数类型的属性
// 注意用 any[]：如果用 (...args: unknown[]) => unknown，
// 带参数的函数（如 (a: string) => void）不满足该约束，会被错误地保留下来
type NonFunctionKeys<T> = {
  [K in keyof T as T[K] extends (...args: any[]) => any ? never : K]: T[K];
};
```

## 任意联合类型的映射

映射类型不限于 `keyof T`，可以迭代任意联合类型：

```typescript
type MyMapped = {
  [K in "x" | "y" | "z"]: number;
};
// { x: number; y: number; z: number; }

// 等价于 Record<"x" | "y" | "z", number>
```

甚至可以迭代对象联合类型，将每个对象通过其辨识字段映射为键：

```typescript
type Square = { kind: "square"; sideLength: number };
type Circle = { kind: "circle"; radius: number };
type Shape = Square | Circle;

// 以 kind 字段为键，值为对应的处理函数
type ShapeHandlers = {
  [S in Shape as S["kind"]]: (shape: S) => void;
};
// {
//   square: (shape: Square) => void;
//   circle: (shape: Circle) => void;
// }
```

## 内置映射类型实现一览

理解了映射类型之后，TypeScript 内置的工具类型就一目了然了：

```typescript
// 所有属性变为可选
type Partial<T> = {
  [K in keyof T]?: T[K];
};

// 所有属性变为必选
type Required<T> = {
  [K in keyof T]-?: T[K];
};

// 所有属性变为只读
type Readonly<T> = {
  readonly [K in keyof T]: T[K];
};

// 选取指定属性
type Pick<T, K extends keyof T> = {
  [P in K]: T[P];
};

// Record 也是映射类型的特例
type Record<K extends string | number | symbol, V> = {
  [P in K]: V;
};
```

`Omit` 的实现则是组合了 `Pick` 和 `Exclude`：

```typescript
type Omit<T, K extends keyof any> = Pick<T, Exclude<keyof T, K>>;
```

注意第二行的 `K extends keyof any`（等价于 `string | number | symbol`），而不是 `K extends keyof T`。标准库用的是前者：这样 `Omit<User, "age">` 在 `User` 没有 `age` 属性时也能通过（结果就是 `User` 本身），而不是报 TS2344。工具类型经常被用在"键不一定存在"的场景，约束写窄了会莫名其妙地编译失败。

## 实际应用模式

### 模式一：条件属性转换

```typescript
// 将所有函数类型的属性变为可选（适合 API 接口的 mock 数据）
// 同样要用 any[]，否则带参数的函数不会被识别为函数类型
type MakeFunctionsOptional<T> = {
  [K in keyof T]: T[K] extends (...args: any[]) => any
    ? T[K] | undefined
    : T[K];
};
```

### 模式二：深层映射

映射类型本身是**浅层**的：`Partial<User>` 只让 `User` 的第一层属性可选，嵌套对象不受影响。要实现深层映射，需要用递归：

```typescript
// 深层 Partial
type DeepPartial<T> = {
  [K in keyof T]?: T[K] extends object
    ? DeepPartial<T[K]>
    : T[K];
};

interface Config {
  server: {
    host: string;
    port: number;
    ssl: {
      enabled: boolean;
      cert: string;
    };
  };
  plugins: string[];
}

type PartialConfig = DeepPartial<Config>;
// 现在 server.ssl 也会变为可选
```

### 模式三：可辨识联合类型的映射

```typescript
// 为可辨识联合类型的每种变体生成处理函数
type ActionMap<Actions extends { type: string }> = {
  [A in Actions as A["type"]]: (action: A) => void;
};

type AddTodo = { type: "ADD_TODO"; text: string };
type ToggleTodo = { type: "TOGGLE_TODO"; index: number };
type TodoAction = AddTodo | ToggleTodo;

type Handlers = ActionMap<TodoAction>;
// {
//   ADD_TODO: (action: AddTodo) => void;
//   TOGGLE_TODO: (action: ToggleTodo) => void;
// }
```

## 检查器里发生了什么

同态映射的判定只看约束。`getHomomorphicTypeVariable`（checker.ts:20797）检查映射类型的约束是不是 `Index` 节点，也就是 `keyof T`，并且 `T` 是类型参数。两个条件同时满足才算同态；`[K in "a" | "b"]` 或 `[K in SomeUnion]` 都不算。

同态映射在实例化时走 `instantiateMappedType`（20808）。源码注释列了五种走向：原始类型不映射，联合类型逐成员分发，数组映射成元素变换后的数组，元组映射成元组，其余才逐属性构造对象。`Partial<number[]>` 得到 `(number | undefined)[]`、元组保持元组，都来自这里。

修饰符和属性类型不是重新推断的。可选、只读标记从源属性复制，映射自己的修饰符再叠加，逻辑在 `resolveMappedTypeMembers`（14741）和 `getMappedTypeModifiers`（14896）。

键重映射也在 `resolveMappedTypeMembers` 里：逐个键算出 `nameType`，结果是 `never` 就跳过该键，其余作为新属性名，必须能赋给 `string | number | symbol`，否则报 TS2322。`getMappedTypeNameTypeKind`（14944）再区分过滤和重命名两种 `as` 用法。

分界线落到代码上只有一行：约束是不是 `keyof` 一个类型参数。是，映射会去读源类型的属性列表，连同属性上的修饰符一起读；不是，映射只拿到一串键名，没有源属性可读，`?` 和 `readonly` 自然无处拷贝。

`as` 子句不改变这个判定。它只是把算出来的新键名当属性名，源属性仍按原键取，所以 `[K in keyof T as ...]` 依旧保留修饰符；换成 `[K in "a" | "b" as ...]` 就不再是同态映射。

复制动作也有代价。属性很多的类型做深层递归映射，每个属性都要单独实例化，实例化数随属性数线性增长。`--extendedDiagnostics` 里的 Instantiations 能直接看到这个量。

行号取自 [TypeScript 5.9.3 的 src/compiler/checker.ts](https://github.com/microsoft/TypeScript/blob/v5.9.3/src/compiler/checker.ts)；7.0 换成 Go 实现，逻辑相同但没有逐行核对。

### 报错现场

```ts
type AsKey<T> = { [K in keyof T as T[K]]: K };

type Locked = Readonly<{ id: number }>;
const locked: Locked = { id: 1 };
locked.id = 2;

type Missing = Pick<{ id: number }, "tittle">;
```

`repro-15.ts(1,36): error TS2322: Type 'T[K]' is not assignable to type 'string | number | symbol'.`。下面还列了 `T[string]`、`T[number]` 的分解。`as` 后面的表达式要产出属性名。改法：加一层转换，比如 ``as `${K & string}` ``，或先过滤掉非字符串键。

`repro-15.ts(5,8): error TS2540: Cannot assign to 'id' because it is a read-only property.`。`Readonly` 只拷贝只读标记，不会让对象变成可写。改法：用 `-readonly` 自己写 `Mutable`，或重新构造对象。

`repro-15.ts(7,37): error TS2344: Type '"tittle"' does not satisfy the constraint '"id"'.`。`Pick` 的键必须属于 `keyof T`。改法：拼写改成 `"id"`，或改用 `Omit`。

### 一句话记住

同态映射像拿原件复印：原件上的 `?` 和 `readonly` 会一并复印，你只改动自己指定的那一项。复印机只认 `keyof T` 这个入口，换成别的键清单，修饰符就没人替你保留。

比喻不成立的地方：复印机不会凭空改值类型，同态映射会按你写的 `T[K]` 或变换后的表达式重写每个属性的类型。

```ts
type Source = { id: string; readonly tag?: string };
type Soft = Partial<Source>;   // { id?: string; readonly tag?: string }

type Loose = { [K in "id" | "tag"]: Source[K] };  // 没有 readonly
```

## 小结

- **映射类型** `[K in keyof T]: ...` 是基于已有类型的属性逐一映射
- **修饰符** `+?`/`-?` 控制可选性，`+readonly`/`-readonly` 控制只读性
- **键名重映射** `as` 子句（4.1+）可以在映射的同时变换键名或过滤属性
- 映射类型可以迭代任意联合类型，不仅限于 `keyof T`
- `Partial`、`Readonly`、`Required`、`Pick`、`Record` 等内置工具类型都是映射类型的实例
- 映射类型是浅层的，深层映射需要递归

## 用不上的时候

### 映射是浅层的

嵌套对象只映射第一层，深层要递归，递归深度还有编译器上限。

### 非 keyof 来源的映射

用 `K in SomeUnion` 映射时，修饰符不会自动保留，`readonly`、`?` 需要手动加。

### 大对象上做重映射

属性多、联合大的映射会明显拖慢编译，类型复杂时先看 `--extendedDiagnostics`。
