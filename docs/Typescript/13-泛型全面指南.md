# 第 13 章 泛型

写一个缓存函数，换一种值类型就要复制一遍代码；写一个 API 客户端，返回值类型跟着请求参数变。泛型让类型随输入变化。这一章讲泛型参数、约束、默认值和推断规则。


一句话：推断是“从实参里收集候选，挑一个最合适的”。显式写 `<string>` 等于告诉检查器不用挑，候选表固定成 `string`。这个说法在只出现在返回值的类型参数上失效：没有实参可收集，只能落到 `unknown`。

`function tag<T>(v: T): T` 调用 `tag<string>(1)` 报 `TS2345`，去掉 `<string>` 就不报。

泛型（Generics）是 TypeScript 类型系统中最强大的特性之一。它让你能够编写**适用于多种类型而非特定类型的代码**，就像函数让值可以参数化一样，泛型让类型可以参数化。这一章全面讲解泛型的语法、使用场景和最佳实践（[TypeScript Handbook：Generics](https://www.typescriptlang.org/docs/handbook/2/generics.html)）。

## 泛型的核心概念

### 从具体的类型到参数化的类型

考虑一个简单的场景：一个函数接受某个值，返回同样的值。

```typescript
// 如果不使用泛型，只能为每种类型分别写一个函数
function identityNumber(x: number): number {
  return x;
}

function identityString(x: string): string {
  return x;
}

// 或者用 any：但会丢失类型信息
function identityAny(x: any): any {
  return x;
}
// const result = identityAny("hello");  // result 的类型是 any，丢失了 string 信息
```

泛型解决了这个问题，**类型变成了参数**。

```typescript
// Type 是类型参数，调用时被具体类型替换
function identity<Type>(x: Type): Type {
  return x;
}

// 使用时
const s = identity("hello");   // s: "hello"（字面量类型）
const n = identity(42);        // n: 42
const b = identity(true);      // b: true
```

调用 `identity("hello")` 时，TypeScript 会**自动推导** `Type` 为 `string`，返回值类型也随之确定为 `string`。你也可以显式指定类型参数：

```typescript
const s = identity<string>("hello");   // 显式指定
const n = identity<number>(42);
```

### 泛型的函数类比

如果你觉得泛型抽象，这个类比会有帮助：

| 概念 | 值层面的函数 | 类型层面的泛型 |
|------|------------|-------------|
| 参数 | `function f(x)` 中的 `x` | `function f<T>` 中的 `T` |
| 传参 | `f("hello")` | `f<string>("hello")` 或自动推导 |
| 作用 | 复用逻辑 | 复用类型关系 |

泛型参数就像**函数的参数**：函数参数让你在不同调用中传入不同的值，泛型参数让你在不同调用中使用不同的类型。

## 泛型函数

### 基本语法

```typescript
// 泛型函数声明
function firstElement<Type>(arr: Type[]): Type | undefined {
  return arr[0];
}

// 箭头函数泛型
const firstElement = <Type>(arr: Type[]): Type | undefined => arr[0];

// 函数表达式泛型
const firstElement2: <Type>(arr: Type[]) => Type | undefined = (arr) => arr[0];
```

TSX 中尖括号会与 JSX 标签冲突，此时可以加逗号消除歧义：

```typescript
// TSX 中的箭头函数泛型：加逗号 <T,> 或 extends 约束
const firstElement = <Type,>(arr: Type[]): Type | undefined => arr[0];
const firstElement2 = <Type extends unknown>(arr: Type[]): Type | undefined => arr[0];
```

### 泛型类型推导

TypeScript 在多数情况下可以自动推导泛型参数，不需要显式写尖括号：

```typescript
function map<T, U>(arr: T[], fn: (item: T) => U): U[] {
  return arr.map(fn);
}

// 不需要显式指定 <string, number>
const lengths = map(["hello", "world"], s => s.length);
// lengths: number[]

// TypeScript 推导过程：
// 1. arr 是 string[] → T = string
// 2. (s: string) => s.length 返回 number → U = number
// 3. 返回值 U[] = number[]
```

### 推断的实际步骤

检查器分三步。收集候选：遍历实参，把形参里的类型参数与实参类型对上，记下候选。选最优：按优先级取最具体的一个，没有更具体的就取联合。检查实参：用选定的类型参数再检查每个实参和返回值。

返回值位置不产生候选。`tag` 的 `T` 出现在参数和返回值，候选全来自实参。`conjure<T>(): T` 的 `T` 只在返回值，调用时没有候选，落到 `unknown`，把它赋给 `string` 报 `TS2322`。

候选按参数顺序参与比较，先定下的类型会约束后面的实参。`pair("a", 1)` 把 `T` 定成 `"a"`，第二个实参 `1` 按 `"a"` 检查，报 `TS2345`。

显式类型实参把参数固定住。`tag<string>(1)` 里 `T` 不再收集，实参 `1` 直接按 `string` 检查。写尖括号的同时丢了推断信息，报错位置也从返回值挪到实参。

数组字面量走另一条路：`getBestCommonType`。有公共父类型就取父类型，没有就取联合。`[new Dog(), new Animal()]` 的元素类型是 `Animal`，`[new Dog(), new Cat()]` 是 `Dog | Cat`，实测报错信息里的类型就是这两个。

上下文类型也会参与推断。`const s: string = conjure()` 里返回值有 `string` 约束，`T` 被定成 `string`，不报错；换成 `const value = conjure()` 再赋给 `string`，`T` 只能落到 `unknown`，报 `TS2322`。同一个函数，写法不同，结果不同。

候选保留字面量。`pair("a", 1)` 的第一个候选是 `"a"`，不是 `string`。字面量原样参与比较，直到被约束或形参类型放宽。

依据：5.x 源码的 `inferTypes`、`getInferredType`、`getBestCommonType`。7.0 检查器为 Go 移植，行号未核对。

### 泛型约束（extends）

有时你希望泛型参数不是任意类型，而是满足特定条件的类型。这时候用 `extends` 添加约束：

```typescript
// 约束 Type 必须有 length 属性
function longest<Type extends { length: number }>(a: Type, b: Type): Type {
  return a.length >= b.length ? a : b;
}

longest([1, 2], [1, 2, 3]);       // 正确：数组有 length
longest("hello", "world");         // 正确：字符串有 length
// longest(1, 2);  // error TS2345: Argument of type 'number' is not assignable to parameter of type '{ length: number; }'.
```

约束的作用是双重的：
1. **限制**：调用方只能传入满足约束的类型
2. **获得信息**：函数体内可以安全地访问约束中声明的成员

```typescript
// 使用 keyof 作为约束：这是 TypeScript 中最常见的约束模式
function getProperty<Type, Key extends keyof Type>(obj: Type, key: Key): Type[Key] {
  return obj[key];
}

const user = { name: "Alice", age: 25 };
getProperty(user, "name");  // 正确：返回 string
getProperty(user, "age");   // 正确：返回 number
// getProperty(user, "email");  // error TS2345: Argument of type '"email"' is not assignable to parameter of type '"age" | "name"'.
```

### 在泛型约束中使用类型参数

可以让一个类型参数的约束依赖于另一个类型参数：

```typescript
// Key 约束为 Type 的属性名
function getProperty<Type, Key extends keyof Type>(obj: Type, key: Key) {
  return obj[key];
}
```

### 泛型默认值

泛型参数可以有默认值，就像函数参数的默认值：

```typescript
// 默认的 Error 类型是 Error
type Result<T, E = Error> =
  | { success: true; data: T }
  | { success: false; error: E };

// 不传第二个参数时默认为 Error
type DefaultResult = Result<string>;
// Result<string, Error>

// 需要自定义错误类型时再传
type CustomResult = Result<string, { code: number; message: string }>;
```

## const 类型参数（TS 5.0）

类型参数前加 `const`（[TypeScript 5.0 发布说明](https://www.typescriptlang.org/docs/handbook/release-notes/typescript-5-0.html) 的 const Type Parameters），推导就按 `as const` 的方式保留字面量。只影响类型，不改运行时行为：

```typescript
function tuple<const T extends readonly unknown[]>(items: T): T {
  return items;
}

const pair = tuple([1, "a"]);
// pair: readonly [1, "a"]
```

不加 `const` 时，同一个调用推导成 `(string | number)[]`：

```typescript
function tupleLoose<T extends readonly unknown[]>(items: T): T {
  return items;
}

const loose = tupleLoose([1, "a"]);
// loose: (string | number)[]
```

两种写法都变只读，区别在生效位置：

| 写法 | 位置 | 影响范围 |
|---|---|---|
| `as const` | 调用处 | 这一次的实参 |
| `const` 类型参数 | 声明处 | 所有调用 |

`as const` 只能贴字面量，贴到变量后面会报错：

```typescript
const raw = { level: "warn" };
const narrow = raw as const;
// error TS1355: A 'const' assertion can only be applied to references to
//   enum members, or string, number, boolean, array, or object literals.
```

对象字面量同样保留属性字面量：

```typescript
function table<const T extends Record<string, string>>(rows: T): T {
  return rows;
}

const routes = table({ list: "/orders", get: "/orders/:id" });
// routes: { readonly list: "/orders"; readonly get: "/orders/:id" }
```

嵌套的数组一起变成只读元组：

```typescript
function nested<const T extends readonly unknown[]>(items: T): T {
  return items;
}

const grid = nested([[1, 2], [3]]);
// grid: readonly [readonly [1, 2], readonly [3]]
```

调用方显式给出宽类型时，`const` 不起作用：

```typescript
declare function tuple<const T extends readonly unknown[]>(items: T): T;

const widened = tuple(["a", "b"] as string[]);
// widened: string[]
```

限制是只能用在函数、方法、类的类型参数上：

```typescript
interface BoxInterface<const T> {
  value: T;
}

type BoxAlias<const T> = { value: T };
```

上面两行都报 `error TS1277: 'const' modifier can only appear on a type parameter of a function, method or class`。类和方法可以：

```typescript
class BoxClass<const T> {
  constructor(readonly value: T) {}
}

const boxed = new BoxClass({ level: "warn" });
// boxed: BoxClass<{ readonly level: "warn" }>
```

不带约束也能用，字符串和数字照样收到字面量：

```typescript
function unconstrained<const T>(value: T): T {
  return value;
}

const flag = unconstrained("on");
// flag: "on"
```

代价是返回值带只读标记。`routes.list = "/other"` 报 `error TS2540: Cannot assign to 'list' because it is a read-only property.`。要可变副本就复制一份，`const copy = [...grid]` 得到的是可变数组。

单次调用需要字面量、又不想让整个函数的返回值变只读时，在调用处写 `as const` 更合适。

## 泛型接口

接口同样可以通过泛型参数来参数化成员类型：

```typescript
interface ApiResponse<T> {
  code: number;
  data: T;
  message: string;
}

// 使用
const userRes: ApiResponse<{ name: string; age: number }> = {
  code: 200,
  data: { name: "Alice", age: 25 },
  message: "ok",
};
```

泛型接口支持嵌套使用，可以构建出精确的类型层次：

```typescript
interface PaginatedResponse<T> {
  items: T[];
  total: number;
  page: number;
  pageSize: number;
}

// 分页的用户列表
type UsersPage = PaginatedResponse<{
  id: number;
  name: string;
}>;

// 更深层嵌套
interface ApiEnvelope<T> {
  code: number;
  data: PaginatedResponse<T>;
  timestamp: number;
}

type UsersEnvelope = ApiEnvelope<{ id: number; name: string }>;
// { code: number; data: { items: User[]; total: number; page: number; pageSize: number }; timestamp: number; }
```

## 泛型类

类的泛型参数让同一个类适用于不同类型的数据：

```typescript
class Stack<T> {
  private items: T[] = [];

  push(item: T): void {
    this.items.push(item);
  }

  pop(): T | undefined {
    return this.items.pop();
  }

  peek(): T | undefined {
    return this.items[this.items.length - 1];
  }
}

// 实例化时指定类型
const numStack = new Stack<number>();
numStack.push(1);
numStack.push(2);
const n = numStack.pop();  // number | undefined

const strStack = new Stack<string>();
strStack.push("hello");
```

静态成员**不能使用**类的泛型参数，因为静态成员属于类本身，而泛型参数只有在实例化后才确定：

```typescript
class Box<T> {
  // static default: T;  // error TS2302: Static members cannot reference class type parameters.

  // 静态方法可以是泛型的，但那是独立的类型参数
  static create<U>(value: U): Box<U> {
    return new Box<U>();
  }
}
```

## 泛型类型别名

```typescript
// 基础泛型别名
type Nullable<T> = T | null;
type Pair<T, U> = [T, U];

// 带约束的泛型别名
type StringKeyed<T extends string> = Record<T, number>;

// 带默认值的泛型别名
type EventHandler<E = Event> = (event: E) => void;
```

## 多泛型参数与类型间的关系

多个泛型参数可以在类型声明中表达**参数之间的类型关系**，这是泛型最强大的用途：

```typescript
// 表达"输入是什么类型，输出也是什么类型"
function identity<T>(value: T): T {
  return value;
}

// 表达"函数将 T 类型数组映射为 U 类型数组"
function map<T, U>(arr: T[], fn: (item: T) => U): U[] {
  return arr.map(fn);
}

// 表达"回调的参数类型取决于 obj 的类型和 event 的类型"
// 注意是取事件处理函数的"参数类型"，不是 O[E] 本身
// O[E] 是函数类型，直接 (data: O[E]) 会让 data 变成这个函数（不是它能接收的数据）
function on<O extends object, E extends keyof O>(
  obj: O,
  event: E,
  callback: O[E] extends (data: infer D, ...args: any[]) => any
    ? (data: D) => void
    : never
): void {
  // ...
}

const user = {
  name: "Alice",
  age: 25,
  onUpdate: (data: { name: string; age: number }) => {},
};

on(user, "onUpdate", (data) => {
  // data 自动推导为 { name: string; age: number }
});
```

## React 中的泛型坑位

React 中最常见的泛型使用场景：

### useState

```typescript
// 从初始值推导
const [count, setCount] = useState(0);           // count: number
const [name, setName] = useState("");             // name: string

// 联合类型需要显式指定（TypeScript 推导可能不够精确）
const [status, setStatus] = useState<"idle" | "loading" | "success" | "error">("idle");

// null 初始值必须显式指定类型
const [user, setUser] = useState<User | null>(null);
```

### useRef

```typescript
// DOM 元素的 ref：初始值 null，需要指定元素类型
const inputRef = useRef<HTMLInputElement>(null);

// 可变值的 ref
const intervalRef = useRef<number | null>(null);

// 只读 ref（useRef 对有初始值的情况会自动 readonly）
const countRef = useRef(0);  // MutableRefObject<number>
```

### 事件处理

```typescript
// 输入事件的泛型
const handleChange = (e: React.ChangeEvent<HTMLInputElement>) => {
  console.log(e.target.value);
};

// 点击事件的泛型
const handleClick = (e: React.MouseEvent<HTMLButtonElement>) => {
  e.preventDefault();
};
```

## 泛型的最佳实践

### 1. 泛型参数应该出现两次或更多

如果一个类型参数只在声明中出现一次，它很可能不需要是泛型，直接用具体类型即可。

```typescript
// 不好：T 只出现了一次，调用方传什么类型都不影响返回类型
function log<T>(value: T): void {
  console.log(value);
}
```

改成不用泛型：

```typescript
function log(value: unknown): void {
  console.log(value);
}

// 正确：T 出现了两次（参数和返回值），泛型有意义
function identity<T>(value: T): T {
  return value;
}
```

### 2. 能用推导就不显式指定

TypeScript 的泛型推导通常很准确，显式指定反而增加了噪音：

```typescript
// 显式指定增加噪音
const users = map<string, User>(names, nameToUser);

// 正确：让 TS 推导
const users = map(names, nameToUser);
```

### 3. 约束尽量精确但不过分

```typescript
function getLength<T>(obj: T): number {
  // return obj.length;  // error TS2339: Property 'length' does not exist on type 'T'.
}

// 正确：约束精确，既限制了调用方，又让函数体能安全使用
function getLength<T extends { length: number }>(obj: T): number {
  return obj.length;
}

// 正确：或者用具体类型替代
function getLength(obj: { length: number }): number {
  return obj.length;
}
```

约束太宽时，`T` 上没有任何成员可访问。

### 4. 泛型参数的命名

常见的命名约定：
- `T`、`U`、`V`：通用类型参数
- `K`：键类型（Key）
- `V`：值类型（Value）
- `E`：元素类型（Element）或错误类型（Error）
- `R`：返回值类型（Return）

对于更复杂的场景，使用描述性的名称更清晰：
```typescript
// 描述性名称在复杂泛型中更清晰
type Result<TData, TError = Error> =
  | { success: true; data: TData }
  | { success: false; error: TError };
```

## 常见报错

四条报错来自同一个文件，用 tsc 7.0.2 实跑：

```ts
declare function tag<T>(value: T): T;
const s: string = tag<string>(1);

declare function pair<T>(a: T, b: T): T;
pair("a", 1);

declare function conjure<T>(): T;
conjure(1);

type Keys<T extends object> = keyof T;
type Bad = Keys<string>;
```

```text
generic.ts(2,31): error TS2345: Argument of type 'number' is not assignable to parameter of type 'string'.
generic.ts(5,11): error TS2345: Argument of type '1' is not assignable to parameter of type '"a"'.
generic.ts(8,9): error TS2554: Expected 0 arguments, but got 1.
generic.ts(11,17): error TS2344: Type 'string' does not satisfy the constraint 'object'.
```

第一处 `TS2345`：显式 `<string>` 固定了 `T`，`1` 按 `string` 检查。改法是删掉尖括号，让实参决定类型。

第二处 `TS2345`：`T` 先被 `"a"` 定住，第二个实参 `1` 类型不符。改法是把两个参数拆成两个类型参数，或用联合约束。

第三处 `TS2554`：`conjure` 不接收参数。改法是去掉实参。

第四处 `TS2344`：`Keys` 要求 `T extends object`，`string` 不满足。改法是放宽约束，或改用 `PropertyKey`。

这四条报错落在实参、第二个实参、多余实参、类型约束上。位置不同，说明推断的失败点不同：前两条是“定住后不匹配”，后两条是“没有推断成功”。

## 小结

- **泛型**将类型参数化，让代码适配多种类型而不丢失类型信息
- 泛型可用于**函数**、**接口**、**类**和**类型别名**
- `extends` 为泛型添加**约束**：限制类型范围，同时在函数体中获得成员访问能力
- 泛型的**默认值**和函数参数的默认值一样，简化常见场景的使用
- 多泛型参数的核心价值是表达**类型之间的关系**（输入-输出关联、对象属性-回调参数关联等）
- React 中 `useState`、`useRef`、事件处理是最常见的泛型使用场景
- 泛型参数不应只出现一次（那就没必要是泛型），能用推导就不显式指定

## 用不上的时候

### 类型参数只出现一次

`function f<T>(x: T): void` 里的 `T` 没有约束任何关系，直接用具体类型更清楚。

### 推断已经够用

调用处能推断出类型时，显式写 `<string>` 只是把类型写死，后续改实现要同步改调用。

### 运行时需要类型

泛型在编译后消失，`instanceof T`、`T.name` 都不存在。需要类型信息时改为传入构造器或校验函数。
