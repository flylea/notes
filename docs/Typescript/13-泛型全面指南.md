# 第13章 泛型全面指南

泛型（Generics）是 TypeScript 类型系统中最强大的特性之一。它让你能够编写**适用于多种类型而非特定类型的代码**——就像函数让值可以参数化一样，泛型让类型可以参数化。本章将全面讲解泛型的语法、使用场景和最佳实践。

## 泛型的核心概念

### 从具体的类型到参数化的类型

考虑一个简单的场景：一个函数接受某个值，返回同样的值。

```typescript
// 如果不使用泛型，只能为每种类型分别写一个函数
function identityNumber(x: number): number {
  return x;
}

function identityString(x: string): string {
  return x;
}

// 或者用 any——但会丢失类型信息
function identityAny(x: any): any {
  return x;
}
// const result = identityAny("hello");  // result 的类型是 any，丢失了 string 信息
```

泛型解决了这个问题——**类型变成了参数**：

```typescript
// Type 是类型参数，调用时被具体类型替换
function identity<Type>(x: Type): Type {
  return x;
}

// 使用时
const s = identity("hello");   // s: "hello"（字面量类型）
const n = identity(42);        // n: 42
const b = identity(true);      // b: true
```

调用 `identity("hello")` 时，TypeScript 会**自动推导** `Type` 为 `string`，返回值类型也随之确定为 `string`。你也可以显式指定类型参数：

```typescript
const s = identity<string>("hello");   // 显式指定
const n = identity<number>(42);
```

### 泛型的函数类比

如果你觉得泛型抽象，这个类比会有帮助：

| 概念 | 值层面的函数 | 类型层面的泛型 |
|------|------------|-------------|
| 参数 | `function f(x)` 中的 `x` | `function f<T>` 中的 `T` |
| 传参 | `f("hello")` | `f<string>("hello")` 或自动推导 |
| 作用 | 复用逻辑 | 复用类型关系 |

泛型参数就像**函数的参数**——函数参数让你在不同调用中传入不同的值，泛型参数让你在不同调用中使用不同的类型。

## 泛型函数

### 基本语法

```typescript
// 泛型函数声明
function firstElement<Type>(arr: Type[]): Type | undefined {
  return arr[0];
}

// 箭头函数泛型
const firstElement = <Type>(arr: Type[]): Type | undefined => arr[0];

// 函数表达式泛型
const firstElement2: <Type>(arr: Type[]) => Type | undefined = (arr) => arr[0];
```

TSX 中尖括号会与 JSX 标签冲突，此时可以加逗号消除歧义：

```typescript
// TSX 中的箭头函数泛型：加逗号 <T,> 或 extends 约束
const firstElement = <Type,>(arr: Type[]): Type | undefined => arr[0];
const firstElement2 = <Type extends unknown>(arr: Type[]): Type | undefined => arr[0];
```

### 泛型类型推导

TypeScript 在多数情况下可以自动推导泛型参数——不需要显式写尖括号：

```typescript
function map<T, U>(arr: T[], fn: (item: T) => U): U[] {
  return arr.map(fn);
}

// 不需要显式指定 <string, number>
const lengths = map(["hello", "world"], s => s.length);
// lengths: number[]

// TypeScript 推导过程：
// 1. arr 是 string[] → T = string
// 2. (s: string) => s.length 返回 number → U = number
// 3. 返回值 U[] = number[]
```

### 泛型约束（extends）

有时你希望泛型参数不是任意类型，而是满足特定条件的类型。这时候用 `extends` 添加约束：

```typescript
// 约束 Type 必须有 length 属性
function longest<Type extends { length: number }>(a: Type, b: Type): Type {
  return a.length >= b.length ? a : b;
}

longest([1, 2], [1, 2, 3]);       // ✅ 数组有 length
longest("hello", "world");         // ✅ 字符串有 length
// longest(1, 2);                  // ❌ number 没有 length
```

约束的作用是双重的：
1. **限制**：调用方只能传入满足约束的类型
2. **获得信息**：函数体内可以安全地访问约束中声明的成员

```typescript
// 使用 keyof 作为约束——这是 TypeScript 中最常见的约束模式
function getProperty<Type, Key extends keyof Type>(obj: Type, key: Key): Type[Key] {
  return obj[key];
}

const user = { name: "Alice", age: 25 };
getProperty(user, "name");  // ✅ 返回 string
getProperty(user, "age");   // ✅ 返回 number
// getProperty(user, "email");  // ❌ "email" 不是 user 的 key
```

### 在泛型约束中使用类型参数

可以让一个类型参数的约束依赖于另一个类型参数：

```typescript
// Key 约束为 Type 的属性名
function getProperty<Type, Key extends keyof Type>(obj: Type, key: Key) {
  return obj[key];
}
```

### 泛型默认值

泛型参数可以有默认值——就像函数参数的默认值：

```typescript
// 默认的 Error 类型是 Error
type Result<T, E = Error> =
  | { success: true; data: T }
  | { success: false; error: E };

// 不传第二个参数时默认为 Error
type DefaultResult = Result<string>;
// Result<string, Error>

// 需要自定义错误类型时再传
type CustomResult = Result<string, { code: number; message: string }>;
```

## 泛型接口

接口同样可以通过泛型参数来参数化成员类型：

```typescript
interface ApiResponse<T> {
  code: number;
  data: T;
  message: string;
}

// 使用
const userRes: ApiResponse<{ name: string; age: number }> = {
  code: 200,
  data: { name: "Alice", age: 25 },
  message: "ok",
};
```

泛型接口支持嵌套使用，可以构建出精确的类型层次：

```typescript
interface PaginatedResponse<T> {
  items: T[];
  total: number;
  page: number;
  pageSize: number;
}

// 分页的用户列表
type UsersPage = PaginatedResponse<{
  id: number;
  name: string;
}>;

// 更深层嵌套
interface ApiEnvelope<T> {
  code: number;
  data: PaginatedResponse<T>;
  timestamp: number;
}

type UsersEnvelope = ApiEnvelope<{ id: number; name: string }>;
// { code: number; data: { items: User[]; total: number; page: number; pageSize: number }; timestamp: number; }
```

## 泛型类

类的泛型参数让同一个类适用于不同类型的数据：

```typescript
class Stack<T> {
  private items: T[] = [];

  push(item: T): void {
    this.items.push(item);
  }

  pop(): T | undefined {
    return this.items.pop();
  }

  peek(): T | undefined {
    return this.items[this.items.length - 1];
  }
}

// 实例化时指定类型
const numStack = new Stack<number>();
numStack.push(1);
numStack.push(2);
const n = numStack.pop();  // number | undefined

const strStack = new Stack<string>();
strStack.push("hello");
```

静态成员**不能使用**类的泛型参数——因为静态成员属于类本身，而泛型参数只有在实例化后才确定：

```typescript
class Box<T> {
  // static default: T;  // ❌ 静态成员不能引用类型参数

  // 静态方法可以是泛型的，但那是独立的类型参数
  static create<U>(value: U): Box<U> {
    return new Box<U>();
  }
}
```

## 泛型类型别名

```typescript
// 基础泛型别名
type Nullable<T> = T | null;
type Pair<T, U> = [T, U];

// 带约束的泛型别名
type StringKeyed<T extends string> = Record<T, number>;

// 带默认值的泛型别名
type EventHandler<E = Event> = (event: E) => void;
```

## 多泛型参数与类型间的关系

多个泛型参数可以在类型声明中表达**参数之间的类型关系**——这是泛型最强大的用途：

```typescript
// 表达"输入是什么类型，输出也是什么类型"
function identity<T>(value: T): T {
  return value;
}

// 表达"函数将 T 类型数组映射为 U 类型数组"
function map<T, U>(arr: T[], fn: (item: T) => U): U[] {
  return arr.map(fn);
}

// 表达"回调的参数类型取决于 obj 的类型和 event 的类型"
function on<O extends object, E extends keyof O>(
  obj: O,
  event: E,
  callback: (data: O[E]) => void
): void {
  // ...
}

const user = {
  name: "Alice",
  age: 25,
  onUpdate: (data: { name: string; age: number }) => {},
};

on(user, "onUpdate", (data) => {
  // data 自动推导为 { name: string; age: number }
});
```

## React 中的泛型坑位

React 中最常见的泛型使用场景：

### useState

```typescript
// 从初始值推导
const [count, setCount] = useState(0);           // count: number
const [name, setName] = useState("");             // name: string

// 联合类型需要显式指定（TypeScript 推导可能不够精确）
const [status, setStatus] = useState<"idle" | "loading" | "success" | "error">("idle");

// null 初始值必须显式指定类型
const [user, setUser] = useState<User | null>(null);
```

### useRef

```typescript
// DOM 元素的 ref——初始值 null，需要指定元素类型
const inputRef = useRef<HTMLInputElement>(null);

// 可变值的 ref
const intervalRef = useRef<number | null>(null);

// 只读 ref（useRef 对有初始值的情况会自动 readonly）
const countRef = useRef(0);  // MutableRefObject<number>
```

### 事件处理

```typescript
// 输入事件的泛型
const handleChange = (e: React.ChangeEvent<HTMLInputElement>) => {
  console.log(e.target.value);
};

// 点击事件的泛型
const handleClick = (e: React.MouseEvent<HTMLButtonElement>) => {
  e.preventDefault();
};
```

## 泛型的最佳实践

### 1. 泛型参数应该出现两次或更多

如果一个类型参数只在声明中出现一次，它很可能不需要是泛型——直接用具体类型即可：

```typescript
// ❌ T 只出现了一次
function log<T>(value: T): void {
  console.log(value);
}
// 改为
function log(value: unknown): void {
  console.log(value);
}

// ✅ T 出现了两次（参数和返回值），泛型有意义
function identity<T>(value: T): T {
  return value;
}
```

### 2. 能用推导就不显式指定

TypeScript 的泛型推导通常很准确，显式指定反而增加了噪音：

```typescript
// ❌ 不必要的显式指定
const users = map<string, User>(names, nameToUser);

// ✅ 让 TS 推导
const users = map(names, nameToUser);
```

### 3. 约束尽量精确但不过分

```typescript
// ❌ 约束太宽——函数体里无法安全访问 members
function getLength<T>(obj: T): number {
  // return obj.length;  // ❌ T 不一定有 length
}

// ✅ 约束精确——既限制了调用方，又让函数体能安全使用
function getLength<T extends { length: number }>(obj: T): number {
  return obj.length;
}

// ✅ 或者用具体类型替代
function getLength(obj: { length: number }): number {
  return obj.length;
}
```

### 4. 泛型参数的命名

常见的命名约定：
- `T`、`U`、`V` — 通用类型参数
- `K` — 键类型（Key）
- `V` — 值类型（Value）
- `E` — 元素类型（Element）或错误类型（Error）
- `R` — 返回值类型（Return）

对于更复杂的场景，使用描述性的名称更清晰：
```typescript
// 描述性名称在复杂泛型中更清晰
type Result<TData, TError = Error> =
  | { success: true; data: TData }
  | { success: false; error: TError };
```

## 本章小结

- **泛型**将类型参数化，让代码适配多种类型而不丢失类型信息
- 泛型可用于**函数**、**接口**、**类**和**类型别名**
- `extends` 为泛型添加**约束**——限制类型范围，同时在函数体重获得成员访问能力
- 泛型的**默认值**和函数参数的默认值一样，简化常见场景的使用
- 多泛型参数的核心价值是表达**类型之间的关系**（输入-输出关联、对象属性-回调参数关联等）
- React 中 `useState`、`useRef`、事件处理是最常见的泛型使用场景
- 泛型参数不应只出现一次（那就没必要是泛型），能用推导就不显式指定

下一章将介绍 `keyof`、`typeof` 和索引访问类型——这三者是映射类型和条件类型的基础，也是泛型最常见约束（`K extends keyof T`）的核心。
