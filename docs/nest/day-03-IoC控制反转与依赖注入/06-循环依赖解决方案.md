# 循环依赖：原因、检测与解决

## 什么是循环依赖？

两个类互相依赖对方，形成闭环：

```typescript
// user.service.ts
@Injectable()
export class UserService {
  constructor(private bookService: BookService) {}  // 需要 BookService
}

// book.service.ts
@Injectable()
export class BookService {
  constructor(private userService: UserService) {}  // 需要 UserService
}
```

Nest 启动时会报错：

```
Error: A circular dependency has been detected.
Please make sure that each side of a bidirectional relationship uses "forwardRef()".
```

## 为什么会出现循环依赖？

常见的业务场景：
- UserService 需要 BookService（查某个用户的图书）
- BookService 需要 UserService（查某本书的所有者）

在业务层面，User 和 Book 确实互相关联。但在代码层面，它们不应该在构造器中互相依赖。

## 解决方案：forwardRef()

```typescript
// user.service.ts
@Injectable()
export class UserService {
  constructor(
    @Inject(forwardRef(() => BookService))
    private bookService: BookService,
  ) {}
}

// book.service.ts
@Injectable()
export class BookService {
  constructor(
    @Inject(forwardRef(() => UserService))
    private userService: UserService,
  ) {}
}
```

**注意：双方都要用 `forwardRef()`**，单方用不够。

## forwardRef() 的原理

`forwardRef(() => Xxx)` 返回一个**懒加载的引用**：不是直接引用 `Xxx` 类（在定义时可能还没初始化），而是用一个函数 `() => Xxx`，在被调用时才去取实际的类。

这解决了 JavaScript 模块加载的"时序问题"——当 UserService 的代码先执行时，BookService 的类定义可能还不存在（因为循环 import）。

## Module 级别的循环依赖

```typescript
// user.module.ts
@Module({
  imports: [forwardRef(() => BookModule)],  // 循环引用
  providers: [UserService],
  exports: [UserService],
})
export class UserModule {}

// book.module.ts
@Module({
  imports: [forwardRef(() => UserModule)],  // 循环引用
  providers: [BookService],
  exports: [BookService],
})
export class BookModule {}
```

和 Provider 级别的规则一样——双方都用 `forwardRef()`。

## 更好的方案：避免循环依赖

`forwardRef()` 是**应急方案**，不是最佳实践。更好的做法是从架构上避免循环：

### 方案 1：引入中间层

```typescript
// 新建 user-book.service.ts（双向查询都在这里）
@Injectable()
export class UserBookService {
  constructor(
    private userService: UserService,
    private bookService: BookService,
  ) {}

  getUserWithBooks(userId: number) {
    return this.userService.findById(userId).then(user => ({
      ...user,
      books: this.bookService.findByUserId(userId),
    }));
  }

  getBookWithOwner(bookId: number) {
    return this.bookService.findById(bookId).then(book => ({
      ...book,
      owner: this.userService.findById(book.userId),
    }));
  }
}
```

UserService 和 BookService 保持独立，UserBookService 负责"双向查询"——它依赖两者，但两者不互相依赖。

### 方案 2：减少 Service 层的互相调用

```typescript
// 直接在 Controller 中组合两个 Service（轻量场景）
@Controller('users')
export class UserController {
  constructor(
    private userService: UserService,
    private bookService: BookService,
  ) {}

  @Get(':id/books')
  async getUserBooks(@Param('id') id: string) {
    const user = await this.userService.findById(+id);
    const books = await this.bookService.findByUserId(+id);
    return { ...user, books };
  }
}
```

### 方案 3：使用事件驱动

```typescript
// 不要直接调用另一个 Service，而是发射事件
@Injectable()
export class BookService {
  constructor(private eventEmitter: EventEmitter2) {}

  async delete(bookId: number) {
    await this.prisma.book.delete({ where: { id: bookId } });
    // 发射事件而不是直接调用 UserService
    this.eventEmitter.emit('book.deleted', { bookId });
  }
}

// UserService 监听事件
@Injectable()
export class UserService {
  @OnEvent('book.deleted')
  async handleBookDeleted(payload: { bookId: number }) {
    // 清理关联数据
  }
}
```

事件驱动的优点是**完全解耦**——BookService 不知道 UserService 的存在。

## 判断循环依赖是否合理的快速检查

问自己一个问题：

> "如果拆分成两个独立的微服务，这个依赖关系还能成立吗？"

如果答案是"不能"，说明这个依赖是架构层面的问题，应该用上述方案重构。`forwardRef()` 只是语法上的妥协，不解决架构问题。
