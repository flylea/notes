# 前端视角的 IoC/DI：Vue/React 中的依赖注入

## Vue 的 provide/inject — 最接近 Nest DI 的前端模式

### Vue 3 中的依赖注入

```typescript
// 祖先组件（相当于 Nest Module）
// app.vue 或 layout.vue
<script setup>
import { provide } from 'vue';
import { UserService } from './services/user.service';

const userService = new UserService();
provide('userService', userService);   // "注册"到组件树
</script>

// 后代组件（相当于 Nest Controller）
// UserProfile.vue（任意层级嵌套）
<script setup>
import { inject } from 'vue';

const userService = inject('userService');  // "注入"依赖
// userService 自动可用，不需要 new
</script>
```

这和 Nest DI 的相似度高达 90%：

| 概念 | Vue 3 | NestJS |
|------|-------|--------|
| 注册依赖 | `provide('key', instance)` | `@Module({ providers: [Xxx] })` |
| 消费依赖 | `inject('key')` | `constructor(private xxx: Xxx)` |
| 作用域 | 组件树（祖先→后代） | 模块树（根模块→子模块） |
| 自动解析 | 向上遍历组件树找 provide | IoC 容器递归解析依赖图 |
| 单例 | 取决于 provide 的位置 | 默认单例 |

### 关键区别

Vue 的 provide/inject 有两个 Nest DI 没有的限制：
1. **字符串 Token**：`inject('userService')` 是字符串，没有类型安全
2. **只能在 setup 中调用**：不能在普通 class 构造器中使用

Nest 的 DI 解决了这两个问题：
```typescript
// Nest: class Token → 完全类型安全
constructor(private userService: UserService) {}
// userService 的类型是 UserService，IDE 有完整的自动补全
```

## React Context — 另一种依赖注入模式

```tsx
// 创建 Context（相当于注册）
const UserServiceContext = createContext<UserService>(null!);

// Provider（相当于 Nest Module 的 providers）
function App() {
  const userService = new UserService();
  return (
    <UserServiceContext.Provider value={userService}>
      <UserProfile />
    </UserServiceContext.Provider>
  );
}

// Consumer（相当于 Nest Controller 的构造器注入）
function UserProfile() {
  const userService = useContext(UserServiceContext);
  // ...
}
```

React Context 的问题和 Vue provide/inject 类似：
- 需要手动创建实例（`new UserService()`）
- Provider 嵌套地狱（10 个 Service = 10 层 Provider 嵌套）
- 没有内置的生命周期管理

## Angular DI — Nest 的直接灵感来源

如果你用过 Angular，Nest 的 DI 会让你感觉像回家：

```typescript
// Angular
@Injectable({ providedIn: 'root' })
export class UserService {
  constructor(private http: HttpClient) {}
}

// Nest — 几乎一模一样！
@Injectable()
export class UserService {
  constructor(private prisma: PrismaService) {}
}
```

Nest 的作者 Kamil Mysliwiec 公开说过 Nest 的装饰器语法和模块系统借鉴自 Angular（他是 Angular 开发者）。所以如果你用过 Angular，Nest 的学习曲线接近零。

## 前端状态管理 vs 后端 Service

| 前端 Store (Pinia/Vuex/Zustand) | 后端 Service |
|------|------|
| 管理 UI 状态（内存） | 管理业务逻辑（数据库+规则） |
| 生命周期 = 页面生命周期 | 生命周期 = 应用生命周期（单例） |
| 组件通过 `useStore()` 获取 | Controller 通过构造器获取 |
| 状态改变 → 自动重渲染 | 无重渲染概念 |
| Actions 修改状态 | Methods 执行业务逻辑 |
| 持久化用 localStorage | 持久化用数据库 |

关键心智模型转换：**前端的 Store 和 Nest 的 Service 都遵循"集中管理逻辑、按需消费"的依赖注入思想。** 区别只是 Store 管的是 UI 状态，Service 管的是数据和业务规则。
