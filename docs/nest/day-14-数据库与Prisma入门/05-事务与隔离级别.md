# 事务与隔离级别

## 事务的概念

**事务 (Transaction)** 是一组操作，要么全部成功，要么全部失败（ACID）。

```
借书操作 = {
  1. 在 borrow_records 中插入一条记录
  2. 将 books.status 改为 'borrowed'
}

// 这两步必须同时成功或同时失败
// 如果第 2 步失败，第 1 步必须回滚——否则书记录已经被借出但状态还是 available
```

## SQL 事务语法

```sql
-- MySQL 和 PostgreSQL 通用
START TRANSACTION;

  INSERT INTO borrow_records (user_id, book_id) VALUES (1, 5);
  UPDATE books SET status = 'borrowed' WHERE id = 5;

COMMIT;  -- 全部成功 → 提交
-- 或 ROLLBACK; → 全部撤销

-- PostgreSQL 也支持
BEGIN;
  ...
COMMIT;
```

## ACID 特性

| 特性 | 含义 | 反例 |
|------|------|------|
| **A**tomicity (原子性) | 全部成功或全部失败 | 借书记录插入成功但状态没更新 |
| **C**onsistency (一致性) | 数据满足所有约束 | 余额为负数、外键指向不存在的记录 |
| **I**solation (隔离性) | 并发事务互不干扰 | 两人同时借最后一本书 |
| **D**urability (持久性) | 提交后数据永久保存 | 服务器断电丢失已确认的订单 |

## 隔离级别与并发问题

```
没有隔离 → 脏读 (Dirty Read)
  ├── 读到别人未提交的更改 → 可能读到 Rollback 的数据

READ COMMITTED → 不可重复读 (Non-repeatable Read)
  ├── 事务内两次 SELECT 同一个数据，结果不同（被别的事务 UPDATE 了）

REPEATABLE READ → 幻读 (Phantom Read)
  ├── 事务内两次 SELECT COUNT 结果不同（被别的事务 INSERT 了）

SERIALIZABLE → 无并发问题（代价：性能最差）
```

## MySQL vs PostgreSQL 默认隔离级别

| | MySQL | PostgreSQL |
|---|---|---|
| 默认级别 | `REPEATABLE READ` | `READ COMMITTED` |
| 查看 | `SELECT @@transaction_isolation;` | `SHOW transaction_isolation;` |
| 修改 | `SET SESSION TRANSACTION ISOLATION LEVEL ...` | 同左 |

## Prisma 中的事务

```typescript
// 交互式事务
await this.prisma.$transaction(async (tx) => {
  const record = await tx.borrowRecord.create({
    data: { userId: 1, bookId: 5 },
  });
  await tx.book.update({
    where: { id: 5 },
    data: { status: 'borrowed' },
  });
  return record;
});
// 任何一步失败 → 自动回滚

// 批量事务
await this.prisma.$transaction([
  this.prisma.borrowRecord.create({ data: { ... } }),
  this.prisma.book.update({ where: { id: 5 }, data: { status: 'borrowed' } }),
]);
```
