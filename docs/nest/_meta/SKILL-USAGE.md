# documentation-writer 怎么用在这套笔记里

安装位置：`~/.agents/skills/documentation-writer/SKILL.md`。来源是 [github/awesome-copilot 的 documentation-writer](https://www.skills.sh/github/awesome-copilot/documentation-writer)。它按 Diátaxis 把一篇文档只标成四种里的一种：Tutorial（跟着做成一件事）、How-to（解决一个具体问题）、Reference（查表）、Explanation（讲为什么）。

在这套笔记里，类型只决定步骤怎么排，不决定能不能讲基础。说人话压过它原文里的英文文档腔。用户已经批准按 `STYLE-GUIDE.md` 重写，不要每章再停下来等大纲批准。

写一章之前先定三件事：

1. 读者是谁。默认是没写过后端的人。第 1–2 章还要照顾几乎没写过代码的人。
2. 读完能做成什么。一句人话，写进正文，不要写成「本章目标」。
3. 这一章是四种里的哪一种。跟着做就一步只加一个新东西；解决问题也要先用 2–5 段白话讲清新概念，再给步骤；查表就在表前或表里把每个新词说成人话，并留一个最小例子；讲为什么也要有一个能看懂的最小例子。

每个新概念用三句，然后再给术语：它是什么（一句生活类比）、没有它会卡在哪、和最容易混的那个差在哪。后面再遇到，用一句话复述，并写明第几章第一次讲过。不能只丢一个链接。

交稿前自问：没接触过后端的人，这一段要不要查资料。要，就改到不用查。
