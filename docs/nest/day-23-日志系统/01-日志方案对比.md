# Node.js 日志方案对比

## console.log 的问题

```typescript
// Day 1-22 我们在用 console.log
console.log('用户登录:', username);
console.error('数据库连接失败:', error);

// 问题：
// 1. 无法分级——开发和生产的日志混在一起
// 2. 无法持久化——进程重启，日志消失
// 3. 无法搜索——需要在一大堆输出中 grep
// 4. 无法按日归档——日志文件无限膨胀
// 5. 不能结构化——纯文本难以用工具分析
// 6. 性能差——console.log 是同步的
```

## 主流方案对比

| 特性 | console | debug | Winston | Pino | Bunyan |
|------|:---:|:---:|:---:|:---:|:---:|
| 日志分级 | ❌ | ✅ | ✅ | ✅ | ✅ |
| 多 Transport | ❌ | ❌ | ✅ | ✅ | ✅ |
| 文件轮转 | ❌ | ❌ | ✅ 插件 | ✅ 插件 | ✅ 内置 |
| JSON 格式 | 手动 | ❌ | ✅ | ✅ | ✅ |
| 异步写入 | ❌ | ❌ | ✅ | ✅ 核心 | ✅ |
| 性能（ops/s） | 低 | 低 | 中 | **最高** | 中 |
| Nest 集成 | ❌ | ❌ | ✅ nest-winston | ⚠️ 手动 | ❌ |
| 学习曲线 | 极低 | 低 | 中 | 中 | 中 |

## 为什么选 Winston

1. **nest-winston** 官方集成，替换 Nest Logger 只需几行配置
2. **Transport 生态丰富**：Console / File / HTTP / MongoDB / Elasticsearch
3. **社区成熟**：Stars 最多，公司招聘 JD 中出现频率高
4. **文档完善**：中文资料多，前端转后端学习成本低

> Pino 性能最高，如果项目对性能极其敏感（高 QPS 日志量级），可以考虑 Pino。但 Nest 集成需要手动适配。

## 前端类比

```
console.log  = 在组件里直接 console.log
  开发时能用，生产环境看不到、没法查

Winston      = 类似前端的 Sentry / 日志上报服务
  自动收集、分级、持久化、可搜索、有 Dashboard
```
