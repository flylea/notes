# 前端表单校验类比

## 思维导图：前端表单校验 → 后端 DTO 校验

```
┌─────────────────────────────────────────────────────────────────┐
│                    前端（Vue/React）                              │
├─────────────────────────────────────────────────────────────────┤
│  表单组件 <template>                                             │
│    <input v-model="form.username" />                            │
│    <span v-if="errors.username">{{ errors.username }}</span>   │
│                                                                 │
│  校验规则（声明式）                                                │
│    rules: {                                                     │
│      username: [{ required: true, message: '不能为空' }],        │
│      password: [{ min: 6, message: '最少 6 位' }],               │
│    }                                                            │
│                                                                 │
│  提交时触发校验                                                    │
│    formRef.validate().then(() => { api.post('/register') })      │
└─────────────────────────────────────────────────────────────────┘
                              │
                              │ 对应关系
                              ▼
┌─────────────────────────────────────────────────────────────────┐
│                    后端（NestJS）                                 │
├─────────────────────────────────────────────────────────────────┤
│  DTO Class                                                      │
│    class RegisterUserDto {                                      │
│      @IsNotEmpty({ message: '不能为空' })                        │
│      username: string;                                          │
│                                                                 │
│      @MinLength(6, { message: '最少 6 位' })                     │
│      password: string;                                          │
│    }                                                            │
│                                                                 │
│  全局 Pipe 自动执行校验                                           │
│    app.useGlobalPipes(new ValidationPipe());                    │
│                                                                 │
│  校验失败自动返回 400                                              │
│    无需手动调用 validate()                                       │
└─────────────────────────────────────────────────────────────────┘
```

## 各前端方案对比

### Vue + VeeValidate

```vue
<template>
  <Form @submit="onSubmit">
    <Field name="username" rules="required|min:2|max:20" />
    <ErrorMessage name="username" />

    <Field name="password" rules="required|min:6" />
    <ErrorMessage name="password" />

    <button type="submit">注册</button>
  </Form>
</template>
```

对应 Nest 后端的 DTO：

```typescript
export class RegisterUserDto {
  @IsNotEmpty({ message: '用户名不能为空' })
  @Length(2, 20, { message: '用户名 2-20 位' })
  username: string;

  @IsNotEmpty({ message: '密码不能为空' })
  @MinLength(6, { message: '密码最少 6 位' })
  password: string;
}
```

**惊人的相似**：前后端都是声明式校验（`required` ↔ `@IsNotEmpty()`，`min:6` ↔ `@MinLength(6)`）。

### React + Zod

```typescript
import { z } from 'zod';

const registerSchema = z.object({
  username: z.string().min(2, '用户名 2-20 位').max(20),
  password: z.string().min(6, '密码最少 6 位'),
});

type RegisterUserDto = z.infer<typeof registerSchema>;
// Zod 的 schema 和 TypeScript 类型是同一份——这更接近 Nest 中 class-validator + TypeScript class 的思路
```

### React + React Hook Form

```typescript
import { useForm } from 'react-hook-form';
import { zodResolver } from '@hookform/resolvers/zod';

const { register, handleSubmit, formState: { errors } } = useForm({
  resolver: zodResolver(registerSchema),
});

// errors.username?.message  ← 和 Nest 的 ValidationPipe 返回的 message 结构类似
```

## 校验为何前后端都要做？

| | 前端校验 | 后端校验 |
|---|---|---|
| 目的 | 提升用户体验（即时反馈） | 保证数据安全（最后防线） |
| 可被绕过 | ✅（curl/Postman/禁用 JS） | ❌（无法绕过） |
| 性能 | 不消耗服务器资源 | 消耗服务器资源（但必须） |

**黄金法则**：前端校验是 UX 优化，后端校验是安全基石。永远不要依赖前端校验。

## 前后端 DTO 同步的最佳实践

### 方案 1：手动维护（小项目 OK）

前端和后端各写一份类型定义，保持一致性靠"人肉同步"。

### 方案 2：OpenAPI 自动生成（推荐）

Day 24 会学 Swagger——后端通过 `@nestjs/swagger` 为 DTO 生成 OpenAPI 规范，然后前端用 `openapi-typescript-codegen` 自动生成 TypeScript 类型：

```
后端 DTO (class-validator) → Swagger/OpenAPI → 前端 TS 类型
      ↑ 唯一真相来源（single source of truth）
```

### 方案 3：共享 DTO（Monorepo）

```
monorepo/
├── libs/shared-dtos/        ← 公共 DTO 包
│   └── src/
│       └── register-user.dto.ts
├── apps/backend/            ← Nest 后端
└── apps/frontend/           ← Vue/React 前端
```

前后端从同一个 libs 导入 DTO——类型永远不会不一致。Day 29 会学 Monorepo。

## 校验失败时的前后端协作

```
前端：
  POST /user/register
  Body: { "username": "jo", "password": "12" }

后端：
  ValidationPipe 校验失败
  → 400 Bad Request
  → { "message": ["用户名 2-20 位", "密码最少 6 位"] }

前端：
  axios.interceptors.response.use(
    undefined,
    (error) => {
      if (error.response?.status === 400) {
        const messages = error.response.data.message;
        // 将后端错误绑定到表单字段
        form.setErrors({
          username: messages.find(m => m.includes('用户名')),
          password: messages.find(m => m.includes('密码')),
        });
      }
      return Promise.reject(error);
    }
  );
```

> 前端的输入就是后端的输出。理解两端的校验机制，你就是一个真正的全栈工程师了。
