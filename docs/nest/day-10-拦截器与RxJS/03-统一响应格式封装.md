# 统一响应格式封装

## 为什么需要统一格式

不同的后端接口返回不同的格式是前端的地狱：

```json
// 用户模块
{ "username": "john" }

// 图书模块
{ "books": [...], "total": 100 }

// 错误时
{ "statusCode": 400, "message": "用户名不能为空", "error": "Bad Request" }

// 三种完全不同的格式，前端要写三种解析逻辑
```

统一格式后：

```json
// 所有成功响应
{ "code": 0, "data": { "username": "john" }, "message": "ok" }
{ "code": 0, "data": { "list": [...], "total": 100 }, "message": "ok" }

// 所有错误响应
{ "code": 400, "data": null, "message": "用户名不能为空" }
```

前端的拦截器只需要一套解析逻辑：

```typescript
axios.interceptors.response.use(response => {
  if (response.data.code !== 0) {
    ElMessage.error(response.data.message);
    return Promise.reject(response.data);
  }
  return response.data.data;  // 只在 code === 0 时返回真正的数据
});
```

## 企业标准的响应格式

```typescript
// 统一响应接口
export interface ApiResponse<T = any> {
  code: number;       // 0 = 成功，其他 = 错误码
  data: T;            // 业务数据
  message: string;    // 提示消息
  timestamp?: string; // 响应时间戳
}

// 分页响应
export interface PaginatedResponse<T = any> {
  code: number;
  data: {
    list: T[];
    total: number;
    page: number;
    size: number;
  };
  message: string;
}
```

## TransformInterceptor 完整实现

```typescript
import {
  Injectable,
  NestInterceptor,
  ExecutionContext,
  CallHandler,
} from '@nestjs/common';
import { Observable } from 'rxjs';
import { map } from 'rxjs/operators';

export interface ApiResponse<T> {
  code: number;
  data: T;
  message: string;
  timestamp: string;
}

@Injectable()
export class TransformInterceptor<T>
  implements NestInterceptor<T, ApiResponse<T>>
{
  intercept(
    context: ExecutionContext,
    next: CallHandler,
  ): Observable<ApiResponse<T>> {
    return next.handle().pipe(
      map(data => ({
        code: 0,
        data: data ?? null,
        message: 'ok',
        timestamp: new Date().toISOString(),
      })),
    );
  }
}
```

### 配合 ExceptionFilter 使用

Interceptor 只处理正常返回的情况，ExceptionFilter 处理异常情况：

```typescript
// Interceptor:
// Controller 正常 return → map() → { code: 0, data, message: 'ok' }

// ExceptionFilter:
// Controller 抛出异常 → catch() → { code: httpStatus, data: null, message: '错误信息' }
```

两者配合才能实现**全接口的统一格式**。

## 防止重复包装

如果 Controller 返回的数据已经被包装过：

```typescript
intercept(context: ExecutionContext, next: CallHandler): Observable<any> {
  return next.handle().pipe(
    map(data => {
      // 如果 Controller 返回了异常格式（不应该，但防止这种情况）
      // 或者数据已经包含了 code 字段
      if (data && typeof data === 'object' && 'code' in data) {
        return data;  // 不再包装
      }
      return { code: 0, data, message: 'ok', timestamp: new Date().toISOString() };
    }),
  );
}
```

## 文件下载不包装

文件下载接口不能包装——前端期望收到文件的二进制流，不是 JSON：

```typescript
@Controller('file')
export class FileController {
  @Get('download/:filename')
  @NoTransform()  // 自定义装饰器：跳过 TransformInterceptor
  download(@Param('filename') filename: string, @Res() res: Response) {
    const file = createReadStream(join('./uploads', filename));
    res.setHeader('Content-Disposition', `attachment; filename="${filename}"`);
    file.pipe(res);
  }
}
```

没有 `@NoTransform()`，Interceptor 会把文件流包装成 `{ code: 0, data: <ReadStream>, message: 'ok' }`——完全错误。

## 全局注册

```typescript
// main.ts
app.useGlobalInterceptors(new TransformInterceptor());
```

或者用 `APP_INTERCEPTOR` token（如果需要注入依赖）：

```typescript
@Module({
  providers: [
    { provide: APP_INTERCEPTOR, useClass: TransformInterceptor },
  ],
})
export class AppModule {}
```

> 全局注册后，所有接口的返回值都被统一包装——前端团队会感谢你的。
