# 参数装饰器全解

## 全部参数装饰器速查

| 装饰器 | 提取来源 | 示例 | 适用场景 |
|--------|---------|------|---------|
| `@Param('id')` | URL 路径参数 | `/users/123` | 资源定位 |
| `@Query('page')` | Query String | `/users?page=1` | 分页/过滤/搜索 |
| `@Body()` | JSON Body | `{ "username": "john" }` | POST/PUT 请求数据 |
| `@Headers('authorization')` | HTTP 请求头 | `Authorization: Bearer xxx` | Token 提取 |
| `@Session()` | Session（需 express-session） | `req.session` | 会话数据 |
| `@Ip()` | 客户端 IP | `::1` / `192.168.1.1` | 日志/限流 |
| `@HostParam('account')` | 域名参数 | `account.example.com` | 多租户 |
| `@Req()` | 底层 Express Request 对象 | — | 需要原生对象时 |
| `@Res()` | 底层 Express Response 对象 | — | 需要原生对象时 |

## @Param — URL 路径参数

```typescript
@Get(':id')
findOne(@Param('id') id: string) {
  return this.userService.findById(+id);
}

// 获取所有参数（不指定 key）
@Get(':userId/books/:bookId')
getBook(
  @Param() params: Record<string, string>,
) {
  // params = { userId: '1', bookId: '5' }
}
```

## @Query — 查询字符串

```typescript
@Get()
findAll(
  @Query('page') page?: string,
  @Query('size') size?: string,
) {}

// 获取所有查询参数
@Get()
findAll(@Query() query: Record<string, any>) {
  // query = { page: '1', size: '10', keyword: 'nest' }
}

// 用 DTO 接收
@Get()
findAll(@Query() dto: PaginationDto) {
  // dto 经过了 ValidationPipe 的校验和类型转换
}
```

## @Body — 请求体

```typescript
@Post()
create(@Body() dto: CreateUserDto) {
  return this.userService.create(dto);
}

// 提取单个字段
@Post()
create(@Body('username') username: string) {
  // 只获取 Body 中的 username 字段
}
```

## @Headers — 请求头

```typescript
@Get()
getInfo(
  @Headers('authorization') token: string,
  @Headers('user-agent') userAgent: string,
) {
  // 提取特定请求头
}

@Get()
getAllHeaders(@Headers() headers: Record<string, string>) {
  // 获取所有请求头
}
```

## @Res 的正确用法

```typescript
// ❌ 错误用法：手动 res.json() 后不再走 Nest 的响应管道
@Get()
findAll(@Res() res: Response) {
  res.json({ data: [] });  // Interceptor、ExceptionFilter 不再生效
}

// ✅ 正确用法：passthrough = true
@Get()
findAll(@Res({ passthrough: true }) res: Response) {
  res.setHeader('X-Custom', 'value');  // 只操作响应头
  return { data: [] };  // 仍然走 Nest 的响应序列化
}
```

> `@Res({ passthrough: true })` 让你可以设置 Cookie、响应头等只能通过原生 Response 对象的操作，但不破坏 Nest 的响应流程。
