# 路由声明与匹配

## 全部 HTTP 方法装饰器

```typescript
@Controller('users')
export class UserController {
  @Get()          // GET    /users
  @Post()         // POST   /users
  @Put()          // PUT    /users
  @Delete()       // DELETE /users
  @Patch()        // PATCH  /users
  @Options()      // OPTIONS /users
  @Head()         // HEAD   /users
  @All()          // 匹配所有 HTTP 方法
}
```

## 路由路径

```typescript
@Controller('users')    // 路由前缀
export class UserController {
  @Get()                 // GET /users
  findAll() {}

  @Get(':id')            // GET /users/123
  findOne(@Param('id') id: string) {}

  @Get(':id/profile')    // GET /users/123/profile
  getProfile(@Param('id') id: string) {}

  @Get('search')         // GET /users/search
  search() {}
}
```

## 路由通配符

```typescript
@Get('ab*cd')    // 匹配 /users/abcd, /users/abXcd, /users/abANYTHINGcd
@Get('*')        // 匹配 /users/ 下的任何路径（兜底路由）
```

> 通配符 `*` 匹配任意字符序列（不含 `/`）。跨路径段的通配用 `**`。

## 路由匹配顺序 — 重要！

Nest 按**先定义先匹配**的顺序处理路由。以下写法有陷阱：

```typescript
@Controller('users')
export class UserController {
  @Get(':id')            // ← 这个在前
  findOne() {}

  @Get('search')         // ← 这个在后
  search() {}
}
```

访问 `GET /users/search` 时，Nest 会匹配到 `@Get(':id')`（因为 `search` 是合法的 `:id` 值），而不是 `@Get('search')`。

**修复**：具体路由放在参数路由前面

```typescript
@Controller('users')
export class UserController {
  @Get('search')         // ← 具体路由放前面
  search() {}

  @Get(':id')            // ← 参数路由放后面
  findOne() {}
}
```

> 这个陷阱前端路由（Vue Router / React Router）也一样存在。解决方式也一样——具体路径放动态路径前面。

## 路由前缀的层级

```typescript
// app.module.ts 中定义全局前缀
const app = await NestFactory.create(AppModule);
app.setGlobalPrefix('api');  // 所有路由前加 /api

// Controller 定义业务前缀
@Controller('users')
// → 实际路由: GET /api/users

// 方法定义子路径
@Get('profile')
// → 实际路由: GET /api/users/profile
```

生产环境推荐用 `setGlobalPrefix('api')`，方便前端区分 API 请求和静态资源请求，也方便 Nginx 做反向代理。
