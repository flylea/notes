# 动态模块：register / forRoot / forFeature

## 为什么需要动态模块

静态模块只能做一件事：

```typescript
@Module({
  providers: [UserService],
  exports: [UserService],
})
export class UserModule {}
// UserService 的行为是固定的，没有配置空间
```

但如果 UserService 需要配置参数（如数据库路径、API 密钥），怎么办？

## 动态模块的基本结构

```typescript
@Module({})
export class DbModule {
  static register(options: DbModuleOptions): DynamicModule {
    return {
      module: DbModule,  // 模块类本身
      providers: [
        {
          provide: 'OPTIONS',  // 将配置注册为 Provider
          useValue: options,
        },
        DbService,  // DbService 可以通过 @Inject('OPTIONS') 获取配置
      ],
      exports: [DbService],
    };
  }
}

// 使用时
@Module({
  imports: [
    DbModule.register({ path: 'users.json' }),  // UserModule 用 users.json
  ],
})
export class UserModule {}

@Module({
  imports: [
    DbModule.register({ path: 'books.json' }),  // BookModule 用 books.json
  ],
})
export class BookModule {}
```

## 三种命名约定的含义

Nest 生态中，你频繁看到三种静态方法名：

### register() — 每次调用创建独立配置

```typescript
// 每个调用方传入自己的配置
DbModule.register({ path: 'users.json' });
DbModule.register({ path: 'books.json' });
// 创建了两个独立的 DbModule 实例，各自有各自的 DbService（不同文件路径）
```

适用场景：**不同模块需要不同配置**

### forRoot() — 全局只配置一次

```typescript
ConfigModule.forRoot({ isGlobal: true, envFilePath: '.env' });
JwtModule.forRoot({ secret: 'mysecret', signOptions: { expiresIn: '7d' } });
```

`forRoot()` 是约定："这个配置是应用级别的，全局只做一次"。通常配合 `@Global()` 使用。

适用场景：**全局配置（数据库连接、JWT 密钥、环境变量）**

### forFeature() — 基于 forRoot 的子配置

```typescript
// TypeORM 的典型模式（Prisma 不需要这个，因为 Prisma Schema 集中管理所有 model）
TypeOrmModule.forRoot({ /* 数据库连接 */ });
TypeOrmModule.forFeature([User, Book, BorrowRecord]);  // 注册实体
```

适用场景：**需要主配置 + 子配置的场景**

## ConfigurableModuleBuilder — Nest v9+ 简化的动态模块

```typescript
// 定义配置接口
interface DbModuleOptions {
  path: string;
}

// 用 ConfigurableModuleBuilder 创建动态模块
@Module({})
export class DbModule extends ConfigurableModuleBuilder
  .newConsumer<DbModuleOptions>()
  .setClassMethodName('register')  // 方法名
  .build() {}
```

这行代码自动生成了 `register()` 和 `registerAsync()` 方法，省去手写动态模块的样板代码。

> 推荐 Nest v9+ 项目用 `ConfigurableModuleBuilder` 替代手写动态模块。

## 手写 vs ConfigurableModuleBuilder 对比

### 手写（旧方案）

```typescript
@Module({})
export class DbModule {
  static register(options: DbModuleOptions): DynamicModule {
    return {
      module: DbModule,
      providers: [
        { provide: 'OPTIONS', useValue: options },
        DbService,
      ],
      exports: [DbService],
    };
  }
}
```

### ConfigurableModuleBuilder（新方案）

```typescript
export const { ConfigurableModuleClass, MODULE_OPTIONS_TOKEN } =
  new ConfigurableModuleBuilder<DbModuleOptions>()
    .setClassMethodName('register')
    .build();

@Module({
  providers: [DbService],
  exports: [DbService],
})
export class DbModule extends ConfigurableModuleClass {}
```

在 DbService 中获取配置：

```typescript
@Injectable()
export class DbService {
  constructor(
    @Inject(MODULE_OPTIONS_TOKEN) private options: DbModuleOptions,
  ) {}
}
```
