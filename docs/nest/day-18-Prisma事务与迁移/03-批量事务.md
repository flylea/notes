# 批量事务

## 什么是批量事务

批量事务将**一组独立的 Prisma 操作**打包成一个数组，一次性发送到数据库执行。

```typescript
// 语法
await prisma.$transaction([
  prisma.user.create({ data: { username: 'alice' } }),
  prisma.book.update({ where: { id: 1 }, data: { status: 'BORROWED' } }),
  prisma.borrowRecord.create({ data: { userId: 1, bookId: 1 } }),
]);
```

## 前端类比

```
交互式事务 = 写一段逻辑代码
  类似 Vue methods 里的方法，有判断、循环、条件逻辑

批量事务 = 传一个操作数组
  类似 Promise.all([...])——一次性提交，不关心中间结果
```

## 完整示例

```typescript
import { Injectable } from '@nestjs/common';
import { PrismaService } from '../prisma/prisma.service';

@Injectable()
export class CategoryService {
  constructor(private prisma: PrismaService) {}

  // 初始化图书分类——批量插入
  async initDefaultCategories() {
    const categories = [
      '计算机科学',
      '文学小说',
      '历史哲学',
      '科学技术',
      '经济管理',
      '语言学习',
    ];

    const operations = categories.map(name =>
      this.prisma.category.create({ data: { name } }),
    );

    // 一次性提交所有操作
    const results = await this.prisma.$transaction(operations);

    return { count: results.length, categories: results };
  }

  // 批量创建图书 + 关联分类
  async batchCreateBooks(books: Array<{ title: string; author: string; categoryName: string }>) {
    const operations = books.map(book =>
      this.prisma.book.create({
        data: {
          title: book.title,
          author: book.author,
          categories: {
            connect: { name: book.categoryName },
          },
        },
      }),
    );

    return this.prisma.$transaction(operations);
  }
}
```

## 核心机制

```
$transaction([op1, op2, op3])
    │
    ▼
┌─────────────────────────────────────┐
│  Prisma 将数组中的操作               │
│  按顺序转换为 SQL                    │
│  放入一个事务中执行                   │
│                                     │
│  BEGIN;                             │
│    INSERT INTO users ...            │
│    UPDATE books SET ...             │
│    INSERT INTO borrow_records ...   │
│  COMMIT;                            │
└─────────────────────────────────────┘
```

## 批量 vs 交互式 选择决策

```typescript
// 场景 1：独立操作——用批量事务
async deleteUserWithRecords(userId: number) {
  // 这三个操作互不依赖，可以批量执行
  return this.prisma.$transaction([
    this.prisma.borrowRecord.deleteMany({ where: { userId } }),
    this.prisma.review.deleteMany({ where: { authorId: userId } }),
    this.prisma.user.delete({ where: { id: userId } }),
  ]);
}

// 场景 2：操作依赖前一步结果——必须用交互式事务
async sophisticatedBorrow(userId: number, bookId: number) {
  return this.prisma.$transaction(async (tx) => {
    // 必须先查询状态，再决定是否创建
    const book = await tx.book.findUnique({ where: { id: bookId } });
    if (!book || book.status === 'BORROWED') {
      throw new BadRequestException('无法借阅');
    }
    return tx.borrowRecord.create({ data: { userId, bookId } });
  });
}
```

## 批量事务的查询限制

```typescript
// ✅ 可以：批量事务中返回数据
const [user, book] = await this.prisma.$transaction([
  this.prisma.user.findUnique({ where: { id: 1 } }),
  this.prisma.book.findUnique({ where: { id: 2 } }),
]);

// ❌ 不可以：操作之间无法引用彼此的返回值
await this.prisma.$transaction([
  this.prisma.user.create({ data: { ... } }),
  // 第二个操作无法拿到第一个操作返回的 user.id
  this.prisma.profile.create({ data: { userId: ??? } }),
]);
```

如果需要前一步的返回值，使用交互式事务：

```typescript
await this.prisma.$transaction(async (tx) => {
  const user = await tx.user.create({ data: { ... } });
  // 可以拿到 user.id ✅
  await tx.profile.create({ data: { userId: user.id } });
});
```

## 批量事务的异常处理

```typescript
async safeBatchDelete(bookIds: number[]) {
  try {
    const operations = bookIds.map(id =>
      this.prisma.book.delete({ where: { id } }),
    );

    const results = await this.prisma.$transaction(operations);
    return { deleted: results.length };

  } catch (error) {
    // 任何一个操作失败 → 全部回滚
    if (error instanceof Prisma.PrismaClientKnownRequestError) {
      if (error.code === 'P2025') {
        throw new BadRequestException('部分图书不存在，操作已回滚');
      }
    }
    throw error;
  }
}
```

## 性能对比

| 方式 | 交互式事务 | 批量事务 |
|------|----------|---------|
| 网络往返 | N 次（每个操作） | 1 次（全部打包） |
| 条件逻辑 | ✅ | ❌ |
| 查询返回值 | ✅ | ✅（但不能跨操作引用） |
| 适用场景 | 复杂业务流程 | 独立操作批量执行 |
| 并行能力 | 串行执行 | 串行执行 |

> ⚠️ 注意：批量事务虽然一次发送，但操作在数据库中**依然是顺序执行**的。如果需要真正的并行，用 `Promise.all`，但那不在同一事务中。

## 实战：初始化种子数据

```typescript
// seed.ts
import { PrismaClient } from '@prisma/client';

const prisma = new PrismaClient();

async function main() {
  // 清理旧数据 + 插入新数据作为一个事务
  await prisma.$transaction([
    prisma.borrowRecord.deleteMany(),
    prisma.book.deleteMany(),
    prisma.category.deleteMany(),
    prisma.user.deleteMany(),
  ]);

  // 然后按依赖顺序插入
  const admin = await prisma.user.create({
    data: { username: 'admin', password: 'hashed_admin', role: 'ADMIN' },
  });

  const category = await prisma.category.create({
    data: { name: '计算机科学' },
  });

  await prisma.$transaction([
    prisma.book.create({
      data: {
        title: 'NestJS 实战',
        author: '张三',
        categories: { connect: { id: category.id } },
      },
    }),
    prisma.book.create({
      data: {
        title: 'Prisma 权威指南',
        author: '李四',
        categories: { connect: { id: category.id } },
      },
    }),
  ]);
}

main()
  .catch(console.error)
  .finally(() => prisma.$disconnect());
```

## 常见陷阱

```typescript
// ❌ 陷阱 1：批量事务中混用 $executeRaw 和 $queryRaw
// 原生 SQL 需要放在 $transaction 数组内，但返回类型不兼容

// ❌ 陷阱 2：批量事务包含有副作用的查询
await this.prisma.$transaction([
  this.prisma.book.findMany(),           // 纯查询——没必要放事务里
  this.prisma.borrowRecord.create(...),  // 写入——有必要
]);

// ✅ 正确：批量事务只放写入操作
const books = await this.prisma.book.findMany(); // 查询放在事务外
await this.prisma.$transaction([
  this.prisma.user.update(...),
  this.prisma.borrowRecord.create(...),
]);
```
