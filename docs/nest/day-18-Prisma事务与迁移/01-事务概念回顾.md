# 事务概念回顾

## 为什么需要事务

借书是个多步骤操作：

```typescript
// 没有事务——危险！
async borrowBook(userId: number, bookId: number) {
  // 步骤 1：创建借阅记录
  await this.prisma.borrowRecord.create({
    data: { userId, bookId },
  });

  // ⚠️ 如果这一步失败了（比如网络问题），步骤 1 已经提交了
  // 结果：借阅记录存在，但书的状态还是 'available' → 数据不一致！

  // 步骤 2：更新图书状态
  await this.prisma.book.update({
    where: { id: bookId },
    data: { status: 'borrowed' },
  });
}
```

## 事务保证 ACID

```
@Transactional()
借书操作 = {
  1. INSERT INTO borrow_records ...
  2. UPDATE books SET status = 'borrowed' ...
}

结果：要么 1 和 2 都成功 → COMMIT
     要么任何一个失败 → ROLLBACK → 全部撤销
```

## Prisma 两种事务方式

| | 交互式事务 | 批量事务 |
|---|---|---|
| 写法 | `$transaction(async (tx) => {})` | `$transaction([op1, op2])` |
| 支持条件逻辑 | ✅ | ❌ |
| 支持查询返回值 | ✅ | ❌ |
| 性能 | 稍慢（多次网络往返） | 快（一次发送） |
| 适用场景 | 复杂的、有条件的业务操作 | 简单的"全执行"场景 |
