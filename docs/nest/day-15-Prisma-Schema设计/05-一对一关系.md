# 一对一关系

## 基本结构

```prisma
model User {
  id      BigInt       @id @default(autoincrement())
  profile UserProfile? // 可选一对一
}

model UserProfile {
  id     BigInt @id @default(autoincrement())
  bio    String?
  avatar String?
  user   User   @relation(fields: [userId], references: [id])
  userId BigInt @unique  // ← @unique 保证一对一
}
```

## 关键：外键 @unique

没有 `@unique`，就是普通的一对多——一个 User 可以有多个 UserProfile。加了 `@unique`，数据库保证外键值不重复，从而实现了**数据库层面**的一对一。

## 可选 vs 必选

```prisma
// 可选一对一：User 可以没有 Profile
model User {
  profile UserProfile?  // ? = 可选
}

// 必选一对一：创建 User 时必须同时创建 Profile
model User {
  profile UserProfile  // 没有 ?
}
```

## 图书管理系统实例：User ↔ UserAuth

```prisma
model User {
  id       BigInt    @id @default(autoincrement())
  username String    @unique
  auth     UserAuth? // 可选的第三方登录信息
}

model UserAuth {
  id            BigInt  @id @default(autoincrement())
  user          User    @relation(fields: [userId], references: [id])
  userId        BigInt  @unique    // ← 保证一对一
  wechatOpenId  String? @unique
  githubId      String? @unique
  googleId      String? @unique
}
```

## 何时用一对一？

- 扩展表过大（User 基本字段 vs UserProfile 扩展字段）
- 敏感信息隔离（User 基础信息 vs UserAuth 第三方登录凭证）
- 可选关联（用户可以选择性填写详细信息）
