# ExceptionFilter 的全局注册方式对比

## 三种注册方式

### 方式 1：`app.useGlobalFilters()`（无 DI）

```typescript
// main.ts
async function bootstrap() {
  const app = await NestFactory.create(AppModule);

  app.useGlobalFilters(
    new HttpExceptionFilter(),
    new AllExceptionsFilter(),
  );

  await app.listen(3000);
}
```

- ✅ 简单直接
- ❌ Filter 无法注入依赖（因为没有经过 DI 容器）

### 方式 2：`APP_FILTER` token（有 DI）

```typescript
// app.module.ts
import { APP_FILTER } from '@nestjs/core';

@Module({
  providers: [
    {
      provide: APP_FILTER,
      useClass: HttpExceptionFilter,
    },
    {
      provide: APP_FILTER,
      useClass: AllExceptionsFilter,
    },
  ],
})
export class AppModule {}
```

- ✅ 可以注入依赖（如 ConfigService、Logger）
- ✅ Filter 实例由 Nest DI 容器管理
- ⚠️ 多个 `APP_FILTER` 的注册顺序可能影响执行

### 方式 3：Controller/Handler 级别

```typescript
@Controller('user')
@UseFilters(UserExceptionFilter)  // 只对 UserController 生效
export class UserController {}

@Get('profile')
@UseFilters(HttpExceptionFilter)  // 只对 profile 接口生效
getProfile() {}
```

## 多个 Filter 的执行顺序

```typescript
// 注册
app.useGlobalFilters(FilterA, FilterB, FilterC);

// 执行顺序：从右到左，类似洋葱模型
// FilterC → FilterB → FilterA → (异常被 A 捕获)
// 如果 A 处理了异常并返回响应 → B 和 C 不执行
// 如果 A 不处理（catch 条件不匹配）→ B 处理 → C 处理
```

**关键规则**：多个 Filter 中，先注册的后执行。只有捕获到匹配异常的 Filter 才会处理。

## @UseFilters 与全局 Filter 的配合

```typescript
// 全局：HttpExceptionFilter → 统一格式
// Controller：UserExceptionFilter → User 模块特殊处理

@Controller('user')
@UseFilters(UserExceptionFilter)  // 先捕获
export class UserController {
  @Post('register')
  register() {
    throw new UserAlreadyExistsException('john');
  }

  // UserExceptionFilter 先匹配 UserAlreadyExistsException
  // 如果 UserExceptionFilter 只 @Catch(HttpException)，则会由全局 HttpExceptionFilter 捕获
}
```

## 注册选择指南

| 场景 | 推荐方式 |
|------|---------|
| 全局统一错误格式 | `app.useGlobalFilters()`（不需要 DI） |
| 需要注入 Logger/ConfigService | `APP_FILTER` token |
| 某个 Controller 特殊错误处理 | `@UseFilters()` |
| 已知异常（HttpException）和未知异常分别处理 | 两个全局 Filter 搭配使用 |

## 推荐配置

```typescript
// main.ts
async function bootstrap() {
  const app = await NestFactory.create(AppModule);

  // 全局兜底：捕获所有异常（不需要 DI）
  app.useGlobalFilters(new AllExceptionsFilter());

  await app.listen(3000);
}

// app.module.ts
@Module({
  providers: [
    // HttpException 的处理需要 DI（ConfigService）
    {
      provide: APP_FILTER,
      useClass: HttpExceptionFilter,  // 需要注入 ConfigService 判断环境
    },
  ],
})
```

这样配置后：
1. `HttpExceptionFilter` 先捕获 `HttpException`（含 ValidationPipe 的校验错误）
2. `AllExceptionsFilter` 兜底捕获未知异常（`APP_FILTER` 注册的在全局之后执行吗？取决于注册顺序）

> ⚠️ 注意执行顺序：多个 `APP_FILTER` provider 之间的顺序不确定。如果对顺序有严格要求，在 main.ts 中按顺序显式调用。
