# NestJS 内置异常类速查

## 完整的 HTTP 异常类

Nest 提供了与 HTTP 状态码对应的内置异常类。它们都继承自 `HttpException`。

```typescript
// 基础用法：所有内置异常都接受两个可选参数
throw new BadRequestException('用户名不能为空');
throw new BadRequestException('用户名不能为空', { description: 'validation_error' });
// 第二个参数是 options，可以携带 description 和 cause
```

## 速查表

| 异常类 | HTTP 状态码 | 语义 | 典型场景 |
|--------|-----------|------|---------|
| `BadRequestException` | 400 | 请求格式错误 | 参数校验失败、业务规则不满足 |
| `UnauthorizedException` | 401 | 未认证 | 未登录、Token 无效/过期 |
| `ForbiddenException` | 403 | 无权限 | 已登录但无权限访问 |
| `NotFoundException` | 404 | 资源不存在 | 查用户/图书不存在 |
| `MethodNotAllowedException` | 405 | 方法不允许 | GET 访问了 POST 接口 |
| `NotAcceptableException` | 406 | 不可接受 | 请求的资源不满足 Accept 头 |
| `RequestTimeoutException` | 408 | 请求超时 | 客户端发请求太慢 |
| `ConflictException` | 409 | 资源冲突 | 重复注册（唯一约束冲突） |
| `GoneException` | 410 | 资源已删除 | 资源永久删除 |
| `PayloadTooLargeException` | 413 | 请求体过大 | 上传文件过大 |
| `UnsupportedMediaTypeException` | 415 | 不支持的媒体类型 | Content-Type 不是 JSON |
| `UnprocessableEntityException` | 422 | 语义错误 | 数据格式对但业务逻辑有问题 |
| `TooManyRequestsException` | 429 | 请求太频繁 | 触发限流 |
| `InternalServerErrorException` | 500 | 服务器内部错误 | 未捕获的异常 |
| `NotImplementedException` | 501 | 未实现 | 接口尚未实现 |
| `BadGatewayException` | 502 | 网关错误 | 代理请求上游返回异常 |
| `ServiceUnavailableException` | 503 | 服务不可用 | 服务维护中 |
| `GatewayTimeoutException` | 504 | 网关超时 | 上游服务超时 |

## 各异常类的行为差异

```typescript
// 1. 默认消息（无参数）
throw new BadRequestException();
// → { statusCode: 400, message: 'Bad Request', error: 'Bad Request' }

// 2. 自定义消息（string 参数）
throw new BadRequestException('用户名不能为空');
// → { statusCode: 400, message: '用户名不能为空', error: 'Bad Request' }

// 3. 自定义响应体（object 参数）
throw new BadRequestException({
  code: 10001,
  message: '用户名不能为空',
  field: 'username',
});
// → { statusCode: 400, message: { code: 10001, message: '用户名不能为空', field: 'username' }, error: 'Bad Request' }
```

## HttpException 的构造参数

```typescript
class HttpException {
  constructor(
    response: string | Record<string, any>,  // 响应体
    status: number,                           // HTTP 状态码
    options?: {
      cause?: Error;          // 原始异常（用于日志追溯）
      description?: string;   // 描述信息（只暴露给开发者，不返回客户端）
    },
  );
}
```

使用 `cause` 保留原始错误：

```typescript
try {
  await this.prisma.user.create({ data: dto });
} catch (err) {
  throw new InternalServerErrorException(
    '用户创建失败',
    { cause: err }  // ← 保留原始 Prisma 异常，便于日志分析
  );
}
```

## 图书管理系统中的典型使用

```typescript
// user.service.ts
@Injectable()
export class UserService {
  async register(dto: RegisterUserDto) {
    const existing = await this.prisma.user.findUnique({
      where: { username: dto.username },
    });

    if (existing) {
      throw new BadRequestException('该用户已注册');
    }
    // ...
  }

  async login(dto: LoginUserDto) {
    const user = await this.prisma.user.findUnique({
      where: { username: dto.username },
    });

    if (!user) {
      throw new BadRequestException('用户不存在');
      // 也可以是 NotFoundException，但 400 对前端更友好（字段级别错误）
    }

    if (user.password !== hashPassword(dto.password)) {
      throw new BadRequestException('密码不正确');
    }

    return { username: user.username };
  }
}
```

> 内置异常类的默认消息是英文的。生产项目建议总是指定 `message` 参数，确保前端收到的错误提示是中文的。
