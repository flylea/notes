# ValidationPipe 的 exceptionFactory

## 问题

默认情况下，ValidationPipe 抛出标准格式的异常：

```json
{
  "statusCode": 400,
  "message": ["用户名不能为空", "密码最少 6 位"],
  "error": "Bad Request"
}
```

但项目的统一响应格式是：
```json
{
  "code": 0,
  "data": { ... },
  "message": "ok"
}
```

两种格式不一致——前端需要特殊处理 ValidationPipe 的错误。

## exceptionFactory 方案

```typescript
// main.ts
import { ValidationPipe, BadRequestException } from '@nestjs/common';
import { ValidationError } from 'class-validator';

app.useGlobalPipes(
  new ValidationPipe({
    whitelist: true,
    transform: true,

    exceptionFactory: (errors: ValidationError[]) => {
      // 自定义错误格式
      const formattedErrors = errors.map(e => ({
        field: e.property,
        message: Object.values(e.constraints || {}).join(', '),
      }));

      return new BadRequestException({
        code: 90000,  // 参数校验错误码
        message: formattedErrors.map(e => e.message).join('; '),
        errors: formattedErrors,  // 详细的字段级错误
      });
    },
  }),
);
```

响应变为：
```json
{
  "code": 90000,
  "message": "用户名不能为空; 密码最少 6 位",
  "errors": [
    { "field": "username", "message": "用户名不能为空" },
    { "field": "password", "message": "密码最少 6 位" }
  ]
}
```

前端可以精确地为每个字段显示错误提示：

```typescript
// 前端处理
if (error.response.data.errors) {
  error.response.data.errors.forEach(err => {
    form.setFieldError(err.field, err.message);
  });
}
```

## ValidationError 结构

```typescript
interface ValidationError {
  target?: Record<string, any>;   // 原始对象（通常被关闭）
  property: string;               // 字段名
  value?: any;                    // 输入值（通常被关闭）
  constraints?: {                 // 校验失败的原因
    [type: string]: string;
  };
  children?: ValidationError[];   // 嵌套对象的校验错误
}
```

## 完整示例：处理嵌套校验错误

```typescript
exceptionFactory: (errors: ValidationError[]) => {
  // 递归展开所有错误（含嵌套）
  function flattenErrors(errors: ValidationError[], parentPath = ''): any[] {
    const result: any[] = [];

    for (const error of errors) {
      const path = parentPath
        ? `${parentPath}.${error.property}`
        : error.property;

      if (error.constraints) {
        result.push({
          field: path,
          message: Object.values(error.constraints).join(', '),
        });
      }

      if (error.children && error.children.length > 0) {
        result.push(...flattenErrors(error.children, path));
      }
    }

    return result;
  }

  const fieldErrors = flattenErrors(errors);

  return new BadRequestException({
    code: 90000,
    message: fieldErrors.map(e => e.message).join('; '),
    errors: fieldErrors,
  });
},
```

## 环境区分

```typescript
exceptionFactory: (errors: ValidationError[]) => {
  const isProduction = process.env.NODE_ENV === 'production';

  return new BadRequestException({
    code: 90000,
    message: isProduction
      ? '请求参数不合法'
      : errors.map(e => Object.values(e.constraints || {}).join(', ')).join('; '),
    // 生产环境不暴露具体字段信息
    errors: isProduction ? undefined : errors.map(e => ({
      field: e.property,
      message: Object.values(e.constraints || {}).join(', '),
    })),
  });
},
```

## 与 ExceptionFilter 的配合

`exceptionFactory` 产出的异常仍是 `BadRequestException`，会被全局的 `HttpExceptionFilter` 捕获后再次包装。两者处理好关系：

```
ValidationPipe
  └── exceptionFactory → throw new BadRequestException({ code: 90000, ... })
                            ↓
                       HttpExceptionFilter
                         └── 识别 code 字段 → 返回统一格式
```

ExceptionFilter 中的处理逻辑：

```typescript
@Catch(HttpException)
export class HttpExceptionFilter implements ExceptionFilter {
  catch(exception: HttpException, host: ArgumentsHost) {
    const status = exception.getStatus();
    const resp = exception.getResponse();

    // 如果 exception 已经包装好 code 字段（来自 exceptionFactory），直接返回
    if (typeof resp === 'object' && (resp as any).code) {
      return response.status(status).json(resp);
    }

    // 否则按默认处理
    // ...
  }
}
```

> `exceptionFactory` + `ExceptionFilter` 的配合是实现**完全自定义的错误响应格式**的标准方案。ValidationPipe → exceptionFactory → HttpException → ExceptionFilter，这条链路保证了无论校验失败还是业务异常回到前端的都是同一格式。
